## 2026-10-03 14:00 登录闭环 + 商店上架范围 + 成本下限（贾维斯）
- 修正术语错误：此前把「同源(same-origin)」与「同站(same-site)」混用。真实卡点是**跨站**不是跨源。`cloud-sync.ts` 用相对路径 `fetch('/api/...')` + `credentials:'include'`，因此**T1 同源路径反代是唯一零前端改动方案**；同站子域方案需 PR #35 的 base URL helper。
- 登录闭环已按实现逐行写入手册 §5.5：Cookie `jx_session`（Path=/; HttpOnly; SameSite=Strict; Max-Age=604800; 无 Domain=host-only; HTTPS 追加 Secure）；六位码/600s/五次失败；token=randomBytes(32) base64url，仅存 sha256；refresh 轮换吊销旧值；logout 置 Max-Age=0。错误码：INVALID_EMAIL / MAIL_UNAVAILABLE / VERIFICATION_STORE_FAILED / RATE_LIMITED(Retry-After 60) / INVALID_OR_EXPIRED_CODE / UNAUTHENTICATED / ORIGIN_REJECTED / INVALID_REQUEST。发码失败自动 invalidate+refundIssue 退额。
- Origin 硬约束：非 GET/HEAD/OPTIONS 请求 Origin 必须精确等于 AUTH_PUBLIC_ORIGIN（前端 origin，非 API 域名），否则 403；OPTIONS 只放行 GET/POST/PUT/DELETE 与 Content-Type/X-Jiuxiao-Account。
- trustedProxyAddresses 四种取值：同机 Nginx 需 127.0.0.1 与 ::1；Cloudflare 需其 IP 段；直连留空；独立反代机需其地址。漏配→限流把所有人算成一个人。
- 无其他登录方式（无 OAuth/微信），符合 ADR-0003。新增登录方式须新 ADR。
