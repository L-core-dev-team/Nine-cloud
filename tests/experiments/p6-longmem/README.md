# P6-LONGMEM-01：离线长剧情评测

这是独立的合成数据实验，未进入正式游戏。只使用 Node 24 的 TypeScript 类型擦除和已有 TypeScript 编译器，不调用 LLM、服务器 API、数据库或任何生产包。没有新增第三方依赖。

在仓库根目录执行一条命令：

```powershell
node tests/experiments/p6-longmem/run.ts --sizes 200,500,1000 --out tests/experiments/p6-longmem/results
```

默认运行 200 回合；`--sizes` 可选择 200、500、1000。生成原始历史 JSON、独立答案 JSON、完整逐题结果、失败案例和汇总表。普通命令的退出码表示工具是否成功运行，**不表示质量全部通过**；`--strict-quality` 在任一历史检索题失败时返回 1，保留全部结果。近期基线的失败不触发该开关。

查询示例：

```powershell
node tests/experiments/p6-longmem/query.ts --text "我第一次遇到那名剑修时，他交给了我什么？" --as-of 180 --budget 1024
node tests/experiments/p6-longmem/query.ts --text "青玉佩归属变化" --from-turn 100 --to-turn 200 --budget 2048
node tests/experiments/p6-longmem/query.ts --text "青玉佩归属" --from-minute 8568 --to-minute 13608
node tests/experiments/p6-longmem/query.ts --text "陆迟说密信藏在哪里？" --npc p-su --budget 4096
```

`--turns 500/1000` 选择容量，`--as-of` 设置查询时点；时间范围为闭区间。自然语言中的中文回合数不会自动解析成范围，应明确提供参数。默认玩家视角；NPC 必须有显式模拟授权。`--strategy recent` 可查询近期截取基线。返回的是完整原文证据与状态标签，不生成剧情答案。实体名可使用数据集列出的别名，未实现任意中文语义理解。

`--history <已生成的 history-200/500/1000.json 路径>` 可重复只读加载保存的合成数据，并先校验来源和时序；不是正式存档导入接口。

测试与类型检查：

```powershell
node --test tests/experiments/p6-longmem/invariants.test.ts
node node_modules/typescript/bin/tsc -p tests/experiments/p6-longmem/tsconfig.json
```

## 数据与独立答案

- `anchors.json`：人工编写的 25 个关键场景及人物/物品/地点词典。全部虚构，不导入 Canon。
- `dataset.ts`：确定性生成连续历史。200 回合包括关键场景与沿途日常；500/1000 扩展只增加日常干扰项，不增加同等数量的复杂事实。
- `gold.ts`：单独人工标注的 60 题及来源、值、时序状态与授权边界，不导入剧情、索引或检索器。评测不生成或修改答案。问题、来源和正确事实在首次评测后未修改；可通过导出的答案哈希比较。
- `retrieval.ts`：中文双字片段、实体别名、通用意图/动作约束、历史链接及来源级可见性。只读、线性扫描预计算文档特征。当前有效事实与历史已失效事实分开；角色说法始终标为未证实。未来来源及未来替代日期不会进入较早查询上下文。
- `evaluate.ts`：只在评测阶段读取答案；检索器本身不访问答案。`run.ts` 执行四档预算两种策略；`query.ts` 可单独运行。

## 预算与真实性

预算只计返回历史证据，包含来源头、原文、事实、有效期、替代关系和不确定性标签。**Token 是估算值：`ceil(UTF-8 字节数 / 2)`。未使用目标 tokenizer，既非精确计数，也非经过证明的上界，不能据此保证真实模型预算或结算费用。** 不包括系统提示词、当前问题或模型输出。

整条来源能装下才返回；不会截断原文或将说法压缩成确认事实。超限项列入 `omittedSourceIds`。多阶段问题在相关候选未完全装入时保守声明证据不足；这可能在答案所需证据已齐时仍拒答，作为 FAIL 保留。

基线只取可见历史中最新来源，在预算内截取，不按查询相关性排序；无查询相关性拒答模块，因此不能把它的上下文自动视为可靠答案。两种策略共享原文格式、估算方法、完整来源打包、时点与权限过滤。相同 `maxSources=8`，避免基线与历史策略使用不同成本口径。

## 指标口径

- Recall@8：**预算打包前**排名前 8 命中的手工预期来源数 / 全部预期来源数，微平均，不包含无证据题的空分母。
- 来源准确率：预算打包后命中的手工支持来源数 / 全部返回来源数；未标注为直接支持的来源计为冗余。其补数是“不支持来源比例”，不是已证实虚假事实比例。
- 历史时序准确率：标记为时序题时，所有必要事实已返回，值与手工时序状态均正确。缺失也算失败。
- 事实错误归属率：与目标事实谓词相同的返回事实中，主体不属于手工答案主体集合的比例。这个指标不代表整个事实内容都经过语义判真。
- 无证据拒答率：无证据题同时返回空证据且 `enoughEvidence=false` 的比例。
- 越权 / 未来来源泄漏：预算前排名集合中的违规来源数量；单位测试也检查串联链接和输出文本。
- 长距离遗忘率：标注为早期关键回忆且查询时点不早于 180 的题，预算打包后仍缺少任一必需来源的比例。
- 重复事实率：同一主体/谓词/值的重复条目 / 所有返回事实条目。历史上真正复现的关系值也会计入，不能解释为所有重复都可安全删除。
- PASS：必要来源、事实值与状态齐全，无泄漏；历史策略还须声明证据充足。负例必须空证据并拒答。**PASS 不要求所有返回来源都相关**，额外来源由准确率单独处罚。
- 延迟：本机单次查询 p50/p95/max，另报索引创建耗时；不包含模型、网络或数据生成。耗时不保证逐次复现，来源和质量结果应可复现。

500/1000 的 60 题保持各自原始查询时点，检测扩大语料时是否越过时间边界；另有独立压力探针把查询时点移到第 500/1000 回合末，观察早期物品、归属链与伏笔。探针的答案亦显式维护，不由检索器生成。

## 限制及正式集成建议

合成词典和人工元数据不能代表真实长局叙事质量，60 题也不是隐藏测试集。关键词意图与实体消歧在自然表达变体上可能失败；足够证据标志是启发式判断。当前 NPC 权限是**整条来源**模拟，未模拟生产 grant、遗忘曲线、召回修订或跨分支规则，不能声称 P4/P5 验收通过。

正式后续可提供只读来源适配器：P3 交付稳定叙事来源 ID、原文、回合/时钟/分支及规则回执；P4 提供按 NPC 冻结授权读取及分页；P5 提供指定时点的可召回过滤结果。玩家档案保留原始叙事，授权世界事件依照回执单独标注，NPC 过滤仅作用于 NPC 查询视图。准确目标 tokenizer、真实数据评测和集成须另行批准，本轮没有接线。
