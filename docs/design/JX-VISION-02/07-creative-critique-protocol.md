# VISION 02｜独立创作与评价协议（仅研究与方案）

## 1. 创意不能由旧版本预先决定
用作者原话、真实世界观和58张参考材料形成初始创意；先做独立方向，再用旧版进行差距和兼容核对。禁止把既有页面树、CSS tokens、签名图形数量或动画额度当作创意约束。Claude可推翻GPT提供的六种候选；不要将本协议变成新的固定美学。
- 先提出彼此不能简单换皮得到的方向，例如空间世界、电影化文字剧场、程序化山水、可交互宇宙、日常生活与人间烟火；也允许完全不同的原创方向。
- 每套至少展示首屏、建角、游戏主场景、长篇剧情、地图/探索、修炼/突破、酒馆/群聊、设置与错误恢复等关联场景的实际设计说明；用有明确视口和状态的设计板或分镜表现关键画面。不要求此阶段实现产品代码。
- 对比设计在十秒内能传递什么、十分钟内玩家做什么、十小时后是否仍然愿意留在世界中。区别首见惊艳、长期游戏和操作清晰，不强迫同一画面同时承担所有目标。

## 2. 把用户参考变成艺术知识
逐图核对原文件、构图、光向、景深、透视、色彩、物件、运动、情感和与九霄的联系；长截图分段查看、查原始技术文献。不要在公开仓库上传未确认授权的原图。来源分成直接观察、官方资料、二手资料、设计推论四级。避免误把设计建议当作技术事实。
研究路线不限：东方山水（散点透视、三远法、虚实、墨色积染）、园林（借景、障景、框景、步移景异）、建筑与舞台调度、电影摄影（景别、镜头、色彩叙事、剪辑、声画关系）、游戏美术（环境叙事、diegetic UI、导航、可供性、玩法反馈）、交互艺术（生成艺术、视觉音乐、信息设计）、字体与编辑设计、光学与数学。可研究《千里江山图》《富春山居图》、James Turrell光空间、传统园林、Breaking Bad / Better Call Saul 的构图和环境叙事、Journey、GRIS、对马岛之魂、黑神话：悟空、艾尔登法环及Awwwards/FWA案例；以上是研究起点，不是规定的审美模板。

## 3. 设计必须能和权威玩法发生关系
提出至少一项有辨识度、由真实玩家行为触发的核心交互机制。示例而非规定：探索地图中的风、雾、光线、道路随地点与事件变化；突破改变真实修为并由镜头、声场、光照表现；玩家的世界记忆可在地图、人物关系和时间轴交叉访问；NPC登场有明确的身份、认知与环境。任何概念说明真实数据来源、事件状态机、AI叙述边界、失效/重试和降级机制。可修改规则与世界契约，但必须给出处、兼容或迁移方案；不能把未实现功能演示成已存在。

## 4. 技术推导、方案验证与工具矩阵
不要只罗列库。将艺术难题拆成光学（光传输、Fresnel、散射、反射、色彩管理）、几何（投影、相机路径、SDF、LOD、地形、空间层次）、动力学（弹簧、阻尼、粒子、噪声、流体近似）、计算（GPU管线、采样、时间插值、资源生命周期）、视觉心理与声音。对关键效果写算法、适用条件、参数意义、单位、限制、可测试假设；只使用确有必要的知识。评估2D、2.5D、实时3D、离线渲染、混合路线，不为了采用WebGPU而采用WebGPU。比较高画质上限、输入延迟、视觉稳定、移动可达、资产生产和迭代成本；先定艺术目标，再选技术与质量档位。
工具候选包括Claude官方frontend-design技能、独立子代理、浏览器与Playwright、Figma/Penpot、Blender/Geometry Nodes、Houdini、Three.js/R3F、Babylon、WebGPU/WGSL、GLSL、GSAP/Motion、Rive、Web Audio、Rust/WASM、Python科学计算等。核验实际版本、许可证、能力、运行环境、安装权限；给作者可执行的安装/提供清单（必需/可选、用途、平台、费用、替代项），不擅自收费或公开私人素材。

## 5. 创作者与评价者分离
借鉴Anthropic独立评价器的研究方法，不把角色设定或自评当作保证。条件允许时由子代理独立扮演艺术总监、游戏设计师、创意技术工程师、可访问性与真实状态评审者，先各自评价候选，后汇总。无法调用子代理时用独立评价轮次并明示不是真正独立评审。
- 对每套方向提出具体反例：哪里像普通AI网页？哪里是借用熟悉风格而非原创？去掉粒子/光效后构图是否仍然成立？它能否让玩家在同一世界中完成真实任务？它是否只在海报上成立？
- 评价维度：原创与辨识度、构图与叙事、空间与尺度、材质与光、动态及声音、交互意义、玩法耦合、长期阅读、跨屏完整性、工程可验证性。使用有证据的分项评价（优秀/有潜力/需要重构或带锚点的1–5评分），不凭空给95分、不给世界级保证。不同方向的矛盾和取舍比总分重要。
- 至少经历初稿、独立质疑、实质重构、复评；必要时继续，不固定轮次数。若用5–15轮研究范式，必须保留各轮变化与停止依据，拒绝只替换形容词和效果名。最终推荐至少一个主方案及一个有根本差异的备选，明确淘汰理由、风险和未验证项。
- 若环境能截图，记录相同状态、相同分辨率、相同数据的新旧候选；无真实截图就标明是概念设计，不假造线上体验或测试。

## 6. 制度、证据与交付
全仓MD按实际效力分类：现行设计、现行工程、作者已签事实、安全/许可/数据、历史验收、过时方案、第三方/生成内容。对现行美学限制逐条列出路径、原文、冲突、替代文本；旧审批记录不能改写成新事实，可在文件顶部标明历史效力或建立替代规范；维护文档引用、索引、自动化脚本及测试的对应关系。不要把全仓枚举当成阅读完成。
在独立候选分支提交研究记录、概念板/故事板（合法可公开）、技术比较、全栈与玩法方案、制度冲突矩阵、独立评价及版本差异、实施路线与成本工具清单。对作者逐项解释什么实际改变，为什么更好，哪些尚无证据。不得在本阶段更改生产产品代码、部署、生产数据、合并现有PR；后续可在作者批准的实施阶段自由重构。
