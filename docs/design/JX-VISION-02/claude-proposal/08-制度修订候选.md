# 08 · 制度修订候选（只提候选，不改任何文件）

**方法**：一名独立子代理对仓库中被 Git 跟踪的全部 **345 份** Markdown 做了分类与审查。VISION 02 基线审计写的“333 份”统计的是 `f1fe6ea`，已经过时。

- 22 份全文阅读；
- 48 份逐行检查含规范用语的句子，并通读全部标题；
- 其余 275 份略读：标题、首段，加上全仓关键词检索的命中行。

完整的逐行冲突矩阵（含原文逐字、建议替换文本、改动风险）见 [appendix/md-冲突矩阵.md](appendix/md-冲突矩阵.md)，全量分类与每份文件的读取深度见 [appendix/md-全量分类.md](appendix/md-全量分类.md)。本研究**没有修改**任何一份制度文件。

## 结论

1. **真正还在以现行口吻冲突的文件有 14 份（A 组）**，都没有效力声明，正文仍规定旧审美或旧技术。最需要先处理的是：
   - `PRODUCT.md` 第 5 行：把 2026-09-23 总方案称为“1.0 现行范围”，但 ADR 0004 已经把社区和收费排除在 1.0 之外；
   - ADR 0001 第 11、41、43 行：浏览器端只准 React，新技术只能凭性能瓶颈数据引入；
   - 两份 2026-09 方案的视觉条款：B 山门构图、“玻璃、粒子和光效只用于导航与短反馈”；
   - 锚点变更记录：它是 E 目录里唯一没有声明的文件，其中“新断言必须同等或更严格”会把旧视觉指纹锁进测试。
2. **GPT 已给 17 份文件加了效力声明（B 组），足以中和冲突，正文应保持原样。** 但声明有两个缺陷：
   - 链接写死为分支 `docs/vision-02-art-direction` 的 URL，分支合并或删除后会失效；
   - 没有说明哪些【定】条款仍作为产品要求有效，例如真实字段、原文不改写、对比度、测试诚实。

   矩阵 §2 给出了候选替换文本。
3. **10 份文件被 CI 哈希锁定**，即 P1 规则包和作者原创输入登记。加一行字也会让 `pnpm test` 失败，或让已批准的规则身份失配。它们不含审美限制，必须原样保留。
4. **“保守”大多不是审美用语，不能删，也不能改名。**
   - `世界书_保守补全版.md` 是 Canon 来源，按路径和 SHA-256 绑定；
   - “保守误拒”“保持 DENY”“保守费率”是测试诚实或财务口径；
   - 问卷里的“克制”是受访者原话。
5. **只改文档解不开发布门禁（C 组）。** 代码与测试里还有三道锁：
   - CI 的 three.js 产物扫描；
   - scene-studio 的排除过滤器；
   - `tests/e2e/foundation.cjs` 里冻结的 AI 编辑器样式。

   实施阶段需要一份经作者批准的“视觉断言重建登记”：行为、数据、无障碍、安全断言保持同等或更严格，视觉指纹换成新基线，并保留新旧证据。
6. **断链与过时引用 12 处**，包括：
   - `docs/README-workspace-guide.md` 的 23 条断链；
   - 一个不存在的命令 `pnpm assets:manifest:check`；
   - 一份世界书转换记录里的本机绝对路径。那是历史快照，按 AGENTS 规定不改，但要确认它不进入公开包。
