# 05 · 独立评审与三轮实质修改

## 评审怎样安排

按 [07 协议](../07-creative-critique-protocol.md)，创作者与评价者分离：

- **第一轮**：三名独立子代理分别担任艺术总监、游戏设计、创意技术与无障碍。
  - 他们拿到的材料是：作者任务书摘要、参考图的文字分析、规则事实、四个方向的说明（删去了我的自评），以及 10 张帧图（四个方向各一张桌面、一张手机，加上线上现行画面）。
  - 他们不知道我倾向哪个方向，也没看过方案 E。
- **第二轮**：另一名子代理身兼三职，只看第二轮帧图和规则事实，不看第一轮评审。

评审原文都在 [reviews/](reviews/)，没有删改。按 Anthropic 的提醒，评价者是 LLM，对 LLM 的作品可能偏宽容，所以下文的取舍只依据评审中**具体、可核对的反例**，不看分数。

## 第一轮：三份评审的结论

| | 美术 | 游戏设计 | 技术与可及性 |
|---|---|---|---|
| 排序 | 乙 > 丙 > 甲 > 丁 | 甲 > 丙 > 乙 ≈ 丁 | 甲（作主体）> 乙 > 丙（作机制层）> 丁（作系统层） |
| 主张 | 以乙为主身份；**否决甲**：它是国风默认图式，名为绢本、实为矢量 | 以甲为骨架，但必须嫁接丙的“字落为迹”，否则只是“一张更漂亮的皮” | “受光的长卷”：以甲的画为世界，以乙的天光为渲染核心 |
| 共同点 | 丙的“玩家写下的字飞向解析出的目标”是全包唯一属于这款游戏的交互 | 同左 | 同左，只在提交那一刻使用 |

**三方都指出的硬伤**（我逐条核对过，全部属实）：

1. **“同一真实存档”是我拼出来的。** 04 文档写“取自线上 1.0 预览版的实际存档”，帧图却把芦花渡、酉初、开场白和体力 92 放在一起；而体力 92 是在望气台环视之后才有的数值。这是我的错误陈述，已在 04 开头更正。
2. 甲的手机帧把落石和鸦群裁到了画外，可它们是序章唯一的任务目标。
3. 乙把向东的河渡画成了开阔海面：没有芦苇，落石成了远处的岛，月牙的亮边背对太阳。
4. 丙飞行的字是倒序，而且示范句“去渡口看看那堆石头”是复合句，确定性解析器不会把它解析到单一目标。
5. 丁在修为 0、炼体期，却画出满溢的灵台和“神识所及”，比真实境界高出一个大境界。
6. 四个方向都只画了“第一眼海报”，没有画完整的一个回合；都没有人物的脸；小字对比度大约只有 2.2–3.8:1。

**评审之间的分歧，我怎样取舍**：

- 美术评审说甲是“平庸传统”，这一点我接受。青绿、松框、孤舟、装裱、落印这一整套图式全部放弃。
- 游戏与技术评审看重甲的“状态规格完整”和“画作为世界”，这一点我也接受，但把它换成**不带古画图式**的形式：以手绘的地点画板为体，用统一天光重新打光。
- 美术评审要求乙“把地点画真，补上门与框”，所以第二轮直接画真实的望气台，并以台柱作框。
- 游戏评审的“摘句为证”，三方都没有反对，采用，并作为备选方案“卷宗”的核心。
- 技术评审的“DOM 是唯一语义真源”“三档降级”“不要采用”清单，全部采用。

## 第二轮：修改了什么

**内容**：改用真实状态链，常量取自 `prologue-v1.constants.ts`：

| 时刻 | 事件 | 体力 | 线索 |
|---|---|---|---|
| 卯初 05:00 | 开局 | 100 | — |
| 05:15 | 移动到望气台 | 95 | — |
| 05:30 | 环视 | 92 | 落石线索 |
| 05:45 | 细察 | 86 | 鸦群线索 |

叙述全部用 `prologue-v1.ts` 的原文。

**画面**：
- 天空由单次散射物理模型按 `gameMinute` 计算，包括瑞利散射、米氏散射与臭氧吸收；
- 水面用菲涅耳反射和小面闪烁；
- 前景用望气台朽木的台柱作框；
- 芦苇在逆光时发亮。

**交互**：
- 言落：只在解析出目标时飞行，目标词作为一个整体飞，不会倒序；
- 复合句进入追问；
- 解析预览带代价；
- 账本列出真实增量；
- 建议签只列当前规则允许的行动。

**版式**：
- 叙述全部用 DOM 横排；
- 数值显示为数字；
- 手机取景以目标为中心，键盘弹起时画面收成一条。

## 第二轮评审：还剩什么问题

原文见 [reviews/盲评-第二轮.md](reviews/盲评-第二轮.md)。评审认为比基线“跨了一个档次，有辨识度，但不像仙侠”，最接近《Firewatch》《Kentucky Route Zero》《Heaven's Vault》《文字游戏》。具体问题：

1. 提交按钮叫“落定”，等待状态叫“未落定”，玩家分不清自己是否已经提交。
2. 追问只有二选一，没有“改写”。
3. 看不到任务目标。
4. 标注写“几十只”鸦，画面里只看得出三四只；“渡船”标注指向空地。
5. 白天三个时刻比黎明还暗。
6. 弧线压住文字。
7. 小字对比度约 3.6:1，手机上签高约 33px。
8. 夜帧的天空渐变看起来是倒的。
9. 夜帧里的体力 86 按规则到不了。

## 第三轮：针对第二轮的修改

| 问题 | 修改 | 状态 |
|---|---|---|
| “落定”与“未落定”混淆 | 提交改叫“落笔”，等待状态叫“结算中”，网络失败叫“这一步还没落定” | 已改，见 [v3 帧](frames/v3/flight-desktop.webp) |
| 追问缺少出路 | 增加“改写这句话（不结算，不耗时）”。“依次都做”**没有采用**：规则每回合只结算一个动作，两件事必须分两回合；把“依次”做成一个选项，会让人以为一次能结算两件 | 已改 |
| 看不到任务目标 | 地名下常驻“任务　通渡　渡槽口被落石堵住” | 已改 |
| 白天过暗 | 曝光的基准值随太阳高度提高；地面反照率和环境光按物理量重新标定 | 已改，见 [v3 时间条](frames/v3/time-strip.webp)：08:00、12:00 已读作白天，16:00 仍偏暗 |
| 弧线压字 | 飞行时上一回合的叙述收起；追问时只画靠近停顿点的一段弧线 | 已改 |
| 小字对比度、手机签高 | 代价文字透明度从 0.5 提到 0.72；手机签的内边距加到约 44px 高 | 已改，**还没有实测对比度**（实验 E6） |
| 鸦群看不见 | 鸦按“灰羽”改为灰色受光，数量 42 只，分布在整个石堆上 | **仍未解决**：晨光里鸦与石同色，放大后仍难分辨。这是程序化占位的上限，交给画板阶段 |
| “渡船”指向空地 | 船舷加一道受光线 | 部分解决：推近镜头里船在叙述区附近，标注被碰撞规则隐藏 |
| 夜帧渐变倒置 | **不改**：东方天际在日落后的粉带与其下的暗带，就是地影与“维纳斯带”，是真实现象，由散射计算自然出现。但评审读成了错误，说明需要更好的取景；记入缺陷 | 已解释 |
| 夜帧体力 86 不可达 | 该帧只用来演示入暮光照与夜间文本，在 06 里标注为示意 | 已标注 |
| “摘句”下划线、“今日长线”暗示了未实现的功能 | 帧里删掉“今日长线可回看”这句话；下划线保留，作为 P2 的提议，在 06 里标明尚未实现 | 已改 |
| 视点不是俯瞰 | 望气台在“渡口外三里”，从三里外的台上看，俯角本来就只有一两度。所以保留平视偏俯的视角，用推近镜头补足细节 | 保留，并说明理由 |

## 我自己对现状的判断（只作记录）

- 光、版式、真实状态管线、言落的状态机，这四样已经用帧图验证到“值得做 P0 实验”的程度。
- 地面画面仍是占位，美术质量的上限取决于画师。第二轮评审说它“不像仙侠”，这一点我同意。“仙侠感”应当来自 Canon 的具体内容（例如九十九座浮空剑峰、吞噬声音的雾），而不是祥云、金边一类的符号。序章只是凡人渡口，此时不像仙侠反而是对的。但这只是我的判断，需要作者裁定。
- 没有做第三轮盲评。第三轮修改是否真的解决了问题，还需要作者或下一轮评审来看。
