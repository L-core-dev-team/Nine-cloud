# 07 · 分阶段实施路线、工具与成本

本阶段只做研究与设计。下面每个阶段都要等作者批准后才能开始；凡涉及付费、门禁修改、生产数据或线上部署的，都单独列出。

## 阶段总览

| 阶段 | 效果 | 依赖 | 验收 | 回滚 | 材料与授权 |
|---|---|---|---|---|---|
| **P0 实验**（约 2–3 周） | 用证据决定主方案还是备选方案，不写任何生产代码 | 作者批准 P0；能借到一台 A53 级安卓机和一台 iPhone | E1–E10 全部有结论（下表），每个实验附截图或录屏、原始数据、通过/失败 | 不涉及生产，无需回滚 | 画师一名试画一个地点（需报价，见成本表）；字体 OFL，免费 |
| **P1 竖切片：序章三地点** | 序章从“审阅面板”变成可玩的天光画面：SceneSpec、言落、追问、账本、建议签、手机键盘态，三档降级 | P0 选定路线；后端拆分提交、可见性视图（§5.1–5.2）；作者批准修改 CI 的 3D/渲染门禁 | 序章闭环（移动→观察→交谈→绕行或战斗→通渡）在三档视口、三种读屏组合下可以完成；“画面 ⊆ 事实”“必入画”“对比度”“言落四路径”测试为绿；中端安卓转场 ≥ 50 fps，空闲 0 fps | 功能开关 `scene.tianguang`，关掉即回到现有审阅面板；后端新增接口只加不改 | 3 个地点的画板与 1 幅岑九小像（画师）；不需要新规则 |

| **P3 酒馆、群聊、设置、首屏、建角** | 全站统一到天光语言 | P1 | 9 类场景都有实现或明确的“未开放”；首屏不出现解释性句子 | 逐页开关 | 首屏与建角各一组画板 |

## P0 实验（照技术评审的 E1–E10，并补两项）

| 编号 | 实验 | 通过标准 | 失败时怎么办 |
|---|---|---|---|
| E1 | **画板重新打光**：用望气台一组画板，在卯、午、酉、夜四个时刻打光 | 作者盲选 4 次里至少 3 次选打光版；A53 级机转场 ≥ 50 fps；显存 ≤ 150 MB；画板总量 ≤ 1.5 MB | 改为每个时辰手绘关键帧，再做淡化过渡 |
| E2 | **竖屏取景**：同一份 SceneSpec 渲染 390×844 和 1600×900 | 必入画锚点在两种画幅里都可见，可点区域 ≥ 44×44 px；自动化检查 | 逐个地点手调取景，美术预算按 ×2 计 |
| E3 | **中文字体管线**：思源宋体与霞鹜文楷切片自托管 | 4G 节流下，首段叙述 1 s 内可见；CLS < 0.05；序章字体流量 ≤ 600 KB；大陆三网可达 | 减少字体，或改用系统字体回退 |
| E4 | **言落**：DOM FLIP 动画与 WebGL 两种实现对比 | 中端安卓 ≥ 55 fps；字序正确；读屏只播报一次；减少动态效果时改为高亮 | 只保留 DOM 版本 |
| E5 | **天空 LUT**：Hillaire 2020 式透射率加多次散射 LUT，与原型的单次散射对比 | 午间与 16:00 不再偏暗偏灰（作者目视判断）；在 Worker 或构建期计算，主线程 0 ms | 每个地点 8 个时刻预烘焙后插值 |
| E6 | **对比度**：24 小时 × 每刻，在文字框下采样 | 小字 ≥ 4.5:1，大字 ≥ 3:1；深色渐变在 OLED 与 LCD 上没有可见色带 | 局部压暗或加底衬 |
| E7 | **读屏与键盘** | 关闭画布后，NVDA + Chrome、VoiceOver iOS、TalkBack 都能完成序章闭环；每回合只播报一次；200% 缩放可以重排 | 阻塞上线 |
| E8 | **国内浏览器矩阵**：微信内置、华为、小米、vivo/OPPO、夸克或 UC、iOS Safari | 全部都能落到某一档，不白屏；context lost 后 1 s 内恢复 | 提高 T2 的门槛 |
| E9 | **画板产能**：一位画师用同一管线画望气台 | ≤ 3 人日合格；> 5 人日说明主方案不可扩展 | 改用模块化套件，或转向备选方案“卷宗” |
| E10 | **阅读测试**：8 名玩家读 3 个回合，比较天光、卷宗和现有面板 | 阅读时间不比纯横排面板慢 10% 以上，理解正确率不下降 | 手机默认使用卷宗版式 |
| E11 | **言落理解测试**（补充）：5 名新玩家，不给说明 | 至少 4 人能说出“我写的字落到了哪里、发生了什么” | 加一次性的引导提示 |
| E12 | **键盘遮挡**（补充）：iOS 与安卓真机 | 键盘弹起时，目标物、上一句叙述和解析预览同时可见 | 把预览贴在键盘上方的工具条里 |

## 成本

| 项 | 估算依据 | 金额 |

| 字体、工具 | 全部开源 | 0 |

## 需要作者授权的事项

1. 批准 P0，以及画师试画的预算。
2. 修改 CI 门禁：`artifact-scan.mjs` 目前禁止 three.js 进入 Web 构建。主方案不用 three.js，但会新增 WebGL2 渲染代码和 KTX2 资产，门禁规则与媒体授权检查需要相应扩展，把 `.ktx2` 等格式纳入。
3. 生产环境保存叙述的隐私口径与保存期限（P2）。
4. 游戏天文（日出 05:00、正午 11:00）作为内容规则的地位。
5. AI 生成图像是否允许进入发布资产（本方案建议不允许）。
