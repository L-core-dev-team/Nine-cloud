# 08 · 全栈架构与数据契约

## 1. 分层

```
L1 权威世界层       packages/domain（规则、确定性 reducer）· packages/content（Canon、序章、规则常量）
                    packages/world【新】（九霄历、天文、天气、事件调度、传闻传播；全部确定性）
L2 世界模拟与叙事层 apps/api（回合事务、NPC 知识、叙述生成、卷宗）· AI provider（只写叙述与对白措辞）
L3 表现导演层       packages/scene【新】（SceneSpec、可见性投影、Director；纯函数，前后端共用）
L4 玩家交互层       apps/web（React 19：书页、输入、言落、证物签、七种形态、无障碍）
                    apps/web/stage【新】（渲染器：three.js r187，WebGL2 默认，WebGPU 增强；按路由懒加载）
                    apps/web/audio【新】（Web Audio：AudioWorklet 合成环境声、分层音乐）
L5 基础设施         PostgreSQL + Drizzle · Cloudflare Pages + 中继 · VPS（Caddy + compose）· Supabase（登录码）
                    tools/artpipe【新】（Python：Blender bpy、AI 重绘、事实合成、许可台账；离线运行，不进生产运行时）
```

**一条硬规则**：L3 和 L4 只能**读取** L1、L2 的结果，绝不写入权威状态。AI 只出现在 L2 的叙述与对白，以及 L3 可选的镜头排序上，而且每次输出都要经过校验。

## 2. 技术选型：逐项比较后的结论

作者已解除对任何语言或框架的预先排斥。下表的结论来自比较，而不是沿袭现状。

| 层 | 选择 | 比较过的替代 | 理由 |
|---|---|---|---|
| 前端框架 | **保留 React 19 + Vite + TS** | Svelte、Solid、原生 Web Components | 现有 150 个文件、测试与无障碍工作都在 React 上；书页与表单是 DOM 密集型界面，换框架没有艺术收益，只有迁移风险 |
| 渲染 | **新增 three.js r187**（锁定精确版本），WebGL2 默认，WebGPU 增强 | Babylon.js、PlayCanvas、OGL、纯 WebGL2 | 生态与示例最多；WebGPURenderer 可以回落到 WebGL2；gzip 后约 195 KB（WebGPU 约 228 KB），只在需要画面时懒加载。OGL 体积小，但缺少 WebGPU 路线；Babylon 包体更大（技术研究 §1） |
| React 绑定 | **不用 R3F**，渲染器是一个独立的命令式模块 | R3F 9.x | 画面是按 DirectorPlan 执行的播放器，不需要声明式场景树；渲染器与 React 解耦，也方便放进 OffscreenCanvas Worker |
| 天空 | Hillaire 2020 四张 LUT，用片元着色器生成 | 单次散射（上一轮的原型） | 多次散射修复了午间偏暗；移动端参数有原文依据 |
| 2.5D | Blender 精确深度图 + 2–4 层前景视差 | 单目深度估计、3DGS | 深度准确，体积小；3DGS 只用在 T3 档的少数展示场景 |
| API | **保留 Hono / Node** | Rust、Go | 规则引擎是 TS，前后端共享；没有性能瓶颈证据 |
| 数据库 | **保留 PostgreSQL + Drizzle** | — | 事件溯源与事务已经在用 |
| 离线资产管线 | **Python + Blender bpy + diffusers** | Houdini（付费）、UE 离线渲染 | bpy 可以用 pip 安装，GPL 不约束渲染输出（Blender 5.3 手册原文）；本轮已实测 |
| 音频 | Web Audio（AudioWorklet、ConvolverNode、PannerNode） | FMOD、Wwise 的网页版 | 零依赖，程序化合成体积小 |

## 3. 关键数据契约（`packages/contracts`）

```ts
// 行动：自由文本加可选的证物签
ActionIntent  { text: string; clarificationOf?: Uuid; evidence?: FactRef[]; idempotencyKey: Uuid }
FactRef       { factId: string; quoteSpan?: { narrationId: Uuid; start: number; end: number } }

// 提交：先返回权威结果，叙述另取（拆分）
TurnCommitted { turnId: Uuid; revision: number; branchId: string;
                visibleEvents: VisibleEvent[]; visibleDelta: VisibleDelta;   // 经可见性投影后的结果，不是原始 stateDelta
                narration: { handle: Uuid; status: 'pending' | 'template' | 'ready' } }
NarrationRecord { id: Uuid; turnId: Uuid; branchId: string; source: 'template' | 'model'; model?: string;
                  spans: { text: string; factRefs: string[] }[];     // 摘句为证的依据
                  aigc: boolean; createdAt: string }

// 可见性视图：只含角色有权知道的
WorldView     { gameMinute; place: PlaceRef; knownFacts: Fact[]; knownPlaces: Known[];
                presentNpcs: NpcPublic[]; quest: QuestPublic[]; perception?: PerceptionLayer }

// 场景与导演（纯函数输出，不落库，可重算）
SceneSpec     { placeId; cameraFamilies; anchors: { id; kind: 'fact' | 'ambient' | 'omen'; factId? ; world: Vec3 }[];
                light: { sun: AltAz; moon?: AltAz & { phase: number }; weather; grade }; safeAreas; altText }
DirectorPlan  { mode: 'you' | 'du' | 'tan' | 'dou' | 'guan' | 'tu' | 'yi'; shots: Shot[]; grade; audioCues; uiCues;
                durationCapMs; seed }

// 卷宗
ChronicleEntry { branchId; day; turnIds: Uuid[]; placeIds; clueIds; summary: { source: 'rule' | 'model'; spans } }
```

**校验规则**（服务端）：

- **证物签**：`evidence` 中每个 `factId` 都必须在该角色的 `knownFacts` 里，否则返回 400 `EVIDENCE_NOT_KNOWN`，不扣时间。`quoteSpan` 只用于界面高亮，不参与裁决。
- **事件日志**：日志里只记录解析后的 `factId`，不记录 `quoteSpan`，因为叙述可能被重新生成或删除，回放不能依赖它。
- **幂等**：`evidence` 要算进幂等键的请求指纹（`turn.ts:12` 的 `requestFingerprint`）。
- 叙述的 `spans[].factRefs` 必须是本回合事件涉及的事实的子集。模型输出不满足时，只保留模板叙述。
- 导出时，`NarrationRecord.aigc = true` 的段落带显式标识。

| 方法 | 路径 | 说明 |
|---|---|---|

| `chronicle_entries` | 卷宗。属于派生数据，可以重算 |

## 5. 确定性、并发与恢复

- **随机数**：全部来自 xoshiro256** 的命名子流，`seed = H(存档种子, 系统名, 键)`；权威路径禁止 `Math.random`。
- **数值**：影响规则的天文量（例如月相灵潮）用整数日序与查表计算，避开不同 JS 引擎在超越函数上的差异；只影响画面的数值才用浮点。
- **事件溯源**：日志存规则输入（行动类型、解析后的目标与 `factId`、种子）与玩家原文的**指纹**，遵守 `turn.ts:5-8` 的“只存指纹、不存原话”；派生状态都可以重算。玩家的原文另存于叙述与卷宗，可以按政策删除，删除不影响回放。
- **增量校验**：存一个“已验证头”检查点，热路径只校验新增的尾部；完整审计放到后台或导出时执行（修复缺陷 4）。
- **幂等**：沿用现有的回合幂等键；叙述句柄也是幂等的。
- **并发**：修订号乐观锁。冲突时返回 409 和服务端视图，客户端只丢弃本地尚未确认的那一份。
- **网络失败**：客户端保留“结算中”的意图与幂等键，恢复后重试，不会重复结算。
- **模型失败**：规则结果照常落定，叙述先用模板，并标“简述”。
- **异步执行器**：叙述生成与导出任务，由 API 进程内的工作者读取 PostgreSQL 任务表执行，带租约与重试；这与现行的 VPS 部署（路线 A）一致。如果将来采用 ADR 0008 的 Workers 路线（B），需要另做设计。

## 6. 版本与兼容

| 对象 | 策略 |
|---|---|

## 7. AI 的边界、成本与合规

| 用途 | 输入 | 输出与校验 | 频率 |
|---|---|---|---|
| 叙述 | 本回合事件与 `stateDelta`；被授权的 Canon 片段；风格 | 片段与 `factRefs`；越界则回落到模板 | 每回合 1 次 |
| NPC 对白 | 人物卡与被授权的知识 | 实体检查 | 每次交谈 |
| 导演排序（可选） | 候选镜头 | 只能返回候选编号 | 默认关闭 |
| 卷宗润色 | 实录 | 每句都要链接实录 | 玩家主动触发 |

**合规**：依据《人工智能生成合成内容标识办法》（2025-09-01 施行，技术研究 §4 已核对第三至十条原文）：

- AI 叙述要有常驻的显式标识；
- 导出时保留标识，并写入隐式元数据。

上一版写“法规要求日志留存不少于 6 个月，与玩家删除冲突”，这是**误读**。第九条的 6 个月留存只适用于“应用户要求提供无显式标识内容”的情形（技术研究 §4 第 179 行），本方案不提供这种内容，所以与“玩家删除”不冲突。是否需要备案，仍请法务判断。

## 8. 九个缺陷：核验与修复路线

核验原文见 [appendix/canon-verify.md](appendix/canon-verify.md) §4。下表的“P1 包”一栏表示该文件在 P1 规则包的哈希清单里，修改它需要重新批准。

| # | 缺陷 | 复现 | 类别 | 严重度 | 修复（R1） | P1 包 |
|---|---|---|---|---|---|---|
| 3 | 先建游客会话即可绕过 Turnstile，约 10 个 IP 一小时就能耗尽全站 600 封邮件额度，并可以骚扰任意邮箱 | 是 | 安全 | **高** | 游客会话也要过验证码；升级流程只允许发往即将绑定的邮箱；额度按会话类型分池 | 否 |
| 8 | 群聊 `multi` 模式未勾选“全员各一次”（界面默认如此）时，系统提示要“仅返回剧情文字”，解析却要 JSON，回合必然失败 | 是 | AI 契约 | **高** | 指令按 `mode` 分支，输出契约放进系统消息 | 否 |
| 4 | 事件链校验每回合全量遍历（API 一次，P2 本机 4–5 次），整局开销随回合数平方增长 | 是 | 性能 | 中→高 | 已验证头检查点加增量校验 | 否 |
| 5 | 避水符的效果标记从未被读取 | 是 | 规则 | 低–中（更正：`prepared` 是“在作业位**或**持有避水符”，见 `prologue-v1-rules.ts:582-585`；在作业位用掉符再开战，仍然有保护。上一版说“用掉以后反而失去保护”，夸大了） | 作者先裁定避水符的语义；修复以**新规则版本**的形式发布（`prologue-v1.1`），旧存档按 v1 回放 | **是** |
| 1 | “已知线索”显示成观察方式“环视”；全仓有三份互相不一致的线索名称表 | 是 | 数据与界面 | 中 | 内容里加 `name` 字段，统一用一个 `labelForContentId()` | **是** |
| 6 | 4 条已签 Canon 的公开正文里混入编辑批注（图号、【待归属】） | 是 | 数据 | 中 | 批注移出正文；构建时加拒绝规则；重新双签 | **是**（registry） |
| 7 | 每次导航都从 localStorage 镜像重载存档；镜像写失败时显示旧数据并误报冲突 | 是 | 数据与界面 | 中 | 导航不再重读；权威源是 IndexedDB | 否 |
| 2 | 非 UUID 的 `clarificationOf` 得到 503，而不是 4xx | 是 | API 契约 | 低–中 | **只改请求契约** `action.ts`（要求 UUID，返回 400）；不改 `turn.ts` 与 `decision.ts` 里已存回执的 schema，否则旧回执与旧导出读不出来 | **是** |
| 9 | CI 的早退分支：API 因规则包不匹配拒绝启动时，e2e 测试仍可能显示绿色 | 部分（等待的错误串在现行源码里不存在，属于潜伏） | CI | 中 | 删除早退分支，另写反向用例 | 否 |

**修复顺序**（按评审 B 更正）：

1. **先修 9**：让 CI 可信。这一步必须在任何 P1 文件改动之前完成；再批准期间，CI 的 P1 测试会变红，应把它标为“预期失败”并附批准单号，不能删除或跳过。
2. **再修 3、8**（高），以及不在 P1 包里的 4、7。
3. **P1 包冻结**（需作者授权）：上一版写“1、2、5、6 合并成一次再批准”，这一说法不成立。P1 包的哈希清单本身就收录了 `contracts/src/{action,turn,save,event,world,index,state-delta,decision}.ts` 和 `domain/src/{event-log,index,rules}.ts`，R1–R4 的每一项契约改动都会触发再批准。所以要先把 P1 冻结成一个只读、版本化的规则模块（`prologue-v1` 的代码与契约快照），之后的新契约与新规则都写在新版本里。
4. **最后修 1、2、5、6**：在新版本里修复；缺陷 6 涉及 Canon 重新双签。

## 9. 部署与运行时预算

| 项 | 预算 |
|---|---|
| 首屏 JS（gzip，不含 three） | ≤ 180 KB |
| three 与渲染器 | 进入“游”形态时才加载 |
| 首帧 T0 天光（AVIF） | ≤ 200 KB；4G 节流下，HTML 加载后 1 s 内首段叙述可见 |
| 每个地点的画板包 | 8 个时刻 × 4 个机位族 × 颜色与深度 AVIF，约 10 MB，按需分片加载 |

画板包放在 Cloudflare Pages 的静态资源里，但**与未来状态有关的层不能公开放置**，例如通渡之后的画面、鸦巢的特写、未投放的伏笔。这些层由 API 在状态到达之后签发短时 URL，manifest 里的提示词也不公开。单文件上限本轮**未核实**。规模扩大后改用 R2，这需要作者批准费用。

`tools/artpipe` 只在开发机或 CI 的离线任务里运行，生产运行时不依赖 Python。
