# 11 · 实施路线、实验体系与验收

**原则**：近期必须可交付，远期不降低艺术目标。每个阶段都要满足四件事：

- 有功能开关，可以回滚；
- 不破坏旧存档；
- 验收条件可以自动化，或有真机证据；
- 产生费用的事项单独批准。

## 1. 分类：什么时候能做什么

| 类别 | 内容 | 前置条件 |
|---|---|---|
| **现在就能做的非生产验证** | 实验 X1–X10（下表）、画板试制、天空 LUT 原型、声音原型 | 作者同意开展实验；不涉及生产 |
| **正式实施必须先解决** | 缺陷 3、8（安全、功能）；拆分提交与叙述；可见性视图；境界顺序的登记 | 作者下达执行命令 |
| **关键可玩竖切片** | R2“天光·芦花渡”：序章三个地点全量新表现 | R1 |
| **中长期核心能力** | 天文与天气、NPC 知识、卷宗与一世浮生、神识、万象天图、社会模拟 | 部分依赖新规则与 Canon |
| **依赖新 Canon 或规则授权** | 突破与天劫、天气的规则效应、灵潮、五域布局、交通耗时、避水符的语义 | 作者签署 |
| **需要真机** | 性能与热节流、国内浏览器、键盘遮挡、iOS 音频 | 真机矩阵 |
| **需要作者提供资源或费用** | GPU（资产生产）、R2 存储、法务意见 | 见 12 |
| **需要单独批准的生产与发布事项** | 叙述保存期限、隐私政策、数据迁移、CI 门禁生效、上线 | 逐项批准 |

## 4. 验收的总原则

1. **证据优先**：写“通过”就必须有 CI run、提交 SHA 或真机录屏。
2. **艺术验收也要有程序**：由创作者按 01 的规格（域色命题、构图纪律、§9 套件规格）逐条验收，并附独立评审的书面反例与玩家测试录像；作者保留否决权，但不需要替创作者做选择。
3. **性能是报告，不是门槛**：只有最低画质档设硬阈值。
4. **无障碍是门槛**：X7 与 X8 不通过，就不上线。
