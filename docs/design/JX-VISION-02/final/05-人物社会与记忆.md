# 05 · 人物、社会与长期记忆

## 1. 现状（核验结论，见 [appendix/canon-verify.md](appendix/canon-verify.md) §5）

- **只有“直接交谈”会产生 NPC 记忆**，授权投影只有 `topicTag` 和 `outcome` 两个字段。移动、观察、战斗、任务都不会让任何 NPC 记住什么。内容里写着岑九“记得所有来过渡口的人”，规则却做不到。
- 内容层的 `canKnow`、`cannotKnow`、`speakingStyle`、`memoryBoundary` 在全仓**没有任何代码读取**。
- 检索是字面子串匹配，按半衰期 10080 游戏分钟加“后续观察数”衰减。现有设计里有几处是对的，应当保留：
  - 遗忘只隐藏，不删除；
  - 原始事件载荷禁止进入 NPC 记忆；
  - 记忆策略的哈希是钉死的。
- 有一条可见性约束没有实现：“南边那片白”的钩子文本应当“仅在玩家确在望气台且没有依赖岑九告知时展示”，现在只要到达望气台就无条件展示。

## 2. 设计原则

1. **没有上帝视角**：每个 NPC 只知道它见证过、被告知过或常识中的事。
2. **知识是数据，不是提示词**：知识存在数据库里，带来源与可信度；AI 只能读取被授权的那一小份。
3. **规则先于叙述**：NPC 的行动（去哪里、做什么、对玩家的态度变化）由确定性规则决定；AI 只负责把它说出来。
4. **成本可控**：不给每个 NPC 配一个持续运行的语言模型。Generative Agents 论文里，25 个智能体跑 2 个游戏日就花费“数千美元”（技术研究 §6），这不可行。

## 3. 数据模型

```
NpcKnowledge {
  npcId, factId,                       // 指向权威事实
  via: witnessed | told | common | inferred,
  sourceEventId, sourceNpcId?,          // 谁告诉的
  confidence: 0..1,                    // 转述会衰减
  learnedAt: gameMinute,
  supersededBy?: eventId                // 只追加，不删改（沿用现有的 supersession 设计）
}
Relationship {
  a, b,
  affinity: -100..100, trust: 0..100, debt: int,
  tags: [师徒|同门|恩|怨|...],
  sinceEventId
}
Routine { npcId, season, slots: [{ fromKec, toKec, placeId, activity }] }
Reputation { characterId, scope: placeId|factionId, value, evidenceEventIds[] }
```

## 4. 机制

### 4.1 见证记忆（修复现有限制，R1–R2）

- 在同一地点、视线可及的 NPC，见证玩家的移动、战斗、绕行与清障。“可见”由地点与天光决定：天黑时见证范围缩小。
- 见证生成 `NpcKnowledge(via=witnessed, confidence=1)`。
- 岑九“记得所有来过渡口的人，但记不住名字”：他对来过芦花渡的角色都有见证记录，但 `name` 字段不授予他。这条边界直接取自内容表的 `memoryBoundary`。
- `canKnow` 与 `cannotKnow` 作为授权白名单与黑名单，由服务端执行。

### 4.2 信息传播（R3）

- **转述**：NPC A 在作息中遇到 NPC B 时，以概率 p 把一条知识告诉 B，B 的可信度 = A 的可信度 × κ（κ ≈ 0.8）。
- **停止传播**：采用 Maki–Thompson 谣言模型——当 A 遇到已经知道的人时，A 停止传播。大群体中约 20% 的人始终听不到传闻（技术研究 §6），这正好产生“消息有人知道、有人不知道”的真实感。
- **确定性**：所有随机数来自 `seed = H(世界种子, 'gossip', 日序)`，可以回放。
- **玩家可见的结果**：NPC 会说“听说……”，并且这句话可以被摘为证物。证物带着它的可信度，规则据此判断这条证物有多大分量。

### 4.3 作息与独立活动（R3）

- 每个 NPC 有按节气划分的作息表。岑九的候选作息：卯时撑船，“一天一趟”；午后补缆；入暮回棚。
- NPC 之间的独立事件由 §7 的事件调度器发出，比如“渡口分舵派人来查落石”。这类事件按条件触发，节奏由一个“天道讲故事者”控制：张弛交替、威胁随时间与财富上升，借鉴 RimWorld 的讲故事者。

### 4.4 关系与声誉（R3–R4）

- 关系只因事件而变：帮忙、拒绝、欠债、冒犯。
- 每次变化都记录在 `Relationship` 上，并附事件 ID；人物卡里可以看到“为什么他对你冷淡”。
- 声誉按地点与势力分别计算，影响价格、可得到的信息、可接取的任务。

### 4.5 宗门与势力（R4 之后，依赖 Canon 扩展）

- Canon 有完整的势力表（中州七家、东瀚两家等），但东瀚与北境的“顶尖势力”清单为空。
- 势力的运行（资源、冲突、招徒）按“日”粒度聚合结算；只有玩家接触的那一部分才细化到个体。这借鉴《矮人要塞》的多分辨率模拟：个体在需要时才“升格”为历史人物。

## 5. AI 的角色与成本

| 层 | 谁来做 | 每回合调用 |
|---|---|---|
| 知识、关系、作息、传播 | 确定性规则 | 0 |
| 对话的措辞 | AI，输入只有：人物卡、被授权的知识（事实 ID 与摘要）、当前对话；输出受 schema 约束，不能声称未授权的事实 | 每次交谈 1 次 |
| NPC 的“反思”（总结一天） | 可选；每个活跃 NPC 每游戏日最多 1 次，只在玩家附近 | 低 |
| 后台 NPC | 不调用 AI | 0 |

**输出校验**：AI 生成的对话里，凡是提到的人、地、物，都要能映射到授权的知识；映射不上的句子删去，或回落到模板话语。现有内容表的小谈回落（例如“你问这个，我答不上来”）正好用作模板。

## 6. 人物的视觉

| 景别 | 表现 |
|---|---|
| 远景 | 剪影（本轮的交谈帧：蓑衣、斗笠、长篙） |
| 交谈 | 受光半身像。制作方式（已定）：Blender 三维人物，按 01 §9 的人物规格建模，用 CC0 或自制材质；不使用 AI 生成面孔。AI 最多只做门禁约束的局部增强，人物的必画特征逐张核对——身份特征必须一致，比如岑九“左耳缺一角”“手背裂口深”，要作为人物卡里的“必画特征”逐张核对 |
| 表情与状态 | 按关系与事件换光，而不是换脸：冷淡时侧光，信任时正面暖光 |

## 7. 验收

| 编号 | 验收条件 |
|---|---|
| N1 | NPC 知识集合 ⊆ 它见证、被告知或常识中的事实（属性测试，覆盖随机生成的事件序列） |
| N2 | `cannotKnow` 中的事实永远不会出现在该 NPC 的授权上下文里 |
| N3 | 同一种子下，传播结果可以逐字回放 |
| N4 | AI 对话不出现未授权实体（基于实体抽取的自动检查，加人工抽检） |
| N5 | “南边那片白”的钩子遵守 `knowledgeConstraint` |
