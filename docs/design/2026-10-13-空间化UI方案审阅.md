## 3. 官方依据与访问边界

Apple 的功能层原则、Regular/Clear 分工和相邻材质处理，优先于附件的示例 CSS。本轮重新查阅 [Meet Liquid Glass 的官方文字稿](https://developer.apple.com/videos/play/wwdc2025/219/) 及 [新设计系统文字稿的几何、层级章节](https://developer.apple.com/videos/play/wwdc2025/356/)：玻璃主要用于导航与控制，应避免叠加材质，圆角要考虑同心关系；Clear 需检查丰富背景上的文字可读性。

[Materials](https://developer.apple.com/design/human-interface-guidelines/materials) 直连返回 JavaScript 壳；通过 Apple 同址官方搜索索引读取材质、Regular/Clear 与内容层说明。[技术总览](https://developer.apple.com/documentation/technologyoverviews/liquid-glass) 和 [自定义视图](https://developer.apple.com/documentation/swiftui/applying-liquid-glass-to-custom-views) 直连也只返回壳，Markdown 入口在本轮浏览工具中返回不支持的内容类型；不把这些本轮抓取说成完整读过正文。此前六项资料的阅读记录仍保留在 [原始任务书与验收映射](../acceptance/2026-10-12/Apple-Liquid-Glass-任务书与验收映射.md)。

本轮读取华为 [UI Design Kit 官方介绍](https://developer.huawei.com/consumer/cn/sdk/ui-design-kit)：其提供 ArkUI 扩展、标题栏/底部导航材质与光场能力。这不证明“鼠标跟随光就是华为规范核心”，也不说明 React 网页可以直接使用该原生渲染器。九霄可借鉴其交互光感，网页实现仍须独立测量和回退。

## 5. 冲突裁定

以下是本轮审阅建议；新增造型仍需运行原型和视觉复核，不作为已实施结论。

| 建议或矛盾 | 裁定 | 原因及执行边界 |
|---|---|---|
| S1 的个人档案馆、Contact、Physics/AI 标签 | 排除 | 是通用个人站示例，不符合九霄玩家入口定位；不引入个人经历 |
| Apple/Huawei/东方 50/30/20、另一处 70/30 | 不用比例验收 | 不能量化品牌风格；以世界内容、操作层级和真实可用性判定 |
| 首页必须恰好五层 | 作为空间关系，非五个渲染器 | 现有海报/雾/光/UI 足以表达深度；避免重复合成成本 |
| Header 下圆角贴顶 vs 24px 悬浮 + 48px 边距 | 保留两个可比较原型，优先首页局部悬浮 | 内容页继续 sticky 结构；不能全站套 fixed，遮挡锚点或输入 |
| 固定 72px Header、30/50/20 导航分配 | 改为内容约束 | 长品牌句、窄屏、文字放大、安全区和实际工具数优先 |
| 六边形 clip-path 门框 | 不采用 | 与最近圆润玻璃方向及现有胶囊矛盾，且已出现滤镜组合问题；东方感由山门和字体表达 |
| 12/24/36、16/28/40、16/28/48 三套圆角 | 不全局替换 | 当前 4/8/12/16/999 已统一；只在新增功能层需要时引入具名组件令牌 |
| 所有 primary 都替换成 JadeButton | 不采用 | 删除、提交、保存和进入世界的语义不同；仅首页入口尝试专用封装 |
| 以 24/32/40px 模糊分三个玻璃等级 | 改为用途分工 | 高模糊不等于光学质感；保留 Regular/Clear，再调整背景遮罩和光学层 |
| 世界书/设置/存档大面积 GlassPanel、玻璃百分比 | 不采用 | 普通内容和长文保持稳定材料；只在功能层使用玻璃 |
| 白色描边、强 80px 光晕、点击爆发 | 不按示例复制 | 需要薄边、局部反射和短响应；不能用霓虹或发光代替折射 |
| 标题复制双层文字并 blur(20px) | 优先沿用 text-shadow | 标题已可见且已有柔光；新增光层须不影响书法轮廓或重复朗读 |
| 替换全部字体为 SF Pro/Inter/HarmonyOS Sans | 不采用 | 保留现有本地品牌字体及中文阅读栈，不引入新字体下载或授权负担 |
| 首页增加 AI 引擎口号、多语言按钮副标 | 精简为可比较文案 | “修途自此启程。”保留；“进入九霄”可试。定位说明放作品简介更自然，避免首屏 AI 术语堆积 |
| 700–1300ms 才出现标题/按钮 | 不采用 | 内容与入口首帧可用，装饰可渐显；导航动作不等待仪式动画 |
| 标题呼吸、按钮每 8 秒光流、全局持续晃动 | 不采用持续循环 | 当前主入口光流已是一次；按交互触发且结束后稳定，尊重减少动态 |
| 全局鼠标光 600px 跟随 `body::after` | 改成局部协调 | 不追踪阅读正文；不每个 mousemove 改全局样式；限定功能表面，合帧、清理、坐标转换 |
| 单看宽度 768px 决定关闭鼠标光 | 改成输入能力与用户偏好 | 大平板可触摸，小窗口可鼠标；判断 pointer/hover、减少动态、省流及页面可见性 |
| 筑基青/金丹金/渡劫紫 | 暂缓规则联动 | 不能读建角草稿/叙事猜境界；先与玩法线程确认权威字段及境界映射，失效/换档立即清除 |
| 所有 Loading 都换“天机推演中” | 不采用 | 读取档案、提交规则、核对回执不是模型思考；保留准确动作，未来仅真实叙事生成可作辅助氛围 |
| 天地/宗门/人物/事件/秘境预设分类 | 以实际 Canon 分类为准 | 不凭视觉稿新增已审核内容、人物、地点或已获得法宝 |
| 添加命格/天道确认、掩去 HP/MP/版本 | 暂缓业务部分 | 保留现有字段和可解释状态；避免把草稿渲染成已授予能力，也不隐藏必要规则/错误信息 |
| 引入 Motion/Three/react-three-fiber | 暂不引入 | 当前材料与短动效可用 CSS/DOM 完成；引入依赖需要独立收益证据 |
| 禁止 WebGL/视频等同于删除现有渲染 | 不采用直接删除 | 附件意图是控制成本；先比较现有与静态回退成本，不损坏现有质量档位 |
| CSS 一定比 Canvas/WebGL 成本低 | 不作事实 | 成本依覆盖面积、滤镜、刷新频率和设备；全屏 blur 或重复滤镜同样可能昂贵 |
| 桌面 60fps / 手机 45fps 必须保证 | 作为目标，不写已通过 | 本机视口模拟不能证明实体低端设备 GPU 帧率、功耗和温度 |
| 按附件五次 commit 顺序机械执行 | 改为风险与依赖顺序 | 先修语义/样式缺陷，再等值拆分，再局部视觉升级；每批可回滚 |

## 6. 本轮发现及视觉判断

**确认的源码缺陷：世界资料切换的选中样式未命中。** `main.tsx` 的 `world-view-switch` 两按钮使用 `aria-pressed`；`style.css` 839/880/1294/1309/1539 附近及 `components/liquid-glass.css:175` 使用 `aria-selected`。保留原生按钮组语义，统一样式匹配 `aria-pressed`，并检查回退选择器及测试断言。切换数据仍可执行；本轮没有新跑浏览器，不能推断影响到数据或游戏规则。

**已看到的截图，不是新截图：** 重新目视已有 [390px 夜间正式首页](../acceptance/2026-10-13/evidence/formal-home-night-390.png) 与 [1366px 昼间正式首页](../acceptance/2026-10-13/evidence/formal-home-day-1366.png)。两张“九霄”标题均完整可见；不得再把它列作缺字问题。

审美判断：目前首页已经有山水深度，但主按钮和读取档案更偏柔雾，边缘亮线较显眼。下一轮应优先比较“背景辨识更清楚 + 薄边聚光 + 稳定文字遮罩”，而不是继续加 blur 或扩大光晕。昼间月景加提亮形成雾白效果，不能描述成已经换成真实晨景资产。手机品牌句被截断，要比较工具密度与品牌占位；不能为长句牺牲触控面积。

**光学能力边界：** 当前 SVG 是平滑噪声位移，不是随轮廓厚度计算的物理透镜，也没有自动逐像素亮度采样和文字反相。CSS `@supports` 只能判断语法能力，不保证真实合成正常；主入口已避开有缺陷的 Edge SVG 路径。可在开发样板增加几何边缘位移对照，先验证真背景、文字合成和成本，再决定集成。

**性能与结构机会：** `main.tsx` 仍装配多个大页面；`style.css` 保留较早声明和后续覆盖。先做等值拆分与级联梳理，再按路由实际需要评估加载拆分。单纯搬文件不会自动减小首包。画面档位已有最多 96 粒子；窄屏并不自动最多 30，若采用附件上限，需要结合分辨率/能力制定并验证新策略。
