# JX-UI-E-01｜《九霄》全站视觉与交互重构任务书

**设计方案：E · 灵境流光 × 云卷书阁**  
**任务性质：完整 UI/UX 设计、前端实现、响应式适配、交互优化及自主验收**  
**执行方式：独立交付；设计与常规开发细节由执行者自主决策，道主只审核最终交付。**

## 一、目标与授权

《九霄》应同时满足三项最高要求：**好看、华丽、舒服**。

- **好看：** 第一眼具有高辨识度与高完成度，避免默认组件库拼装感和廉价仙侠页游风格。
- **华丽：** 允许高质量场景美术、玻璃材质、动态光影、粒子、3D、Shader、WebGL 等；华丽来自构图、材质与空间层次，不靠满屏发光。
- **舒服：** 长时间游玩、阅读、编辑角色卡时文字清晰、布局稳定、操作自然。装饰与可读性冲突时，优先保障阅读和交互。

**产品印象：入口令人惊艳，游玩使人沉浸，细节让人愿意长期使用。**

执行者可以自行决定配色微调、字体搭配、构图、动效、组件拆分、素材制作及合法的免费依赖，不需要逐阶段请示。但不获授权不得产生外部费用、调用真实 AI API、改变业务规则、合并 main 或生产部署。

## 三、三层视觉体系

### A · 灵境流光：展示与世界层

用于首页、世界大厅、角色卡库、角色详情、用户概览及进入世界的入口。

关键词：**仙山、云海、琉璃、灵玉、星辉、通透、空间纵深、精致东方幻想**。

允许高品质大画面、玻璃表面、光影和流畅的入场动效；突出品牌和沉浸感。

### C · 云卷书阁：游玩与阅读层

用于单人会话、群聊、原生游戏正文、历史阅读、剧情回顾。

关键词：**纸感、书卷、淡墨、留白、月光、优雅中文排版、安静耐读**。

正文必须占据视觉中心；辅助功能可收起，动态背景不得干扰长时间阅读。支持舒适的深色夜读和浅色纸感主题。

### T · 精密工具层

用于世界书、角色卡编辑、Persona、AI 设置、存档、账号、导入导出及后台性质的配置页面。

使用高品质现代工具 UI，强调信息层次、可发现性和操作效率；不强制做成装饰性卷轴迷宫。

**三层共用品牌、组件、图标、间距与交互规则，不允许形成三套互不协调的产品。**

### 字体与排版

建立品牌标题、中文文学正文、功能界面三级字体系统。品牌标题可有东方韵味，正文使用高可读中文字体，按钮与表单使用清晰无衬线字体；不把书法字体用于正文。合法授权，字体加载失败时保持布局稳定。

延续、整理现有 Token，统一颜色、间距、字号、行高、圆角、阴影、材质透明度、动画时间、层级和焦点样式。优先定义语义 Token，避免散落硬编码。

### 材质

可复用设计：灵玉玻璃、月光磨砂、玄青金属、宣纸丝绢、淡墨叠层、低对比度阵纹、柔光描边。复杂纹理主要放在展示背景层，正文和表单下方使用稳定的足够不透明的承载面。

## 五、页面范围与设计要求

### P01：首页及品牌入口

全站视觉冲击力最高。包含九霄品牌、大型东方幻想场景、进入按钮、原生游戏/角色卡入口、继续游玩、必要服务状态与合规信息。可采用仙门、云海、星轨、浮岛和缓慢视差，但不能牺牲操作性。不得将未开放功能标成可用。

### P02：世界大厅

突出最近游玩、新建修仙角色、进入角色卡、存档、世界设定、设置及账号入口。**最近游玩必须醒目且快速到达。**

### P03：角色卡库

设计为高端人物收藏馆，而非普通表格。覆盖封面、名称、搜索、现有筛选、导入、卡片详情、建立会话、继续会话、单人与群聊。缺失图片使用统一优雅占位；资源必须获授权。

### P04：角色详情及人物志

体现人物画像、名称、描述、性格、背景、开场、示例对白、世界书、版本与来源。细节可以用抽屉/折叠/分页，但不能隐藏编辑、版本和导出能力。

### P05：单人角色扮演

**阅读体验核心页。** 桌面建议辅助导航 + 宽度受控的中央正文 + 可收起的角色/世界信息；移动端正文优先。保留行动输入、发送状态、历史滚动、错误查询、原键恢复与长文阅读。不把所有剧情压成窄气泡。

### P06：多人群聊

发言者名称及头像清楚但不过度花哨，显示手动、自动、multi、严格多人选项和角色选择。按真实发言 ID 展示历史，不得混淆或改变排序、回复校验和存档语义。对白应像故事而非数据库记录。

### P07：原生修仙游玩

保留人物信息、游戏正文、行动入口、真实世界状态、存档、辅助面板。可适度增加境界铭牌、灵纹与地域氛围，但**不得虚构未实现的状态与机制**。

### P08：世界书及设定中心

采用高效率工作台。涵盖浏览、搜索/分类、编辑、详情、关联、启停、长文本、错误和不可用状态。优先工具效率，装饰克制。

### P09：AI 设置及模型状态

清楚区分前端 AI 设置与角色卡宿主真实状态、模型名称、协议、可用性、授权和限制。绝不能暗示“随便填 API Key 就必然可玩”，不得泄露密钥。

### P10：存档、历史、账号与用户空间

如个人修行档案馆。突出本地/云端存档、继续、历史、备份恢复、导入导出、账号状态。危险操作须有明确提示和确认。

### P11：移动端完整适配

移动端不能是桌面三栏的机械压缩。使用紧凑导航、抽屉式信息、占主导的正文和稳健的输入栏。妥善处理软键盘、安全区、滚动、弹窗及旋转。至少测宽度 **360、390、430、768、1024、1440、1920px**。

### P12：小说阅读模式探索

制作可编辑高保真概念，考虑章节式正文、场景分隔、目录、注释、日夜阅读、沉浸全屏。**如不存在正式内容生成或导出接口，不得在可用产品中伪装已有该功能。**

## 六、动效规范

采用三级动效：

1. **品牌级：** 首页与大厅的云海、光影、星轨、仙门、场景转场，可以精致华丽。
2. **交互级：** 卡片、导航、按钮、抽屉、弹窗以短促、自然、明确的运动提供反馈。
3. **阅读级：** 仅轻微状态过渡与合理加载反馈，禁止持续闪烁和遮挡正文。

必须尊重 `prefers-reduced-motion`、现有图形设置和省流模式，3D 特效提供静态降级；不以常驻高 GPU 占用换取装饰。未经用户操作不得播放突兀音效。

## 七、舒适度与无障碍

- 中文正文优先稳定排版、舒适字号行高和段落间距；可将约 35–45 汉字行宽作为初始目标，再按设备调整。
- 用户阅读旧记录时，新回复不能无条件强制滚动到底部。
- 保留既有阅读位置和草稿恢复机制。
- 输入框与软键盘不相互遮挡；移动弹窗可完整操作。
- 夜读不刺眼，文字对比充分，重要状态容易发现。
- 以 WCAG 2.2 AA 为目标，覆盖键盘、焦点、标签、状态公告、对比度和减弱动画。

## 八、技术实现与资源

允许采用 Figma/Penpot、Blender、After Effects、Rive、Spline、Three.js、React Three Fiber、Motion、GSAP、WebGL、SVG 等，执行者根据复杂度自行选择。**默认保留当前 React/Vite 工程，优先复用已有玻璃、场景和设计系统**。

所有新资产必须来源可追溯、授权清晰、体积受控，有响应式分辨率与静态替代。不擅自购买素材、订阅平台或引入收费运行依赖；不上传非法字体文件。

1. **现状审计：** 查看现有页面、功能和路由；记录桌面/移动基线截图，列出可复用组件和高风险流程。

4. **组件实现：** 扩展现有 GameShell/LiquidGlass/SceneAtmosphere/Token；逐页替换，确保行为不变。
5. **动效与细节：** 补齐加载、空数据、错误、禁用、焦点、弹窗、滚动、不同屏幕与性能降级。
6. **全面回归：** 每迁移一个关键流程即测试；最终完整运行质量与浏览器验收。
7. **收尾交付：** 完整设计源文件、Draft PR、截图录屏、测试报告与预览说明。

## 十一、工程与视觉验收

### 工程检查

以实际仓库入口为准，至少检查：

- `pnpm typecheck`
- `pnpm test`
- `pnpm build`
- `pnpm test:e2e:design`
- `pnpm test:e2e:ui`
- 现有 Liquid Glass 专项测试
- 角色卡浏览器/集成测试，以及登录、保存、恢复、群聊和账号隔离回归

不得删除断言、跳过原有安全检查或用假数据制造 PASS。

### 必测流程

登录/退出、角色卡导入、建会话、继续会话、单人行动、群聊选人、严格 multi、失败查询及恢复、存档、世界书、账号隔离、阅读位置、移动软键盘、深浅主题及图形质量设置。

### 性能目标

尽量达到 LCP ≤2.5s、INP ≤200ms、CLS ≤0.1；属于目标而不是未经测量的结论。报告中必须注明测试设备、网络和运行条件。低端设备降级特效但不可失去主要功能。

### 截图与录屏

至少提供首页、大厅、卡库、人物详情、单人阅读、群聊、世界书、AI 设置、存档、失败及恢复状态的桌面与移动截图；检查深浅主题。视频演示完整真实流程，不得仅提交效果图。

### 不予通过的情形

仅有 Figma 无可运行页面；只有首页好看；按钮不可用；移动端不能游玩；特效妨碍阅读；权限/存档/恢复被破坏；用静态假数据掩盖真实状态；冒充上线未实现功能；缺少完整验收证据。
