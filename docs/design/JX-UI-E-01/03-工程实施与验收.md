## 2. 分支与 PR 策略

```bash
git fetch origin refs/pull/119/head:refs/remotes/origin/pr-119
```

```bash
git checkout -b codex/jx-ui-e-01 origin/pr-119
```

- 在 `codex/jx-ui-e-01` 上开发，开 **Draft PR，目标分支为 `main`**，PR 描述第一段写明"本 PR 叠加在 #119 之上，须在 #119 合并后再审"。这样 #119 不被修改，UI 差异在 #119 合并后自动收缩为纯 UI 改动。
- **【定】** 不向 #119 的分支推送；不合并 `main`；不部署生产；不启用 Cloudflare Pages 正式渠道。
- 若 #119 在执行期间更新：`git fetch` 新 HEAD 后用 `git merge` 合入 UI 分支（不 rebase 已推送的提交），并重跑 P06 相关测试。
- 若 #119 已合并入 `main`：把 UI 分支与新 `main` 合并对齐，在 PR 中注明。
- 提交粒度：每个提交只做一件事，可单独回滚。建议前缀 `ui(tokens)`、`ui(shell)`、`ui(lobby)`、`ui(story)`、`ui(tool)`、`test(ui)`、`docs(ui)`。

## 3. 技术选型裁定

GPT 给出的五方案提示中推荐了 Next.js、Tailwind、shadcn/ui、Framer Motion、Three.js、Tauri。结合仓库现状逐项裁定：

| 技术 | 裁定 | 理由 |
|---|---|---|
| React 19 + Vite 8 + TS | **保留** | 任务书 E 明确要求；已有完整路由、状态与测试 |
| Next.js | **不采用** | 等于重写平台；当前是 Cloudflare Pages 上的 SPA，无 SSR 需求 |
| Tailwind CSS | **不采用** | 会与现有 Token 体系和 `design-token-audit` 测试形成两套样式系统 |
| shadcn/ui、Radix | **默认不采用**；仅当原生 `<dialog>`、Popover API 无法满足某个复杂组件（如可搜索下拉）时，单独引入对应 Radix 原语 | 依赖需固定版本并通过 `pnpm license:check` |
| Motion（原 Framer Motion） | **默认不采用**；CSS 过渡 + Web Animations API + View Transitions API 足够 | 若确需弹簧物理（例如底部弹层手势），可引入并说明收益与包体增量 |
| Three.js / React Three Fiber | **默认不采用** | 现有 `SceneAtmosphere` 原生 WebGL 已覆盖大气层。若要做 3D 浑天仪作为首页可选的"电影"档效果，必须：懒加载、仅首页、仅高画质档、减弱动画与省流时不加载、有 SVG 静态版 |
| GSAP | **不采用** | 许可证条款需单独评估，且无必要 |
| View Transitions API | **采用（渐进增强）** | 入卷/出卷转场；不支持时退化为淡入淡出 |
| CSS `@layer`、容器查询、`:has()` | **采用** | 解决级联混乱（D10）；均有回退 |
| Tauri / 桌面端 | **不在本任务范围** | ADR-0006：应用商店上架属 1.0 范围变更 |
| Penpot / Figma | **二选一作为设计源文件** | Penpot 开源免费；Figma 免费版亦可。**不得购买付费席位** |
| `@axe-core/playwright` | **采用为开发依赖** | 无障碍自动扫描；MPL-2.0，需 `license:check` 通过或在许可证白名单中登记 |
| Lighthouse（CLI） | **采用为本机测量工具** | Apache-2.0；不进入运行包 |

## 4. 架构方案

### 4.1 CSS 分层

在 `apps/web/src/design-system/` 建立层次声明，所有样式文件归入以下层之一：

```css
@layer jx.reset, jx.tokens, jx.base, jx.materials, jx.components, jx.layouts, jx.pages, jx.overrides;
```

- `jx.tokens`：原始色阶、语义 Token、层与主题切换（草案见 [tokens-v2-草案.css](tokens-v2-草案.css)）。
- `jx.materials`：七种材质的工具类与回退。
- `jx.components`：按钮、输入、卡、抽屉、对话框等。
- `jx.pages`：页面专属样式，逐步从 `style.css` 迁出。
- `jx.overrides`：迁移期临时覆盖，**M8 时必须为空或每条有说明**。

现有 `style.css` 的 1561 行不一次性重写。每迁移一个页面，把该页规则移入对应文件并归层，迁移记录写明"原行号 → 新位置"。

**注意：** `tests/e2e/design-token-audit.cjs` 读取固定文件列表（`tokens.css`、`landing.css`、`style.css`、`liquid-glass.css`、`game-shell.css`）检查原始 Token 值。新增 CSS 文件时，须把文件加入该审计列表，使审计范围只增不减。

### 4.2 Token 接入

1. 保留 `tokens.css` 中所有被审计锁定的原始 Token（间距、圆角、字号），不改值。
2. 新增 `tokens-v2.css`（以草案为起点），定义色阶、语义 Token、材质、动效、层级、断点注释。
3. 页面根节点设置 `data-jx-layer`。在 `Shell` 中按路由映射：

| 路由 | 层 |
|---|---|
| `/`、`/lobby`、`/cards`（库与人物志）、`/saves` 概览、`/intro` | `lobby` |
| `/cards/session/*`、`/game/*`、`/world`（正文） | `story` |
| `/settings/*`、`/new`（建角表单）、`/turns`、世界书管理 | `tool` |

4. 旧语义变量（`--line`、`--muted`、`--panel`、`--accent`、`--jx-glass-*`、`--jx-crystal-*`）在迁移期映射到新语义 Token，迁移完成后保留为别名或删除；删除前用 `rg` 证明无引用。

### 4.3 组件目录

```
apps/web/src/
  design-system/
    tokens.css            （现有，原始 Token）
    tokens-v2.css         （新增，语义 Token）
    layers.css            （新增，@layer 顺序）
    materials.css         （新增）
    light-controller.ts   （现有）
  ui/                     （新增：无业务逻辑的展示组件）
    Button.tsx  IconButton.tsx  Segmented.tsx  Chip.tsx
    Field.tsx  TextArea.tsx  Select.tsx  Switch.tsx  Checkbox.tsx
    Dialog.tsx  Sheet.tsx  Drawer.tsx  Toast.tsx  StatusLine.tsx
    Skeleton.tsx  EmptyState.tsx  ReceiptCard.tsx
    ArmillaryRing.tsx  MoonGate.tsx  Scroll.tsx（立轴卡）  Monogram.tsx（首字占位）
    PlaceBadge.tsx  SpeakerMark.tsx  Seal.tsx  Icon.tsx
  story/                  （新增：书阁层展示组件）
    ReadingColumn.tsx  TurnBlock.tsx  ActionNote.tsx  NarrativeProse.tsx
    GroupSegment.tsx  Composer.tsx  NewReplyPill.tsx  ReadingPrefs.tsx
  components/             （现有：GameShell、LiquidGlass、GlassHeader 等，继续使用）
  routes/                 （现有：业务路由，只替换其展示部分）
```

**【定】** `ui/` 与 `story/` 内的组件不得发网络请求、不得读写存档与 `sessionStorage` 中的业务键；业务状态仍由现有路由组件持有并通过属性传入。这样可以证明"只换了视觉"。

### 4.4 `main.tsx` 的等值拆分

`main.tsx` 约 80 KB，包含 `Shell`、`WorldHub`、`SaveManager`、`NewCharacter`、`World`、`LegacyGame`、`App` 等。允许按页面把展示组件拆到 `pages/` 下，规则：

- 一次只拆一个组件，拆分提交中**不改任何行为与样式**，跑完整测试后再做视觉修改。
- 路由判断、`go()`、存档读写、导入导出、主题与画质状态保持在原位置，不在拆分时改动。
- 拆分提交的说明里写"纯移动，无行为变化"，并附测试结果。

### 4.5 开发样板路由 `/__design`

仿照现有 `/__liquid-glass`：

- 仅 `import.meta.env.DEV` 时可访问；生产构建访问时重定向到 `/`。
- 扩展 `tests/e2e/liquid-glass-production-guard.cjs`（或新增同类测试），断言生产构建中不含样板代码与样板入口。
- 内容：色板（含两主题、三层）、字体与字号阶、七种材质、全部 `ui/` 与 `story/` 组件的各状态、签名动效（可重放）、P12 概念稿、使用固定样例数据的各页面预览。
- 样例数据放在 `apps/web/src/design-fixtures/`，文件头注明"样例数据，仅用于开发样板"，**不得被正式路由引用**（用测试或 lint 规则保证）。

这个路由连同 Penpot/Figma 文件一起，构成任务书 E 要求的"可编辑设计源文件"。

### 4.6 功能开关

| 开关 | 默认 | 用途 |
|---|---|---|
| `VITE_JX_NOVEL_MODE` | 关 | P12 成卷阅读 |
| `VITE_JX_HERO_3D` | 关 | 若实现了 3D 浑天仪 |

开关只控制入口显示，不改变数据。

**规则：**

1. **【定】可访问名优先保留。** 按钮文字、`aria-label`、表单标签被测试按名称定位；改文案前先搜索测试。

3. 确需删除或改名的锚点：在**同一提交**中更新测试，新断言必须**同等或更严格**（例如原来断言元素可见，新断言须仍断言可见且可操作），并在 `docs/design/JX-UI-E-01/锚点变更记录.md` 中逐条登记"旧锚点 → 新锚点 → 理由 → 涉及测试"。
4. **【定】** 不删除断言、不跳过测试、不放宽超时来掩盖问题、不用样例数据让测试通过。

## 8. 里程碑

每个里程碑结束时提交一份简短记录到 `docs/acceptance/<日期>/JX-UI-E-01-M<n>.md`：做了什么、测试结果（命令与输出摘要）、截图路径、未完成项。

### M0 · 现状审计与基线（必须先完成）

- 重新核验 SHA（§1），建分支（§2）。
- 在未改代码的分支上运行：`pnpm typecheck`、`pnpm test`、`pnpm build`、`pnpm test:e2e:design`、`pnpm test:e2e:ui`、`pnpm test:e2e:liquid-glass`、`pnpm test:e2e:liquid-glass-production`。记录每条的通过/失败；**基线已失败的测试单独列出**，以后不能把它们归咎于 UI 改动，也不能借机删除。
- 截取基线截图：P01–P11 × 7 个宽度 × 2 主题（能到达的页面），角色卡相关页面用 `pnpm dev:cards`（默认合成演示，**不要传 `--provider-config`**）。
- 用 Lighthouse 与 `web-vitals` 测基线 LCP、CLS、INP（规程见 §9.4）。
- 生成测试锚点完整清单（§6）。
- 输出：`M0` 记录、基线截图目录、锚点清单、高风险流程清单。

### M1 · 设计系统

- `tokens-v2.css`、`layers.css`、`materials.css`；字体自托管与切片；图标集。
- `ui/` 基础组件与 `/__design` 样板路由；生产守卫测试。
- Penpot/Figma：Token 库、组件库、三层 × 两主题的样张。
- 自动化：对比度测试（读取语义 Token 计算 §4.5 目标）。
- **可选的方向快照**：把 `/__design` 截图与首页、大厅、单人阅读三张样张发给道主。道主可以不回复，执行继续；若道主提出方向性修改，优先处理。

### M2 · 外壳与灵境层

### 9.2 视觉回归矩阵

新增 `tests/e2e/jx-ui-e-visual.cjs`（Playwright）：

| 维度 | 取值 |
|---|---|
| 页面 | P01、P02、P03、P04、P05、P06、P07、P08-a、P08-b、P09、P10、画面设置、失败与恢复状态 |
| 宽度 | 360、390、430、768、1024、1440、1920（高度按 16:9 或常见手机比例） |
| 主题 | 夜色、晴昼 |
| 附加 | 390 与 1440 宽度下：`prefers-reduced-motion`、`prefers-reduced-transparency`、省流模式、200% 文字缩放 |

每张截图自动检查：无横向滚动（`scrollWidth ≤ clientWidth`）、无元素溢出视口、主操作在视口内、文字未被裁切（检测 `scrollHeight > clientHeight` 且 `overflow: hidden` 的文本容器）。截图存入 `test-results/jx-ui-e/`，最终报告选取代表张。

### 9.3 无障碍

- `@axe-core/playwright` 扫描上述全部页面 × 两主题，**严重与较严重问题为 0**。
- 键盘全流程：首页 → 大厅 → 卡库 → 建立会话 → 提交行动 → 查询请求 → 返回，全程只用键盘完成，并录屏。
- 焦点可见：每个可聚焦元素的焦点环与相邻颜色对比 ≥ 3:1。
- 焦点不被遮挡（WCAG 2.2 2.4.11）：在 390 宽度下，Tab 到输入栏上方最后一个元素时，它不被输入栏遮住。
- 状态公告：提交、生成中、完成、失败均通过 `aria-live` 区域播报（用 Playwright 读取 live 区域文本断言）。
- 屏幕阅读器抽查：至少一种（NVDA + Chrome，或 VoiceOver + Safari）跑通单人会话流程，记录结果。无法执行时如实写"未验证"。

### 9.4 性能测量规程

任务书 E 的目标：LCP ≤ 2.5 s、INP ≤ 200 ms、CLS ≤ 0.1。

| 项 | 规程 |
|---|---|
| 构建 | `pnpm build` 后用 `vite preview` 或等效静态服务器，**不用开发服务器测量** |
| 设备档 | 桌面：无节流；移动：Lighthouse 默认移动模拟（4× CPU 降速、慢速 4G）。若有实体机，加测一台中低端 Android，写明型号 |
| 次数 | 每页 5 次取中位数 |
| 页面 | P01、P02、P03、P05 |
| INP | 用 Playwright 驱动真实交互（打开抽屉、切换主题、输入并提交），通过 `web-vitals` 的 `onINP` 采集；Lighthouse 的 TBT 只作参考 |
| 预算 | 首页首屏 JS（gzip）相对 M0 基线增长 ≤ 10%；首屏字体 ≤ 150 KB；首屏图片 ≤ 300 KB；常驻 GPU 动画在"均衡"档以下不超过一个 |
| 报告 | 写明浏览器版本、操作系统、CPU、是否节流、网络条件；**未测量的指标写"未测量"，不得写"达标"** |

### 9.5 人工视觉复审

每个页面完成后，执行者按 [01 §12](01-设计总纲.md#12-设计自检问题) 七个问题自查。M8 时再整体走查一次，重点看：三层之间是否像同一个产品、灵玉青与香槟金是否越界、每屏是否只有一个焦点。

## 11. 风险与停止线

### 11.1 风险登记

| 风险 | 可能性 | 影响 | 缓解 |
|---|---|---|---|
| 样式迁移导致未覆盖页面回退 | 高 | 中 | 每迁移一页跑视觉矩阵；`jx.overrides` 兜底 |
| 改文案破坏按名称定位的测试 | 高 | 中 | §6 规则；先搜后改 |
| #119 期间更新导致 `CardSession.tsx` 冲突 | 中 | 高 | P06 放在 M4 后段；合并后重跑严格多人测试 |
| 自托管宋体增加首屏体积或 CLS | 中 | 中 | 切片、度量校准、首页题字不依赖宋体 |
| 卡库原文件解码耗内存 | 中 | 中 | 并发与尺寸上限、LRU |
| View Transitions 在部分浏览器表现不一 | 中 | 低 | 特性检测，失败即淡入淡出 |
| 竖排题字在部分宽高比与场景冲突 | 中 | 低 | 允许回退横排（P01） |
| WebGL 在低端机发热 | 中 | 中 | 沿用画质档；书阁层大气默认静止 |
| 无法在本环境测实体设备 | 高 | 中 | 如实标注"模拟测量"，不写成实机结论 |

### 11.2 停止线

遇到以下情况，**暂停该部分**，记录现状与最小处理建议，其他不越界的工作继续：

1. 需要改动 `apps/api`、`packages/contracts`、`packages/db`、`packages/domain`、`supabase`、`functions` 才能实现某个界面。
2. 需要新增后端接口（例如卡片缩略图、会话时间戳、已触发世界书条目）。
3. 需要改变存档格式、`sessionStorage`/`localStorage` 中已有业务键的名称或结构、IndexedDB 结构。
4. 需要调用真实 AI 供应商、产生任何外部费用、购买素材或订阅。
5. 需要改动登录、人机验证、账号隔离逻辑。
6. 某个现有测试在基线已失败，修复它需要改业务代码。
7. 发现 Canon 数据、世界书内容需要修改（参照 `AGENTS.md`：不得重跑世界书整理脚本覆盖现行结论）。
8. 任何合并 `main`、部署、发布的需要。
