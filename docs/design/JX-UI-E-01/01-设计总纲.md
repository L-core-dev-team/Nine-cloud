## 1. 现状诊断

以下判断来自 2026-11-22 在 `main@f1fe6ea` 上实际截取的 1440×900 与 390×844 截图，以及 `docs/acceptance/2026-10-11` 的历史移动端游玩截图。它们是本方案要解决的具体问题，不是泛泛的审美意见。

**已经做对、必须保留的资产：**

1. 水墨夜山场景图（`/scenes/gate-moonlight*.webp` 与 `candidate/` 四场景）质量高，有真实的东方气质。它是全站最值钱的视觉资产。
2. 马善政楷书"九霄"题字有辨识度，已按 OFL 子集化到 9.4 KB。
3. `SceneAtmosphere` 已有 WebGL 2 / WebGL / Canvas 2D / 静态四级后端、上下文丢失处理和画质档位。
4. `LiquidGlass` 的 Regular/Clear 分工、无透明回退和生产守卫测试。
5. `GameShell` 的阅读位置记忆、`visualViewport` 软键盘补偿和 `data-keyboard` 标记。
6. 文案普遍诚实：未开放的功能写明未开放，错误信息说清原因。

**需要解决的问题：**

| # | 位置 | 现象 | 根因 |
|---|---|---|---|
| D1 | 首页 | 副标题、开放说明、两个链接各自套一块深色矩形，像贴在画上的补丁；"九霄。"在 1440 宽度下孤字换行 | 用"文字护盾"解决对比度，而不是用画面明暗分区 |
| D2 | 首页 | 左栏、居中浮框、左下链接三种对齐并存；开放说明浮在山门正前方 | 没有构图网格，元素按出现顺序堆叠 |
| D3 | 首页 | "进入世界"和"读取存档"同等描边胶囊，主次不分 | 按钮层级没有设计 |
| D4 | 大厅 | 7 个同等权重按钮排成 2 列网格；"新开一局"用浅色渐变，看起来像被禁用 | 大厅被当成菜单，而非"去处" |
| D5 | 全站 | 主按钮有三种外观：首页描边胶囊、大厅浅渐变卡、AI 设置浅渐变条 | 缺少按钮语义 Token |
| D6 | AI 设置等工具页 | 按钮、标签、表单都用宋体 | 三种字体声部没有执行到工具层 |

| D8 | 角色卡未开放 | 只有一行字和一个未加样式的灰色"返回"按钮 | 空态、不可用态没有设计 |

## 2. 创意北极星

> **仰观九霄，俯读人间。**

"九霄"是天的最高处。产品里有两种根本不同的观看姿态：

- **仰**：在首页和大厅，玩家抬头看一个世界。看的是天穹、云海、远山、星轨，需要纵深和惊奇。
- **俯**：进入故事后，玩家低头读一页书。看的是纸、墨、灯下的字，需要安静和稳定。

第三种姿态服务于前两种：

- **执**：在世界书、角色卡编辑、设置里，玩家是坐在案前执笔的人。看的是器物和刻度，需要清楚和高效。

三层视觉体系由此而来。它们不是三种"皮肤"，而是三种**光源、镜头和材质**：

| | 灵境（仰） | 书阁（俯） | 案头（执） |
|---|---|---|---|
| 对应方案 | A · 灵境流光 | C · 云卷书阁 | T · 精密工具 |
| 页面 | 首页、大厅、卡库、人物志、档案馆概览 | 单人会话、群聊、原生游玩、历史、小说模式 | 世界书工作台、卡片编辑、Persona、AI 设置、存档管理、账号、画面设置 |
| 光源 | 月光从画面上方逆光照来，有景深 | 一盏顶光落在纸面中央，四周渐暗 | 均匀平光，无氛围光 |
| 镜头 | 远景、仰角，可轻微视差 | 近景、俯视，固定不动 | 正视，平面 |
| 背景 | 场景图 + 大气渲染层 | 场景图压暗到 15–25% 并模糊，或完全隐去 | 纯色或极淡阵纹，无场景 |
| 主材质 | 灵玉玻璃、玄青金属、柔光描边 | 夜笺 / 宣纸丝绢 | 玄青实底、细线 |
| 字体声部 | 题字 + 宋体标题 + 界面黑体 | 宋体正文为主 | 界面黑体为主 |
| 动效级别 | 品牌级（每次访问一次） | 阅读级（只有状态过渡） | 交互级 |
| 信息密度 | 低 | 低，但连续 | 中高 |

**【定】一页只属于一层。** 层由页面根节点的 `data-jx-layer="lobby|story|tool"` 声明，语义 Token 随之切换（见 §4.4）。弹窗、抽屉继承所在页的层，不自带新层。

### 2.1 层与层之间的过渡

两次关键过渡是整个产品的情绪节点，必须专门设计：

- **入卷**（灵境 → 书阁）：从大厅进入一个会话或存档。画面上方的场景向后退、变暗、轻微模糊，纸面从下方 12 px 处浮起并显影。时长 560–640 ms。这一瞬间是"抬头看天"变成"低头读书"。
- **出卷**（书阁 → 灵境）：返回大厅时反向播放，时长缩短到 360 ms，不拖延离开。

工具层与其他两层之间只做 160 ms 交叉淡化，不做仪式。

## 3. 签名元素

整站只允许两个签名图形和一套签名色系。它们是"远看就知道是九霄"的东西，因此**【定】用量必须克制，并严格限定位置**。

### 3.1 浑天环

浑天仪是中国古代观测天体的仪器：几道同心但倾角不同的铜环，环上刻有度数。它同时承载"九霄（天）"和"精密（器）"两层含义，恰好连接灵境层和案头层，也避开了廉价页游最常见的"发光符文法阵"。

**造型规则：**

- 2–4 道椭圆环，线宽 0.75–1.5 px，香槟金（`--jx-ornament`），透明度 35–70%。
- 外环带刻度：每 10° 一短刻，每 30° 一长刻，刻线长 3/6 px。
- 环上最多 3 颗星点（2–3 px 圆点，月白），代表星宿，不画星座连线。
- 不发光、不加外发光、不填充渐变。线就是线。

**允许出现的位置：**

| 位置 | 形态 | 动效 |
|---|---|---|
| 首页题字背后 | 大环，直径约 55–70 vmin | 首次加载时环线描画显影 1400 ms，之后静止；高画质档可以 240 s/圈极慢自转 |
| 真实 AI 生成等待 | 24 px 小环 | 匀速旋转，`prefers-reduced-motion` 下改为三点渐显 |
| 原生游玩的地点铭牌 | 只取一段弧线与刻度作为装饰线 | 无 |
| 空态插画 | 单环 + 一句引导 | 无 |
| 工具层滑块、进度 | 只借用刻度语言（刻线），不画环 | 无 |

**禁止：** 当按钮背景、当卡片边框、满屏旋转、出现在正文阅读区。

### 3.2 月洞门

月洞门是江南园林里的圆形门洞。门洞里是另一处风景。它延续了现有"月下入界山门"的母题，又给"进入另一个世界"一个具体的形状。

**造型规则：** 圆形遮罩（`clip-path: circle()` 或 `border-radius: 50%`），外沿 1 px 玄青金属线 + 内侧 1 px 月白高光。门洞内是对应场景图的局部。

**允许出现的位置：** 大厅的三处"去处"入口；人物志的头像（可选）；群聊发言者头像（缩小为 28–36 px 圆形时就是普通头像，不再强调门洞）。

**禁止：** 用在按钮、对话框、工具层任何位置。

群聊里每个角色需要可区分的颜色。本方案不用随机色相，而采用国画矿物与植物颜料的传统色名，饱和度统一压低，和水墨场景同源。

## 4. 色彩系统

### 4.1 与现有品牌的关系【待确认 D-1】

`PRODUCT.md` 的品牌承诺列出"粉晶高光、朱红印章与深蓝夜色"。任务书 E 给出的参考色是灵玉青、香槟淡金、星雾紫。两者同时作为强调色会出现五种强调色并存，正是廉价仙侠页游的典型症状。

本方案的处理：

| 旧品牌元素 | 方案 E 中的去向 |
|---|---|
| 深蓝夜色 | 保留，扩展为"玄"色阶，是全站基底 |
| 月纸白 | 保留，更名"月白"，承担标题与正文 |
| 朱红印章 | 保留，只用于品牌印记，不承担任何状态语义 |
| 桃粉微光 | 退出界面强调色；保留在场景美术（梅、花瓣）和角色色"胭脂"中 |
| 新增灵玉青 | 成为**唯一的交互强调色**：焦点、选中、主操作、链接 |
| 新增香槟金 | 成为**仪式色**：浑天环、品牌装饰、重要铭牌描边；不用于文字段落和状态 |
| 新增星雾紫 | 只进入场景大气渲染和天空渐变，**不作为任何界面元素的颜色** |

这样每种颜色只有一个职责。若道主坚持保留桃粉为交互色，替代方案是：桃粉取代灵玉青的位置，灵玉青退为场景冷光，其余规则不变。

### 4.3 颜色职责规则

1. **【定】灵玉青只表示"可以操作/正在操作"。** 不能用来装饰标题，不能当背景大面积铺开。
2. **【定】香槟金只表示"重要且稳定"。** 品牌、浑天环、地点铭牌、人物志标题线。不能用于按钮文字、链接和状态。
3. **【定】任何一屏的面积比例**：基底与文字 ≥ 90%，灵玉青 ≤ 5%，香槟金 ≤ 3%，其余颜色合计 ≤ 2%（场景美术不计）。
4. 朱印每屏最多出现一次。
5. 夜读正文不用纯白，晴昼正文不用纯黑。

### 4.4 语义 Token 与层切换

组件只引用语义 Token，不直接引用色阶。语义 Token 由 `data-theme`（`night|day`，沿用现有值）× `data-jx-layer`（`lobby|story|tool`）共同决定。完整草案见 [tokens-v2-草案.css](tokens-v2-草案.css)。核心语义：

| 语义 | 灵境 · 夜 | 书阁 · 夜 | 案头 · 夜 | 书阁 · 晴 |
|---|---|---|---|---|
| `--jx-bg-canvas` | 场景图 | `xuan-900` | `xuan-900` | `zhi-200` |
| `--jx-surface-reading` | — | `xuan-850` | — | `zhi-100` |
| `--jx-surface-1` | 灵玉玻璃 | `xuan-800` | `xuan-800` | `zhi-50` |
| `--jx-fg-body` | `yue-50` | `yue-100` | `yue-100` | `mo-800` |

### 4.5 对比度目标

| 对象 | 最低 | 本方案目标 |
|---|---|---|
| 长篇正文 | 4.5:1（AA） | ≥ 10:1，并提供"柔和"档约 9:1 以减眩光 |
| 次要文字 | 4.5:1 | ≥ 5:1 |
| 大号标题（≥ 24 px 或 18.66 px 粗体） | 3:1 | ≥ 7:1 |
| 图标、边框、焦点环等非文字 | 3:1 | ≥ 3:1，焦点环 ≥ 4.5:1 |
| 场景上的文字 | 4.5:1 | 以文字所在区域背景的**最亮像素**计算，靠暗角与渐变遮罩保证，不靠文字底衬 |

## 5. 字体与排版

### 5.1 三个声部

| 声部 | 字体 | 用途 | 来源与许可 |
|---|---|---|---|
| **题字** | 马善政楷书 Ma Shan Zheng | 只用于"九霄"品牌字和极少数仪式性两三字短语（如地点铭牌的地名） | 已在仓库，SIL OFL 1.1，已子集化；新增字形需重新子集化并保留 `OFL-MaShanZheng.txt` |
| **书卷** | 思源宋体 / Noto Serif SC，400 与 600 两档 | 剧情正文、页面标题、人物志、世界设定正文 | SIL OFL 1.1；**须自托管**并按 `unicode-range` 切片 |
| **案头** | 系统无衬线栈 | 按钮、表单、导航、状态、表格、数字 | 不下载，使用系统字体 |

案头声部字体栈【荐】：

```css
--jx-font-ui: system-ui, -apple-system, "PingFang SC", "HarmonyOS Sans SC", "MiSans",
  "Microsoft YaHei UI", "Microsoft YaHei", "Noto Sans SC", "Source Han Sans SC", sans-serif;
```

书卷声部字体栈【荐】：

```css
--jx-font-literary: "JX Noto Serif SC", "Noto Serif SC", "Source Han Serif SC",
  "Songti SC", "STSong", serif;
```

**为什么必须自托管宋体：** Windows 上没有思源宋体时会回落到点阵感明显的"宋体/SimSun"，长文阅读体验差；Google Fonts 在中国大陆访问不稳定，而本站有 ICP 备案、面向大陆用户。**【定】运行时不得引用 Google Fonts 或任何境外字体 CDN。**

**切片要求：** 每片 ≤ 80 KB woff2，按 `unicode-range` 声明；首屏只加载实际出现字符所在的切片；`font-display: swap`；用 `size-adjust`、`ascent-override` 为回落字体校准度量，使字体替换造成的 CLS ≤ 0.02。切片工具可选 fonttools `pyftsubset`（MIT）或其他许可证经 `pnpm license:check` 核验的工具。

**【荐】阅读偏好中提供"楷"体选项**：霞鹜文楷 LXGW WenKai（SIL OFL 1.1），同样自托管切片，用户选中后才加载。它不进入默认视觉身份。

**【定】禁止：** 书法字体用于正文、按钮和表单；宋体用于按钮与表单（解决 D6）；中文正文加字距（`letter-spacing` 只允许用在题字和少于 6 字的标题）。

### 5.2 字号阶

仓库的设计审计测试锁定了现有原始字号（12/14/16/18/20/24/32/40 px 对应的 rem）。方案 E 不改这些值，在其上增加语义别名：

### 5.3 中文排版规则

| 项目 | 规则 |
|---|---|
| 行宽 | 默认 `max-inline-size: 38em`（约 38 字），偏好可调 32–46em；移动端为视口宽减两侧各 20 px |

| 数字 | 案头层 `font-variant-numeric: tabular-nums`；正文保持比例数字 |
| 内容 | **【定】不得改写 AI 或用户输出的文字本身**（不替换引号、不合并段落、不删空行），排版只能通过样式实现 |

### 6.2 材质规则

1. **【定】超过两行的文字，下方必须是不透明度 ≥ 0.86 的面或纸。** 这条规则直接取代现有的"文字护盾"做法（D1）。
2. **【定】玻璃不叠玻璃。** 玻璃面内部的子元素用细线和内凹，不再嵌套玻璃（解决 D7）。
3. **【定】材质决定圆角。** 玉是打磨过的，所以圆润；纸是裁出来的，所以利落；金属是铸出来的，所以细。

| 材质 | 圆角 |
|---|---|
| 灵玉玻璃 | 16 px（大面）/ 12 px（卡）/ 999 px（胶囊工具） |
| 月光磨砂 | 16 px |
| 玄青金属 | 4 px |
| 夜笺 / 宣纸 | 2–4 px |
| 案头控件 | 8 px |
| 月洞门 | 50% |

这些值都来自现有已锁定的 4/8/12/16/999 圆角阶，无需新增原始值。

4. 每种材质都有实色回退：`prefers-reduced-transparency: reduce`、`data-jx-data-saver`、低画质档下，玻璃与磨砂改为同色相的不透明面。

## 9. 动效系统

### 9.1 三级动效

| 级别 | 时长 Token | 用于 | 规则 |
|---|---|---|---|
| **品牌级** | `--jx-dur-ceremony` 1400 ms；`--jx-dur-scene` 600 ms | 首页浑天环显影、入卷/出卷、场景切换 | 每次访问每种最多播放一次；可被任意输入打断；**内容和按钮在首帧即可见可点**，只有装饰层延迟出现 |
| **交互级** | `--jx-dur-quick` 140 ms；`--jx-dur-base` 220 ms；`--jx-dur-panel` 320 ms | 悬停、按压、开关、抽屉、弹窗 | 位移 ≤ 8 px；按压缩放 ≥ 0.97；抽屉用 `transform`，不动画 `width/height` |
| **阅读级** | `--jx-dur-quick` 140–200 ms | 新回复出现、状态切换、加载 | 只动 `opacity`（可加 ≤ 4 px 位移）；**不打字机、不逐字出现、不闪烁、不循环** |

缓动：

```css
--jx-ease-out: cubic-bezier(0.2, 0.8, 0.2, 1);     /* 交互默认 */
--jx-ease-in-out: cubic-bezier(0.65, 0, 0.35, 1);  /* 场景转场 */
--jx-ease-ink: cubic-bezier(0.33, 0, 0.15, 1);     /* 墨迹晕开、显影 */
```

现有 `--jx-motion-feedback`（160 ms）、`--jx-motion-settle`（280 ms）、`--jx-motion-ease` 保留为别名，不删除。

### 9.2 签名动效清单

| 名称 | 触发 | 表现 | 降级 |
|---|---|---|---|
| 开天 | 首页首次加载 | 浑天环 `stroke-dashoffset` 描画显影；星点逐个亮起 | 减弱动画：环直接静态显示 |
| 入卷 | 大厅 → 会话/存档 | View Transitions API：场景层 `scale(1.04)`、亮度降至 40%、模糊 6 px；纸面从下方 12 px 浮起显影 | 不支持 View Transitions 时：160 ms 交叉淡化；减弱动画：无动画 |
| 出卷 | 会话 → 大厅 | 入卷反向，360 ms | 同上 |
| 墨迹晕开 | 新回复写入历史 | `opacity 0→1` + `filter: blur(2px)→0`，200 ms | 无动画 |
| 落印 | 建立会话成功、导出完成等少数完成时刻 | 小印章 `scale(1.12)→1`，220 ms | 无动画 |
| 星环等待 | **仅限真实 AI 生成请求进行中** | 24 px 浑天小环匀速旋转 + 准确文字"正在生成回复" | 三点渐显 |

**【定】** 加载文案必须准确描述正在发生的事。读取存档、提交规则、核对回执不是"推演天机"（沿用 2026-10-13 空间化 UI 审阅的裁定）。

### 9.3 降级矩阵

| 条件 | 品牌级 | 交互级 | 阅读级 | WebGL 大气 | 玻璃 |

| 默认 | 开 | 开 | 开 | 按画质档 | 开 |

## 10. 文案语气

- 灵境层可以有一点诗意，但只在标题和品牌句；按钮永远用动词说清后果："进入九霄""继续上次行旅""导入角色卡"。
- 书阁层几乎不说话，让正文说话。状态提示短、准确："正在生成回复""回复已保存""请求未完成，可查询原请求"。
- 案头层纯功能性。名词用玩家理解的说法："模型连接"而不是"provider config"。
- 同一动作全流程同名：按钮"建立会话"→提示"会话已建立"；按钮"导出存档"→提示"存档已导出"。
- 错误说明发生了什么、怎样处理，不道歉、不含糊。现有 `cardError` 的写法是好的范例，保持其信息量。
- 空状态是邀请："还没有角色卡。导入一张 PNG 或 JSON 卡片开始。"
- **【定】不写未实现的能力**；不写"热门""推荐""会员"（ADR-0004：1.0 不含社区与收费）。

## 11. 反模板清单

以下做法在当前代码或常见 AI 生成页面中出现过，本项目中禁止，除非页面规格明确要求：

1. 每个标题上方都放一行小字"眉标"（现状："月下山门""山门之内""山河地理 · 设定与图鉴"）。每页至多保留一处真正携带信息的眉标。
2. 用"A · B · C"中点串拼接元信息，除非它们是真实数据字段。
3. 中文正文与按钮加大字距。
4. 金色斜面按钮、发光描边、彩虹渐变、常驻旋转法阵、满屏粒子、自定义鼠标、滚动劫持。
5. 所有内容一律切成相同圆角、相同阴影的卡片网格。
6. 给按钮文字后面加"→"。
7. 在场景图上给每段文字套深色矩形（D1）。
8. 用玻璃包裹玻璃、用容器包裹分段控件（D7）。
9. 把"热门角色卡""今日推荐""会员专享"等没有数据来源的模块做进界面。
10. 用"天机推演中""灵气汇聚中"等文案替代准确的加载状态。
11. 照搬 Apple、Huawei、任何游戏或其他产品的界面外观。参考它们的原则，不复制它们的形状。

## 12. 设计自检问题

每完成一个页面，执行者用以下问题自查并把答案写进页面验收记录：

1. 这一页属于哪一层？光源、材质、字体声部是否与该层一致？
2. 这一屏最想让玩家做的一件事是什么？它是不是最醒目的？
3. 去掉所有动效和透明度后，这一页还能完整使用吗？
