Apple Liquid Glass（液态玻璃）官方规范实现任务书

一、任务目标

请按照 Apple iOS 26 / macOS Tahoe 的 Liquid Glass 官方设计规范，为当前项目实现高保真、可交互的液态玻璃 UI。

特别注意：我要的是 Apple Liquid Glass，不是传统 Glassmorphism 毛玻璃。

不要只使用 backdrop-filter: blur()、半透明白色背景和圆角来敷衍完成任务。

请实际阅读下方 Apple 官方资料、检查项目技术栈、实现可运行代码、进行视觉验收。

二、必须实现的视觉特性

1. 半透明与背景融合

玻璃必须能够显示其后方的真实内容，且随背景内容变化而变化。

应具有合理的背景模糊、亮度调节与环境色彩透射。

不能使用固定颜色的半透明矩形冒充真正的动态材质。

2. 光学折射感

真实 Liquid Glass 的重要特征是玻璃边缘与背景光线之间的复杂交互。

请根据当前技术平台实现可行的光学近似，包括：

* 边缘附近的轻微背景畸变或折射。
* 圆角轮廓附近的自然光线聚集。
* 与背景亮度相关的柔和边缘高光。
* 透明玻璃具有厚度与空间层次的视觉效果。

如果当前平台不能原生实现真实光学折射，请选择合适的近似方案，例如 SVG Filter、WebGL 或轻量 Shader，但必须明确其兼容性和性能限制。

禁止用单纯的白色描边冒充完整折射效果。

3. 动态环境适应

玻璃应根据底层背景变化，保持合适的透光度、明暗关系和文字可读性。

必须支持浅色与深色环境。

区分两种设计模式：

Regular Glass： 优先保证可读性，适合有文字的导航、侧边栏和浮层。

Clear Glass： 优先呈现背景内容，适合图片或视觉丰富的背景上方的悬浮控件。

不要让所有玻璃都使用相同的不透明度或模糊强度。

4. 流体交互与动效

Apple Liquid Glass 不只是静态视觉效果，还需要有自然的动态响应。

针对适当的交互控件，实现：

* 按压时自然的形变或视觉响应。
* 悬停、选中与释放时的柔和过渡。
* 相邻玻璃控件在适当场景下的融合、分离或形态过渡。
* 动画结束后恢复稳定形态，不得持续无意义晃动。

动画需流畅、克制，避免果冻式夸张弹跳。

5. 空间层级

这是必须遵守的官方设计原则：

Liquid Glass 主要属于悬浮在内容之上的功能层，而不是所有内容容器的默认背景。

优先应用于：

* 顶部导航栏
* 底部工具栏
* 悬浮按钮
* 选项切换器
* 弹出式操作菜单
* 重要的临时交互控件

普通文章、内容卡片和大面积阅读区域不应全部套上液态玻璃。

保持界面内容清楚、操作层级明确。

三、技术实现要求

首先检查现有代码，识别真实技术栈。

情况 A：Apple 原生应用

若项目为 SwiftUI / UIKit / AppKit，并且目标 SDK 支持 Liquid Glass：

优先使用 Apple 提供的官方 API，而不是手工模拟。

SwiftUI 可考虑：

* glassEffect(_:in:)
* .regular / .clear
* .interactive()
* GlassEffectContainer
* glassEffectID(_:in:)
* glassEffectUnion(id:namespace:)
* .buttonStyle(.glass)

根据实际系统版本检查 API 可用性，不得直接假设所有设备都支持。

情况 B：React / Vue / Electron / Tauri / 普通网页

必须明确：Web 无法直接等同于苹果原生 Liquid Glass 渲染。

请设计可复用的 Web 液态玻璃组件，实现尽可能接近的效果。

可采用分级实现：

* 基础层：真实背景透射、模糊与适应性亮度。
* 光学层：边缘高光、细腻内阴影、适度折射与环境反射。
* 交互层：按压反馈、选中态、自然过渡与组件融合。
* 降级层：不支持高级效果或性能不足时，自动退化为稳定的普通半透明控件。

建议封装统一组件及样式变量，避免每个按钮各自实现一套互不一致的玻璃效果。

不要为了追求视觉效果引入高开销全屏实时着色器。

四、设计质量要求

1. 玻璃轮廓必须干净、圆润，强调一致的圆角与同心几何关系。
2. 高光需要自然且克制，禁止使用厚重的白色发光边框。
3. 透明度不能高到看不清文字，也不能低到变成普通实心按钮。
4. 避免大量彩色玻璃与霓虹泛光。颜色只用于真正重要的交互状态。
5. 尽量使用项目已有的设计语言，不得擅自重构整个 UI。
6. 在背景图片、纯色背景、动态滚动背景上分别验证效果。
7. 支持触摸设备与鼠标操作。
8. 尊重系统减少动态效果、降低透明度和提高对比度等无障碍偏好。
9. 优先保证稳定帧率与正常响应，避免因视觉效果产生明显卡顿。

五、禁止事项

* 不得用普通毛玻璃冒充完整 Liquid Glass。
* 不得仅通过修改透明度就宣称实现了折射。
* 不得使用静态 PNG 覆盖层伪装动态玻璃。
* 不得全界面滥用玻璃材质。
* 不得复制一个未经验证的第三方演示效果就直接交付。
* 不得牺牲可读性、交互功能或性能来换取装饰效果。
* 不得擅自修改项目业务逻辑、API、存储结构或其他无关功能。
* 不得把无法实现的苹果原生光学行为谎称为已经精确复刻。

六、实施步骤

第一阶段：检查

读取当前项目代码、技术栈、组件结构、设计系统与运行环境。

简要汇报哪些官方能力可以原生实现、哪些必须近似模拟。

第二阶段：原型

先制作一个可运行的 Liquid Glass 样板，至少包括：

1. 悬浮玻璃按钮
2. 玻璃导航栏
3. 玻璃弹出菜单
4. 玻璃控件按压与形态过渡演示

先证明材质有效，再考虑推广到整个项目。

第三阶段：验证

必须实际运行程序，并在以下情况检查：

* 明亮复杂背景
* 深色复杂背景
* 内容滚动与控件交互

提供截图或录屏作为证据。

检查透明效果、光学层次、文字可读性、动画流畅性与降级行为。

第四阶段：集成

样板通过视觉验收后，才逐步集成到项目现有功能控件。

优先采用低风险、可回滚的改动，不要直接覆盖整个前端。

七、最终交付标准

最终必须提交：

1. 实际使用的技术方案。
2. 完整的可运行组件代码。
3. 样式文件及必要依赖。
4. 组件复用方法。
5. 不同背景和交互状态的视觉证据。
6. 性能、兼容性与无障碍测试结果。
7. 与苹果原生 Liquid Glass 尚存的差异。
8. 修改文件列表及验证命令。

最高验收原则：

我要看到的是具有光学质感、实时环境响应、清晰空间层级和自然流体交互的苹果风格 Liquid Glass。

不是背景模糊的半透明圆角矩形。

请从检查项目环境与官方资料开始，先做最小可运行原型，再进行真实视觉验收。
