## 1. 结论与建议范围

“所有登录方式”必须先变成一个有限的方式清单。邮箱、手机号、Passkey、密码和各类第三方登录不是同一个功能的按钮；每增加一种，就增加凭据验证、身份关联、恢复、风控、隐私和验收路径。若不限定清单，“全部”没有可测试的完成定义。

建议把“闭环”定义为：**用户使用任一已启用方式登录后，都落到同一个稳定账户；绑定、解绑、换号、换邮箱、恢复、会话撤销、导出、关闭、恢复关闭及删除都不会丢失或串用账户数据。** 每一种已启用方式都要有注册、验证、登录、退出、变更、遗失恢复和安全撤销流程。

以成本和当前代码为约束，建议分两层实施：

1. **首期：邮箱 OTP + 手机号 SMS OTP。** 复用现有邮箱认证；为手机号增加身份表和短信服务。短信有一次性试用额度，但没有可保证长期免费的国内发送方案。
2. **后续降本：Passkey。** 用户完成一次已验证登录后可登记 Passkey，日常登录无需重复发送邮件或短信。它不能替代找回流程，也不能把用户锁在单一设备上。WebAuthn 由浏览器和认证器执行公钥凭据注册、验证，服务端保存公钥并验证签名。[1]

首期不建议再加入密码登录或微信、Apple、Google 等 OAuth。它们不是“闭环”的前置条件；每个新提供方都必须单独做回调校验、身份冲突、关联/解绑和恢复。**若产品要求这些提供方，先逐个写入批准清单，再估算并实现；不能把“等”解释为所有提供方都必须上线。** 现行 ADR 0005 明确要求新增 OAuth/微信等方式前先写新 ADR。

## 2. 本地项目现状与关键约束

以下是本任务书依据的仓库事实，不是生产验收结论：

- 现有服务端使用 Hono、PostgreSQL 和 Drizzle；邮件验证码由服务端生成，六位、十分钟有效；会话是不透明随机 Cookie，七天有效，服务端存哈希并支持刷新轮换与退出撤销。参见 `apps/api/src/services/email-auth.ts`、`apps/api/src/routes/auth.ts`、ADR 0003。
- 账号生命周期已有邮箱变更、账户关闭、关闭后恢复、账户导出和受控删除相关实现。永久删除仍受数据政策和 `ACCOUNT_DELETE_ENABLED` 门禁约束；冷备份及日志的清除规则尚不能据此视为已闭合。参见 `apps/api/src/services/account-lifecycle.ts`、ADR 0003。
- 现行表以邮箱作为账号字段和验证码主键：`auth_accounts.email NOT NULL`，`auth_challenges.email` 为主键。手机号不能只靠新增一个前端输入框接入；必须把挑战和账号身份从“邮箱字段”推广成可关联的身份模型。参见 `packages/db/drizzle/0003_s6_email_auth.sql`。
- 云档和游戏数据以既有 `auth_accounts.id` / `owner_id` 作为稳定归属。迁移中必须保留这些 ID，不得因手机号、Supabase 用户 ID 或 OAuth subject 改变而重建账户或转移存档。
- ADR 0005 的历史默认路线是不开放在线账号与云同步；1.0 不引入 OAuth/微信。用户随后明确要求完成登录工程，已用 ADR 0007 记录在线 OTP 范围和 Supabase Auth/Hono 边界。P1/P2 仍各自按其台账管理，没有因登录工作而改动。
- 认证交接文档仍将生产 Hono API 路由、SMTP 配置、生产邮件到达和 iPhone 实机闭环列为待完成事项。Supabase 默认 API URL 已存在，但 Pages 网站尚未接入；网站已部署不代表认证闭环已上线。
- 用户已明确 Supabase 是本项目后端。Supabase MCP 实查到项目 `deyzirwnzjxsmyvfrsdb`（`LYL-bird's Project`）状态为 `ACTIVE_HEALTHY`，区域 `ap-northeast-2`，组织套餐为 Free；项目 API URL 是 `https://deyzirwnzjxsmyvfrsdb.supabase.co`。这修正此前“没有已确认后端服务地址”的过宽表述：托管后端地址已确认，不需要再寻找 VPS IP 才能访问 Supabase 服务。

## 3. 登录方式清单与成本判断

| 方式 | 首期定位 | 主要成本 | 结论 |
|---|---|---|---|
| 邮箱 OTP | 保留，首期 | SMTP 服务、发件域配置和投递运营；当前供应商及免费额度未核实 | 已有后端，改造量最低。免费额度须以供应商账户和正式条款验证。 |
| 手机号 OTP | 已列入首期，运行时默认关闭 | 短信逐条计费、短信签名/模板审核、滥用防护和号码地区适配；预算/地区/限流值须业务方签收 | 腾讯云可提供首次开通赠送量，但它是一次性额度，不是长期免费承诺。当前价目列出个人认证 100 条、企业认证 200 条，赠送有效期三个月；低用量自定义包最低 1,000 条、价目为每条 0.05 元，即至少约 50 元。是否符合本账号领取条件须在腾讯云控制台核实。[2] |
| Passkey | 降低长期 OTP 成本的后续方式 | 一次性研发、设备兼容与账户恢复成本；无逐次短信/邮件发送费 | 可减少已登记用户的重复 OTP；仍需邮箱或手机号等找回路径。须在 iPhone Safari、Android 和桌面浏览器实测。[1] |
| 密码 | 暂缓 | 密码存储、防撞库、重置邮件、泄露响应和支持成本 | 当前产品已有无密码 OTP 路线。除非用户明确需要，不为“方式齐全”增加高维护凭据。 |
| 微信 / Apple / Google OAuth | 单项审批后再做 | 账户/开发者资质、审核、回调域、身份冲突、维护；不同提供方成本与资格须分别查证 | 不属于低成本首期。现行 ADR 0005 要求新增前先决策。 |
| Supabase Auth | 已由 ADR 0007 选为邮箱/手机号 OTP 凭据验证源；Hono 仍签发业务会话并持有 owner 映射 | 当前组织 Free；短信仍向外部供应商付费。自定义 `api` 域另收费。[3][13][14] | 仓库实现已接入；线上项目配置、迁移、SMTP、短信 Hook 和 Hono API 部署未完成。默认 `supabase.co` URL 可用，不需要购买自定义域。 |

Cloudflare Turnstile Free 方案当前列出无限挑战/验证请求，可用于短信发送前的人机校验；它不会替代服务端的按手机号、IP、账户和总预算限流。[4] 国内短信发送前还需要可用签名及已审核模板，实际发送会受腾讯云审核和运营商报备状态影响。[5]

### 可供签收的 SMS 预算参考值

腾讯云国内短信低用量档公开价约为每条 ¥0.05；自定义套餐最低 1,000 条，约 ¥50，赠送额度是否可领须按认证主体及首次开通资格核实。按这个单价估算，¥50、¥100、¥250 分别约对应 1,000、2,000、5,000 个计费短信段；这是预算量级，不是任何地区、短信长度或账单的保证值。[2]

| 预算选项 | 现金授权 | 适用范围 | 到限处理 |
|---|---:|---|---|
| A | ¥0/月；只用账户可能具备的一次性赠送量 | 本地开发、少量封闭验证 | 赠送额度耗尽或到期即停发 SMS；只保留邮箱 |
| B（建议首轮） | **最高 ¥50/月，不自动续购** | 小规模封闭测试；约 1,000 个国内计费短信段的价目量级 | 达预算或总量阈值先到者立即停发；不得自动买套餐 |
| C | ¥100/月，不自动续购 | 测试人数扩大后再考虑；约 2,000 段 | 同上，必须由负责人另行批准 |
| D | ¥250/月，不自动续购 | 明确扩大测试且已看过实际用量后 | 同上，不作为默认档 |

**建议签收值：首轮选择 A 或 B。** 若启用手机号 SMS 登录，建议选 B：赠送量先抵用，短信发送的现金支出仍封顶 ¥50/月；将“实际购买套餐金额”和“本月短信发送消耗”分别计数。短信供应商按预付包计费，月度应用上限不能自动阻止控制台人工充值，故购买权限仍须人工控制。此建议是可撤回的预算提案，不替业务方签收。

建议试运行限流初值（上线前由业务方签收，并根据真实误拦率调整）：同一手机号最多 3 次/小时、5 次/日；同一 IP 最多 20 次/小时、50 次/日；每个验证码最多 5 次错误验证；重发间隔至少 60 秒；全站每天最多 30 个计费短信段。以 30 天计，全站限量约 900 段、按 ¥0.05 约 ¥45；¥50/月仍是最终硬上限。共享出口 IP 可能误伤多人场所，因此 IP 限流须配合 Turnstile、账号/号码配额与监控，不能单独封锁合法用户。

### 成本底线

- **可以把平台新增固定费压到接近零，但不能承诺“全功能永久免费”。** 现有 Node API、PostgreSQL、备份、域名和邮件投递仍可能有成本；具体 VPS/数据库/SMTP 供应商报价在本任务中没有核实。
- **手机号 SMS 登录不能承诺长期免费。** 赠送量用完后须购买短信套餐。腾讯云当前国内价目显示自定义包最低 1,000 条；低用量档按 0.05 元/条计，约 50 元起。号码地区不同，资费、模板和资质要求也会不同。[2]
- 降低短信费用的有效办法是“邮箱作为常用入口，SMS 用于手机号登录、绑定和恢复”，并设置服务端预算硬上限、短信发送总量上限和无自动续购策略。预算耗尽时关闭新 SMS 发送，同时保留邮箱登录。Passkey 尚未进入实现范围。
- 不把 Supabase 默认邮件 SMTP 当正式免费发信服务：官方说明当前默认上限为每小时 2 封，且只发送给项目团队预授权地址，无投递 SLA。[6]

## 4. 推荐技术方案

### 4.1 已确定的身份与 API 承载方式

ADR 0007 已记录本项目采用的边界：Supabase Auth 验证邮箱/手机号 OTP；Hono 签发可撤销会话并承载现有账号生命周期、云档和游戏 API；PostgreSQL 保留原 `auth_accounts.id` 作为稳定 owner。Hono 与 Supabase Auth 是凭据验证和业务会话两个不同层次，不是两套互相竞争的身份权威。

网站仍须通过实际部署的同源 `/api/*` 入口连接 Hono。Supabase 项目默认 `https://deyzirwnzjxsmyvfrsdb.supabase.co` 是 Auth/API 地址，不会托管 Node/Hono。ADR 0007 不要求创建 `api.jiuxiaogame.cn`，也不要求购买 Supabase 自定义域。此架构决策已完成；生产 API、隐私政策、SMS 预算和实际服务商配置仍未完成。

### 4.2 数据模型改造

迁移已按 ADR 0007 落为 `auth_external_identities`：保存 Supabase subject、身份类型、HMAC 标识摘要和原 owner；唯一索引拒绝活动邮箱/手机号映射冲突。OTP 挑战和验证码尝试由 Supabase Auth 管理，本项目不复制验证码或访问令牌。Passkey 尚未获 ADR 0007 批准，首期不创建 WebAuthn 凭据表。

迁移 `0016_supabase_external_identity.sql` 在任何 DDL 前拒绝大小写不敏感的邮箱重复。只读预检脚本先列出冲突摘要和 owner 数；迁移仍须在正确业务库备份后应用。旧邮箱尚未批量回填为 Supabase 身份，首次通过已验证 OTP 时按邮箱映射至原账户。原 `auth_accounts.id`、会话 owner 及云档 owner 均保持不变。

不能仅凭“邮箱字符串相同”或“手机号字符串相同”自动合并两个账户。Supabase 文档也把安全身份关联与已验证身份、人工关联区分开；它的手动关联功能目前标为 beta，不能替代项目自己的合并政策。[7]

### 4.3 API 与浏览器会话

- 网站调用 Hono 同源 `/api/auth/*`。Hono 服务端以 Supabase publishable key 请求 OTP 与校验结果，不把 Supabase access/refresh token 返回或持久化到浏览器。
- 邮箱变更、手机号解绑和账号删除通过仅部署于 Hono 服务端的 `SUPABASE_SECRET_KEY` 调用 Auth Admin API；新的 `sb_secret_...` 只放在 `apikey` header，不作为 Bearer JWT。旧 `service_role` JWT 仅作兼容路径。
- 登录成功后，Hono 签发七天 `HttpOnly` Cookie；生产要求 HTTPS 并设置 `Secure`、`SameSite=Strict`。Hono PostgreSQL 保存会话令牌哈希，支持轮换、退出吊销和服务端 owner 校验。
- 邮箱首次登录和已验证邮箱登录都映射到原内部 `owner_id`；手机号必须在登录账户中显式验证绑定后才可替代登录。未绑定或冲突的 Supabase subject 不得创建可访问云档的新 owner。
- 网站生产必须将同源 API 路径转发到真实 Hono 服务。当前 Pages API 路由仍未接通，所以仓库实现不等于线上已运行。
- Passkey 注册/认证端点未实现，且 ADR 0007 将其列为后续阶段；OAuth、密码同样不在当前批准范围。

### 4.4 绑定、解绑、换号与恢复规则

- **绑定：**当前首期仅支持手机号。先证明当前已登录邮箱账户，再向新号码发 OTP；事务中检查唯一性后关联。若号码已归属其他账户，返回冲突；首期不提供转移或合并。
- **解绑：**手机号解绑需要当前会话和新近验证的邮箱 OTP；服务端必须确认远端 Supabase 用户仅持有该手机号身份，再删除远端用户并撤销本地映射。验证/删除失败则整体拒绝解绑。账户邮箱身份必须继续可用。
- **换邮箱：**先验证当前邮箱，再向新邮箱发送并验证 OTP；用服务端 Supabase Admin API 同步设置新邮箱及已验证状态，然后更新本地账号并撤销旧邮箱映射。`SUPABASE_SECRET_KEY` 未配置或远端身份不唯一时，事务不得完成。
- **恢复关闭账号：**邮箱或已绑定手机号 OTP 均可恢复 30 日内关闭的账户；超过窗口后由经过政策门禁的计划任务触发删除。
- **手机号遗失/回收：**号码不能被当作永久所有权证明。允许用户用另一个已验证身份或已登记 Passkey 登录后换号；对无法证明旧账户控制权的请求，不把旧号上的新用户自动并入旧账户。
- **身份冲突/账户合并：**只有在两个账户都分别完成新鲜认证、展示将转移的数据范围并由用户明确确认后，才启动合并工作流。合并需要单独审计；首期默认不提供跨账户自动合并。
- **关闭与恢复：**关闭需账户操作邮件 OTP，并撤销现有 Hono 会话；邮件或已绑定手机号 OTP 可在 30 日内恢复。超过窗口的删除受数据政策和 `ACCOUNT_DELETE_ENABLED` 双重门禁控制。Supabase Auth 用户、在线业务数据可由工程路径清理；冷备份、主机日志和供应商副本仍按各自保留政策处理。

## 6. 安全与成本验收标准

所有标准同时适用于已启用方式；任何一项失败都不算闭环。

1. 一个账户可以绑定多个经验证身份；这些身份登录后返回相同内部账户 ID 和同一份授权范围。
2. 两个未关联账户的云档互不可读写；相同但未验证的邮箱/手机号不会造成账户接管或合并。
3. 验证码不可重放；过期、猜错次数用尽、重发冷却和额度耗尽时被服务端拒绝；所有响应不泄漏账号存在性。
4. 登录会话为 HttpOnly/Secure Cookie；退出、改密钥/改身份、关闭账户和安全事件能吊销适用会话；不在本地存储 Bearer token。
5. 绑定、解绑和换号均验证现有账户控制权及新身份控制权；解绑后至少保留一个可用身份。
6. 账户导出、关闭、恢复和删除按批准的数据政策执行；云档、冷备、审计日志的实际保留范围写清楚。
7. SMS 有供应商额度、应用层总额度和人工预算三层限制；无自动续购。成本面板能将试用额度与付费发送分开统计。
8. 每种启用方式完成服务单元测试、PostgreSQL 集成测试、API/浏览器测试和真实 provider 冒烟。生产发布后在 iPhone Safari 重新验证登录会话和云档 API。
9. 安全日志不含验证码、完整手机号/邮箱、Cookie、OAuth token、SMTP/Tencent secret。客服排查可用 request ID 和脱敏身份摘要定位。
10. 已关闭 SMS/provider 或认证服务不可用时，网站明确提示并允许其他已绑定方式继续登录；不得悄悄切换到另一个账户。

## 7. 隐私政策与 AppGallery / 鸿蒙衔接

这不是发布后的文案补丁。手机号登录会把手机号和验证码交给短信链路；邮箱登录会把邮箱及验证码交给 SMTP 链路。上线前必须先清点真实数据流，再写政策、同意界面和删除/申诉入口。华为开发者文档要求在 AppGallery Connect 提交隐私声明链接；其 App 审核指南还要求应用内可找到政策、披露自身及受托第三方/嵌入代码的数据处理、说明用户权利，并允许有账号系统的应用便捷注销。[9][10]

按《个人信息保护法》第十七条，处理前应清楚告知处理者身份与联系方式、目的/方式/类别/保存期限及权利行使方式；第二十一条要求委托处理约定目的、期限、方式、信息种类与保护措施；向其他个人信息处理者提供信息时，第二十三条另规定告知接收方及处理信息并取得单独同意。短信供应商究竟属于受托处理者还是独立个人信息处理者，要按实际合同和业务控制关系判断，不能只凭“短信服务商”这个名称下结论。正式文本应由运营主体审定，必要时请中国大陆个人信息保护法律顾问复核。[11]

上线前需要完成一份逐字段数据清单：

| 数据/服务 | 登录闭环中的用途 | 政策和技术需交代的事项 |
|---|---|---|
| 邮箱地址 | 邮箱 OTP、账号找回、经用户发起的邮箱变更 | SMTP 服务提供方及接收字段；账号期间的保存规则；更正/解绑方式 |
| 手机号码 | 短信 OTP、绑定/变更/找回 | 短信服务商及接收手机号/短信正文；适用地区；签名/模板；供应商保存期限和合同角色 |
| 验证码挑战 | 短时完成验证、防重放和限流 | 说明短期处理；当前设计保留 HMAC 摘要而非明文 OTP；过期/删除机制 |
| Session Cookie | 保持登录及服务端鉴权 | Cookie 用途、期限、撤销方式；不得把 Cookie 作为营销标识 |
| 来源 IP、请求和风控记录 | 频控、反滥用、故障排查 | 记录字段、保存期限、访问人员和删除方式；必须避免记录完整 OTP、Cookie 或完整手机号 |
| Passkey 公钥（第二阶段） | 证明用户控制已登记的公钥凭据 | 不保存私钥；列出凭据撤销、删除、丢失恢复和保留规则 |
| 云主机、数据库、SMTP、短信、Turnstile | 提供认证、投递、风控服务 | 按真实供应商/法人、处理目的、数据类别、部署地区、分包和保留合同逐一披露 |

核验点：

1. 公开独立政策 URL；网站设置页和拟上架应用内均能便捷打开；鸿蒙 App 首次开始个人信息处理、发送 OTP 或初始化第三方认证 SDK 前，应展示清楚的隐私告知，并按实际处理依据取得同意或落实其他合法性基础。仅有 URL 返回 200 或通用 SPA 壳不算政策上线。
2. 依据实际实现逐项列出邮箱、手机号、Cookie、IP/风控和第三方服务的数据流。不要在政策里写“不会共享”同时把手机号发给 Tencent SMS，或把邮箱/验证码发给 SMTP。
3. 列明提供方、处理目的、数据字段、地点、期限、联系方式、撤回/查询/复制/更正/删除途径，以及账户注销入口。描述必须与日志、数据库、配置和供应商真实行为一致。
4. 默认不集成 Huawei AGC Auth SDK；若以后采用，须单独审查 SDK 隐私声明。华为给出的 HarmonyOS ArkTS 认证 SDK 合规指南列出可能处理 AAID、邮箱、手机号、密码、Provider UID 和应用信息，并要求在调用 SDK 前完成告知及同意流程。[12]
5. 政策和数据处理协议未批准前，生产接口不发送 OTP，不收集真实测试者的邮箱/手机；仅用隔离测试环境与合成数据验收。

## 8. 目前不能承诺的事项

- 不能承诺邮箱和手机号同时“永久免费”。腾讯云赠送量有限且有有效期；其国内短信当前有付费套餐价格，且开通与签名审核要以控制台结果为准。[2][5]
- 不能只创建 Supabase 项目或添加 MCP 就完成网站认证；必须改应用、数据库模型、API 会话映射和账户生命周期。其免费层适合验证，但一周无活动会暂停，且不提供自动备份；短信仍需短信服务商。[3]
- ADR 0007 已记录本次在线账号架构范围。新增 Passkey、密码或任何 OAuth 提供方仍需单独决策与 ADR；本次不把未批准方式算作首期工程缺项。
- 不能在本任务书里宣称真实邮件、短信、iPhone Safari 或线上 API 已通过。这些都要在配置生产服务并完成真实端到端验收后再报告。

## 9. 建议的首期验收产品定义

建议将本次目标定为：

> **同一账户支持邮箱验证码和手机号验证码登录；用户可在登录后绑定多个已验证身份；可通过另一种已绑定身份或后续 Passkey 恢复；所有方式共享同一账户 ID、会话与数据生命周期。Passkey 作为节省反复短信的第二阶段能力。首期不承诺微信、Apple、Google、密码登录。SMS 无自动续购，并受人工批准的月预算硬限制。**

如果必须将微信、Apple、Google 或密码列入首发，需先把具体名称写进 ADR 和验收表。未列入的方式不属于“闭环未完成”，而属于未批准范围。
