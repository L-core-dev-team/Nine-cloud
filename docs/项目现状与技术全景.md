## 1. 项目到底是什么

《九霄》当前是一款面向手机浏览器的 AI 修仙文字 RPG 原型。它不是通用聊天前端，也不是已经上线的商业平台。当前发布物仍以单 HTML 为核心。玩家自行填写兼容 Chat Completions 的 API 配置。剧情、角色、物品、关系、地点、时间、事件、记忆和存档均在浏览器本地运行。

长期目标是把 AI 从“续写小说的旁白”变为“连接玩家意图、游戏规则和持续世界状态的桥梁”。真正的裁决顺序应是：

`玩家自然语言 → 意图/行动表示 → 规则结算 → 权威状态提交 → AI 叙事呈现`

当前产品只完成了这条链路的一部分。它已经能分离正文生成与状态提交，并校验大量结构化状态；但仍没有独立的通用意图解析器，也没有足以裁决任意修仙行动的完整规则引擎。不能把“多模型岗位 + 状态 JSON”误称为完整 AI 世界模拟。

## 2. 当前可运行交付物

- `outputs/九霄WEB-1.0/九霄WEB-1.0.html`：当前统一预览入口。
- `outputs/九霄WEB-1.0/九霄_WEB_1.0_空白版.html`：无预置角色进度的试玩版。
- `outputs/九霄WEB-1.0/九霄_WEB_1.0_临江仙存档版.html`：带临江仙历史快照的迁移验证版。
- `outputs/九霄WEB-1.0/source/`：可交付源码副本和独立构建材料。
- `outputs/九霄世界书/`：世界书转写、来源索引和审核记录。

HTML 内嵌样式、脚本、山门 WebP 和游戏夜山图，因此主体可单文件分发。`manifest.json` 仍保留在同目录，用于 Web 安装元数据。更稳定的本地运行方式是 HTTP 服务；直接双击 `file://` 时，浏览器的文件、跨域和存储策略可能不同。

## 3. 已实现能力

### 3.1 游戏与存档

- 角色创建、自由文本行动、剧情消息和行动建议。
- 多存档、导入、导出、切换和损坏数据拒绝。
- 旧临江仙 HTML/JSON 快照迁移，保留旧原文并抽取可识别状态。
- 输入草稿、待结算正文、失败重试和刷新恢复。
- 多标签页乐观冲突检测，避免旧标签页静默覆盖较新的浏览器存档。
- 人物、物品、关系、生命状态、地点、时间、世界事件和伏笔等结构化字段。

### 3.2 AI 调度与故障边界

- 单 AI 模式与五岗位配置。
- 剧情、导演、状态、档案等岗位按职责使用独立提示。
- 导演或状态岗位失败时有受控回退；双重结算失败时保留正文而不推进世界。
- 原始回复、整理后的正文和待处理状态分层保存。
- JSON 围栏、尾逗号、字符串控制字符等兼容修复；拒绝截断、多根对象、危险键和可执行表达式。
- 服务商用量按实际返回记录；缺失用量不伪造为零。
- API 密钥仅保存在当前会话配置，不进入仓库和存档导出。

这些能力保证“失败可恢复”和“状态提交有门槛”，不保证真实模型在长局中一定保持战力、人设和因果一致。

### 3.3 记忆与世界资料

- 短期记忆和长期记忆数据结构。
- 周期性归档建议与人工审阅入口。
- 世界资料全文、OCR 转写、原图索引和待校状态。
- 事件、人物引用和死亡状态的部分一致性约束。

当前记忆系统是本地原型。它不是 Mem0，也没有接入 SillyTavern UwU Memory。NPC 的独立认知、消息来源、可信度、传播和遗忘曲线尚未形成可验证系统。OCR 资料也不是全部 Canon；待校文本不能当作作者确认事实。

### 3.4 UI 1.0

- 用户确认的 B 构图：中央山门、纵向月华、低位“进入世界 / 读取存档”。
- 首页首屏与角色创建、作品简介、世界设定形成连续任务流。
- 桌面端使用约 680px 阅读面和左侧功能轨；手机端保留底部导航并扩大剧情宽度。
- 玉玻璃用于导航、输入和短时反馈；高不透明烟纱用于长文、表单和模态框。
- 响应式移动/桌面山门图；游戏页保留原夜山背景。
- `prefers-reduced-motion`、`prefers-reduced-transparency`、无 `backdrop-filter`、Save-Data 和低性能设备降级。
- 首屏按钮使用 anime.js 编排一次性入场；粒子低密度且不拦截输入。

这只是响应式 Web 验收。它没有经过 iPhone Safari、Android WebView、HarmonyOS ArkWeb、Windows/macOS 原生壳或应用商店审核。

## 4. 当前没有的能力

- 没有后端、账号、云数据库、云存档、支付、订阅、社区和运营后台。
- 没有独立自然语言意图解析器和通用行动中间表示。
- 没有覆盖战斗、修炼、炼器、任务、经济、宗门和地图的权威规则引擎。
- 没有可证明稳定的数百小时世界模拟。
- 没有 NPC 私有知识图谱、消息传播、可信度或真实遗忘曲线。
- 没有 Mem0、UwU Memory、Jev、Tauri、Capacitor 或原生 SDK 集成。
- 没有真实厂商 API 的系统长局报告。
- 没有完成全部 182 张设定截图的逐图人工校订。
- 没有 Android、iOS、HarmonyOS、Windows、macOS 或 Steam 发布包。
- 没有商业化收费能力，也没有应用市场合规和支付审查结论。

## 7. 项目的独有特征

### 7.1 AI 不是权威数据库

剧情模型可以提出变化，但状态必须经过校验后原子提交。失败时正文和待处理行动可保留，世界不被半提交。这比“把全部历史塞回聊天记录”更接近游戏事务模型。

### 7.2 叙事与状态分层

玩家看到的是小说式剧情。系统保存的是角色、关系、物品、事件和记忆。两层允许未来引入规则裁判，也降低模型漂亮但事实错误时污染存档的风险。

### 7.3 证据分级的世界书

世界书不仅保存文字，还保存截图来源、OCR 转写和待校状态。项目承认“模型可读”不等于“作者确认”。这种来源追踪是长线世界一致性的基础。

### 7.4 可恢复优先

原始回复、待结算正文、重试路径、存档导出、旧档迁移和多标签冲突检测共同服务一个目标：模型、网络或浏览器失败时，不让玩家数小时进度静默消失。

### 7.5 双轨记忆愿景

规划保留传统“完整存档继续”路线，同时探索人物会遗忘、误记和只知道自己接触过的信息的路线。两者必须架构隔离。前者保证玩家控制权，后者提供世界感。当前只完成基础记忆结构，尚未实现可验证遗忘曲线。

### 7.6 修仙优先，再抽象平台

项目先用《九霄》打通规则语义、长局状态和内容生产，再考虑恋爱、末世、科幻等题材。现阶段不提前抽象万能平台，避免把未稳定的接口固化成技术债。

## 8. 双人协作边界

- 合作者是发起者、世界观作者和产品思想负责人。其最终权责应集中在世界观 Canon、剧情语气、修仙体验、设定冲突裁决和阶段验收。
- 技术联合负责人负责架构、AI/Agent 方案、状态安全、测试、跨端技术和工程流程。其职责是把愿景变成可复现系统，而不是替作者改写世界观。
- 共同决策项包括存档 schema 变更、公开发布、商业模式、隐私规则、第三方依赖和阶段 Definition of Done。
- GitHub 采用功能分支、短提交、Pull Request、双人审阅和主分支保护。世界观变更与运行代码变更尽量拆成独立 PR。

三份详细执行文件位于 `docs/九霄双人并行实施方案.md`、`docs/合作者执行方案.md` 和 `docs/技术联合负责人执行方案.md`。

## 9. 七阶段当前判断

| 阶段 | 当前状态 | 严格判断 |
|---|---|---|

| 五、NPC 认知 | 字段/构想阶段 | 没有来源、可信度、获知时间、传播、误记和遗忘系统 |

## 11. 下一阶段优先级

1. 用作者真实接口完成单 AI 与多岗位的 30 回合以上长局，记录失败、费用、延迟和状态漂移。
2. 逐图校订关键世界规则，把 Canon、待核和本局生成内容分层。
3. 定义行动中间表示和最小规则裁判，先覆盖移动、观察、交谈、使用物品和基础战斗。
4. 实现 NPC 认知来源、可信度和获知时间，再讨论遗忘曲线。
5. 在真实 Android、iOS 与 HarmonyOS 设备上验证浏览器版，再决定 Capacitor、Tauri 或原生壳。
6. 后端、账号、支付和商业化必须在隐私模型、成本模型和商店政策明确后单独立项。
