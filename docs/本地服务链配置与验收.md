# 本地服务链配置与验收

## 范围

本文件描述开发环境的容器服务链：PostgreSQL → Drizzle migration → Hono API，以及用于后续认证邮件联调的 Mailpit。它不代表账号、云存档、邮件发送业务或公测后端已经完成。

## 首次启动

要求 Docker Desktop Linux Engine 已启动。仓库根目录执行：

```powershell
if (-not (Test-Path -LiteralPath '.env')) {
  $bytes = [byte[]]::new(32)
  [System.Security.Cryptography.RandomNumberGenerator]::Fill($bytes)
  $secret = [Convert]::ToHexString($bytes).ToLowerInvariant()
  "POSTGRES_PASSWORD=$secret`nDATABASE_URL=postgresql://jiuxiao:$secret@127.0.0.1:5433/jiuxiao`nAPI_PORT=8787`nAPI_HOST=127.0.0.1`nWEB_PORT=5173" | Set-Content -Encoding ascii .env
}
docker compose config --quiet
docker compose up --build -d
```

`.env` 被 Git 忽略。不要复制真实密码到 issue、终端截图或仓库。若 `.env` 已存在，先保留现有密码；变更密码需要同步重建数据库卷或执行 PostgreSQL 密码轮换，不能只改环境变量。

## 服务入口

| 服务 | 本机地址 | 用途 |
| --- | --- | --- |
| API liveness | `http://127.0.0.1:8787/health` | 确认 API 进程响应，不证明数据库可用 |
| API readiness | `http://127.0.0.1:8787/ready` | 执行 `SELECT 1`，确认 API 到 PostgreSQL 链路可用 |
| PostgreSQL | `127.0.0.1:5433` | 本地开发数据库，仅绑定 loopback |
| Mailpit UI | `http://127.0.0.1:8025` | 查看测试邮件；业务尚未接入 SMTP |
| Mailpit SMTP | `127.0.0.1:1025` | 本地邮件测试端口；不是生产邮件服务 |

Compose 启动顺序由健康条件约束：数据库 healthy 后执行 Drizzle migration；migration 成功后启动 API。API 容器的健康检查调用 `/ready`。`/health` 保持 liveness 语义，避免数据库短暂不可用时误判进程已经死亡。

## PostgreSQL 集成测试

`pnpm test` 运行不依赖数据库的单元测试。缺少 `TEST_DATABASE_URL` 时，Vitest 会跳过 PostgreSQL 专项。为避免把“跳过”误报成“集成通过”，`pnpm test:integration` 和 `pnpm --filter @jiuxiao/api test:s6:integration` 都要求有效的 PostgreSQL URL；缺失或格式错误会立即失败。为降低误操作风险，测试库名称必须以 `jiuxiao_test` 开头。集成测试会写入数据，只能指向可丢弃的测试库，不要指向生产库、共享库或保存重要进度的开发库。

本机 Docker Compose 启动后，可用忽略的 `.env` 中 PostgreSQL 密码创建一次性数据库，再迁移并运行专项。此命令不会打印连接 URL；它会保留当前 PowerShell 已有环境变量，并在退出时删除本次生成的随机测试库：

```powershell
$previousDatabaseUrl = $env:DATABASE_URL
$previousTestDatabaseUrl = $env:TEST_DATABASE_URL
$testDatabase = 'jiuxiao_test_' + [guid]::NewGuid().ToString('N').Substring(0, 8)
$databaseCreated = $false
try {
  $localEnv = ConvertFrom-StringData -StringData (Get-Content -Raw -LiteralPath '.env')
  if (-not $localEnv.ContainsKey('DATABASE_URL') -or [string]::IsNullOrWhiteSpace($localEnv['DATABASE_URL'])) { throw '.env does not define DATABASE_URL.' }
  $testUri = [System.UriBuilder]::new([uri]$localEnv['DATABASE_URL'])
  $testUri.Path = '/' + $testDatabase
  $env:DATABASE_URL = $testUri.Uri.AbsoluteUri.TrimEnd('/')
  $env:TEST_DATABASE_URL = $env:DATABASE_URL

  docker compose exec -T db psql -v ON_ERROR_STOP=1 -U jiuxiao -d postgres -c "CREATE DATABASE $testDatabase"
  if ($LASTEXITCODE -ne 0) { throw 'Could not create isolated PostgreSQL test database.' }
  $databaseCreated = $true

  pnpm --filter @jiuxiao/db db:migrate
  if ($LASTEXITCODE -ne 0) { throw 'Database migration failed.' }
  pnpm test:integration
  if ($LASTEXITCODE -ne 0) { throw 'PostgreSQL integration tests failed.' }
} finally {
  if ($databaseCreated) { docker compose exec -T db psql -v ON_ERROR_STOP=1 -U jiuxiao -d postgres -c "DROP DATABASE IF EXISTS $testDatabase" | Out-Null }
  if ($null -eq $previousDatabaseUrl) { Remove-Item Env:DATABASE_URL -ErrorAction SilentlyContinue } else { $env:DATABASE_URL = $previousDatabaseUrl }
  if ($null -eq $previousTestDatabaseUrl) { Remove-Item Env:TEST_DATABASE_URL -ErrorAction SilentlyContinue } else { $env:TEST_DATABASE_URL = $previousTestDatabaseUrl }
}
```

GitHub Actions 使用单次运行的 PostgreSQL 17 服务容器，先迁移，再执行这组测试；不能因未设置数据库而静默跳过。当前工作分支的 CI 改动仍需远端检查运行通过后，才能记为 CI 集成验证通过。

## 验收命令

```powershell
docker compose ps
docker compose logs --tail 80 db migrate api mail
Invoke-RestMethod http://127.0.0.1:8787/health
Invoke-RestMethod http://127.0.0.1:8787/ready
docker compose exec -T db pg_isready -U jiuxiao -d jiuxiao
docker compose exec -T db psql -U jiuxiao -d jiuxiao -c '\dt'
```

`/ready` 应返回 HTTP 200，并包含 `dependencies.database=ok`；数据库中应出现 `game_saves`、`turn_requests`、`turn_events` 迁移表。`/health` 返回 200 但 `/ready` 返回 503 时，只能说明 API 进程活着，服务链尚未就绪。

Mailpit 是容器可用性准备，不是邮件业务验收：API 目前没有 SMTP 客户端或验证码发送路由。数据库 schema 也只是后续存档/回合的结构基础，当前 API 不提供账号、鉴权、存档读写或规则结算接口。

## 停止与数据

```powershell
docker compose down
```

该命令保留 `jiuxiao_pg` 数据卷。只有确认需要清空本地数据库后，才运行 `docker compose down -v`；这会永久删除该开发卷中的数据。

## Docker MCP

Docker MCP Toolkit 已通过本机 Docker Desktop CLI 建立 `jiuxiao-local-dev` profile，并写入 Codex MCP 客户端配置。配置命令：

```powershell
docker mcp profile create --name jiuxiao-local-dev --connect codex
codex mcp list
```

配置检查中 `codex mcp list` 将 `MCP_DOCKER` 列为 enabled。Gateway dry-run 能读取 314 项 catalog 并加载内置管理工具，但本机日志同时报告 Docker Desktop secret-store 与 backend API pipe 不可用；profile 当前没有额外 MCP server。Codex 重启或刷新 MCP 后才会向新会话提供 Gateway 工具。当前会话没有动态加载 MCP tools，因此只能确认客户端配置已写入，不能宣称本轮已通过 Codex MCP 发出实际工具调用。Docker CLI 对本机 Engine 的连接和 Compose 服务链是单独实测的。

## 最近一次本机复验（2026-09-28）

本轮 Docker Engine 版本为 `29.8.1`。执行 `docker compose up --build -d` 后，`db`、`api` 与 `mail` 均保持运行，`migrate` 退出码为 0；`/health` 返回 `ok`，`/ready` 返回 `ready` 且数据库为 `ok`。`pg_isready` 接受连接，`\dt` 可见 `game_saves`、`turn_events`、`turn_requests`。此外，S6 PostgreSQL owner 隔离与 CAS 并发专项 1/1 通过。该复验使用 Docker CLI/Compose；当前 Codex 会话仍未暴露 Docker MCP 工具。API 仍未挂载身份、云存档或邮件验证码业务路由。
