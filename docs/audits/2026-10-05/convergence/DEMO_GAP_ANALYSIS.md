## 最小可发布 Demo 方案（待负责人批准范围）

不是完整游戏，只完成一个已批准序章闭环：进入→建档→移动/观察/对话中的代表行动→一次澄清→规则提交→叙事→保存→关闭重开继续。

### 最少系统

前端入口与一个序章；正式规则/初始状态；事务/事件/存档；最小Canon和授权NPC记忆；一个AI叙事岗位。公开云档Demo另需真实认证/API/数据库/邮件与可发布素材；没有资源时只能称内部Demo。

### 可以复用

main 的页面、角色草稿、存档、事务、事件/回放、规则reducer、AI适配、账号/云档；#51解析和澄清；#35部署URL边界。不要另建平行引擎或平行认证。

### 六个收尾工作包

1. 固定#51输入/内容与#35部署差异，形成同一候选代码基线。
2. 把已批准序章内容和规则映射装配为正式provider与初始状态；既有裁定先复用，未映射不自动当作者未提供。
3. 把输入→澄清→规则→已提交状态→一个AI岗位接成一条调用链。
4. 接Canon机器回执和最小授权NPC检索消费；不将candidate内容直接视为发布完成。
5. 验证真实回合保存/重开/丢响应/回放，替代单靠模拟回执得出的产品结论。
6. 核实发布场所：已授权素材、Pages/API/邮件数据库及一个真人模型/手机流程；不假造外部结果。

这是六组工作，不等于六个缺陷或六天工期。现有模块较多，剩余主要是装配与验收；生产资源与批准对象会影响时间。

### 可以关闭

收费与社区；其余地域开局；未授权场景媒体；未接入高级AI选项；首次Demo非必要岗位。关闭这些不应删除历史成果或绕过安全门禁。
