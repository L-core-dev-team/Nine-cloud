## S6 本轮已实现内容

### 所有者隔离与 revision 比对写入

- `apps/api/src/services/cloud-save-service.ts`：校验 `SaveEnvelope`、首次 revision 必须为 0、后续 revision 必须严格加 1；owner ID 由调用方可信会话提供。
- `apps/api/src/services/postgres-cloud-save-repository.ts`：按 owner 过滤列表/读取/更新；CAS 更新同时匹配 `saveId + ownerId + expectedRevision`。竞争失败后只查询该 owner 的当前 revision。其他账户的档案对调用方表现为不存在。
- `apps/api/src/services/cloud-save-service.test.ts`：覆盖输入校验、owner 隔离、revision 冲突不覆盖。
- `apps/api/src/services/cloud-save-repository.integration.test.ts`：真实 PostgreSQL 双账户隔离和双并发单胜者集成用例；使用 `pnpm --filter @jiuxiao/api test:s6:integration` 执行，必须显式设置 `TEST_DATABASE_URL`，且现有迁移已应用。

### 有意未开放的边界

当前 HTTP API 仍未挂载认证或存档路由。数据库 repo 已可由服务层调用，不代表匿名用户能写云档。本地 IndexedDB 的玩家存档是富对象，包含对话、历史和旧版本归档；共享 `SaveEnvelope` 仅描述 `WorldState`。在双方确认完整同步范围、敏感字段清单和版本升级方案之前，把富对象硬塞进现有 schema 有静默丢数据与上传旧配置风险。

Better Auth 目前没有安装或配置。官方文档给出的 Hono 挂载使用 `app.all("/api/auth/*", c => auth.handler(c.req.raw))`；Email OTP 默认 OTP 为六位、有效五分钟、最多三次尝试，且默认以明文形式保存 OTP。启用前必须显式改为哈希存储、限流并审查统一错误/计时行为；邮箱发送器、域名、保留政策和生产密钥尚未决定。本地 Mailpit 不能证明生产邮件投递或账号服务可用。参见 Better Auth 的 “Hono Integration,” “Email OTP,” and “Drizzle ORM Adapter,” *Better Auth Documentation*, accessed 28 Sept. 2026: [Hono](https://better-auth.com/docs/integrations/hono), [Email OTP](https://better-auth.com/docs/plugins/email-otp), [Drizzle](https://better-auth.com/docs/1.6/adapters/drizzle)。

## S6 尚需完成的工作

1. **统一同步合同：** 定义游客保存的核心状态、剧情记录、附件/世界书引用、旧 HTML 归档与密钥字段边界；规定云端可存的数据、最大载荷、版本兼容与导出格式。补充契约往返测试。
2. **确定身份与邮件政策：** 作者选定发件域和真实邮件供应商；定义验证频率、OTP 过期/尝试次数、账号删除、数据保留、备份保留和隐私告知。开发 Mailpit 与正式邮件发送器分环境实现。
3. **安装并配置认证：** 固定 Better Auth 与适配器版本；按当前官方 schema generator 生成 Drizzle 表和可回滚迁移；OTP 使用哈希存储、严格 trusted origins、cookie/CORS/CSRF 及请求限流；生产缺密钥或发件器时服务必须 fail closed。
4. **挂载授权 API：** 完成 session 中间件；列表/读取/写入/删除/分支复制由服务端 session 确定 owner；错误响应避免泄露其他账户是否存在；HTTP 不接受客户端 ownerId。
5. **接入 Web：** 游客默认仍只写本地；登录后由玩家明确开启同步；断网入队；冲突显示云端/本地/复制分支；操作可取消且状态可恢复。
6. **做安全集成验收：** 两个真账号互读互写拒绝、同 revision 并发写单胜者、重试幂等、断网恢复、账号导出删除、迁移失败回滚、日志无密钥/OTP/正文抽样。随后做部署密钥、发件器和灾备演练。
