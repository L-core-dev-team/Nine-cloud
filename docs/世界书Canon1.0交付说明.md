# 《九霄》世界书 Canon 1.0：作者侧交付

本分支仅提交世界书数据包、构建脚本与审核记录。游戏页面、场景、AI 请求和存档逻辑由合作者的开发分支继续维护；本分支未改动这些文件。

## 内容与来源

- 182 个旧编号已逐条核对去向：179 张原图及配对转写，另 3 条按用户原先指定排除。
- 179 张原图均对应正式条目的来源引用；原001是章节目录，放在 `documentOutlineSourceRefs`，其余正文页附于相应条目。
- 正式版有 33 个条目：世界概述 1、地域 6、势力 16、体系 10。原060—061 的无标题正文单列为“修仙基础”，不猜原图标题。
- 原图哈希、逐图独立 OCR 比对、旧编号去向及残缺片段保存在作者侧私有审核资料中；玩家运行版不带这些内部字段。仓库中的来源登记仅保留来源 ID、类型和审核方法。
- 已按用户授权裁定原088 的阶数笔误、圣火教别名、原120→118及原173→174跨图衔接；修复原165→164正文被来源标记截断的问题，并按已有作者裁定保全原051、原052、补005的天工阁匠师等级细节。裁定记录在 `canon.registry.json` 的 `decisions` 中。

## 审核边界

182 个旧编号均已有裁定去向。179 张原图和 28 张补图逐张经过**从图片重新运行的独立 Windows OCR**，再与已有逐图转写交叉核对；独立 OCR 四字片段覆盖率低于 85% 的 18 张原图、3 张补图均已直接查看。补004为无关开发截图，仍排除于世界书；补026因 OCR 识字异常也直接查看。补充目视原077时发现旧转写补出了原图上缘看不到的结丹过程，现已在正式 Canon 中删除并记入裁定。私有 `image-by-image-review-20260925.json` 逐张记载方法、发现和素材哈希，旧 182 条各有独立去向。23 张原图此前已有定点视觉复查记录。

这构成作者委托的**逐图独立 OCR 交叉核对与差异复核**，不能表述为作者本人把 179 张全部逐字目视签收。`reviewSummary.imageByImageIndependentOcrCrosscheckComplete` 为 `true`；`reviewSummary.imageByImageVisualVerificationComplete` 仍为 `false`。合作者审查时不应再报告“182 条全未审核”，也不应报告“全部原图人工目视终审完成”。

原图截断、无法辨认的部分不编成硬设定。正式内容中的省略号表示缺口，不为缺失文字赋予设定效力；58 条未发布片段（含缺口说明、审核备注及五条无归属残句）留在私有审核资料。六个仍无法从现有截图安全恢复的核心缺口在作者登记的 `reviewQueue` 中列为 `pending_review`，不会进入玩家运行版，包括经济体系正文、一处功法全名、三组机构缺页及物价表缺失的两行。只有标题而缺可靠正文的“经济体系”不作为正式条目发布，“经济与物价参考”有独立正文，正常保留。

旧设定截图补足了编号图裁断的五毒神教地龙脉、蛛神脉功法名：《地龙腐骨功》《蛛神罗网策》均已从图像直接核实并归回各自分支；金蟾脉及门规处的滚动重叠也已去重。对应裁定见 `author_20260925_013`。这两张旧截图是私有素材，仓库只记录其文件标识，不把截图或本机路径加入公开运行包。

原091/092的天阶功法重复句已按截图去重；昊天剑宗与冰神宫跨图缺标题的段落已分别移入描述性“组织架构”“门内风气”小节，不再归到前一个“弟子等级”或“内部结构”小节。缺字仍用省略号保留边界，对应裁定见 `author_20260925_014`。

万兽山庄与偃师府原图中的风气段也已从“弟子等级”移入描述性“门内风气”小节；偃师府《千机百变诀》的滚动重复开头只保留完整段一次。对应裁定见 `author_20260925_015`。

玉清阁、四海商会、稷下学宫三处无法归属的页首孤字残句只保存在私有记录，不拼接进玩家正文；可确认的后续条目仍保留。对应裁定见 `author_20260925_016`。

原016的完整尺寸截图证实玉清阁功法名为《万化丹尘》，逐图TXT的“万[看不清1字]丹王”是误读。正式版已恢复完整名称，移出待确认清单，对应裁定见 `author_20260926_017`。

供玩法规则核对的[九境五域世界书依据表](九境五域世界书依据表.md)已从正式条目提取；其中不擅设原图没有给出的数值和通行门槛。

逐页转写到正式正文的八字片段覆盖检查发现 7 页低于 80%：原001为目录、原051/052的等级表已按异文合并、原088有记录过的阶数裁定、原092包含别名与跨章节边界、原094为表格读序、原121为标题边界。其余 172 页未触发该阈值。该检查只是遗漏筛查，不能替代原图阅读；原始结果留在私有 `runtime-source-coverage.json`。

## 供合作者接入

- 正式、无内部来源资料的运行数据：`packages/content/src/canon-runtime.json`。
- 带版本、来源引用、裁定与真实审核状态的作者侧登记：`packages/content/src/canon.registry.json`。
- 查询、按场景选取、形成 AI 只读上下文：`packages/content/src/index.ts`。
- 运行数据由 `node scripts/build-canon-runtime.mjs` 从登记生成；`node scripts/test-worldbook-final.mjs` 检查条目来源、179 张图的去向、逐图 OCR 审核状态、运行版隔离和关键正文。

接入游戏时请调用 `retrieveCanon` 选取相关条目，再通过 `buildCanonPromptContext` 提供给 AI；不要将作者侧登记中的来源和审核字段塞入剧情提示词，也不要让 AI 的回合输出回写正式 Canon。本分支未自行改动合作者的游戏接入代码。
