## 安全审计与修复

1. **0021**：只复用0020原文修复时间戳倒序导致的漏执行，不新增遗忘/观察规则。本轮测试逐字归一化核对被嵌入SQL，覆盖空库、0019升级、已有0020、重复执行、部分字段、同名对象冲突、事务中断回滚后重试。保留旧v1/v3整行数据及迁移登记；错误必须原子回滚，不清库纠错。这不是对任意人工篡改数据库结构的自动修复保证；若已有结构漂移，应停止升级人工核对，不重写历史迁移。
2. **身份隔离**：复用真实PG的游客创建、会话轮换、OTP升级保留owner和存档、已有邮箱不被占用、并发升级与撤销测试。提供商响应模拟，不冒充生产Supabase验收。
3. **回执行动关联修复**：原页面仅核对saveId/key/revision。本轮在POST返回与GET恢复两处追加服务端根分支行动指纹验证，包含原文、角色、expectedRevision、clarificationOf。错配保留待决请求和草稿、不写成功历史。单测直接使用领域prepareTurn产生的回执交叉验证，浏览器注入同key但不同原文的回执验证拒绝。
4. **unknown/版本冲突**：unknown只查询或用户明确选择同key原请求重试，不自动换key；版本冲突不会被写为已结算。若其他标签已推进存档而旧请求没有回执，当前仍需人工核查，客户端不擅自撤销待决请求。本轮没有增加不具备服务端证明的“放弃并重新提交”捷径。
5. **缓存**：既有端点/账号/存档三维隔离、CAS草稿、退出epoch防迟到写入及8000字恢复继续回归；缓存不是权威状态源。历史UI记录不替代服务端回执认证。

## 自由输入现状与审批边界

现行 `p1-nlu-runtime.ts`、`prologue-v1-nlu-fixtures.ts` 提供移动、观察、交谈、使用、战斗接线；没有acquire_item/quest的自然语言模板。`P1-MAP-作者可执行映射.md` MAP03已给出避水符来源和任务奖励，后续规格对照明确MAP01–06为共同认可输入：**不要求重签已认可的来源/奖励事实**。缺的是以下自然语言入口边界，不能把旧冲突表当作当前事实。

| 提案（待批准，不执行） | 限定语义 |
|---|---|
| 拾取“目标名”／捡起“目标名” | 仅匹配现有规则簿、当前位置可见且未领取的来源；数量固定该来源既有quantity。唯一匹配映射acquire_item；不得从文本猜测新物品或数量 |
| 领取“任务名”的奖励 | 仅匹配当前存档已知任务；映射既有questId与claim_reward，由现有规则判断完成、已领取和容量 |
| “领取奖励”等无任务名表达 | 请作者决定：只在唯一可领取任务时接受，还是一律要求任务名；多任务必须澄清 |
| 同名物品／缺项 | 请确认澄清选项如何以已有sourceId区别，不新增Canon；选择前零事件零时间 |

“灵石”“令牌”等用户示例不是当前场景存在性证据，不新增目标。

| 验收场景 | 当前结论 |
|---|---|
| 正常拾取 | 自然语言BLOCKED待模板批准；结构化规则已有来源与数量检查 |
| 不存在物品 | 未映射文字拒绝/澄清，不算正常拾取闭环 |
| 同名目标 | BLOCKED待目标选择协议，禁止任意取首项 |
| 背包满／合法限制 | 规则已有INPUT_INVENTORY_FULL；自然语言端到端待签 |
| 正常领奖 | 自然语言BLOCKED；现有结构化测试不替代 |
| 未完成任务领奖 | 规则ENV_QUEST_NOT_READY；自然语言端到端待签 |
| 重复领奖 | 规则ENV_QUEST_ALREADY_CLAIMED；自然语言端到端待签 |
| 断网刷新重试 | 现有已批准自然语言行动验证同key；不能据此声称拾取/领奖已通过 |
