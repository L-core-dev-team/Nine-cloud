# 安全安装顺序与黄金基线依赖

本文件是待审安装方案，不授权执行。当前0023只在专属测试库执行；正式journal、正式签署值和生产均未修改。P01–P06仍BLOCKED，T01–T16仍0 PASS/16 BLOCKED。

## 已证实的0022兼容风险

旧候选安装后，未带V2归属声明的旧pending/running generation在UPDATE时被 `narrative_generation_managed_v2` 拒绝，错误为 `NARRATIVE_MANAGED_DECLARATION_REQUIRED`。用真实gr01_app连接分别重现了两种状态。不能先安装再让旧worker自然完成，也不能为了恢复写入就伪造managed/legacy声明。

最终候选在新0023开头加入事务内SHARE表锁和未完成任务检查。存在任一pending/running即抛出 `NARRATIVE_0022_UNFINISHED_GENERATIONS`，整笔迁移回滚，归属表不留下半成品。真实非管理员旧writer在0022下完成一次发布、将另一次运行中任务转为failed，停止并撤权后，迁移成功。没有改写历史0022。

## 待批准的安装顺序

1. 固定旧版本、所有实例/worker和数据库角色清单，冻结旧入口流量并停止接收新任务；对数据库、迁移身份、回执/正文、pending/running/failed/published分布和授权配置留存可信备份与摘要。
2. 在0022语义下逐项处理旧未完成任务：由旧受信writer完成并发布；或按已批准的故障/取消政策，通过原授权路径终结为failed。保留原回执、事件、attempt和已有正文，不重结算，不补写V2归属。没有明确处理授权的遗留任务继续BLOCKED。
3. 确认所有旧pending/running已清零；排空并停止所有旧worker、renderer及在途发布。数据库终态不证明外部模型或旧进程停止，必须取得独立进程、流量及外部调用证据。
4. 对旧数据库LOGIN角色及所有可切换的角色路径执行实际撤权与会话清退，核验表级/列级写权限、继承/SET ROLE、DDL/对象所有权、绕过触发器能力。NOLOGIN本身不会终止已有连接。完整部署证据目前未建立。
5. 由独立安装角色预置四个彼此职责隔离的NOLOGIN、非超级用户、无CREATEDB/CREATEROLE/BYPASSRLS能力的角色：schema_owner、operator、erasure、runtime。应用登录仅授予runtime及必要业务权限，不能继承或切换到其他三者。安装角色与应用角色分离。
6. 在维护窗口及单事务内安装获批0023，锁住旧G写入并再次检查零pending/running；拒绝时回滚，不能绕过检查。正式迁移编号/journal注册、锁等待/statement/代理预算及回滚方案仍需批准。本轮只有独立开发迁移包。
7. 复核字段、触发器、函数owner/search_path/EXECUTE ACL、最小应用权限、独立删除连接和生命周期；新fence默认无行。安装后旧writer不可恢复服务。只有后续明确签署及启用授权、真实运维fence证明、新旧读取/写入成对切换均齐备时，才能启动新链。

降级不能简单删除新触发器后重启旧writer。0023替换删除授权函数并新增归属约束，需冻结流量、停writer，通过审核的前向修复或可信备份恢复处理，另核对外部副作用。这里没有证明生产在线降级。
