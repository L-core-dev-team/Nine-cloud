# 《九霄》M3 数据留存与恢复安全政策 V1.0

决策编号 JX-M3-DATA-POLICY-01。批准主体为道主，裁定日期为 2026-11-20。三项业务政策已批准。批准时实施状态为 PENDING_IMPLEMENTATION。本文件根据道主在本任务中提供的政策全文登记。实现与实测边界另见 [本轮回执](M3-EXTERNAL-RECONCILIATION.md)。

## 1. 基本原则

采取最小必要保留。账号永久删除后，删除玩家正文、角色卡、世界书、存档及无关身份信息。仅保留消费对账、删除核验、安全审计必需的有限数据。保留字段即使是摘要或审计记录，仍按可能关联个人的信息保护。留存期限、最终清理权限、旧备份解除隔离权限分别控制。

## 2. 字段与用途

| 数据 | 处理 |
|---|---|
| 玩家聊天、角色卡、世界书、存档 | 永久删除时清除活动数据库中的相关记录 |
| 邮箱、会话凭据及无需保留的身份映射 | 在对应删除流程中清除 |
| 授权 ID、配置摘要、累计额度消耗 | 有限保留，用于防止重复使用和恢复回退 |
| 删除操作摘要、生命周期审计 | 有限保留，用于核验永久删除和异常恢复 |
| 尚未确认删除的 Supabase UUID | 只在完成远端删除所需期间保留，确认后清除 |
| 与上述目的无关的玩家内容 | 不得以对账名义延长保留 |

## 3. 期限与起算点

| 数据类别 | 期限 | 起算点 |
|---|---|---|
| 玩家正文 | 不额外保留 | 永久删除事务提交时清除活动数据 |
| 普通数据库备份 | 30 天 | 每份备份创建完成时 |
| 已完成删除的审计摘要 | 6 个日历月 | 本地和云端相关删除均确认完成时 |
| 授权 ID、配置摘要、累计额度消耗 | 6 个日历月 | 授权关闭、最后一次额度变动、账号删除完成三者中的最晚时点 |
| 未确认删除的远端 UUID | 直到明确确认删除 | 超过 7 天仍未确认，升级人工核查 |
| 依法需要保存的网络安全日志 | 适用时不少于 6 个月 | 对应事件发生时 |

期限属于初版内部业务政策。实际法律适用、日志分类和法定保留例外须在正式运营前复核。

## 4. 保留例外

未确认的云端删除、无法核对的消费差异、可能重新引入旧状态的备份、已记录且仍有效的法律或安全保留义务，均阻止仅凭期限清除仍需要的证明。例外须记录具体原因、批准主体、最小范围及定期复核要求，不得无限期保留无关玩家内容。备份到期后按政策安全销毁或继续受控隔离，不自动解封。

## 5. 权限

经合法身份验证及确认的玩家可申请永久删除，由受控流程执行。已批准的维护程序可在预设范围内执行常规到期清理，保留审计。最终删除消费及审计证明须独立对账，并由道主对具体批次批准。旧备份解除隔离须独立核验通过，道主对具体实例单独批准。授权维护人员可先紧急封闭、停止写入，再报告。临江仙仅为技术执行者。独立核验者不能代替道主批准；正式解封前应分离执行与核验职责。

## 6. 备份隔离与恢复

旧快照恢复默认阻止玩家连接。须验证备份来源、哈希、时间和目标；完整核对备份之后的删除和消费，不发生退款、重发或额度回退；独立核验并取得道主对指定实例的批准。缺少任何一项均保持隔离。批准本政策不等于批准某次解除隔离。

## 7. 技术限制

消费、删除和审计表可能随旧库一并回退。必须在备份恢复边界之外保存可信依据，并对其完整性、访问、期限与备份实行保护。普通日志、同库另一张表和随快照恢复的副本不能自动视作可信独立来源。

## 8. 尚未授权

真实 Supabase 删号联测、真实玩家清理、生产迁移、旧备份解封、正式生产恢复或部署、原生 T1 待签规则启用均须独立验收和相应批准。
