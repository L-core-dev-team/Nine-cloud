## 数据流与验证方式

1. 备份来源须独立登记完整归档的 SHA-256、备份完成时刻和只读状态摘要。合成源在备份期间停写。复用现有回环隔离恢复工具；显式设置 `collectReview` 后，对实际送入 pg_restore 的同一字节流计算 SHA-256。在连接上限为 0 且 PUBLIC CONNECT 已撤销的恢复库内，通过只读一致性事务采集额度、删除审计、投递状态和账号摘要，随后封库。未传选项的原恢复路径不变。输入只允许来自已验证来源的备份，归档本身的安全准入仍由原恢复流程负责。
2. 核验身份仅连接维护库，实查指定随机库名的连接上限和 `datallowconn`，拒绝管理员、库所有者及其继承身份。核验入口不接受开库命令。私有核验输入含可关联摘要，公开回执只含实例、归档摘要、Commit/Tree、策略、证据头、门禁与原因。
3. 库外事件为版本 1 协议：UUIDv4 同时作为事件 ID 与幂等号，正整数顺序号、上条记录哈希、UTC 毫秒时间、来源、政策版本及限定负载。消费事件只含批准和绑定摘要、增量 1 与累计值；本地确认删除含 owner 与操作摘要；远端投递含操作和 subject 摘要以及 pending/unknown/retry/completed。原始 UUID 只在现有受限投递队列未决时保留。逐键校验后才写入合成适配器；未知字段拒绝。记录 SHA-256 覆盖 UTF-8 JSON 编码的原顺序。用于匹配的摘要仍可能关联身份，应受政策保护。
4. 业务测试先登记外部意图，PG 提交后才确认相同事件 ID。相同 ID 与相同负载幂等，内容冲突拒绝。独立见证在停写时从源库另行取状态摘要，固定序号、链头、未决数、源状态和账号集合，绑定备份及恢复实例。每次读取须用新挑战、固定来源和受信 Ed25519 公钥验证；旧签名、截尾、重排、不同来源或错误政策都不能复用。无完整起点、超过本版 1 万事件或单表 1 万行均拒绝；大库或可信基线轮换须另行设计。测试限制签署切点新鲜度为 60 秒，并非数据留存期限。
5. 没有外部确认、PG 已提交而外部写入失败、源状态与事件重放不符、未决远端操作、额度有差异或已删账号仍在，保持 DENY。账号集合发生其他变化也保守拒绝。源与证据均完整且一致的结论上限是 REVIEW_READY；批准始终单列为需要道主逐实例裁定。每次核验提交脱敏回执到独立审计接口；审计写入未获匹配摘要确认时返回 DENY。未获确认的外部写入须按同一 ID 核实，不能直接当作缺失或成功。

生产缺口具体在双写边界：当前业务事务并未调用合成意图记录器。两个存储不能天然共同提交；若真实 writer 可漏记意图、见证可回滚、源不可达或切点不完整，生产就缺少可认证的完整历史。需要隔离的持久追加存储、不可回滚的独立头记录、固定信任根、可信停写/连续性证据和可恢复的未决操作协议。测试适配器的进程内能力分离和临时密钥可验证协议；同一 OS/进程管理员仍在共同信任域。实际签署、权限安装、持久审计和清理均须另行验收。库内加表、普通日志和签名有效的旧前缀都不足以替代该边界。

## 留存与权限

按 UTC 算日历月，目标月缺同日时取月末同一时刻。30 天从备份完成计，到期只能转销毁审查或继续隔离。双端相关删除均确认后取较晚时点加 6 个日历月；消费取授权关闭、最后变动及适用的删号完成时点中最晚者。时点缺失按保留处理；只有明确不适用才可省略对应时点。未决 UUID 超过 7 天提示人工复核。任何在册保留例外、未完成核对、未确认远端删除或旧备份风险均阻止自动清理。记录例外应含原因、批准主体、最小范围、复核时间；复核逾期不自动取消例外。到期的最终审计和额度记录始终要求独立核验与道主对批次批准。本模块只返回政策评估结果，不具有清理能力。

## 六组验收与复核入口

| 场景 | 检查 |
|---|---|
| 1 消费回退 | 源库从 1 增到 2；旧副本得到 ALLOWANCE_MISMATCH。故障窗口和库外读失败均 DENY。 |
| 2 删除复活 | 删除 A 后把旧归档再次恢复进第二实例；真实账号集合及删除记录与外部切点不符，得到 DELETION_MISMATCH。 |
| 3 证据错误 | 删头/尾、重复、乱序、改写、换源/政策/公钥、重放挑战和超期切点拒绝。即使事件链本身有效，独立源摘要不一致也拒绝。 |
| 4 远端未确认 | 使用现有投递代码与进程内假远端，pending/unknown 限制恢复并保留原操作号和待投递 UUID；模拟完成后 UUID 置空。 |
| 5 证据完整 | 每次核验后真实玩家 PG 登录均收到 55000，目录核验登录尝试更改数据库属性收到 42501。完整证据最多进入人工审核。 |
| 6 期限与权限 | 用可控时钟覆盖月底、30 天边界、6 个日历月、严格超过 7 天、未完成核对、有效例外、日志复核及专门批次审批。 |

本地定向命令为 `node --test tests/integration/m3-reconciliation.test.mjs` 及设置独立测试 PG 二进制目录后的 `node tests/integration/card-install-upgrade.mjs --m3-only`。二者只使用合成输入；实例工具生成新目录、独立端口，收尾检查 PID 目录、进程已停与端口拒连。CI 在原双实例演练中实际调用新的 PG 用例，并单独运行策略/完整性测试。PG 用例输出受测 Git Commit/Tree 和逐次脱敏回执，以当前 PR HEAD 的 verify 作业为准。没有生产凭据要求。
