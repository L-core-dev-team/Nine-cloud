# CARD-INTEGRATION-06A Provider 与 HTTP

Provider：card-provider-runtime 组合已有 createProviderTransport、createCardModel 与 createCardEgressFetch；地址与凭据来自服务端可信配置，卡片不得决定端点、密钥或代理。受控白名单 HTTPS 443、禁止用户信息/查询/重定向、仅公网 IPv4、每次 DNS 校验并固定已验证 IP，TLS SNI/Host 使用原授权域名；响应大小限制、超时/取消沿现有逻辑。真实目标地址、DNS 及证书配置、账户使用授权、调用次数和费用上限须由道主明确批准后再做真实测试。模型输出限额不是输入 token 预算；群聊100000字节上限不等于真实 tokenizer 上限，需在真实模型前对输入、保留输出预算、上下文窗口进行按模型计数及拒绝处理。成功验收应验证授权目标、完整会话、无跨账号泄露及计费边界；失败需验证超时、网络错误、SSRF 拒绝和请求可查且不重复写入。此轮无外部模型请求。

真实 TCP：仅回环端口，独立 PostgreSQL，真实 Email Cookie/Session、合成卡/模型。在测试宿主包装器中等待 app.fetch 完成后延迟回送响应，客户端 AbortController 断开；GET 原 key 返回 completed、同 key 再 POST 返回 completed，模型调用1次。该人为延迟证明已提交响应丢失可查询，不等于真实代理故障或处理中途断线。正常 TCP 完成经导入、创建会话和认证验证；处理中主动取消、处理中连接中断及未知 COMMIT 的真实 TCP 传播 NOT VERIFIED；此前应用内模拟取消不替代。脚本和 JSON 保存于独立本地审计目录，不含真实密钥。

完整业务链：本轮6文件54项隔离回归覆盖用户请求的各项功能的多个测试；这些是按场景拆分，不等于一次串行完成全部14步的单个实测。真实 Provider、真实移动设备、生产迁移、内容审核和生产开放均未验收。


补充实际 TCP 串行流程：合成 JSON 卡及世界书导入、卡库查询、Persona、单人创建与行动、已提交响应丢失查询、登出并重新获取 Cookie、单人历史、双角色群聊手动/自动、群聊历史、编辑卡后旧会话引用和 V2/PNG 导出 PASS。为免真实等待，在隔离数据库将合成邮箱验证码 issued_at 回拨两分钟。此串行流程未覆盖备用开场、多角色单次结构化输出和第二账号；这些只由本轮54项隔离回归的各自用例覆盖，不能合称同一条串行全项通过。
