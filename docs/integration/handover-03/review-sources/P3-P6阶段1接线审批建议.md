## 明确结论：仍需修改后重新审核

PostgreSQL原文持久化基础值得保留，T1的插入位置也合理。但**现有pending补丁不宜原样批准**：全局分流会接管旧回执；false仍可能生成；活租约与失败被混淆；重复行动可能重领failed；工厂配对接线和跨实例writer切换未完整交付。现在不是推倒重做，而是修订这些有限边界。

本轮交付的是推荐设计与验收门槛，不是接线实施授权，也不是重签批准。没有应用patch、修改源码/摘要/范围、执行迁移、提交、推送、合并或部署。

## 请道主裁定的有限事项

|事项|推荐裁定|产品影响|
|---|---|---|
|T1任务登记故障|回滚整次尚未提交行动；提交结果未知先查回执|正文任务存储故障会影响行动可用性，但不会丢失已结算行动的任务|
|false与选项固化|不生成正文，保存suppressed归属；同key保持首次选择并返回原结果|不允许利用重复行动请求启动新的正文生成；独立重试仍待审|
|取消与20秒等待|提交前可确认取消则回滚；提交后只取消等待；超时返回真实pending/running|离开页面不撤销游戏事实，也不自动把生成标为失败|
|崩溃恢复|允许固定版本任务的有界租约恢复；显式failed禁止自动重领|可能重复计算，但只有一个有效发布；具体重试上限在修订包中固定|
|旧回执与切换|可信归属分流；无旧原文明确不可恢复；旧writer排空后配对开启新链|不补造历史，不让新旧正文竞争|

以上尚未视为批准；若接受，再授权制作独立修订补丁。具体重试上限、等待参数及归属schema属于下一份可审查diff，不能仅凭本方案启动运行。
