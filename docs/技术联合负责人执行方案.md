# 《九霄》技术联合负责人执行方案

> 角色：AI/Agent 架构、工程交付、平台与商业技术负责人
>
> 目的：把愿景转成可验证系统，并阻止未经验证的先进方案进入主链。

## 1. 你的最终责任

你负责五个结果：

1. 世界事实不由叙事模型随意改写；
2. 存档可迁移、可恢复、可审计；
3. 新模型和 Agent 方案经过基准测试；
4. Web、移动、Harmony 和桌面共享稳定领域核心；
5. 商业化不会泄漏 Key、私人记忆或失控消耗模型费用。

## 2. 当前四周任务

### 第 1 周：建立可信基线

- 修复 `verify_delivery.py` 的源码/交付不一致；
- 明确 `work/` 为当前唯一手工源码；
- 建立 CI：核心、AI/JSON、构建一致性和敏感信息扫描；
- 加入 Issue/PR 模板、CODEOWNERS 和贡献说明；
- 记录模拟测试、真实 API、真机和产品验收四类证据。

完成标准：干净克隆能够构建并通过离线测试。

### 第 2 周：真实 API 与可观察性

- 建立模型支持矩阵；
- 单 AI/多 AI 分别跑真实回合；
- 记录阶段、模型、延迟、token、失败与恢复；
- 对日志脱敏；
- 不把单个厂商的 Model ID 写死为产品前提。

完成标准：30 回合可追踪，失败不损坏存档。

### 第 3 周：PWA 与真机基线

- 明确在线、离线和 BYOK 边界；
- 验证 iOS Safari 与 Android Chrome；
- 测试键盘、安全区、文件导入导出、后台恢复和刷新；
- 形成 HarmonyOS NEXT 独立测试清单；
- 不在此周同时启动三个原生工程。

完成标准：发布支持矩阵，而不是笼统写“支持手机”。

### 第 4 周：行动中间表示预研

- 定义 `ActionIntent`、`RuleDecision`、`DomainEvent`、`NarrativeInput`；
- 只实现“雷符炸洞”最小领域；
- 建立确定性规则基线；
- 为 Jev 和通用模型建立同一评测接口；
- 先存原始输入、解析提案与拒绝原因，再谈 Agent 编排。

完成标准：解析失败不会推进世界。

## 4. 技术采用门禁

### Mem0

仅当它在固定数据集上显著改善召回，而且成本、延迟、删除和数据隔离可接受时采用。必须保留 Local Adapter 和导出能力。托管版与开源版分别写 ADR；没有数据流图和删除验证时，不得上传私人世界书或长期角色记忆。

### UwU Memory

优先重写适配《九霄》事件契约的最小管线。若复用代码，记录许可证、版本、修改与安全审计。摘要只能是派生数据。

### Jev

只处理有限问题和有限候选。必须记录概率、阈值与升级路径。不得把厂商置信度当作已校准概率。采用前完成离线标注集评测。

### 遗忘

只改变 NPC 检索与表达。世界事件不可删除。参数必须版本化。玩家切换模式时展示影响并生成备份。

### 原生壳

Capacitor、ArkWeb、Tauri 都先做薄型 Spike。Spike 通过文件、存储、生命周期、支付沙盒和性能门槛后才进入正式工程。

## 5. 后端最小顺序

1. 写威胁模型和数据分类；
2. 定义账号、权益、存档、AI 网关接口；
3. 实现匿名设备身份与加密备份；
4. 实现服务端模型代理、配额和成本日志；
5. 再接商店支付和回执；
6. 最后做跨端同步和订阅运营。

不得先搭完整微服务。两个人的项目优先模块化单体和可替换端口。

## 6. GitHub 操作

- 使用 `codex/feat-*`、`codex/fix-*`、`codex/research-*`；
- 一个 PR 对应一个 Issue；
- PR 必须列出未修改项和证据等级；
- 对 Schema 变更提供迁移、回滚和旧档样例；
- 对研究分支写成功指标和终止条件；
- 生成 HTML 由构建产生，不做主要人工编辑对象。

工程 PR 的完成定义：

- 自动测试通过；
- 风险场景通过；
- 需要时有真实 API 或真机证据；
- 日志无 Key 和私人原文泄漏；
- 合作者已完成产品语义审查；
- 文档和迁移说明同步。

## 7. 关键指标

| 领域 | 指标 |
| --- | --- |
| 动作解析 | 准确率、拒识率、校准误差、P95 延迟、每千次成本 |
| 状态 | 不变量违规、幂等失败、重放差异、迁移失败 |
| 记忆 | Recall@K、错误事实率、来源覆盖、摘要重建差异 |
| NPC | 越权知识泄漏、传播可追溯率、信念冲突解释率 |
| 多端 | 崩溃、恢复、文件、键盘、生命周期、支付恢复 |
| 商业 | 单回合成本、活跃用户成本、退款、滥用、毛利敏感性 |

指标阈值必须在实验前写入 Issue。测试后再定阈值会产生选择性解释。

## 8. 你必须避免的失误

- 不要把新框架当作产品进展；
- 不要把测试数量当作真实稳定性；
- 不要用 Mem0 替代领域数据库；
- 不要用 Jev 替代规则；
- 不要删除“低分记忆”来制造拟真；
- 不要在核心未稳时同时维护五个平台；
- 不要为了平台化重写当前可玩的全部代码；
- 不要把 BYOK 当成隐私免责。
