# ADR 0001：语言与运行时边界

状态：已采纳为 1.0 工程原则，2026-09-23。适用范围：S1 以后新增的代码。它不锁死未来技术，也不改变双作者的产品与 Canon 决策权。

## 背景

《九霄》需要浏览器界面、确定性规则、服务端事务、内容工具、媒体处理和后续多端分发。不同语言均可完成其中一部分；把每种功能跨多个语言和框架重写，会增加状态同步、构建、调试与交接成本。现有旧原型是 JavaScript 与 Python 构建，新工作区已选 React/TypeScript、Hono、Drizzle/PostgreSQL。用户允许按任务选用 JavaScript、TypeScript、Go、Rust、Python、C++ 等技术，但要求项目结构保持清晰。

## 决定

1. Web 界面、共享契约、游戏规则和 Node API 在 1.0 主路径使用 TypeScript。浏览器端仅保留一个应用框架，即 React。旧单 HTML/JavaScript 留作迁移依据，不成为第二条新版发布链。
2. PostgreSQL 的持久结构、索引与迁移以 SQL 为最终可审核制品；Drizzle 负责类型化定义和生成。迁移文件入库，运行环境与应用提交使用同一 Git SHA。
3. Python 继续承载现有原型打包、OCR 辅助及确有证据处理需要的离线工具。它不直接写玩家权威存档或事件表。
4. 以后可以在受测量支持的热点采用 Go、Rust、C++/CUDA、Python/R/Julia 等专用程序，也可为 Android、iOS、HarmonyOS 分别采用平台语言。引入前须有一份 ADR，写明当前瓶颈、替代方案、边界协议、构建与部署、数据所有权、测试、维护人、回退方案及实测收益。只因语言流行或“顶尖”不构成理由。
5. 一个权威状态只由规则事务写入。媒体、OCR、插件、MCP、模型和其他语言编写的服务通过版本化契约请求或返回候选结果，不绕过 `ActionIntent → DomainEvent`。跨进程通信先用明确的 JSON/HTTP 或队列协议，确有性能证据再改二进制协议。

## 检查方式

每个新增工作区包须写清职责与所有者；CI 从锁文件构建同一制品，运行类型检查、合同测试、许可证检查及迁移验证。任何第二套前端框架、第二个规则实现或独立构建流水线均需按本 ADR 提出证据和迁移成本，不能以“先试一下”直接进入主线。

## 当前限制

S1 的性能与运营数据尚不足以证明 Node、PostgreSQL 或 React 在长期负载下是最终最优。当前选择优先减少跨层复制和两人团队维护成本。S3 长局、S5 场景与 S6 在线负载测量后，可以按上述证据流程调整；调整不能破坏旧档、事件回放或玩家任务。
