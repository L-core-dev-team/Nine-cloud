# ADR 0006：应用商店上架属 1.0 范围变更

状态：**LYL 已决定，2026-10-03。Bird 待签。**

## 决定与依据

LYL 于 2026-10-03 提出「1.0 完成后需上架鸿蒙与 iOS 应用商城」。该要求与现行基线冲突，因此按范围变更处理：

1. **确认这是范围变更**，不是环境问题，也不是既有方案的补充。
2. **在新 ADR 明确之前，维持 `docs/九霄1.0公测版重建总方案.md` §9 的现行分发口径**：「Web/PWA 是 1.0 正式分发；Android、iOS、HarmonyOS 与桌面安装包须另做签名、更新、真机和商店验证，不在此版声称已通过。」
3. **软著与 APP 备案材料准备可与内测并行**；具体办理路径、材料要求和周期须由运营主体按目标平台与属地窗口核实。旧稿中的“20–40 个工作日”是计划估算，不是官方时限承诺。
4. **版号归属判定列为 M2 的前置调研**：九霄在 Apple 侧被归为「游戏」还是「工具/娱乐」，决定是否必须取得网络游戏版号（ISBN）。在判定完成前不承诺任何上架时间表。
5. **不因商店需求而提前引入收费**。ADR-0004（1.0 不含社区与收费）不受本 ADR 影响。

## 已知阻断项（按严重度）

| ID | 项 | 说明 |
| --- | --- | --- |
| SB-1 | 网络游戏版号（ISBN） | iOS 中国区游戏类需要；周期与成本最高，且与 AI 生成内容审查叠加 |
| SB-2 | 软件著作权及平台材料 | 尚未取得目标商店对九霄的正式材料清单；不得把软件著作权的强制性写成已核实结论，须由运营主体按目标版本确认 |
| SB-3 | 纯血鸿蒙与 Web 容器路线 | Android APK 不能直接视为 HarmonyOS NEXT 发布包；华为提供 ArkWeb Web 组件，但它不证明九霄的包型、性能或审核路径可行。需在目标设备验证 |
| SB-4 | AI 生成合成内容标识 | 适用要求取决于服务形态、内容生成与传播路径；不得把备案、显式标识、文件元数据标识合并成一个无条件结论，须由运营责任人按实际流程核实 |
| SB-5 | 鸿蒙版 APP 备案 | 独立于网站 ICP 备案；包名创建后不可修改 |
| SB-6 | 开发者账户、审核账号与账号功能 | 当前 Apple 官方材料不支持“个人开发者账号一律禁止登录/注册功能”这一概括。App 若允许创建账户，须提供 App 内删除账户；含账户功能的提交还须提供可供审核的有效演示账户或完整演示模式。账户类型与审核方式须按实际产品和审核要求确定。 |

## 工程边界

- 商店上架**不改变** Web 侧 1.0 的任何事实：权威链路、回合事务、双记忆模式、Canon 门禁一律不动。
- 原生壳是**新增**工程项，当前仓库完全不存在；BYOK 密钥必须改用 Keychain / 鸿蒙 KeyStore，**不得留在 WebView localStorage**。
- 不得为了过审而在壳内弱化 `HttpOnly` / `SameSite` 契约或绕过 fail-closed 门禁。
- 商店版本与 Web 版本必须同源构建、同指纹走签，不得为审核单独编译分支。

## 后续变更

- 里程碑分期（M0 Web 公测 → M1 软著与备案 → M2 iOS → M3 鸿蒙）及其前置条件见主索引 §12.7。
- 版号判定、鸿蒙 Web 组件可行性、软著名称一致性口径等待核项见主索引 §12.8。
- 鸿蒙侧可评估**元服务（Meta Service）**，但功能范围、审核口径与研发成本均待官方规则及原型评估确认。
- 本 ADR 不表示任何商店资质已具备，也不表示 iOS 或鸿蒙已可提交审核。
