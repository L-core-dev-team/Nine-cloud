# ADR 0009：视觉与渲染技术选型

- 状态：Accepted（2026-11-26）
- 决策依据：作者授权“ADR 0009 → 批准”“渲染及资产路线 → 不限制，允许继续创新”“CI 门禁重构 → 批准”。本 ADR 由 Claude 记录。
- 取代：旧制度中“只准 React、只凭性能数据才能引入新技术”的艺术性限制（见最终方案 02 第 6 条）。安全、许可、数据、无障碍规则不变。
- 依据：[最终方案 08 §2](../design/JX-VISION-02/final/08-全栈架构与数据契约.md)、[09](../design/JX-VISION-02/final/09-资产生产体系.md)、[10](../design/JX-VISION-02/final/10-制度门禁与仓库治理.md)

## 决定

1. 保留 React 19 / TypeScript / Vite / Hono / PostgreSQL。新增 three.js（WebGL2 为默认，WebGPU 为增强）、Web Audio。离线资产管线可用 Blender（bpy）、Python、AI 生成模型及其他工具。
2. 渲染分档：T0 静帧加纯 DOM 兜底，T1 画板加运行时打光，T2 实时三维元素，T3 WebGPU 与三维高斯泼溅等。每档有开关，失败自动降档。
3. 渲染与资产路线**不是封闭清单**。Blender + CC0 扫描材质 + G-buffer + 运行时打光是 2026-11 在无 GPU 云端容器中验证过的推荐路线，不是唯一许可路线。有 GPU 时可以使用更强的生成模型、ControlNet、三维重建或程序化方法，前提是通过“画面 ⊆ 事实”门禁、许可登记与人工审阅。
4. 现有 `scan:artifacts` 门禁会拒绝 three.js 进入 `apps/web/dist`。改为“渲染依赖登记表”：登记过的依赖（名称、版本、许可、用途、引入 ADR）允许进入；未登记的继续拒绝。门禁改造与 three.js 的首次引入在同一个 PR 中完成。
5. 所有正式资产记录来源、许可、生成模型与版本、提示词、种子、哈希；公开仓库不放未授权素材和私人参考图。
