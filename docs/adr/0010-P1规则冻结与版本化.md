# ADR 0010：P1 规则冻结与版本化

- 状态：Accepted（2026-11-26）
- 决策依据：作者 2026-11-26 的执行授权（PR #124 授权评论与执行命令），其中“P1 冻结与升级 → 批准”“双作者签收 → 取消”。本 ADR 由 Claude 依授权记录，不是作者签名。
- 关联：[最终方案 08 §6、11 X14](../design/JX-VISION-02/final/11-实施路线与验收.md)、[执行台账](../execution/JX-VISION-02/README.md)

## 背景

`prologue-v1` 的玩法规则有两道钉：`scripts/p1-rule-candidate-bundle.files.json` 的字节摘要（只作诊断），以及 `scripts/p1-rule-semantic-source-digest.mjs` 所列文件的 AST 语义摘要 `semanticSha256`（强制，钉在 `apps/api/src/services/p1-review-rule-approval.ts`，线上 preview-1 的批准文件也引用同一值）。

语义摘要的文件表不只有规则，还包括共享契约 `packages/contracts/src/*` 和回合管线 `server-turn.ts`、`turn-runtime.ts` 等。所以 R1–R4 的任何契约或管线改动都会让 P1 插件拒绝加载，规则本身却没有变。没有冻结机制，修复和新契约都推进不了。

## 决定

1. `prologue-v1` 是冻结的规则版本。它的规则身份由两样东西确定：
   - `scripts/p1-frozen-rules.mjs` 列出的 14 个冻结文件（规则、内容、常数、NLU 夹具、P1 插件与记忆策略、金样文件）的字节摘要，锁在 `scripts/p1-frozen-rules.lock.json`；
   - 金样回放测试 `packages/domain/src/prologue-v1-frozen-replay.test.ts`：6 条旅程、24 步的决策、事件与存档逐字节不变。
2. CI：`pnpm test` 第一步运行 `node scripts/p1-frozen-rules.mjs --check`；金样回放在 domain 的 vitest 中运行。冻结文件有任何改动，CI 失败。
3. 共享契约与回合管线可以继续演进。演进后语义摘要会移动，用 `node scripts/p1-frozen-rules.mjs --repin "原因"` 重新固定：脚本先确认冻结文件与锁一致，再写入新值，并把旧值、新值、提交和原因追加到 [`p1-repin-log.md`](../execution/JX-VISION-02/p1-repin-log.md)。同一次 CI 中金样回放与 `tests/e2e/p1-authenticated-candidate.cjs` 必须通过。
4. 规则修复（缺陷 1、2、5、6）写进新规则版本（暂名 `prologue-v1.1`），使用新文件，不改冻结文件。旧存档按 v1 回放，新存档用新版本创建；不回填旧存档。
5. `--write-lock` 只在引入冻结或新增一个冻结版本时使用，不得用来接受对 `prologue-v1` 的修改。金样文件同理，只由显式的 `P1_GOLDEN_WRITE=1` 本地运行生成，CI 从不写入。

## 后果

- 线上 preview-1 的 API 宿主上有一份批准文件，要求 `approvedBy` 同时含 LYL 与 Bird，并且 `semanticSha256` 等于代码中的固定值。重新固定之后，**部署新 API 前必须在宿主上安装新的批准文件**。双签已于 2026-11-26 取消，`preview-release-runtime.ts` 的批准格式需要改为新范围（只要求作者授权记录），这项改动与宿主上的文件安装都要由有服务器权限的人执行。不能伪造 Bird 的批准。
- 本 ADR 引入时，`--semantic` 实测得到的值与钉住的 `sha256:8b938f92…422006` 一致，冻结文件摘要 `sha256:6bc7b69d…7eab1`。
