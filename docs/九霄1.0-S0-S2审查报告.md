## 3. 已修复的缺陷

### 3.1 导入数据没有运行时校验

原实现对任意 JSON 对象都创建存档，`{}` 或无关对象也可能被当作有效旧档。现在由 `packages/contracts/src/legacy-save.ts` 校验已记录的旧 JSON 形状；空对象、数组和无识别字段的对象会被拒绝。

### 3.2 旧消息对象被破坏

原实现使用 `messages.map(String)`，结构化消息会变成 `[object Object]`。现在保留消息对象本身，旧 `status`、`intel`、`memory` 等字段进入单独的 `legacySupplement`，不冒充权威世界状态。

### 3.3 非法 revision 可能写入 NaN

原实现对 `revision` 直接使用 `Number(...)`。现在所有 revision 通过安全的非负整数转换，非法值回退到 0。

### 3.4 浏览器存储失败会导致未处理异常

原实现的 `localStorage.setItem` 没有错误边界。现在草稿和存档写入均返回成功/失败状态，容量不足或存储被禁用时保留页面并显示可恢复错误。

### 3.5 随机 ID 没有回退路径

原实现直接调用 `crypto.randomUUID()`。现在优先使用 UUID，运行环境没有该 API 时使用本地唯一回退值；该回退只用于本地临时存档，不能替代服务端 ID。

### 3.6 构建 manifest 固定写成 S1

原实现无论当前阶段都写入 `stage: S1`。现在构建命令显式使用 `--stage S2`，脚本也拒绝未知阶段，Web/API/迁移 schema 三份 manifest 的阶段和 commit 一致。

### 3.7 Web 源码和样式难以审查

原实现把主要页面压在单行文件中，导致错误边界、状态流和迁移逻辑难以复核。现在存储、旧档解析和页面入口分为 `storage.ts`、`legacy.ts`、`main.tsx`；样式也恢复为可审查的分段结构，并补充了通知和岗位字段样式。

## 4. 仍然阻断 S2/G1 的问题

这些不是通过改文案可以解决的缺口：

1. 方案要求旧 `localStorage` 原样备份后校验并写入 IndexedDB。当前浏览器实现仍把新局写在 `localStorage`，只对用户选择的文件做文本备份。
2. 方案要求 S2 恢复旧 AI 配置的完整字段、真实 Model ID 校验、连接测试和调用记录。当前只恢复了五个岗位的 Model ID 会话字段，并明确标注其余能力未迁移。
3. 方案要求世界设定搜索、来源标识和从游戏阅读层返回原位置。当前 `/world` 只是安全的待审核占位页。
4. 方案要求导入预览、重复 ID、超限、中断恢复和跨标签竞争测试。当前只实现格式拒绝、文件大小上限、原文备份和同 ID 替换。
5. S0 对照表仍有随机开局、TXT 补充资料、面板恢复、pending 回合、旧单 AI 配置等条目未逐项迁移或裁定。

在这些项目完成并由作者 A/B 复核前，不能把 PR 可合并、CI 通过或本地 E2E 通过称为 G1 通过。

## 6. 审查结论

当前代码比上一版可靠，但它仍是 **S2 的局部工程切片**。最严重的风险已从“错误导入和静默破坏数据”降为“方案要求的能力尚未实现”。下一步应优先完成 IndexedDB 迁移与完整旧档字段矩阵，再实现 AI 设置的完整旧能力；在此之前不应进入公测发布或宣称 G1 通过。
