# 《九霄》1.0 S1 工程基线

> 2026-09-24 复核。本文描述当前代码能做什么及如何复核。S1 是工作区和共享契约，不是公测产品，也不代替 G1 的两作者验收。

## 交付边界

`apps/web` 是 React/TypeScript/Vite 工程预览，目前已有山门入口、`/lobby`、建角、游戏存档查看、世界占位页和五岗位 AI 设置。游戏规则未接入；页面不得把待处理行动显示成已结算剧情。旧单 HTML 留在 `outputs/` 供比对和迁移。`apps/api` 连接 PostgreSQL 并提供 `/health` liveness 与 `/ready` 数据库 readiness，但没有对外开放存档或认证接口。`packages/db` 的初始 Drizzle migration 已在本机开发数据库执行。`packages/domain` 对全部候选行动返回 `RULES_NOT_READY`；作者未签规则表前不会提交事件。

共享 `packages/contracts` 用 Zod 校验 `ActionIntent`、三态 `Decision`、`DomainEvent`、`SaveEnvelope`、世界最小状态和错误码。`schemaVersion`、Canon、规则、记忆策略与修订号分开记录。候选行动的载荷是接口草案；S3 必须用作者签署的玩法表审查其种类与字段。S1 不能从这些类型推断任何已经可玩的内容。

## 全新克隆复核

前提：Node 24、pnpm 11.19、Git。运行：

```powershell
pnpm install --frozen-lockfile --registry https://registry.npmjs.org
pnpm license:check
pnpm typecheck
pnpm test
pnpm build
pnpm test:integration
pnpm test:e2e
```

浏览器端 `pnpm dev:web`，API 端 `pnpm dev:api`。打开 `http://127.0.0.1:5173` 与 `http://127.0.0.1:8787/health`。`test:e2e` 在 390×844 和 1366×768 检查工程预览与 HTTP 健康端点；Windows 优先使用本机 Edge，CI 使用已安装的 Playwright Chromium。`pnpm build` 生成 Web、API 和迁移 schema 产物的同一 Git SHA 清单。构建产物在 `dist/`，不提交仓库。

`pnpm` 11 默认阻断依赖安装脚本。`pnpm-workspace.yaml` 只允许 esbuild 运行必要的二进制安装脚本；新增有构建脚本的依赖需单独审查。许可证检查当前只接受 MIT、Apache-2.0、BSD-3-Clause、ISC、MPL-2.0；这是自动筛查，不代替发行时的署名与法律审查。

## 本地容器

`.env` 是 Git 忽略的本机文件，首次启动生成随机数据库密码；不要把它复制到仓库。`docker compose up --build -d` 启动 PostgreSQL、Mailpit、迁移 job 和 API。数据库映射本机 `127.0.0.1:5433`，Mailpit 网页 `127.0.0.1:8025`、SMTP `127.0.0.1:1025`，API `127.0.0.1:8787`。数据库健康后运行初始 Drizzle migration；迁移成功后 API 才启动。`/health` 只代表进程可用，`/ready` 执行 `SELECT 1` 后才报告数据库就绪。

2026-09-24 本机实际验证：Docker Desktop Linux Engine 29.8.0、Compose 5.5.1；`db`、`mail`、`api` 均为 healthy，迁移 job 退出码为 0；`/health` 和 `/ready` 返回 200；PostgreSQL 可查询并含 `game_saves`、`turn_requests`、`turn_events` 三张业务表及 Drizzle 迁移记录；Mailpit 网页返回 200 且 SMTP 端口可连接。该结果只证明本机开发服务链，不证明 SMTP 已由业务 API 使用，也不证明账号、云存档接口或生产部署可用。

## S1 验证记录与后续门禁

| 检查 | 当前记录 | 局限 |
| --- | --- | --- |
| `pnpm install` | 固定依赖与锁文件安装完成 | 只测本机与当前镜像源 |
| `pnpm typecheck` | 五个工作区项目通过 | 不证明运行时规则 |
| `pnpm test` | 旧原型 28 核心 + 54 AI 回归；新契约/域/API 单测 | 旧回归含合成与内嵌材料，不代替真机 |
| `pnpm build` | Web、API、schema 可构建 | 发布流水线与部署尚未演练 |
| `pnpm test:integration` | `/health`、`/ready` 成功/失败与未开放路由检查通过 | API 测试使用注入的 readiness adapter；真实容器链另作本机验收，无账号测试 |
| `pnpm test:e2e` | 手机/桌面工程预览与 API 通过 | 无真实玩家任务 |
| `pnpm license:check` | 当前 80 个条目属于五类已列许可证 | 发行署名仍待检查 |
| Docker Compose | `config --quiet`、构建及本机服务启动通过 | 只限本机开发配置；无生产容灾/公网测试 |
| GitHub CI | `efb7e24` 的 `verify` job 通过 | 不含数据库容器与玩家流程验收 |

G1 前半仍需作者 B 在全新克隆与 CI 复核，并由作者 A 确认预览中没有对玩家误导的入口。S2 才迁入首页、建角、世界、游戏和 AI 设置；S0 的旧功能对照表是逐项验收清单。旧版 `build_v1.py` 与 `build_worldbook_ui.py` 继续保留，不再是新版构建入口。
