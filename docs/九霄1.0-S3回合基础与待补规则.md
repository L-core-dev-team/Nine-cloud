## S3 已开始的代码工作

| 能力 | 当前实现 | 边界 |
| --- | --- | --- |
| 回执契约 | `packages/contracts/src/turn.ts` 记录幂等键、存档 ID、带算法版本的请求指纹、决策和结果修订号；候选快照单独返回 | 不在每个回执中重复存储整份快照，也不存原始玩家输入或密钥；SHA-256 指纹仍可能泄漏低熵文本的猜测信息，持久化前需在 API 层评估带密钥摘要与密钥轮换方案 |
| 回合准备 | `packages/domain/src/event-log.ts` 校验存档/行动并先确认两者存档 ID 一致，再查旧回执、处理旧修订冲突、校验规则事件并生成候选快照 | 只计算候选，不写数据库；调用方将来必须在一个事务中写请求回执、事件和新快照 |
| 事件回放 | `replayEvents` 按输入顺序回放；一回合内多个事件共用同一修订区间；拒绝跳版、错档、重复事件 ID 和乱序链 | reducer 必须由该存档对应的签署规则版本提供。没有 reducer 时不能构造状态 |
| 单事件投影边界 | `project` 接受显式 reducer；未提供时继续报错 | 当前无生产事件 reducer |
| 测试 | `packages/domain/src/event-log.test.ts` 使用明确标记的合成事件验证事务边界、重复请求、版本冲突、校验及重放 | 测试 reducer 仅检验基础设施，不是游戏玩法或 Canon 的证据 |

生产 `evaluate` 仍对所有行动返回 `RULES_NOT_READY`。这不是可玩回合；这是防止未批准规则写入世界状态的保护。

### 2026-09-27 幂等边界校验

重复请求仍会在旧修订冲突前取回第一次回执，但必须先确认本次提供的存档快照属于请求指定的存档；跨存档快照不能借匹配的旧回执得到“重复成功”。回归测试仅使用合成回合，不改变签署规则门禁。

### 2026-09-25 增量防护

事件回放现在拒绝与存档 `ruleVersion` 不同的事件，并在每次投影前后校验负载及状态是可安全序列化的普通 JSON 数据。NaN、循环对象或错误规则版本不能作为合法回放结果。这些检查只保护基础设施；合成测试事件仍不构成玩法规则。后续行动实现、签稿及作者操作见 [S0–S4 缺口与 Bird 交接清单](九霄1.0-S0-S4缺口与Bird交接清单.md)。

## 进入完整玩法前需要签署的输入

由作者 A 提供规则表并由 A/B 按[双作者分工与交付门禁](九霄1.0双作者分工与交付门禁.md)复核：

1. 移动、修炼、获得/使用物品、交谈、战斗、任务各自的前置条件、成本、成功结果、失败结果、占用时间及可恢复方式。
2. 九境、五域的正式名称、关系、通达条件、限制与逐格代表路径。没有正式命名或机制的格子要标待议，不由工程侧补写。
3. 人物、背包、地图、任务和时间状态的字段语义，以及哪些字段只允许规则事务更改。
4. 事件类型与负载、规则版本升级方式、旧事件重放兼容策略、存档快照频率和回滚/分支语义。
5. 代表性成功、失败、恢复和边界样例；每类行动至少有可判定结果，且不得依靠叙述模型直接改状态。

输入未齐时，可以继续完成通用事务、测试工具和契约审查；不得将合成规则放进默认运行链，也不得声称序章可玩。

## S3 退出条件

- 作者签署的玩法规则表覆盖六类行动、九境五域及代表性失败恢复样例。
- 游客和 API 使用同一领域包；规则版本与存档版本不匹配时拒绝静默写入。
- 规则事件事务原子提交；同一幂等键不重复推进状态、消耗物品或世界时间。
- 日志从约定快照连续重放得到同一状态；损坏日志明确报错且不覆盖原存档。
- 成功、失败、澄清、重试、重复提交和冲突都有自动化测试；100 回合长局测试通过后再进入 S3 内部验收。
- A 验玩法与 Canon，B 验状态不变量和工程证据。未签署前只能报告“基础设施实现”或“进行中”。
