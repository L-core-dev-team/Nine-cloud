# 九霄 1.0 S2：导航、建角与本地迁移阶段记录

**状态：S2 导航与功能承载层有新实现；G1 未签收，不能称 S2 完成**
**复审分支：`codex/jiuxiao-s0-s2-audit`**
**更新日期：2026-09-25**

## 1. 阶段目标

S2 只处理玩家从首页到游戏入口的连续路径。它不提前伪造 S3 的规则结算，也不把未审核资料发布为世界书。

本阶段交付四件可复现的事情：

1. 山门首屏以“九霄”为主，只提供“进入世界”；进入后在 `/lobby` 选择续档、新开、作品简介、世界设定、AI 设置或跳过 AI 配置。
2. 建角页承载旧原型中的十个字段，并保存未完成草稿。
3. 新建角色后生成版本化本地存档，刷新页面后仍可继续进入同一局。
4. 菜单提供原文备份、旧档导入和 JSON 导出，失败时不改写已有存档；AI 与世界页关闭返回之前的山门或当前存档。
5. `/game/:id` 提供旧消息文本呈现、角色/情报/记忆面板入口、存档工具与待处理行动输入。行动只存为草稿，不结算状态。

## 3. 导航契约

| 路径 | 唯一职责 | 当前行为 |
| --- | --- | --- |
| `/` | 山门入口 | 突出“九霄”，左上角为短句；点击“进入世界”才进入任务选择 |
| `/lobby` | 选择去处 | 有档时显示继续游玩；可新开、读简介、世界设定、AI 设置；跳过设置回最近档或直接建角 |
| `/intro` | 阅读旧版作品简介 | 照录旧版简介，创建角色/世界资料分别进入对应页面 |
| `/new` | 完成建角 | 显示十个原型字段；草稿写入浏览器本地；最多三项天赋 |
| `/world` | 阅读审核状态 | 明确显示 Canon 尚未发布，不展示待核 OCR；现可将 TXT 附加到当前存档，不等于世界书导入/索引 |
| `/game/:id` | 阅读旧消息、查看存档和写下行动意图 | 显示最近可解析文字；面板读历史字段；提供设定、导出与补充资料入口；行动不推进回合 |
| `/settings/ai` | 配置 AI 候选值 | 五岗位、青鸟候选、协议适配、同源迁移和脱敏日志弹窗；实际回合调度未接 |

入口分为两步：山门视觉页负责进入；山门内的任务页负责续档、开局和查阅设置。品牌短句和“九霄”不再重复。晴昼/夜色偏好存于本机浏览器，不进入存档。山门图在所有路由作为遮罩底图。书法字用于标题，阅读和参数使用衬线正文保持辨识。沉浸按钮使用 CSS 双层描边；不是原生光照。

## 4. 本地迁移行为

### 4.1 导入前备份

用户选择 `.json`、`.txt` 或 `.html` 文件后，浏览器先下载一份原文备份，命名为 `九霄-导入前原文备份-时间戳.txt`。备份发生在解析之前。解析失败时，现有 `localStorage` 存档不改写。

### 4.2 当前可识别格式

- 本项目导出的 `{ format: "JIUXIAO_SAVE", version: 1, save: ... }` JSON；对象必须含可识别旧档字段。
- S0 记录的原型 JSON：支持 `id`、`name`、`turn`、`world.location`、`player`、`messages` 等常见字段映射。
- 纯文本或 HTML：去除脚本、样式和标签后保留为一条历史消息，角色字段使用文件名和默认地域。页面在读取文件前拒绝超过 20 MiB 的文件；底层 `parseLegacySave` 也会依据 `File.size` 再次拒绝超限输入，避免其他调用路径绕过限制。解析器边界由 Web 单测覆盖，页面预读拒绝由 E2E 覆盖。该路径只保证原文保留，不宣称恢复旧版本全部语义。

下载 JSON 存档时，导出器会递归脱敏结构化的 API Key、鉴权头和访问令牌字段；普通世界、人物、记忆字段仍按原样写入，原有 `JIUXIAO_SAVE` v1 包格式保持可导入。v1 存档重新导入时保留待处理行动队列和已有历史资料；首次归档后重复往返不会继续嵌套整份存档。导入仍将规则与 Canon 版本标记为未验证，不据文件自述授予权威状态。本地 `legacyArchive` 与导入前原文字节备份不被改写；原文备份因此仍可能含原文件自带的密钥，不能当作脱敏导出文件分享。模拟浏览器 E2E 已覆盖旧档中顶层及嵌套 API Key 的导出脱敏和普通字段保留。

### 4.3 明确未完成项

本阶段保留 `localStorage` 作为兼容来源，并将存档写入 IndexedDB v2。检测到旧 `jiuxiao_v1_library` 时，用户点击按钮后先下载原文备份，再通过校验迁移，旧键不会删除。JSON 导入会在预览中列出全部顶层字段；真实私档样本已有隔离 E2E 证据，证明备份逐字节一致、迁移 payload 深度相等。跨标签同档冲突现可选择载入最新版或另存分支；E2E 验证两个标签页的待处理行动都没有被静默覆盖。模拟“IndexedDB 已写入、localStorage 镜像未写回”的恢复时序后，刷新可从 IndexedDB 重建镜像。本地存档改名和确认删除已实现，并有模拟移动端/桌面端 E2E 覆盖；云端 `expectedRevision` 和跨设备同步仍未实现。

AI 设置含五个青鸟档位、五岗位参数、多种协议适配器、模型目录、调用记录弹窗和旧配置来源提示。调用日志按钮不再滚动到迁移区；关闭配置返回进入前路由。旧配置仅检查同源 sessionStorage，无法从 file:// 页面自动读取；JSON 存档不含 API 配置。各协议只有有限的探测实现，尚不能称支持所有服务商 API 变体；真实连接、账号权限、费用与游戏调度未验证。

游戏页现在呈现本地存档中最近 80 条可读文字、状态工具入口和本地行动输入。“角色状态、综合情报、星记忆”只保留一组入口；展开内容时不再重复显示同名大标题。行动意图按存档排队，输入草稿按标签页保存，刷新后仍能恢复。它记录的仍是“待规则处理”文本，不等同于可玩的叙事回合。旧档非文本消息会保留但不会强制序列化到阅读栏。详细映射见 [旧功能对照与存档样本](九霄1.0旧功能对照与存档样本.md)。

同理，导入后的状态统一标为 `pending_rules`。它不会直接写入权威世界事实，也不会触发模型调用。

## 6. 阶段门禁

S2 的工程证据已经形成，但 G1 仍不能标记为公开通过。原因是：

1. 真实样本只覆盖 LYL 提供的一个 JSON 导出；损坏档、超限、配额耗尽和所有强制关闭时机尚未覆盖。
2. 本地跨标签同档冲突及 IndexedDB 镜像恢复有自动化证据；旧 HTML 的全部行为仍未迁移，完整管理与云端 `expectedRevision` 也未实现。
3. `/world` 有 7 条审核地理条目的搜索和来源说明。初代世界书副本自述“未入库”，其原图批次数与待办中 182 条 OCR 的对应关系未核清；完整条目审核和游戏内阅读层尚未完成。
4. AI 已有本地设置界面，但真实 Model ID 校验、用户授权后的真实 API 测试与各服务商兼容仍需单独验收。
5. Docker/WSL Compose 本轮重新构建并通过本地数据库、迁移、API readiness 与 Mailpit 检查。本地容器通过不代表生产环境或认证/存档 API 已通过。

因此本次新增的界面与本地承载层仍不能关闭 G1。LYL 已确认功能保留方向；其余旧功能按矩阵继续迁移。Bird 提供 OCR 原图后再审核 Canon；真实设备任务在规则驱动的游戏链可测后执行，不将模拟视口冒充设备验收。当前五岗位 API 也未做真实模型调用。
