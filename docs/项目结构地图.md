# 《九霄》项目结构地图

**用途：** 说明 1.0 当前代码、旧原型、文档、测试和本地资料各自放在哪里。它只描述仓库结构，不把目录存在误写成功能已经验收。

## 从哪里开始

| 需要做什么 | 入口 |
| --- | --- |
| 查看当前阶段结论、已销账缺陷和仍未关闭事项 | [S0–S7 阶段缺口与人工交接清单](九霄1.0阶段缺口与人工交接清单-2026-09-29.md) |
| 了解代码目录和模块责任 | 本文件 |
| 启动 Web 预览 | `pnpm dev:web`，打开 `http://127.0.0.1:5173` |
| 启动本地 API、数据库和 Mailpit | `docker compose up --build -d`；命令和服务边界见[本地服务链配置与验收](本地服务链配置与验收.md) |
| 运行代码质量检查 | `pnpm typecheck`、`pnpm test`、`pnpm build`、`pnpm test:integration`、`pnpm test:e2e` |
| 查找历史原型或对照旧行为 | `outputs/`、`work/`；执行前先读各自的 `README.md` |

全新克隆的 Node、pnpm 和测试库要求以根目录 `README.md` 及当前 CI 为准。`pnpm test:integration` 需要单独、可丢弃的 PostgreSQL 测试库；不要把开发库或真实用户数据作为测试目标。

## 仓库目录

```text
.
├── apps/                  可运行应用：Web 与 API
├── packages/              Web/API 共用的契约、领域、内容与数据库模块
├── docs/                  当前规格、阶段证据、历史审计和决策记录
├── scripts/               构建、内容检查、迁移审计和授权清单工具
├── tests/                 浏览器端到端测试与合成旧档样本
├── work/                  旧 HTML 原型源码、构建/维护脚本与迁移对照材料
├── outputs/               已导出的旧原型和历史交付物
├── .github/               CI 工作流和仓库配置
├── docker-compose.yml     本机 PostgreSQL、迁移、API 与 Mailpit 服务定义
├── package.json           pnpm 工作区命令入口
├── pnpm-workspace.yaml    apps/* 与 packages/* 工作区边界
├── pnpm-lock.yaml         已锁定依赖版本
├── .env.example           本地环境变量模板
└── .env                   仅本机使用的密钥和地址；不得提交
```

`node_modules/`、`dist/`、`test-results/` 是本机构建或测试产物，不是产品源码。不得手工编辑生成文件来替代上游源文件。

## 应用与共享包

| 路径 | 主责与主要入口 | 边界 |
| --- | --- | --- |
| `apps/web/` | React + TypeScript + Vite 的玩家端工程预览。`src/main.tsx` 组装页面和导航；`src/style.css` 管理全局样式；`src/storage.ts`、`src/idb.ts`、`src/export-save.ts` 处理本地存档；`src/ai-settings.tsx` 与相邻 AI 模块管理 BYOK 配置；`src/scene.tsx`、`src/scenes/`、`src/routes/GraphicsSettings.tsx` 管理场景与画质入口。 | 页面存在不等于所有旧功能已经等价迁移；规则未签时游戏行动不结算。浏览器中的 API Key 不会因此变成服务端保险库。 |
| `apps/api/` | Hono/Node 服务。`src/index.ts` 是进程入口，`src/app.ts` 组装应用；`src/routes/` 放 HTTP 路由；`src/services/` 放云档、账本与 NPC 记忆事务逻辑。 | PR #33 候选包含 auth/turns/saves 路由；认证默认关闭，权威回合仍需已签规则。不是生产上线证明。 |
| `packages/contracts/` | Zod 运行时校验和前后端共享的行动、事件、存档、世界状态与错误契约。 | 契约描述允许传输的数据形状，不自行批准任何玩法结果。 |
| `packages/domain/` | 确定性规则入口、事件日志、状态投影、回放与记忆策略。 | 规则由已签署的游戏规格决定；未签的行动必须 fail closed，模型不能直接写入世界事实。 |
| `packages/content/` | 受审核内容、Canon 发布投影和固定场景清单。`canon.registry.json` 保存来源/审核记录；`canon-runtime.json` 是面向玩家阅读器的白名单运行数据；`src/scenes/manifest.ts` 保存受控场景 ID。 | 来源登记、草稿索引和公开运行数据是不同层。只有明确批准并由构建脚本生成的数据进入玩家包。 |
| `packages/db/` | Drizzle 数据库 schema、配置及顺序迁移，目录为 `src/` 与 `drizzle/`。 | 本地表和迁移成功不等于账号、在线接口或生产部署存在。迁移须可复跑、可审查；不要手改已应用迁移。 |

## 权威数据流

```text
玩家输入
  → Web 形成 ActionIntent
  → contracts 校验
  → domain 依据已签规则接受或拒绝
  → DomainEvent
  → 状态投影 / 事件日志 / 持久化
  → 页面呈现结果
```

AI 只能提供剧情文本或待审建议，不能越过规则层直接写角色属性、物品、NPC 记忆或世界 Canon。候选邮箱认证由服务端 cookie 确认主体；手动客户端备份使用 local-untrusted-v1，不能作为权威规则状态，也不是自动双向同步。生产生命周期仍在 G-06。

## 工具、测试和旧原型

| 路径 | 用途 | 维护规则 |
| --- | --- | --- |
| `scripts/build/`、`scripts/build-canon-runtime.mjs` | 生成构建清单和 Canon 公开运行投影 | 用 `--check` 检查源与产物一致；不要绕过白名单复制来源档案。 |
| `scripts/audit/`、`scripts/*worldbook*` | 依赖许可、旧功能盘点、世界书索引和内容审核辅助 | 私有原图审阅脚本需要用户指定的私有目录；不能对缺失素材报告“已审核”。 |
| `tests/e2e/` | Playwright 浏览器任务回归，截图写入忽略的 `test-results/e2e/` | 截图和日志不能覆盖 `docs/audit/` 中的受审材料。 |
| `tests/fixtures/` | 可提交的合成旧档和测试样本 | 不放真实用户存档、API 凭据或未审核原图。 |
| `work/` | 旧单 HTML 的源码、构建脚本、资源及兼容回归 | 保留为历史行为与迁移证据。不得为目录美观擅自移动或批量重写旧原型。 |
| `outputs/` | 已生成的原型 HTML、恢复指南及历史交付物 | 看作可比对的历史产物；需要更新时从源和脚本重新生成，并对照哈希。 |
| `docs/` | 设计方案、阶段记录、ADR、来源说明和交接材料 | 当前状态只以最新阶段缺口清单和当前代码/CI证据为准；有日期的报告保留为历史快照。 |

## 语言和新增技术的边界

当前产品主线是 TypeScript/React 与 Node/Hono；PostgreSQL 使用 SQL/Drizzle；CSS、HTML、JSON、YAML 和 Markdown 承担 Web、配置与文档工作；Python/JavaScript 脚本处理离线素材和审计。旧 HTML 是迁移基线，不是新版应用入口。不要为了语言统计而另加 Go、Rust、CUDA 或第二套前端框架。新技术先用 ADR 说明要解决的实测问题、基线、量化收益、依赖/许可证、安全面、回退路径和责任人。

## 本地私有文件

`.env`、真实存档、服务商密钥、调用记录和未审核世界书原图均不进入 Git。`九霄素材-水墨古风/` 是用户提供的本地素材目录；除明确安排的素材审核/接入任务外，不由目录整理或通用脚本批量重命名、移动或提交。Git 工作树显示该目录未跟踪时，不得使用 `git add -A` 把它带入提交。

目录用途或阶段状态有变更时，更新本地图和对应模块 README；不要再在多份阶段报告中维护互相独立的“当前缺口”副本。
