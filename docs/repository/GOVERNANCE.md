# 仓库治理规则（整理候选）

## 文档权威与职责

- 根 README 只回答产品、快速入口与贡献；AGENTS 只给导航、通用操作与真实边界；Claude 项目指令由正在进行的 VISION 02 分支维护，本轮不新增竞争 CLAUDE.md 或改动 DESIGN/PRODUCT。未来在协调合并后令 Claude 入口引用共同导航，专题 Skill 按需读。
- docs/README 是唯一通用文档入口。STATUS 是状态/证据路由，不能取代运行配置或审批。架构地图只记录模块职责。专题由原有业务文档、源代码、签署或实际回执维护。
- 文件状态使用 ACTIVE_GUIDE、DECISION（核对是否生效）、DRAFT、EVIDENCE、HISTORICAL、GENERATED、UNKNOWN；状态与日期/适用 SHA/来源同时维护。历史签署原文不改写，发现过时结论增加现行索引或纠正链接。
- 不把所有 MD、实验输出、旧任务书加载进 AI 默认上下文。路径/专题规则放相应模块；根说明保持短。新规范必须写清适用范围、反例、证据、维护人/责任角色；避免同时维护多个相同事实副本。
- 文档整理不改变设计艺术自由、玩法、技术选型或作者裁决；旧制度冲突记录待协调，不替正在工作的 Claude 作决定。

## 分支生命周期

- main 为默认集成线；feat/fix/docs/chore 等短期分支以 PR 为交付；archive/ 只保存经过确认的历史基线。已存在 codex/、shuilongyin/、claude/ 命名不强行改名。
- 所有 OPEN PR 的 head/base、正在进行的会话、发布/回滚引用、未知归属一律 HOLD。不能以时间久、名字像历史、内容相同或 PR 已合并单独作为删除依据。
- 清理前核对 head SHA、目标 main 祖先关系或 squash/rebase 内容等价、依赖 PR、实际发布/回滚、作者是否仍使用。确认保留策略与可恢复引用后再删除；未合并独有工作保留原样或经拥有者批准归档。
- 不 force push，不改 Git 历史，不替他人关闭 PR，不自动删除分支。本轮只新增整理分支与 Draft PR。

## 资产/证据

- 生成构建产物优先 CI artifacts/明确版本 Release；可复现实验保留源码、配置、种子、摘要、关键证据、校验和。大型原始资产可评估 Git LFS 或受权限管理的对象存储，必须核对额度、许可、生产构建可取回性。
- 源码、真实运行资产、授权审批、迁移、黄金样本、测试夹具、引用对象与历史证据有不同保留期限。目录名不是保留判据。
- 不公开真实密钥、用户存档、未授权图片、私有作者材料；已经存在的内容需另行权限/隐私审计。禁止以清理名义重写历史或删除唯一证据。

## 验收

每次结构 PR 提交基线、文件旧新路径映射、链接与构建依赖核对、实际测试状态、回滚方法。按 [MIGRATION](MIGRATION.md) 执行。未跑的命令不可写 PASS。
