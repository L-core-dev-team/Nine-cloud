## 1. 复核边界与结论

本轮从合并后的 `main` 建立独立分支。复核覆盖跟踪文件清单、主要工作区、阶段方案、应用构建与测试入口、CI、数据库测试边界、旧版迁移和世界书审核门禁。对 API/数据库、迁移、页面路由、场景回退和旧档恢复等高风险路径结合代码与自动化证据核对。

这不等于已经逐字人工验证 753 个文件中的每条旧业务分支，也不构成上线安全认证。图片和视频的权利、原作者意图、真机性能、外部模型服务、正式邮件、支付和法律意见无法由静态检查替代。以下结论只陈述可复现证据；未验证项继续列为缺口。

当前产品仍是私有工程预览。已有页面、数据库结构和服务层不等于已开放玩家服务。`ActionIntent → 规则 → DomainEvent → 状态投影`仍是权威边界；未签署的玩法规则继续拒绝结算。

## 2. 本轮自行修复

### 2.1 数据库集成测试不得静默跳过

此前 PostgreSQL 专项在 `TEST_DATABASE_URL` 缺失时会被 Vitest 跳过。CI 仍可能显示成功，造成“已测试”与“实际未跑”的证据错位。本轮做了以下修改：

- `.github/workflows/ci.yml` 使用一次性 PostgreSQL 17 service container，等待健康检查后先运行迁移，再运行测试。
- `apps/api/package.json` 的 `test:integration` 和 `test:s6:integration` 都执行 URL 前置检查；`test` 也运行守卫测试。
- `scripts/assert-test-database.mjs` 不输出 URL、用户名或密码；拒绝缺省 URL、非 PostgreSQL 协议、空数据库名，以及不以 `jiuxiao_test` 开头的库名。
- `scripts/assert-test-database.test.mjs` 覆盖缺失、错误协议、无数据库名、非测试库名和有效测试 URL，并验证凭据不出现在诊断中。
- 本地服务链文档改为随机命名的一次性测试数据库，测试后删除该库，并恢复 PowerShell 原有环境变量。禁止对生产、共享或保留玩家数据的开发库运行集成测试。

此改动把“测试命令可以运行”收紧为“没有独立测试库便失败”。CI 远端检查须在本分支推送后再确认；本地通过不能代替 GitHub Actions 结果。

### 2.2 E2E 不再覆盖审查截图

`tests/e2e/foundation.cjs` 以前把新截图写进 `docs/audit/`，会覆盖被跟踪的设计审查截图，造成回归证据被运行测试改写。现在写入忽略目录 `test-results/e2e/`。测试运行不应再改变审查基线。

### 2.3 文档状态与代码对齐

- `README.md` 过去称当前工程尚无 IndexedDB、AI 设置和游戏页面，与现有代码不符。现已说明这些页面和本地能力已存在，同时明确规则结算、认证与生产云同步仍未完成。
- `docs/项目现状与技术全景.md` 保留为 2026-09-22 历史快照，不再被误读为当前状态。
- `docs/README.md` 和阶段执行清单指向本报告。
- `docs/adr/0001-语言与运行时边界.md` 新增本轮技术清单审查，说明“可用工具”与“项目必须引入的技术”不是一回事。

## 5. 第二点：技术清单的取舍与语言占比

用户给出的语言、范式、架构、算法、类型、工具和交叉领域清单非常广。它适合作为检索范围，不适合作为技术任务清单。把每个名词都引进仓库会增加构建矩阵、运行时、依赖更新、安全边界和双人维护成本，却不自动提升可玩性或质量。

### 5.1 当前实际分工

| 技术 | 当前用途 | 采用理由与限制 |
| --- | --- | --- |
| TypeScript + React | 主要 Web 页面、状态与交互；共享合同和确定性领域逻辑 | 与浏览器和现有团队技能匹配。权威规则只有在作者签署后才能启用。 |
| Node.js + Hono | Web API、健康/就绪端点、待认证的云存档服务边界 | 同一语言覆盖 Web 工具链，减少两人团队跨栈维护；生产身份/云档路由尚未开放。 |
| PostgreSQL + SQL/PLpgSQL | 持久结构、迁移、owner 隔离、CAS 与账本约束 | 关系约束和事务适用于存档版本与账本；不代表账号/付费已经上线。 |
| JavaScript/Node 脚本 | 构建、审计、浏览器 E2E、迁移辅助 | 属于工程自动化，不作为玩家权威状态实现。 |
| Python | 离线素材派生和旧版辅助 | 适用于离线批处理；不得绕过内容审核或更改玩家权威状态。 |
| CSS/HTML/JSON/YAML/Markdown | 页面结构、样式、数据/配置、工作流和记录 | 属于现有 Web 工程必要构件，不应被误算成多套应用技术栈。 |
| WebGL 2/1、Canvas 2D | 场景氛围、雾、水光和粒子；能力回退 | 不是路径追踪、WebGI、神经渲染、超分或 120 FPS 实测承诺。 |

### 5.2 GitHub 显示近乎全是 HTML 的真实原因

已读取 GitHub Languages API。本次远端统计是：HTML `93,461,494` 字节（约 `98.996%`）、TypeScript `383,392` 字节、JavaScript `278,491` 字节、CSS `165,233` 字节、Python `112,690` 字节，其余为少量 PowerShell、PLpgSQL 和 Dockerfile。

本地 753 个跟踪文件中有 15 个 `.html`，合计 `93,461,494` 字节。多个旧版导出 HTML 单文件约 11.9 MB；世界书基线和玻璃效果旧页面也保留为迁移依据。当前 `apps/web/src/`、`apps/api/src/` 与 `packages/` 中存在 TypeScript 实际源码。GitHub 的语言比例按被跟踪文件统计，不表达新版界面的运行入口，也不反映“当前开发是不是 React”。

因此“突破 HTML 比例”不应靠额外塞入 Go、Rust、CUDA、Java 或其他语言来改图表。正确路线是继续在 TS/React 主线交付 S2–S6；旧 HTML 作为可核对迁移证据保留。只有当旧样本已由自动化矩阵覆盖、保留价值经过双方确认后，才讨论归档迁移或调整跟踪方式。不要把源文件误标为生成物来人为美化统计。

### 5.3 引入新技术的准入门槛

任何新语言、框架、数据库、渲染后端、神经网络或分布式模式，先写出：

1. 要解决的具体玩家任务或工程瓶颈，以及当前失败证据。
2. 同设备、同输入、同画质/正确性门槛下的现有实现基线。
3. 可重复的量化目标，如 p95 延迟、帧时间、内存、包体、构建时长或错误率。
4. 替代方案、依赖与许可证、安全面、部署路径、责任人和撤回办法。
5. ADR 与验收测试；收益不超过长期维护成本时，不合入主线。

眼下没有性能数据支持 CUDA、WebGPU 光追或神经渲染进入生产路径。浏览器 GPU 支持、功耗/温升、移动端显存、浏览器标签页节流和降级路径都未完成真机测量。可另建隔离基准原型，不得因此宣称已支持游戏级光追或 120 帧。
