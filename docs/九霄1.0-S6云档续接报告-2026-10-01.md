# S6 云档续接工程报告

本轮从 PR #32 的 `fdf1e12` 新建 continuation 分支，不修改 main 或合作者的 PR #31。

## 已实现

- 生产 API 可选接入 PostgreSQL 邮箱验证码认证与可信会话 owner；默认关闭。验证码 HMAC、一次消费、五次猜测上限、每地址一分钟冷却/每小时六封、全站每小时六百封。会话只持久化随机 token 的 SHA-256；HttpOnly/SameSite=Strict，HTTPS 下 Secure；刷新原子替换旧 token，退出吊销。
- SMTP 只通过部署环境提供，生产要求 TLS，关闭附件文件/URL 访问和调试日志；异常不把 SMTP 密钥或底层连接详情返回前端。
- 新迁移 0003 只新增认证表；不会改写既有存档或世界书。Compose 注入可选配置，开发 Vite 代理 `/api` 到现有 API。
- 手机菜单与现有导航新增账号/云档入口：登录、刷新、退出、手动备份、分页查阅、恢复为本地新副本。
- 独立 IndexedDB 云队列按账号分区；上传前保存脱敏的待上传快照。断网、超时、未知结果保留队列；相同 mutation 重试确认已提交结果；CAS 冲突暂停并提供显式本地更新或云端另存副本。上传过程中新增的本地编辑不会被旧确认清掉。
- 每次云档访问附带预期账号，服务端仍只从可信 cookie 取 owner，并拒绝账号切换后的旧队列。该头不授予任何权限。
- 云端备份为 `local-untrusted-v1` 传输档，保留原始 LocalSave 内部结构与历史资料；不等同于规则批准的 DomainEvent 或权威游戏状态。传输 revision 与档内原始回合分开。
