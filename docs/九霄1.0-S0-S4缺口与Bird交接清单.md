## 二、Bird 世界书工作：已知事实、交付与操作

远端 [Bird 草稿 PR #12](https://github.com/L-core-dev-team/Nine-cloud/pull/12) 的头分支是 `codex/worldbook-author-20260925`，基分支是 `codex/jiuxiao-development-20260924`。其 PR 描述称：182 项旧 OCR 清单可映射为 179 张编号原图与 3 项排除内容；另有 24 张相关补图、7 处重复图 UUID 映射；原 120 整页漏收已写入私有修订候选；23 张至少局部目视核查；34 条新候选为 32 条 `pending_review`、2 条 `conflict`、0 条 `confirmed`。这些是 **PR 作者报告**，不是当前工作区的原图复核结果。`worldbook-private-review` 未进入此仓库；PR 仍为草稿，不可据其 `CLEAN` 合并状态发布 Canon。

Bird 在保管原图的私有机器上执行下列步骤。路径均由 Bird 自行选定，原图、逐图文字和私有审阅结果不得作为普通 PR 附件：

1. 固定输入版本。记录原图目录、旧 OCR 清单、原始拼接稿、修订候选稿的总数、SHA-256、生成日期和 Git 提交；将重复图 UUID 与排除项的理由写入私有登记。不要把“182 项”写成“182 张原图”。
2. 在 Bird 的工作分支使用现有脚本，依次运行：

   ```text
   node scripts/restore-worldbook-page-120.mjs <private-source-dir> <private-review-dir>
   node scripts/audit-worldbook-sources.mjs <private-source-dir> <private-review-dir> <private-revised-draft>
   node scripts/build-worldbook-review.mjs <private-review-dir> <private-source-dir>
   node scripts/check-worldbook-text-coverage.mjs <private-source-dir> <private-review-dir>
   node scripts/write-worldbook-author-handoff.mjs <private-review-dir>
   node scripts/test-worldbook-review.mjs <private-review-dir>
   ```

   每个脚本的输入须指向同一次冻结批次。保存退出码、覆盖率明细及生成清单的哈希。自动文字片段命中不能替代逐页目视核对。
3. 逐张目视对照原图与转录，先处理未目视的页面、片段覆盖低的页面、原 120 缺页与断句、来源别名，再处理普通条目。逐条标 `source-confirmed`、`context-restored` 或 `authorized-completion`；后两类要分别写恢复依据与 LYL 授权，不能冒称原图原文。保留无法辨认的位置、原字形和异文。
4. 将两个冲突单列交给 LYL：原 088 写“四大基础品阶”却列凡/黄/玄/地/天五阶；原 092“拜火圣教”与其他资料“圣火教”的关系未定。请附两个版本的原图 ID、页内位置与对游戏规则/名称的影响。LYL 可以选定、声明两者不同，或保持未决；未决条目不得发布。原稿中合体→化神等顺序也只能据原图和作者裁定处理，不套用常见修仙顺序。
5. 完成每一条拟发布 Canon 的条目 ID、标题、分类、正文、原图 ID、证据类别与版本。LYL 验设定语义，Bird 验来源和转录。两人分别审阅**完全相同的内容摘要**后给出批准时间；改一字或换原图需重新审批。`test-worldbook-review.mjs` 当前断言 0 条 confirmed；真实批准后应更新测试和预期，不能让这个断言永久阻断发布。
6. 从私有审核结果显式转换到新发布器输入。候选 JSON 形如 `{ "canonVersion": "<已定版本>", "candidates": [{ "id": "...", "title": "...", "category": "...", "body": "...", "sourceIds": ["..."], "evidence": ["source-confirmed"], "status": "approved", "reviews": [{ "reviewer": "LYL", "decision": "approved", "contentSha256": "<完整SHA-256>", "reviewedAt": "<ISO时间>" }, { "reviewer": "Bird", "decision": "approved", "contentSha256": "<相同摘要>", "reviewedAt": "<ISO时间>" }] }] }`；来源 JSON 为 `{ "sources": [{ "id": "...", "sha256": "<原图SHA-256>", "path": "<私有原图目录内相对路径>" }] }`。摘要须由 `digestCandidate` 对实际候选和已核原图哈希计算，不能手填猜测值。运行 `pnpm --filter @jiuxiao/content build` 后执行 `node scripts/audit/publish-approved-worldbook.mjs <候选JSON> <来源JSON> <私有原图目录> <输出JSON>`。没有两人批准、哈希不符或仍有待核标记，命令必须失败。发布产物还需人工抽查，再经独立 PR 接入玩家搜索；此命令本身不发布网站。

**Bird 交付给 LYL：** 私下提供逐图审阅清单与冲突证据、32 条候选的逐项意见、原 120 的完整/残缺边界、可公开 Canon 候选及来源哈希、命令/测试记录。GitHub 只上传脱敏脚本、可公开的已批准文本与审计摘要。先完成 PR #12 的审阅与基分支协调，再按依赖顺序接入本分支；不得把两个分支的源码未经检查直接覆盖。

## 三、必须由 LYL 作出的产品与内容决定

1. **Canon 裁定。** 逐条看 Bird 提供的原图/转录差异，明确上述两个冲突、原 120 断句和所有作者补全项。给出条目 ID、定稿文本、理由、来源与批准时间。对仍不确定的内容选择“暂不发布”即可；不要用沉默代表批准。
2. **玩法规则签稿。** 给六类行动（移动、修炼、获得/使用物品、交谈、战斗、任务）一张可执行表：意图字段、前置条件、消耗与时间、成功/失败事件、状态字段、恢复步骤、至少一正一反例。另给九境×五域的正式名称、通达条件、禁则和未定格标记。Bird 核对设定/剧情一致性；工程据签稿实现 reducer，不能让模型自由改写权威状态。
3. **G1 同版验收。** 等下述工程剩余行为迁移完成，LYL 和 Bird 在同一 Git SHA、同一构建 manifest 上分别走一遍首页→建角/续档→世界→AI 设置→导入/导出→故障恢复。对照 `九霄1.0旧功能对照与存档样本.md` 每行标通过、阻断或审定淘汰；记录浏览器、系统、日期、截图/日志、签收者。此前“保留旧功能”的决定只是范围确认，不能代替此验收。
4. **真实凭据与设备。** 由持有者在本机填 API Key 做逐岗位连接测试；不得上传 Key/响应正文。完整可玩链稳定后再做手机、平板、桌面设备/浏览器、弱动效、离线和性能验收。现阶段保留待办，不把模拟视口当真机通过。

## 四、仍属工程任务，不应转嫁给作者

- **S2/G1：** 旧版 `runTurn`、行动建议、GM 覆盖、记忆归档等行为的规则化迁移；更多旧档损坏、重复 ID、容量耗尽与意外中断矩阵；AI 各真实协议差异的可测适配。作者决定语义，工程负责代码及测试。
- **S3：** 收到签稿后实现六类行动的纯 reducer、失败条件、100 回合回放和游客/API 同规则测试。签稿前不把合成事件接入生产。
- **S4：** 将获批 Canon 接入版本化检索与来源页面；为旧七条做新审批补录；把 NPC 可见事件权限、两种记忆策略及叙事重试接到回合后流程。当前 `packages/domain/src/memory/` 只是原语，不是已运行的 NPC 系统。
- **后续 S6/S8：** 对象级鉴权、账号、云档冲突、真实回合 API、数据导出/删除与物理设备验收按原阶段推进。Docker 本机服务健康不等于这些业务已经存在。

## 五、合并与验收顺序

1. 先核对本分支 CI、测试和差异；Bird 的 PR #12 单独审阅，不因 GitHub 显示可自动合并就并入 `main`。
2. Bird 私有逐图审阅与 LYL 冲突裁定完成后，产生第一批双人签收的 Canon；发布器拒绝其余材料。该批可小，不必等待整本完成，但只能声称已批准的范围。
3. LYL 签署规则表后，工程接入真实结算与叙事；随后再做 G1/G2 同版本体验和可靠性验收。阶段状态以退出条件而非启动日期判断。
