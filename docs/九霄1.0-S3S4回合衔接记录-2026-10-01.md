# S3/S4 服务端回合与可见记忆衔接记录

本次只补既有契约之间的工程衔接，不制定六类玩法数值，不修改作者 Canon 或合作者设计文件。

## 已实现

- `ServerTurnService` 使用服务端提供的规则、Canon 和记忆策略版本；无规则包即返回 `rules_not_ready`。版本不匹配、其他账号/角色、客户端旧档备份均拒绝结算。
- 复用 `prepareTurn` 的确定性规则与指纹、`prepareNpcMemoryTurn` 的过滤后可见观察，以及原有 PostgreSQL 状态/事件/回执/记忆同事务提交。
- 增加 owner 过滤的持久化回执查询和 PostgreSQL 组合适配器。请求重试先核对指纹；旧快照与新记忆交错时先查询并发赢家回执，不对新记忆重复投影。
- 仅提交成功后按显式选项请求叙事；默认不发模型请求。模型只获得回执副本，不能反写状态、Canon 或记忆。叙事异常/超时保留已提交回执，显式重试不重复结算；超时发出 AbortSignal，即使适配器忽略取消，调用也能返回失败状态。
- 拒绝/澄清只返回规则决定，不建立权威状态变化。规则拒绝回执目前不落库；本次不宣称完整回合生命周期日志或生产岗位调度已经完成。

## 证据

9 项合成规则单测：无规则门禁、账号/旧档隔离、十次重试、十次并发、请求 ID 内容冲突、版本冲突、叙事故障/超时/取消、事务失败不调用叙事、模型不能改原回执。API 类型检查通过。

新增 2 项隔离 PostgreSQL 集成测试：十客户端并发只写一份状态/事件/回执/可见记忆；服务重新实例化后用原回执恢复叙事而不再次推进版本。已在 56d75a2 的 [CI run 36842673627](https://github.com/L-core-dev-team/Nine-cloud/actions/runs/36842673627) 全部通过，包括 2 项真实隔离 PostgreSQL 回合集成。本机无 PostgreSQL，没有本机数据库测试记录。最新 HTTP/取消改动仍以最新提交 CI 为准。

## 尚未完成

这是内部服务器服务及真实数据库适配，不是已上线可玩链。当前生产入口在认证开启时挂载只接受 Intent 的 HTTP 边界，但没有装载规则包，继续返回 RULES_NOT_READY；认证关闭时接口不存在。尚无正式六类规则包、权威初始存档创建、可玩回合 UI 和五岗位模型调度。作者规则内容输入及必要审批到位后才能连接正式玩法；不能把这些未完成代码误写成仅差人工签收。

Canon 同摘要双人回执、正式媒体许可证、真实 SMTP/API/设备与 S7 范围决议仍由既有交接清单管理，不在此另造审批。

HTTP 边界补充：请求只允许 intent 与可选布尔 requestNarrative；16 KiB 上限、严格 ActionIntent 校验、可信会话及预期账号匹配、同源写保护，拒绝客户端 owner/状态/事件。4 项 HTTP 单测加入本轮 CI。

叙事取消：HTTP 请求取消信号传给表现层；取消返回 NARRATIVE_CANCELLED 并向适配器发出 abort，不撤销既有规则事务、不再次结算。当前本地回合/HTTP 测试合计 13 项通过；最后一次完整 API 单测 43 项通过、11 项数据库用例跳过，不把跳过记为通过。
