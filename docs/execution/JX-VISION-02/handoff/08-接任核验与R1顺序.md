## 当前产品入口与设计差距

1. 浏览器 `CloudGame.tsx` 使用 `/api/turns` 或 `/api/games/:saveId/turns`，经 Hono 路由校验 owner、输入和配额，进入 `ServerTurnService.execute`。领域层 `packages/domain/src/event-log.ts` 执行 `prepareTurn`，产生请求指纹、决定、事件与回执。根分支默认字段从旧指纹省略，旧重试依赖这个约定。
2. `PostgresNpcMemoryTurnRepository.commitAcceptedTurn` 在同一事务锁定存档、核对修订并提交事件、回执与授权记忆。随后 `ServerTurnService.completed` 读取授权回忆，请求叙述或模板兜底，当前 HTTP 请求仍等待叙述。`turn_requests` 的 attempt 状态已存在；`StoryArchive` 在隔离开关下支持按回执保留和分页，生产启动主动拒绝开启。待签 T1 也已有 publication、worker、writer fence 与六角色隔离实现，应优先复用。正常宿主、隔离组合、生产开启分别验收。
3. `GET /api/games/:saveId` 返回完整 save 和 latestReceipt，`routes/turn-http.ts` 的成功分支返回内部结果，Web 还在客户端投影回执。R1 要把角色可见性落实到服务端实际响应，涵盖创建、读档、回执恢复、故事页、重试、建议、叙述上下文。隐藏 UI 无法去除已发往浏览器的数据。
4. `AuthoritativeGameService` 目前用单一 runtime 创建存档并从当前 Canon 文件取哈希。`ServerTurnService` 按单一规则/Canon/记忆三元组拒绝不匹配。v1.1 需要按存档选择规则与精确 Canon 工件，保留 v1 路径；只修改全局默认版本会让旧档失去结算能力。
5. P2 的 `commitLocalAuthoritativeTurn` 仍逐次执行 `readAndVerifyHistory`。本机原有 integrity 与 replay checkpoint 有不同职责；增量化必须保住跨标签并发检测、初次打开、完整导出、还原与篡改拒绝。隔离实验 `packages/scene-gate` 不能代替正式 `packages/scene`。正式前端仍是 React/Vite，API 是 Hono/Node + PostgreSQL/Drizzle，边缘中继、Supabase 登录与 Pages 部署仍为不同边界。

## 数值实验的复现边界

- X12 原型 `final/lab/shenshi.py` 设置 10 米网格，横向 240 点、纵向 220 点。它用 SciPy 稀疏直接解计算静态屏蔽泊松方程，水边与外框省略出域邻居，对应无流边界。无平流时 `D=1`、`λ=1/380²` 给出 380 米衰减尺度。原型用了平滑面源且显示前按最大值归一化；R4 比对无限平面点源的 K₀ 解时，应另设单源、匹配边界或控制远边界误差，避开点源奇点，并先用未归一的数值检查源、耗散与边界通量平衡。文中 SOR 是可选实现，原型运行记录对应稀疏直接解。
- X13 的 30 帧计划含 15 张不合格帧，样本内漏掉 1 张即为 6.7%。即使 15 张全被识别，在随机独立抽样假设下，真实漏检率的单侧 95% 二项上界仍约 18.1%（1 − 0.05^(1/15)）。达到原计划时应报告标定集分母、混淆矩阵与可信范围；如用于外推，另用独立标注集。G1 同一遮罩内的回贴相关性、G2 全图边缘、G3 整图分类都不能代替跨帧几何与人工视审。
