模型与功能变化很快，开始前用 `/model` 和 `/effort` 核对本机实际可选的项。

## 1. 模型

文档中的别名：

| 别名 | 对应模型（Anthropic API） |
|---|---|
| `opus` | Opus 5.5 |
| `sonnet` | Sonnet 5.5 |
| `haiku` | Haiku 5.5 |
| `fable` | Fable 模型，文档的描述是“用于最难、运行最久的任务” |
| `opusplan` | 计划时用 opus，执行时用 sonnet |

设置方式：`/model <别名>`、`claude --model <别名>`，或 settings.json 的 `"model"`。

| 角色 | 推荐 |
|---|---|
| 主会话（编排、架构、契约、规则版本、艺术方向、评审取舍） | `opus`。如果 `/model` 里有 `fable`，并且额度允许，可以在 R2 渲染核心、新规则版本设计这类长而难的阶段改用 `fable` |
| 规格明确的实现子任务（单个缺陷、单个组件、测试补齐） | `sonnet` |
| 只读的大范围搜索、文件盘点 | `haiku` |
| 独立评审 | 一个全新的 `opus` 子代理，不给它看实现者的推理，只给它看差异与规格 |

## 2. 思考强度（effort）

- 等级：`low`、`medium`、`high`、`xhigh`、`max`。Opus 5.5、Sonnet 5.5、Haiku 5.5、Fable 都支持全部五级，默认都是 `medium`。
- 设置：
  - `/effort <级别>`；
  - `claude --effort <级别>`；
  - settings 的 `"effortLevel"`，只接受到 `xhigh`；
  - 环境变量 `CLAUDE_CODE_EFFORT_LEVEL`，优先级最高。
- `max` 只能在会话里或用环境变量设置。

| 等级 | 用在九霄的哪些任务 |
|---|---|
| `medium` | 文档编辑、简单脚本、按清单跑测试、已知模式的样式调整 |
| **`high`（推荐默认）** | 日常功能开发、缺陷修复、前端组件、资产管线脚本、测试编写 |
| `xhigh` | 契约与存档格式改动；数据库迁移；P1 重新固定与新规则版本；权威结算、可见性视图、事件日志；认证与安全；G-buffer 重新打光与 three.js 渲染架构；导演层；里程碑级的艺术评审 |
| `max` | 只用于少数一次性的高风险决断：生产数据迁移方案；首次设计 `prologue-v1.1` 并论证旧存档兼容；R2 竖切片的最终独立评审；任何“做错了就不可逆”的步骤。用完就降回去 |

## 3. 减少不必要的 Token 消耗

1. **不要通读仓库**。按 handoff/01 §5 的权威来源表取用；用 `rg` 定位，再读片段。
2. 一个会话做一个阶段性任务。完成后更新执行台账，再 `/clear` 开始下一项。台账就是跨会话的记忆。
3. 大量重复的生成（批量渲染、批量 AI 推理）写成脚本放到后台跑，只读汇总结果，不把日志灌进上下文。
4. 子代理的返回值要短：只要结论、SHA、通过与失败的数字。
5. 读日志用 `tail` 或 `grep`，不要整段读入。

## 4. 子代理、并行与独立评审

- 子代理**不会**减少用量（文档原话：它们增加 token 用量），但能隔离上下文、并行推进。适合并行的是互不相干的修复，例如缺陷 4 与缺陷 7。
- 并行开发一律用独立的 worktree：
  - `claude --worktree <名字>`；
  - 或在子代理定义里写 `isolation: worktree`。
  - 每个子代理一条分支，最后由主会话合并。
- 把 `scripts/p1-rule-semantic-source-digest.mjs` 的文件表和 `scripts/p1-frozen-rules.mjs` 的冻结表写进每个子代理的指令里，避免误改。
- 多个测试共用一个 PostgreSQL 时，每个子代理用自己的库名（`jiuxiao_test_<任务>`）。
- **独立评审的流程**：每个里程碑（R1 合并前、R2 竖切片完成时）开一个全新子代理，只给它规格、差异和测试结果，让它找问题；主会话逐条处理，再请第二个评审复评。不要让实现者评审自己的工作。

## 5. 长会话与中断恢复

- 自动压缩会保留项目根的 `CLAUDE.md`、自动记忆和最近读过的少量文件。所以：
  - 项目根 `CLAUDE.md` 保持简短，只指向执行台账；
  - 每完成一项，立刻把 SHA、测试结果、下一步写进 [执行台账 §4](../README.md)，再提交。
- 主动压缩时给出焦点，例如 `/compact 保留 R1 缺陷 4 的进度与下一步`。`/context` 可以查看上下文被什么占用。
- 恢复会话：
  - `claude --continue`：本目录最近的会话；
  - `claude --resume`：选择会话；
  - `claude -n <名字>`：给会话命名，方便找。
- 中断之后，按 [执行台账 §6](../README.md) 的恢复入口操作，**不要凭记忆**。

## 6. 本地权限与安全

- **原生 Windows 上 Claude Code 没有沙箱**（文档原话：命令在原生 Windows 上不经沙箱运行）。要用沙箱，在 WSL2 发行版里运行 Claude Code，并安装 `bubblewrap` 与 `socat`；WSL1 不支持。
- 推荐两种配置，二选一：
  1. **WSL2 + `/sandbox` + `default` 模式**，加允许规则。这是最稳妥的组合。
  2. **原生 Windows + `default` 或 `acceptEdits` 模式**，加允许规则。可以在 `~/.claude/settings.json` 里开启 `auto` 模式（项目级设置里写 `auto` 不生效）。文档提示 auto“不保证安全”。
- `bypassPermissions` 只适合隔离的容器或虚拟机，**不要**在装有个人文件的主机上使用。
- 允许规则示例（项目 `.claude/settings.json`，只放无破坏性的命令）：

```json
{
  "permissions": {
    "defaultMode": "default",
    "allow": [
      "Bash(pnpm install --frozen-lockfile)", "Bash(pnpm typecheck)", "Bash(pnpm test:*)",
      "Bash(pnpm build)", "Bash(node scripts/p1-frozen-rules.mjs --check)",
      "Bash(git status)", "Bash(git diff:*)", "Bash(git log:*)"
    ],
    "deny": ["Bash(git push --force:*)", "Bash(git push -f:*)", "Read(./**/.env)", "Read(./deployment/api.private.env)"]
  }
}
```

- 凭据只放在环境变量或本机文件里，不进仓库、不进提示词、不进提交信息。
