## 1. 九霄是什么

《九霄》（Nine-cloud）是一款面向中文玩家的 **AI 修仙文字 RPG**，在手机和桌面浏览器里直接玩。

核心循环：

1. 玩家用自然语言写下行动（“去望气台”“对岑九说：这石头怎么办”）。
2. NLU 把它解析为结构化意图。
3. **权威规则**结算，写入事件日志与存档。
4. AI 只负责叙述已经结算的结果，**不能决定事实**。

作者是 **LYL**（GitHub 账号 `LYL-Z`），物理学本科生。另一个签署者“Bird”是 AI 代理复核者的标签，不是人。历史上还有 Codex 代理（`codex/*` 分支）和其他协作者（如 PR #125 的作者）参与。

### 长期目标

作者的原话是要达到“世界级”的艺术水平：宏大、沉浸、高级，自由创新，前后端全面设计，科学与艺术融合。方案的一句话：

> **九霄是一个按真实天时运转、可以走进去、可以读、可以写、也会记住你的修仙世界。**

## 2. 作者的明确要求（汇总）

| 方面 | 要求 |
|---|---|
| 艺术 | 世界级艺术水平，明显降低“AI 感”；不受旧色系、布局、材质、框架限制；可用一切工具和语言。参考目标：空间与自然、人物与材质、宏大与沉浸、科学与幻想（是方向，不是九霄成品）。具体要改进：远景的荒漠感、地形几何占位、植被、芦苇、水体、岩石、建筑、木构材质、人物服装、光影曝光色彩、空间纵深与尺度、镜头声音动画交互、构图与文学叙事 |
| 玩法 | 权威结算；画面不能多于事实（“画面 ⊆ 事实”）；天文、季节、气候、世界演化；地图是后续核心玩法；人物有局部知识与长期记忆 |
| 工程 | 先修可信 CI 和已知缺陷；规则版本兼容；不回填旧存档；每次提交有真实 SHA、测试记录、截图或录屏；未测的写 NOT RUN；不得为了变绿删测试或放宽阈值 |
| 诚实 | 不虚构签名、同意、法律意见、备案状态；不夸大完成度；不能只凭测试数量、自评或报告宣称“世界级” |
| 资产 | 暂不聘请付费画师；允许 AI 生成、程序化、三维渲染与合法素材进入正式资产；不能因为一次 SD 1.5 CPU 重绘失败就永久排斥 AI |
| 费用 | 新增付费必须先给出预算并获批准；先用已有资源 |

作者的协作偏好（本地会话可能读不到云端的个人设置，所以写在这里）：

- 默认简体中文，保留必要的英文术语；直接、认真、有判断，不奉承，也不为反对而反对；
- 先结论，再依据；
- 明确区分已证实事实、推断、假设与建议；时效性信息要联网核实，不编造来源与结果；
- 工程上先理解现状再改动，解决根因，不改测试迎合实现；
- 交付时如实区分已完成、部分完成、受阻、未验证；
- 高风险操作（删除、覆盖、对外发布、付费、账户安全）先确认授权范围。

## 3. 世界书 Canon 与规则

- **Canon 1.0**：34 条原图整理条目进入运行包。数据在 `packages/content/src/canon.registry.json`、`canon-runtime.json`；阅读版从 `outputs/九霄世界书/README.md` 进入。
  - 必须遵守根目录 `AGENTS.md` 的世界书规则：旧“182 张原图未提供”“全部 OCR 未审核”已被推翻；不重跑 `scripts/prepare-worldbook-final.mjs` 和 `scripts/write-worldbook-author-handoff.mjs`；私有原图和逐图草稿不进公开玩家包。
- **九境顺序**：炼体→炼气→筑基→结丹→元婴→化神→合体→大乘→渡劫。这是作者 2026-10-03 的更正，原稿顺序相反、原稿不改。见 [ADR 0011](../../../adr/0011-九境顺序.md)。
- **五域**：中州、东海、南疆、西荒、北原（另有妖域）。依据见 `docs/九境五域世界书依据表.md`。Canon 对方位、尺度、天文多数**空白**，方案的地理与天文是“兼容扩展”（作者已授权 Claude 自主创作并登记），不改 Canon 1.0 正文。
- **序章 `prologue-v1`**：三个地点，芦花渡 → 望气台 → 折桂坪（奖励后解锁）。NPC 有岑九（摆渡人）和水鱼鸦（鸦群）。
  - 时间：1 刻 = 15 分钟；从 05:00（gameMinute 300）开始，17:00（第 48 刻）天黑。
  - 体力与灵力：各 100；修炼每刻 +800，上限 10000。
  - 真实链路：05:00 出发 → 05:15 到望气台（体力 95）→ 05:30 环视（92，得“落石线索”）→ 06:00 细察（86，得鸦群线索）。
  - 天黑后：观察落石会被“太暗”挡下；战斗按“清除并受伤”处理。
  - 规则身份已**冻结**，见 [ADR 0010](../../../adr/0010-P1规则冻结与版本化.md)。

| 层 | 技术 | 入口 |

关键事实：

- **生产前端是手动直传**到 Cloudflare Pages。Git 自动构建从 11-09 起一直卡在排队。
- `main` 的 push **不会自动部署**。CI 只有一个 workflow：`.github/workflows/ci.yml`，job 名是 `verify`，约 20 分钟，包含 PostgreSQL、Mailpit、Docker 镜像冒烟、Playwright e2e。
- 线上 API 的 preview-1 规则加载要求宿主上有一份批准文件，`approvedBy` 含 LYL 与 Bird，`semanticSha256` 等于代码中的固定值（`apps/api/src/services/preview-release-runtime.ts`）。改动后果见 ADR 0010。

**说明**：`AGENTS.md` 协作导航里“不擅自合并或部署”、`docs/repository/STATUS.md` 里“生产发布需指定拥有者批准”是对一般协作者的规定；对 JX-VISION-02 执行者，作者已明确授权“阶段性合并及发布按既有权限和验收流程自主推进”。“既有流程”指：CI 通过才合并；部署前记录回滚点、部署后实测线上；生产数据库迁移先有验证过的备份与回滚。

**作者已经授权（2026-11-26）**：设计与工程全部由 Claude 自主决定；取消双作者签收与阶段性再批准；可用现有及已授权的 GPU；批准 P1 冻结与升级、ADR 0009、CI 门禁重构、正式产品开发；合并与发布按既有权限和验收流程自主推进；境界顺序、地理、历法、新 Canon 兼容扩展、避水符语义、线索名称、仓库整理、PR 整合顺序都由 Claude 决定。每项决定的落实见 [执行台账 §2](../README.md)。

**仍然禁止或需要另行取得**：

- 新增付费（租 GPU、付费 API、付费存储、云真机、画师）：先给出预算并获批准。
- 伪造任何人的签名或同意。历史签署记录完整保留，签署原文不回写。
- 虚构法律意见、用户同意、备案状态。叙述持久化等生产政策，没有合规依据时只能做隔离开关，不在生产开启。

“最高项目决策权”不等于拥有所有外部账号的管理员权限。缺凭据时，明确列出需求，其余工作照常推进。

5. 回滚点：记录上一次生产部署 ID（上次是 `85adf881`，再上次是 `9a1c7ad0`）。
