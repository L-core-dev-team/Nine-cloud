# 02 · 设计继承与试错

最终方案的全文在 `docs/design/JX-VISION-02/final/`。本页不重复正文，而是说明三件事：方案的骨架是什么，为什么是现在这样，哪些结论只在特定条件下成立。

## 1. 骨架：七根支柱和一条铁律

**铁律：画面、声音、文字都由同一份权威世界状态驱动；画面 ⊆ 事实。** 任何表现层都不能显示规则没有结算的东西。这条贯穿全部支柱。

| 支柱 | 要点 | 主要章节 |
|---|---|---|
| 天时 | 权威游戏时间驱动日月星辰、节气、天气、作息；光就是时钟。九霄标准时取天衍城子午线；芦花渡约北纬 30°，秋分时 05:00 日出、17:00 日落，与规则的“17:00 天黑”吻合 | final/04 §1–5 |
| 山河 | 每个地点都是地理连续的真实空间：远景→近景→物件。芦花渡：河自西向东，渡槽在南岸，落石从上游堵住槽口；望气台在渡口西南三里丘顶，折桂坪在其北 | final/04 §6、01 §9 |
| 镜语 | 虚拟导演是一个纯函数（`DirectorPlan`），按规则挑选镜头、光、声、界面形态，**不能改事实**。规则优先，AI 只能在规则给出的选项里挑 | final/07 §1–3 |
| 言落与证 | 自由文字行动；解析出的目标词“落”到画中那个物件上；叙述里的事实短语可以“摘句为证”，作为下一步行动的证物（证物在日志里只存 `factId`，并进入请求指纹） | final/03 §5、08 §3 |
| 卷宗 | 阅读是一等形态；今日长线 → 年谱 → “一世浮生”人生长卷；可删除、可完整导出 | final/03 §11–12、05 |
| 神识 | 境界决定能看见哪些层：灵气标量场、流线、灵脉拓扑、生命、星象、法域。灵力场模型是屏蔽泊松方程，边界零通量；阵法是最大流，破阵是最小割 | final/06 |
| 万象 | 天下、域、地、景、物（含灵脉）五个尺度无缝切换；地图是后续核心玩法；只显示玩家 `Known` 的东西 | final/04 §6 |

其余关键设计：

- **SceneSpec**：每个场景元素分为 fact、ambient、omen 三类，fact 必须 ⊆ 可见事实。
- **七种界面形态**：游、读、谈、斗、观、图、忆。只有能进入的形态才显示标签页；“斗”由事件触发；“图”在实现之前隐藏。
- **契约**：回合提交返回 `visibleEvents`、`visibleDelta` 与 `branchId`，提交与叙述分离，叙述异步（Postgres 任务表）。见 final/08。
- **存档**：不回填旧存档。新字段只出现在新规则版本创建的存档里。
- **社会与记忆**：NPC 有 `NpcKnowledge`、`Relationship`、`Routine`，靠确定性规则运转，AI 只负责措辞（final/05）。
- **玩家旅程**：16 段，加上“芦花渡一旬”“上游”两个序章之后的循环（final/03 §17）。

## 2. 方向是怎么收敛的

| 阶段 | 方向 | 结果与理由 |
|---|---|---|
| VISION-02 第一轮（`claude-proposal/`） | 四个独立方向：**长卷**（横向长卷叙事）、**天光**（真实天时与光为核心）、**字境**（以字为景）、**灵台**（以修炼内观为界面） | 评审认为天光最能把规则、时间、空间统一起来；卷宗（由长卷演化）最能承载文学与记忆 |
| 第一轮之后 | 天光与卷宗二选一 | 作者裁定：**以天光为主，融合卷宗、字境、灵台** |
| 最终方案 | 七根支柱 | 字境不单列支柱，它的思想用在三处：书页排印、功法与阵法的“道纹”、稷下学宫“以言为法”；灵台并入神识；长卷与卷宗合并为卷宗 |
| 方案 E（PR #120） | 已上线的全站界面 | 作者认定只是初版。可复用的是组件与交互的工程成果，不是审美规则 |

GPT 提供过 G（山河之间）、H（人间镜语）、I（万象天图）、J（一世浮生）四个方向和六个机制。逐条采纳情况见 final/02。

## 3. 独立评审的关键意见（final/13、reviews/）

两名独立评审（A：艺术与体验；B：架构、数据与证据）加一次复评。被采纳并已修订的要点：

1. 帧图里出现过违反规则的状态，已全部按“序章真实状态链”重画。例如 05:15 就出现证物、交谈页里没有人、“忆”里混入不同分支。
2. 文字对比度先前没有实测。修订后 8 处测量全部 ≥ 4.5:1。
3. 文档里残留旧说法：`stateDelta` 应为 `visibleDelta`；“按时刻烘焙”应为 G-buffer。
4. 数学错误已改：边界条件、最小割、结丹的晶格不是 Morse–Smale、半径。
5. 缺陷 5 的严重度被夸大，已更正：在作业位用掉避水符再开战，仍有保护。
6. AIGC“日志留存 6 个月与删除冲突”是误读，已更正。
7. 境界顺序的推荐撤回，改为两个选项对等呈现；执行阶段已按作者既有更正裁定（ADR 0011）。
8. 评审 B 提出 P1 包哈希清单包含共享契约，因此必须先冻结，这才有了 X14 与 ADR 0010。

## 4. 试错经验（最重要的部分）

### 4.1 AI 整图重绘为什么失败

- **做法**：Blender 渲染 → SD 1.5 img2img（CPU，768×432，约 10 步去噪，每张 63–295 s）→ 遮罩合成。
- **结果**：12 帧在人工审阅下全部不合格。
  - **抹掉事实**：落石、鸦群在合成前、遮罩区内的相关系数只有 0.22–0.59。
  - **编造**：遮罩外出现现代建筑、别墅、海鸥。
  - **地理漂移**：同一机位、四个时刻，河道各不相同。
- **原因**：整图重绘没有几何约束（没有 ControlNet 深度、边缘，没有 inpaint 遮罩控制）；模型老而小（SD 1.5）；只有 CPU，步数和分辨率都被压低；去噪强度一旦高到能改善质感，就会改写内容。
- **结论的适用范围**：这只证明“**无约束的整图重绘不可用于事实画面**”。它**没有**证明 AI 不能用于九霄。在 GPU 上，用更强的模型（SDXL、FLUX 等，先核对许可）配合深度、法线、边缘 ControlNet、局部 inpaint、IP-Adapter 风格参考，完全可能通过门禁。这正是实验 X1(b)，至今未做。

### 4.2 曾经出现的循环论证

上一版用“合成后遮罩区相关系数 0.99”证明事实得到保持。这是循环论证：先把渲染原样贴回遮罩，再在同一块遮罩上测相关，结果必然接近 1。已撤回。正确做法是测**合成前** AI 输出在事实遮罩里的保持度（G1 ≥ 0.95），并辅以人工审阅。

### 4.3 自动门禁的漏检

门禁实测（final/09 §4）：

- G1（事实区相关）有效；
- G2（边缘相关）太宽松；
- G3（CLIP 禁止概念）漏检，6 帧不合格的漏过了；
- G4–G6 没有实现。

所以门禁只能作提示，最终以人工审阅为准，直到 X13 用 30 张人工标注帧完成标定（漏检率 ≤ 5%）。

### 4.4 地理一致性与游戏状态

真正能保证“画面 ⊆ 事实”和地理连续的，是**几何**：同一套三维场景，状态层（落石在 / 不在，鸦群在 / 不在，渡船搁浅 / 浮起）由权威状态切换。任何 2D 生成方法都必须以这套几何为约束（深度、法线、遮罩），否则会漂移。这是原则，与使用哪种渲染器无关。

### 4.5 Blender + CC0 + G-buffer 的研究成果

- 实测：Blender 5.2（bpy 5.2.5）+ Cycles，1280×720、48 spp，在 4 核 CPU 上每帧约 3 分钟。
- 真实扫描的 CC0 材质（Poly Haven：`aerial_grass_rock`、`brown_mud_02`、`forrest_ground_01`、`old_planks_02`、`rock_face`）明显消除了近景的程序化感。
- 天空方向约定已实测：sky `sun_rotation` 是从正北顺时针的方位角。
- **G-buffer 运行时重新打光**只设计、未实现（X3）。设计是：每个机位族烘焙颜色、法线、深度、遮罩，运行时按实时太阳与天光做延迟着色；验收标准是与 Cycles 真值在 6 个时刻的 ΔE₀₀ 中位数 ≤ 8。

### 4.6 现有原型还没解决的艺术问题

- 远景空旷、有荒漠感，缺少层次。
- 地形是几何占位。
- 植被、芦苇、水体还是占位：芦苇只是实例化的简单面片，水没有真实的反射与流动。
- 没有房屋、木构、船的成品资产。
- 人物（岑九、鸦群）只有规格，没有模型。
- 曝光与色彩只调到“能看”。

这些都在 final/01 §9“序章套件规格”里有具体规格（尺寸、颜色、结构）。例如：

- 芦苇高 1.5–3 m，穗色 #C9BBA0；
- 灰羽鸦体长 45 cm，羽色 #6E7176，头与翼黑色；
- 岑九穿三层蓑衣，戴约 60 cm 的斗笠，手有裂口，左耳有缺口；
- 舢板约 7 m 长；
- 民居为土坯墙，顶覆茅草或小青瓦；
- 植被用枫杨、柳、乌桕；
- 望气台有四根朽桩。

### 4.7 哪些只是原型

`final/frames/` 里的所有帧、`final/lab/ui.html` 的界面叠加，都是**非生产设计帧**，用来验证构图、规则一致性和管线方向。不要把它们当作最终美术标准去复刻。最终品质应当远高于它们。

### 4.8 哪些限制来自云端环境，而不是项目原则

| 限制 | 来源 | 本地应当怎样 |
|---|---|---|
| 只用 CPU 渲染、48 spp、1280×720 | 云端容器没有 GPU | 用 GPU（OptiX、CUDA、HIP 或 Metal，视硬件而定），提高采样和分辨率 |
| AI 只试了 SD 1.5 CPU 整图重绘 | 同上 | 试 ControlNet 约束的局部增强、更强的模型、三维重建、程序化植被 |
| 没做 G-buffer 运行时打光、three.js 原型 | 时间与阶段（设计阶段禁止写生产代码） | R2 的核心任务 |
| Poly Haven 下载要带浏览器 User-Agent | 代理与站点策略 | 正常下载即可 |
| Cloudflare 部署需要本地中继 `cf-shim.mjs` | 云端代理改写上传 JWT | 本地不需要 |
| 没有真机、读屏测试 | 云端没有设备 | X3、X8、X9 需要作者的真机 |

**Blender + CC0 + G-buffer 是推荐路线，不是规定。**

- ADR 0009 第 3 条写明，渲染与资产路线不是封闭清单。
- 只要守住“几何约束、画面 ⊆ 事实、许可登记、人工审阅”这四条，接任者可以替换或升级其中任何一环，例如改用实时引擎烘焙、三维高斯泼溅、程序化生态系统或更好的生成模型。
