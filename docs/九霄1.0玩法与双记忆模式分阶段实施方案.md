# 《九霄》1.0 玩法与双记忆模式分阶段实施方案

- **方案日期：** 2026-09-29
- **文档性质：** 面向后续实现的专项路线，不是代码实现报告、阶段签收或公测承诺。
- **代码基线：** 本方案所用九霄工作区基线为提交 cda8d20；当前阶段状态仍以[2026-09-29 阶段缺口与人工交接清单](九霄1.0阶段缺口与人工交接清单-2026-09-29.md)为准。
- **优先范围：** 首次可玩行动、规则提交、可核对回执、NPC 知情边界、两种记忆模式、模型失败回退。

## 1. 目标和结论

《九霄》的玩法主张是：玩家进入一个持续存在的世界；玩家行动先由规则结算；叙述只解释已提交的变化。玩家不配置模型也能行动和完成序章。配置 BYOK 后，模型提高叙事表达质量，不获得额外行动权限。

本方案采用以下架构决定：

1. **规则事务是唯一世界事实写入者。** 玩家输入先成为 ActionIntent；签署过的领域规则决定接收、拒绝、失败结果与 DomainEvent；投影更新状态。模型、记忆引擎、摘要器、插件和场景导演只能提供候选或表达。
2. **NPC 记忆只覆盖其有权知道的事件。** 目击、转述、观察授权和其他披露规则先生成 NPC 可见观察，再进入记忆。两种记忆模式都不能直接遍历未过滤的全局事件日志。
3. **“存档与继续”是 NPC 授权观察的永久、无衰减检索模式。** 它不代表 NPC 知道所有世界事件，也不要求每轮把全部历史塞入有限上下文。完整性指授权观察不会因策略衰减而从记忆索引中消失，并可依靠可核查索引按需检索。
4. **“真实遗忘”是同一授权观察集上的检索可访问性衰减。** 不删除事件或 NPC 观察，不做误记、不把甲的事记到乙头上。独特线索可以按版本化规则唤起完整或残缺的原始观察。
5. **Mem0 和 UwU Memory 不作为九霄的强制运行依赖。** 九霄先实现有版本、有权限、可回放的 TypeScript 记忆内核和适配接口。Mem0 对应“结构化人物资料的语义检索”职责；UwU Memory 对应“剧情摘要与相关历史检索”职责。外部项目仅作为可选适配器或离线评测候选，不能成为权威数据源。
6. **记忆策略在建档时选择并固定。** 每个存档写入模式和策略版本；建议默认选“存档与继续”，把“真实遗忘”作为玩家主动选择，避免未预期的记忆衰减。两种 NPC 认知物化结果使用按存档和模式隔离的存储域；禁止同一剧情中途静默切换。跨模式转换只能通过玩家明确选择、复制存档、预览、转换和新分支完成。
7. **遗忘只随游戏时间和 NPC 亲历事件变化。** 现实时间不衰减 NPC 记忆。作者 A 已确认 1.0 核心闭环排除离线世界演化，P7 留待后续单独裁决。默认关闭；若未来批准开启，现实时间只能作触发，游戏时间必须有上限，且 NPC 死亡、物品失窃、任务失败列入禁变黑名单。

这些决定是本专项的工程方案。规则数值、角色表现、Canon 和序章结果仍须由产品/Canon 负责人提供并由双方按现有门禁签署。

### 2.1 语言、运行时与存储的选型结论

当前源码主线是 TypeScript 工作区：React/Vite Web、共享 Zod 契约与纯 TypeScript domain、Node/Hono API、Drizzle 生成并以 SQL 迁移为准的 PostgreSQL 结构；本地档已使用原生 IndexedDB。P0–P5 沿用这条主线，不增加 Python/FastAPI 记忆服务、第二套前端框架、LangChain/LangGraph、外部向量库或新的规则运行时。这样能让浏览器游客、API 和离线回放调用同一套确定性规则与检索代码。Mem0 已有 Node/TypeScript SDK，但 SDK 可调用不等于它适合充当 NPC 事实源；是否加入只由隔离实验的质量、隐私、延迟、离线和维护数据决定。

零配置的首轮必须由浏览器本地规则与 IndexedDB 完成，不以当前尚未接入正式认证的 API/PostgreSQL 为前提。云端只在现有 S6 身份、逐档授权和同步缺口签收后，提供同一 port 的第二个持久化 adapter。服务端和浏览器共用 domain 契约，不承诺其数据库物理事务相同；两端各自必须提交完整的权威事务与可恢复 outbox。

## 3. 可验收的首轮体验

### 3.1 一轮的事务顺序

1. 玩家打开本地档，首屏展示上次位置、已提交的世界简报、一条有来源的未解钩子和至少一个可执行行动。离线演化关闭时，不得伪造离线期间发生的事件。
2. 玩家可点击建议行动，也可输入自然语言。点击建议只把可编辑文本写入输入框；编辑后的内容与手输内容必须走同一个确定性解析器。
3. 解析器规范化文字，并用词表和行动模板得到候选 ActionIntent。参数完整且唯一匹配时进入规则层；缺参数或多个同等匹配时先澄清。未知表达不报错、不结算、不推进时间。
4. 规则层读取权威存档、当前时间、资源、位置、关系和已签规则版本，作出 accepted、rejected 或需补充输入的决定。合法失败也是规则结果，不能被叙事模型改写成成功。
5. 被接受的结果在单一权威事务中提交 DomainEvent、状态投影、游戏时间、回合回执和冻结的 NPC 授权观察 outbox。模式记忆库之后幂等投影；不能将跨库双写称作一个原子事务。唯一幂等键重复提交不得二次扣费、推进时间或增加关系。
6. 叙事层拿到已提交回执、受权限约束的记忆证据和本轮允许表达的事实。无模型时用预写文本与确定性拼句；BYOK 时模型只改写正文。两条路径必须呈现同一组状态事实。
7. 玩家可点开状态回执核对具体字段、事件 ID、前后修订、事件时间、规则版本与事实来源。结尾给出一个由当前状态支持的钩子或选择。
8. 模型超时、取消或输出不合规时，只重新生成或使用确定性叙事模板。重试引用同一回执，不重新调用规则、不重掷随机结果。

每个完成回合必须有可核对状态变化、可见回执、游戏时间推进和状态支持的后续钩子。澄清和规则拒绝属于尚未完成的输入，不计为成功回合，也不得伪装成已发生的世界变化。

### 3.2 五类序章输入与六类完整规则

序章界面至少支持移动、观察、交谈、使用物品和战斗五类。观察必须产生规则定义的观察/调查记录或可验证线索变化，不允许只回一段空泛描写。交谈必须在满足规则时改变已定义的关系、话题、任务线索或已知事实；单纯陪聊不自动假造好感。每类行为需对应至少一个有语义的可投影字段或事件。

序章需完成首个任务，因此任务进度/完成也必须由规则验证并入账。它不能被视为叙事附带字段。完整 1.0 仍以当前 S3 要求的移动、修炼、获得/使用物品、交谈、基础战斗、任务六类规则为准；五类序章按钮不能替代修炼规则、完整规则签署或其他阶段门禁。

## 4. 记忆数据模型和隔离边界

### 4.1 三种不同的数据，不能混称“记忆”

| 数据域 | 内容与权威来源 | NPC 能否直接读取 |
| --- | --- | --- |
| 世界事实 | 签署规则提交的不可变 DomainEvent、状态投影和规则版本；事件可查询、校验和重放 | 不能直接读取全局事件；必须通过 NPC 可见性授权形成观察 |
| 角色档案与 Canon | 经作者审核、版本化的角色身份、关系初值、设定、能力边界和公开世界资料 | 仅读取对该 NPC、场景和请求有权限的已批准字段 |
| NPC 主观认知 | 从规则事件经观察授权后建立的目击、转述或其他明确渠道；只描述 NPC 有资格知道的内容 | 由存档模式和 NPC 身份约束；不得通过玩家摘要、UwU 摘要或另一个 NPC 的记忆绕过过滤 |

当前 `SaveEnvelope` 只有一个 `memoryPolicyVersion` 字符串，没有 `memoryMode` 或 `branchId`；旧 `npc_memory_journals` 也是每存档一个 JSONB 行。P4 需要显式迁移这两项契约，不能把当前字段描述成已经实现的档位隔离。

权威世界事件在存档有效期内只追加、不自动裁剪；日常回合、摘要和记忆整理不得改写或删除。必须同时承认数据边界：本地浏览器数据可能被用户清除、浏览器驱逐或设备损坏，云账号/存档删除也有单独的产品与隐私规则。因此“永不删除”可作为存档运行期内的游戏不变量，不能脱离用户删除、导出备份和平台存储承诺宣称物理永久保存。事件表还需在数据库角色权限上禁止常规运行账号 UPDATE/DELETE，并给回放校验明确的规则版本与完整性摘要；这比只在 TypeScript 命名为 immutable 更强，但不抵御数据库管理员恶意改写。

每条授权观察应保留 saveId、branchId、授权策略版本、schemaVersion、npcId、唯一 grantId、来源 eventId/eventRevision、授权时游戏时刻、目击/转述渠道，以及一份冻结的、字段白名单化的 `authorizedFacts`。`NpcObservationGrant` 与权威 outbox 不携带 Continue/Forgetting 检索模式；记忆模式只存在于目标分支的 `SaveMemoryPolicy` 和投影封套中。这样同一授权观察集才能被两条模式公平比较，而运行中的存档仍只投影到被选中的一个模式库。来源 eventId 只用于证明出处；NPC 检索只能读冻结的授权事实，不能借引用去取回整条原始事件负载。展示摘要、Mem0 向量和 UwU 摘要都是可重建衍生物，不可作为唯一事实载体。密钥、玩家私密材料、未发布 Canon 和模型内部推理不进入普通 NPC 认知。

### 4.2 类型和持久层契约

TypeScript domain 用判别联合表示存档模式，避免一个可空字段拼出非法策略；共享 Zod schema 在 HTTP、导入导出和 IndexedDB 读取边界校验，类型推导复用 schema，SQL migration 再以 NOT NULL、CHECK、UNIQUE 和外键约束守住持久层。建议 `SaveMemoryPolicy` 固定 `mode`、`policyVersion`、`schemaVersion`、`clockBasis`、`policyArtifactHash`、cue/normalizer/index 版本。云端把 mode、branchId、policyVersion 等查询/约束字段设为明确列，不只塞进一个 JSONB；具体参数可存带 hash 的版本化 payload。Continue 与 Forgetting 分别有只读策略对象，运行中不可就地改模式；NPC 可见性规则版本与 memory mode/version 是两个独立契约。

| 契约 | 必需字段/不变量 |
| --- | --- |
| `NpcObservationGrant` | saveId、branchId、npcId、grantId、eventId/revision、稳定的 NPC grant sequence、游戏时刻、观察渠道、授权规则版本/hash、字段白名单化且冻结的 authorizedFacts；不含 memoryMode；唯一键确保重复投影不重复计数 |
| `MemoryEvidence` | save/branch/mode/policy hash、npcId、grantId/eventId、被召回的 fact IDs、`partial` 标记、量化分数、游标和确定性排序键；没有证据时显式 abstain，不交给模型补全 |
| `ProjectionCursor` | saveId、branchId、mode、最后连续处理的 outbox revision/grant sequence；游标只越过已持久化 grant，不以“收到消息”作为完成 |
| `MemoryStorePort<M>` | `appendGrant` 幂等、`query` 纯读、`getCursor`、`rebuildFromOutbox`；mode 是编译期泛型也是运行时固定元数据，外部 SDK 不实现权威 port |

数值型游戏状态、游戏时刻和存档修订使用整数单位；访问分数使用版本化固定点（例如 0–10000），不以不同 JS 引擎的浮点排序决定同分顺序。数据库至少约束 `(saveId, branchId, npcId, grantId)` 唯一和 `(saveId, branchId, npcId, npcGrantSequence)` 唯一；分支记录必须保存父 branch 与 fork revision，防止检索越过分叉点读到未来授权。TypeScript 类型只能减少调用错误，不能替代运行时授权、数据库约束或物理存储隔离。

模式库消费者收到的 projection envelope 才绑定目标 `mode` 和 `policyArtifactHash`。创建跨模式分支时，从模式中立的授权账本构造新 envelope 并重建目标库；测试可用同一冻结 fixture 分别投影两份副本。真实存档运行时不双写两个模式库，也不允许一个库充当另一库的回退。

### 4.3 两条模式

| 模式 | 可见观察集 | 检索规则 | 不允许的解释 |
| --- | --- | --- | --- |
| 存档与继续 | NPC 已获得授权的全部观察及其冻结 factRefs；每次新增观察仍须通过相同权限过滤。检索可回指事实片段，不依赖有损摘要 | 不按时间或离线时长降低可访问性；可按明确线索检索并回指原事件 | 不能叫“全知模式”；不能读其它 NPC 的观察、未披露事件、其他存档或全局未过滤事件 |
| 真实遗忘 | 和继续模式相同的初始授权观察集 | 按游戏时间跨度与 NPC 亲历的事件数量衰减可访问性；匹配的人名、物品、地点、共同经历等线索可以提高访问并返回完整或受限片段 | 不能删底层事件；不能误记/错配人物；不能跟真实离线时间衰减 |

两种模式的差别只有 NPC 检索可访问性和最终可见的观察片段。两种模式读取相同规则事件和同样的授权决定。继续模式也不能让叙事摘要替代观察授权。

### 4.4 隔离、事务和投影恢复

不能把“两个独立数据库”直接同步写入当作一个 ACID 事务。那会产生半提交：世界事件已落库，遗忘库写入失败；或记忆已写入，世界回合回滚。正确边界是：一个权威事务提交世界事实和可重放的观察授权 outbox；之后由幂等投影器把已批准的授权观察物化到该存档选中的模式库。摘要和检索索引由该投影重建，不参与规则提交。

| 层 | 本地零配置实现 | 云端扩展（仅在 S6 签收后） |
| --- | --- | --- |
| 权威事务 | 扩展现有 `jiuxiao-1` IndexedDB，以一个 readwrite transaction 同时写存档修订、`world_events`、回执和 `observation_outbox`；这几项必须在同一个数据库/事务里 | 在权威 PostgreSQL 事务中写 `game_saves`、`turn_events`、`turn_requests` 和 outbox；复用现有锁/CAS/幂等路径，不能跨 PostgreSQL database 做伪原子写 |
| 模式存储 | 为 Continue 与 Forgetting 分别建立独立命名的 IndexedDB 数据库；每个库启动时写入固定 mode/version 元数据，adapter 拒绝另一模式数据；库内仍以 saveId/branchId/npcId/grantId 分区 | 使用两个 PostgreSQL database 与独立连接身份；在同一 PG cluster 下仍是数据库级隔离，不是物理主机或管理员级安全边界。普通运行角色只能连指定模式库；独立模式的向量索引也不能共用 |
| 投影 | outbox 记录按 grantId 幂等投影；启动和每次事务后可按存档追平，不要求常驻服务 | API/worker 使用独立消费者推进游标；一个模式故障不得阻塞世界事实提交，也不能将另一个模式库作为回退 |

浏览器同源页面可访问该来源下的多个 IndexedDB 数据库，用户清除站点数据也可能同时清空它们。因此这提供独立持久路径和防止业务串线的结构，不是防恶意同源脚本的安全沙箱或跨设备备份。真实安全边界仍是可信浏览器来源、会话密钥与服务端身份权限。IndexedDB 事务可以原子提交多项对象存储写入，但事务生命周期短，且浏览器/操作系统对持久落盘和驱逐有自己的限制。P2 必须在开启事务前完成规则计算和可序列化数据准备；事务中只发 IndexedDB 请求，不 await 模型、网络或其他可能让事务自动关闭的工作。高价值回合可请求 `strict` durability hint，但它仍不是备份承诺。存档导出与可恢复备份必须作为耐久性路径，不能把 IndexedDB 描述成永不丢失（World Wide Web Consortium）。

投影器只能消费权威事务中冻结的 `authorizedFacts`，不得在延迟处理时用“当前可见性规则”重算历史授权；否则规则升级会改变 NPC 过去被允许知道的内容。权威 outbox 是 mode-neutral；模式消费者构造的投影 envelope 含 grantId、saveId、branchId、目标 mode、eventRevision 和 memory `policyArtifactHash`。检索开始前要求投影游标达到回执要求的授权修订；若未追平，则对相同 outbox 前缀做确定性读穿/重建。若存储仍不可用，规则回合仍保持已提交，叙事退回只使用当前回执和确定性文本，不能读陈旧或跨模式记忆。

读取时同时验证存档所有者、模式库固定标签、saveId、branchId、NPC ID、policyArtifactHash 和游标。存档策略只能来自服务端/存档元数据，不能由前端 query 参数覆盖。PostgreSQL RLS 可作为逐档纵深防护，但不能代替这些约束：table owner、superuser 和 `BYPASSRLS` 角色能绕过 RLS；数据库角色应为非 owner 且无 `BYPASSRLS`（PostgreSQL Global Development Group）。继续与遗忘之间的迁移必须创建新分支、预览并基于同一授权账本重建目标库；绝不复制衰减分数、提示缓存或向量索引。

### 4.5 遗忘和可复现性

检索是纯函数。输入签名至少包含 saveId、branchId、NPC ID、规范化线索、游戏时刻、NPC 自己的授权观察序号、事件/观察游标、policyArtifactHash、线索词典哈希、规范化算法版本、索引 schema 版本、候选上限/阈值和 decayModelVersion。相同签名必须得到同一组有序 eventId/grantId、同一事实片段和同一量化分值；“同一游戏时刻”若已有新事件或新授权观察，就不是同一检索签名。查询本身不强化记忆；强化只能来自已提交且幂等的新授权观察/规则互动事件，否则再次提问会改变自己测试的结果。

把遗忘视为访问性下降而不是数据删除，与 Rana 等人的 Oblivion 研究方向一致；该预印本不验证九霄的游戏规则或确定性产品承诺（Rana et al.）。本方案当前公式只是透明、可复现的工程基线：A = clamp(S × 2^(-(Δg/Hg + Δn/Hn)) + C, 0, 1)。S 是规则/作者给定的片段显著性；Δg 是游戏时间跨度；Δn 只能计入此 NPC 在该观察之后收到的不同授权 grant 数，绝不能计入其未获知的全局事件；Hg/Hn 是固化在策略制品中的参数；C 是类型化线索对同一授权片段的匹配项。线索匹配不能扩大权限，只能唤回该 grant 允许的原始字段。

不要把这个公式称为“人类遗忘定律”。P5 先将该指数式作为简单基线，同时离线比较幂律/ACT-R 类基线；采用与否看九霄自己的盲评结果。ACT-R 的认知理论只能提供比较思路，不能直接证明游戏 NPC 的遗忘参数有效（Anderson and Schunn）。现有 AI 记忆遗忘仓库 `memory-decay-core` 提供多种衰减实现，但 README 的 `/auto-tick` 默认将现实秒数换成记忆 tick，搜索也会触发检索强化；这与“游戏时间唯一计量”和“纯查询可复现”冲突，所以只适合离线对照，不能直接作为运行依赖（Memory Decay Core）。近期 Memora 基准与 FAMA 指标把过时/失效记忆纳入长期记忆评测，可作为“当前事实已被后续事件更新”的测试启发；个性化对话基准不是九霄 NPC 规则准确性的证据（Uddin et al.）。

所有候选函数都必须满足单调性：其他输入固定时，更多游戏时间或更多该 NPC 的后续授权观察不能让普通旧片段更容易命中；查询线索只能提高被准确匹配片段的访问性；相同版本和签名完全确定。参数、量化表、词典和权重写入策略制品 hash；用纯整数/固定点计算与无 locale 依赖的规范化，避免不同设备 ICU/运行时导致排序变化。检索阈值和参数在盲评样例上做敏感性比较后才固定，不能用人工随手设定的半衰期冒充测量结果。不要用随机采样制造“像人类”的波动。

线索分成稳定实体线索（人物、物品、地点）、关系线索和经历线索。词表、别名和线索到记忆片段的映射必须可审核。若线索只匹配多个相似经历，NPC 返回“想起相似片段但无法确认”或向玩家澄清；不以 LLM 猜测事件归属。1.0 允许遗忘和残缺回忆，不允许错记。

BYOK 文本可以不同，但证据集合不能不同。NarrativeContext 只收到已授权 MemoryEvidence，每项带 eventId 和可展示事实片段；叙事输出的姓名、关系、物品、位置和历史断言必须能回指该回执、当前投影、批准 Canon 或 NPC 授权观察。模型输出不符合证据时，弃用该段并降级确定性模板。首版把权威结果和数值写在独立的结构化叙事槽位；高风险事实句用作者文本或规则模板，模型只改写允许的风格和感官描写。模型可附 factId/eventId 作为断言来源，程序能校验已结构化的字段，但无法形式化证明任意自由文本没有暗含新事实。因此状态回执永远是可验证依据；不得宣称开放式模型正文已被完整事实验证。

有限模型上下文不能保证在一次生成中装下全部授权历史。因此“永久完整回忆”可可靠承诺的是：底层观察未被衰减删除，所有记录有稳定索引，能够按线索精确查询，重要的身份/关系锚点有直接字段验证；不能据此承诺模型总能复述任意一段数百回合前的逐字原文。对“名字和关系”这类验收锚点，应设置结构化、可回放的 NPC 关系/披露记录并在 T80 场景直接核验。

### 4.6 时间、离线和回滚

记忆衰减只读游戏内分钟/时辰/日期和 NPC 亲历事件序列。现实时间不改变 NPC 可访问性。离线世界演化属于单独存档级开关，默认 off；现实时间只作为触发条件，真正结算的游戏时间不得超过经产品负责人批准的上限。当前可供评估的上限候选是 7 个游戏日，不作为已批准常数。

离线结算用起止检查点、事件序列范围和幂等 catch-up ID 生成可重复事件；时钟倒退按零补算处理，超过上限截断并显示回执。游客设备的现实时间可被修改，因此它只用于触发和有上限的低风险补算，不能授予重要奖励或制造不可逆结果；展示所用的时钟来源。NPC 死亡、物品被盗、任务失败不得在玩家不在场时发生。任何被排除的事件类型均需由规则白名单显式允许，不能通过 LLM 或后台 worker 绕过。

## 5. Mem0、UwU 与其他开源项目的采用决定

### 5.1 为什么接口职责优于直接依赖

Mem0 开源 SDK 支持自托管和替换组件；官方文档列出的 library 默认 LLM/embedding 使用 OpenAI，并以本地 Qdrant/SQLite 保存向量与历史，self-host server 则默认使用 Postgres/pgvector（Mem0 AI, “Open Source Overview”）。它适合做结构化资料的候选抽取、实体关联和语义检索实验，不适合作为人物设定唯一原件或强一致世界数据库。

UwU Memory 是 SillyTavern 扩展，做旧消息摘要和 RAG 检索；其 README 提供保留最近回合、摘要长度和检索数量配置。LanceDB 插件为可选项，没有插件会退回最近记忆且不做语义检索；摘要会依赖配置的摘要 API。它适合作为摘要流水线的参考，不是完整不可变剧情账本，也不能直接接入九霄的事件授权模型。（ICSLI）

因此落地成三个九霄自己的 port：

| 九霄职责接口 | 权威数据 | 外部适配职责 |
| --- | --- | --- |
| CharacterProfileMemory | 作者审批的角色档案、关系基线和结构化 Canon 事实 | Mem0-compatible adapter 可建立可删除/重建的语义检索索引；候选事实须回指审批来源，不能自动写回 Canon |
| PlotChronicle | DomainEvent、事件时间线和原始叙事版本/来源指纹 | UwU-style adapter 可生成按事件范围定位的长线摘要和 RAG 候选；摘要可检查、改写、重建，禁止直接供 NPC 绕过观察权限 |
| NpcCognitiveMemory | 授权观察日志、固定存档策略、检索规则与记忆证据回执 | 可替换确定性 TypeScript 实现、后续记忆引擎或离线比较器；任何外部模型只提供提案，不写权威观察或事件 |

Mem0 和 UwU Memory 的“融合”发生在职责与适配协议层，不能把两者的默认 SDK 数据表拼成一份互相读写的记忆库。1.0 默认实现应先使用项目现有 TypeScript/数据库技术，保持游客无模型、本地优先、可导出和可回放。达到离线能力、检索质量、延迟、数据隔离、迁移和维护指标后，再通过 ADR 引入可选 adapter。

### 5.2 值得对照的其他开源项目

“更强”取决于任务。GitHub Star、项目自报基准和功能数量都不能代替九霄回放集的对照结果。当前可核验项目的适配边界如下：

| 项目 | 公开资料能支持的能力描述 | 九霄适用位置与限制 |
| --- | --- | --- |
| Mem0 | 有 Node/TypeScript SDK、自托管和可替换组件；其 library 默认 LLM/embedding 是 OpenAI，默认向量与历史存储分别为本地 Qdrant/SQLite（Mem0 AI, “Open Source Overview”） | 可作为结构化角色资料的候选抽取或语义索引对照；Canon 原件、事实审批和 NPC 规则授权必须由九霄自己的结构化数据负责 |
| SillyTavern UwU Memory | 对旧消息生成摘要、保存向量并按上下文检索；LanceDB 插件缺席时退回近期记忆（ICSLI） | 可对照剧情摘要与 RAG 体验；它不是完整、不可变、逐事件可核对的剧情账本，摘要有损 |
| Hindsight | 将 retain/recall/reflect 等 memory 操作分层；retain 会用 LLM 抽取/规范化事实，recall 混合向量、关键词、图与时间检索，仓库报告其 benchmark 结果；公开实现以 PostgreSQL/pgvector 或 Oracle 等为主（Vectorize） | 适合作为 2.0 Agent memory 候选；仓库自报成绩不能证明九霄的规则权限、同签名可复现性或游客本地闭环，LLM 抽取/融合不能替代冻结的授权 grant |
| Letta | 提供带持久状态和可编辑 memory/tool 的 Agent runtime（Letta AI） | 可研究持久 Agent 状态编排；它不能因此取得 DomainEvent 或 NPC 授权 grant 写权限，且须评估服务和迁移成本 |
| memory-decay-core | 提供指数、幂律等衰减实现，但默认支持基于现实秒数的 auto-tick，搜索可能强化记忆（Memory Decay Core） | 可作为离线算法对照；默认时间和查询副作用不符合九霄的游戏时间与纯检索契约 |
| 九霄原生基线 | TypeScript 纯函数、固定授权 grant、可版本化策略与确定性排序 | 作为 1.0 的事实/权限基线；只有外部候选在同一 held-out fixture 有可重复增益，才评估可选接入 |

统一比较指标包括授权精度、事实召回、错误归属、拒答正确率、跨设备确定性、离线行为、P95 延迟、上下文 Token、存储成本、迁移可逆性和隐私路径。比较未完成前，不给项目排绝对名次。

**首选路线：** 先完成九霄原生、确定性且可回放的记忆能力；再把 Mem0 及其他检索器作为可插拔对照。此方案不是拒绝外部创新，而是拒绝让外部记忆状态获得规则写权限。

## 6. 分阶段实施路线

每个阶段只在依赖满足后启动。A 表示产品与 Canon 负责人，B 表示工程负责人；具体签收仍按[双作者分工与交付门禁](九霄1.0双作者分工与交付门禁.md)执行。阶段完成不等于公测通过。

### 阶段 P0：锁定契约和风险决定

- **依赖：** 本方案审阅；不依赖模型服务。
- **P0 已签收：** [P0 双记忆契约](九霄1.0-P0双记忆契约与评审记录.md) 和 [ADR 0002](adr/0002-npc-memory-modes-and-authorized-observation-ledger.md) 已于 2026-10-03 完成 A/B 审阅。签收只锁定契约，不代表对应代码、记忆库或 P1–P8 已实现。当前阶段状态以[独立缺口清单](九霄1.0P0-P8玩法与双记忆阶段缺口与人工交接清单.md)为准。
- **A 的交付：** 按用户已确认的两种模式语义编写玩家说明，不重新打开已定边界；为线索分类、残缺回忆语气、人物关系锚点和序章目标给出有来源的 Canon 输入。A 已确认 1.0 核心闭环排除离线演化、P7 后续单独裁决；若未来评估 P7，再另行批准上限和字段边界。
- **B 的交付：** 建立或更新 ADR；定义 ActionIntent、RuleDecision、DomainEvent、TurnReceipt、NpcObservationGrant、MemoryEvidence、PlotDigest 和 SaveMemoryPolicy 的版本字段；列出可信输入、可读权限、写入者和失败策略。

**步骤：**

1. 固定状态权威、NPC 授权观察和叙事证据三个边界。
2. 记录现有 exact-recall-v1/accessibility-v1 的迁移策略；不得把它们直接等同新存档模式，也不得改旧策略语义而不升版本。
3. 把当前裸 `memoryPolicyVersion` 升级为一个版本化 SaveMemoryPolicy 契约，至少固定 mode、policyVersion、schemaVersion、clockBasis、参数/词典制品哈希；将 NPC 可见性/授权策略版本独立建模，不能把它并入 mode。模式只能在建档或显式分支迁移时选择。为当前 SaveEnvelope 增加 branch lineage 字段并给出旧档策略。
4. 设计权威事件事务、冻结授权观察 grant/outbox 与模式库投影游标；在单一数据库事务内写权威事实和 outbox，不设计跨数据库双写。
5. 分开定本地 IndexedDB 与 S6 后云端 PostgreSQL 的存储边界、备份语义、权限角色与恢复方式；确认事件只在存档有效期内禁止自动删除，衍生索引/摘要可重建。
6. 建立无模型输入词表、已知/缺参/歧义/未知表达样例及序章世界字段清单；未知表达须以安全引用原输入请求确认，不能声称解析器理解了它。

**退出门槛：** 文档契约通过 A/B 评审；没有“全局事件可直接注入 NPC”“模型可确认游戏事实”或“摘要可替代事件账本”的未决字段。

### 阶段 P1：签署最小可玩规则和序章输入

- **依赖：** P0 的契约和现有 Canon 审核流程。
- **A 的交付：** 六类 S3 行动规则的前置条件、资源成本、成功、合法失败、拒绝、耗时、状态字段、边界样例；序章地点、人物、物品、阻碍、任务目标、文案和钩子。
- **B 的交付：** 规则输入/输出 schema、事件类型/负载、版本化状态投影和规则测试样例。

**步骤：**

1. 先为移动、修炼、物品取得/使用、交谈、基础战斗、任务签署完整规则表。
2. 明确观察属于什么领域行为：确定其会改变的已批准字段/事件；禁止把普通叙述包装成“状态已改变”。
3. 为首段五类输入逐一映射到 Rule Action 和 DomainEvent；确认任务完成必须被事件和投影验证。
4. 为每类行动给出成功、失败、重复、无资源、目标不可见、超时/取消和规则版本错误样例。
5. 作者先签内容与规则；工程侧确认事件重放、幂等和不变量可实现。

**退出门槛：** S3 G-03 所需签署实际完成；六类规则都可执行审查；首段 Canon 和奖励没有由工程或模型补写。若规则未签，继续停留 fail closed。

### 阶段 P2：完成权威回合事务与可核对回执

- **依赖：** P1 规则表签署。
- **工程范围：** packages/contracts、packages/domain、packages/db、apps/api，以及 apps/web 的本地规则调用和 IndexedDB 权威持久路径；具体以实施时的项目结构地图为准。

**步骤：**

1. 将确定性词表解析器输出限制为签署过的 ActionIntent schema；缺参数/歧义只返回 clarification，不触发 DomainEvent。
2. 规则函数在只读候选快照上结算；合法失败必须给规则结果；同一 idempotency key 重放第一次回执。
3. 复用现有 Postgres 事务仓储的 CAS/幂等/回滚结构，不再造第二套云端权威提交器；同一事务写 DomainEvent、状态快照、TurnReceipt、授权观察 outbox 和事件完整性摘要。浏览器端先在事务外生成所有确定性结果，再把 state、events、receipt、outbox 放入同一 IndexedDB database 的短 readwrite transaction；事务内不运行模型、不访问网络、不等待定时器或非 IndexedDB promise。任一权威写失败时整笔回滚；模式记忆库不参加这笔跨库事务。
4. 为浏览器端补存档事件表/对象存储及按 revision 回放检查点，保留本地事务离线可完成；API/PG 仅作为 S6 后的同步路径。禁止要求无配置新玩家必须先登录或连云端。
5. 建立从已提交回执到 UI 状态回执的映射；只展示能回指 eventId 和 stateRevision 的变化。
6. 叙事请求携带已提交事实与允许记忆证据，不允许再次请求规则层修改决定。
7. 超时、用户取消、模型 JSON/正文无效、进程崩溃和重复请求均从原 receipt 恢复，不重复消费道具或推进时间；投影失败由 outbox 恢复，不回滚已提交世界事实。

**退出门槛：** 每条显示给玩家的结算都可由数据库事件和投影复验；相同请求不重复提交；叙事重试前后事件、状态、游戏时间、NPC 观察数和回执修订完全相同。

### 阶段 P3：游客零配置行动闭环和可编辑按钮

- **依赖：** P2；真实签署规则和首段 Canon。
- **界面范围：** 首屏世界简报、行动编辑框、五类行动建议、状态回执和后续钩子。

**步骤：**

1. 首屏直接显示当前地点、上次停留点、已提交事件摘要和一条有证据来源的钩子；没有离线模拟事件时，文案明确世界未离线推进。
2. 提供移动、观察、交谈、使用物品、战斗建议按钮；点击后先填充可编辑自然语言，不直接绕过解析器。
3. 手输、编辑过的按钮文本和快捷键共用同一词表、别名、槽位解析和规则入口。
4. 已知且唯一的动作自动提交；可补齐的槽位询问具体缺项；歧义输入列出候选让玩家选。未知表达不推测意图：将玩家原文安全地引用为待确认文本，并展示可接受动作示例；确认前不结算、不推进时间、不写事件。
5. 无模型路径使用作者审核的叙事片段、规则化句式和状态回执完成整个 Q 任务。
6. BYOK 只在规则提交后生成叙事。它不得增加动作种类、提高成功概率或更改权限。
7. 等待时显示实际阶段（正在判定、已结算、正在叙述、可重试），不用虚假的“世界正在变化”动画暗示已提交事件。

**退出门槛：** 新玩家无配置能开始并完成首个任务；首个可点动作在目标设备首屏 3 秒内出现；目标新玩家完成首任务不超过 3 分钟。先在明确模拟视口验证，再安排真机门禁；模拟数据不能替代真机证据。

### 阶段 P4：接入 NPC 授权观察与“存档与继续”模式

- **依赖：** P2 权威本地事件事务、已签的 S3 规则与观察授权规则。云端 adapter 另依赖 S6 G-06，不阻断本地模式。

**步骤：**

1. 把调用方传入任意 visibleSummary 的弱边界升级成版本化授权投影器；每个观察 grant 明确 NPC、事件、来源渠道、获准字段、事实值快照、grantId 和规则/授权版本。投影器拒绝未列白名单的字段，不复制原事件 payload。
2. 世界事务只在权威 IndexedDB/PostgreSQL 中提交冻结 grant outbox；用 grantId 幂等物化至 Continue 独立记忆库。授权发放逻辑不可在投影延迟后按新规则重算。
3. 每个新存档初始化不可变 SaveMemoryPolicy；Continue 库的存储标签和适配器固定为 continue-v1，仅保留授权观察，不做访问性衰减。
4. 为姓名、关系、共同经历建结构化 anchor/实体倒排索引；精确查询用事件 ID、NPC ID、entityId、relationId、游戏时间范围和稳定 eventId 排序，不先上向量搜索。
5. 加载 NPC 上下文前检查授权游标是否追平回执要求的 revision；落后时从持久 outbox 对同一 grant 前缀确定性读穿/重建。outbox 或模式库不可用时，使用本回合 receipt 做无模型叙事，不返回旧游标记忆。
6. 为云端目标 schema 预先写 database/role/迁移约定；只有 S6 真认证、所有权、逐档授权和备份验收通过后才接入云端模式库。
7. 日志只保留安全授权 ID、游标和结果摘要；不记 API Key、私密正文或完整 NarrativeContext。

**退出门槛：** 同一 NPC 对未授权、未目击、未收到转述的事件检索始终为空；Continue 模式的授权 grant 不衰减；从同一事件/outbox 前缀重建得到相同授权观察；消费者重试不重复写入；不能从玩家总摘要、另一 NPC、另一模式或落后游标旁路获取事实。

### 阶段 P5：实现真实遗忘线

- **依赖：** P4 的完整授权观察基线；固定的游戏时间定义。

**步骤：**

1. 建立同一批已授权 grant 的盲评 fixture；比较指数基线与一个幂律/ACT-R 类可复现基线。指标先分别看无提示精确回忆、线索唤回、非目标遗忘、实体错配和运行成本，不用一个汇总分掩盖错误归属。
2. 建立与 Continue 完全独立的 Forgetting IndexedDB/PG 数据库及 `forgetting-v1` adapter；只从模式中立的授权 outbox 构建新分支，不复制 Continue 分数、检索 cache 或摘要。路由拿到错误 mode、branch 或 artifact hash 时 fail closed。
3. 固定点实现胜出的透明规则基线；把游戏时间跨度、该 NPC 后续授权 grant 数、片段显著性和类型化线索匹配作为版本化输入。通过参数敏感性和产品盲评后冻结新建存档策略；不得对旧档静默换版本。
4. 将观察拆成有限的授权事实片段，各片段携带来源与确定性访问分。唯一线索可以返回同一事件的完整授权片段；部分线索只返回命中的授权片段，显式标为 `partial`，不让模型填补未召回事实。
5. 纯检索不写入记忆；规则事件的显式反复经历或回忆后的新互动若要强化，必须有规则定义的幂等授权 grant，不能依赖“模型似乎想起来了”。
6. 建立遗忘曲线解释面板：最近记忆、线索是否匹配、游戏时间和事件来源可检查；不暴露未授权记忆或模型内部推理。
7. 对同一 fixture 做固定游戏时间重放、不同真实离线时长、不同运行时、浏览器刷新、分支复制和版本升级回放；用相同签名复算并逐字段比对。

**退出门槛：** 同一检索签名的证据结果按 grantId/eventId/片段逐项完全一致；无歧义线索零错配；遗忘只影响 NPC 片段检索，不改事件、状态、时间线或关系；未授权的全局事件甚至不能增加该 NPC 的 Δn；现实离线时长不改变 NPC 记忆；无模型模式可解释部分/未唤回片段。

### 阶段 P6：角色资料、剧情摘要和可插拔适配器评测

- **依赖：** P2 至 P5 的事实边界和可用本地记忆基线。

**步骤：**

1. 建立作者审批的结构化 CharacterProfile/Canon 查询接口；每个字段带 sourceId、版本、可见范围和审批状态。Canon 原件和确定性 ID/关系查找不依赖向量索引。
2. 存档叙事原文、规则事件和摘要三者分开保留。PlotDigest 记录覆盖的 event/turn 区间、生成器与 prompt 版本、输入/输出哈希、模型供应商/模型 ID、是否人工审核和重建状态。
3. 摘要采用异步、可重建流程。任务按事件范围幂等、可续跑并设并发/成本上限；失败时继续用近期回合和事件，不阻塞规则行动。
4. 添加 typed NarrativeContext：author-approved profile、当前 StateFacts、npc-authorized MemoryEvidence、scene context、style instructions 分类型排序；适配钩子在类型化 prompt 项形成后、Token 化前执行。高风险事实由核心从 canonical record 取回并重新授权，不能信任适配器返回的正文。
5. 定义最小 adapter 契约：输入仅为批准资料或带界限的事件范围；输出为候选 source ID、摘要 artifact ID 和来源区间；核心重新读取并校验来源、模式、NPC 权限和修订。适配器没有写 DomainEvent、Canon、授权 grant、MemoryEvidence 或状态投影的接口。
6. RisuAI/SillyTavern 的可见格式化器仅作为渲染阶段参考；不要把 AFTER_MARKDOWN 一类 DOM 格式化钩子误当成语义化模型提示钩子。
7. 在隔离 fixture 上对照 Mem0-compatible 和 UwU-style adapter。Mem0 官方提供 Node/TypeScript SDK，但其开箱默认仍包括外部 OpenAI LLM/embedding；可改 provider，不能据此假定已支持游客浏览器离线运行（Mem0 AI, “Open Source Overview”）。UwU 的流程是总结旧消息并将摘要用于 RAG；LanceDB 插件不可用时会降级为近期记忆。这证明它适合作为摘要/检索参考，不证明其摘要等同完整剧情账本（ICSLI）。
8. 外部语义索引只返回候选来源 ID；1.0 的 NPC 记忆结果仍由固定版本 TypeScript 检索内核决定。索引/摘要差异不得改变 Continue/Forgetting 的授权集合或精确记忆回放结果。游客首段不加载 Mem0/UwU 服务，也不需要 BYOK 才能完成首任务。
9. 用来源事件对摘要做事实覆盖、遗漏、时序、来源链接和错误合并评测；不合格摘要只重建，不改写事件。记录 adapter、embedding、模型和索引版本，以便复现实验，不把供应商自报 benchmark 当九霄验收数据。

**退出门槛：** 关闭所有外部记忆服务时，序章和两条 NPC 模式仍可运行；替换 adapter 不影响规则回执、授权集合、核心 NPC 检索回放或存档格式；每一段 NPC 历史摘要不能绕过显式授权；候选检索只有在预先固定的 held-out fixture 上显示可复现的效果提升、报告不确定性且错误归属/未授权召回仍为零时，才进入 ADR 讨论，不以单次跑分自动引入运行 adapter。

### 阶段 P7：存档级可选离线世界演化

- **依赖：** 在线/本地权威回合、时间规则、备份/分支和黑名单恢复已稳定。若这些条件缺失，整个阶段留在禁用状态。

**步骤：**

1. 开关只在建档/世界设置页由玩家显式开启，默认 off，并说明离线模拟范围。
2. 计算现实时间触发窗口，截断到经 A 批准的游戏时间最大值；现实时间本身不写成游戏事实。
3. 仅执行批准过的低风险环境事件；禁止死亡、失窃、任务失败、强制关系破裂和其他玩家不在场时不可挽回的结果。
4. 使用固定 catch-up ID、开始/结束修订和规则版本实现幂等；系统崩溃后从检查点重做不得重复推进。
5. 恢复在线后先展示拟结算事件和受保护事项；所有实际变化仍须通过规则事务并出状态回执。

**退出门槛：** 默认关闭的档没有任何现实时间依赖；开启档在相同检查点和触发窗口中回放一致；游戏时间不超批准上限；黑名单事件计数为零；系统时钟回拨不生成负时间或重复事件。

### 阶段 P8：整合评测、迁移与发布门禁

- **依赖：** P0–P6；P7 若未就绪，不阻断核心模式发布，但不得宣称离线演化已上线。

**步骤：**

1. 以同一条首段剧情分别运行无模型、BYOK、叙事服务超时、刷新/恢复、继续模式和遗忘模式。
2. 建立 80 回合以上 NPC 记忆长局：固定 Canon、授权事件、线索和模式；比较 T5 到 T80 人名/关系锚点、事实来源和遗忘线的可访问性变化。
3. 记录规则、事件、NPC 授权观察集、检索签名、摘要版本、模型响应状态和展示回执；密钥和不必要原始隐私内容不得进入日志。
4. 旧存档迁移必须可预览、可回滚。当前 `exact-recall-v1` / `accessibility-v1` 是检索策略名，不自动映射成 Continue / Forgetting 存档模式。若历史 grant 和策略来源可以完整证明，才允许生成迁移预览；否则保留旧存档只读兼容并要求玩家明确选新分支，不能从摘要或原始对话重建“当时 NPC 获准知道的内容”。迁移失败保留原档；从模式 A 到 B 必须基于授权账本建立新分支并重建，不覆盖旧档。
5. 故障注入覆盖权威提交后、消息读取、模式库写入后但游标提交前、摘要任务中断、浏览器配额不足、存档导入损坏和策略版本未知。恢复必须幂等；无法确定授权来源时 fail closed，不以另一个模式的数据填洞。
6. A 评叙事、角色、Canon 和误导风险；B 评事务、权限、可复现、隐私、性能与恢复。双方绑定同一 Git SHA 和验收结果。

**退出门槛：** 所有核心指标有原始证据、负责人和边界；“通过模拟”与“真机通过”、“mock”与“真实模型服务”分开报告；阶段文件及对应的 P 轨、S 轨缺口清单按实际提交更新。

## 7. 评测和成功指标

以下是后续实现必须达到的目标，不是当前测试结果。

先冻结带完整来源链的事件/grant fixture，再定义查询的目标 evidence ID、允许的部分召回和必须 abstain 的歧义查询。训练/调参、验证和最终验收按角色/场景/事件切分，不能把同一事件的改写句同时放进调参集和验收集。玩家线索按实体、关系、经历、错名和近似经历分层；保留“未知线索”和无授权线索作为负例。

结构化事实召回用自动指标核对 grant/fact ID、精确率、召回率、误归属和 abstain；叙事自然度与摘要质量另由不知道 adapter/模式身份的评审者按固定 rubric 盲评。两名评审者独立标注，报告一致性和分歧裁决，不把单一 LLM judge 分数当事实正确性。比较算法时报告每类结果、误差区间、fixture 规模和设备/运行时；离线 benchmark 结论不外推为真实玩家体验。

| 指标 | 计算/验收口径 | 目标 |
| --- | --- | --- |
| T5 到 T80 角色锚点 | 对继续模式中获得授权的测试 NPC 检查玩家名字与关系来源、答案及 eventId | 100% 返回正确的权威事实和对应授权观察；不把该结果外推为任意叙事回忆正确 |
| 无授权事件泄漏 | 对未目击、未转述、未授权及跨存档/跨 NPC 事件做查询与提示注入检查 | 0 条未授权 eventId 进入 MemoryEvidence/NarrativeContext |
| 遗忘可复现 | 固定 save/branch/NPC、规范化 query、游戏时刻、授权游标、policy artifact、线索词典/规范化/索引版本、候选限制和 decay version 后重复计算 | 有序 grant/event ID、片段和量化分值完全一致 |
| 误记 | 让玩家提供易混人物、物品、地点和相似经历线索，检验返回证据 | 1.0 不允许错误人物/事件归属；无法消歧时返回不确定或澄清 |
| 叙事失败不重结算 | 注入超时、拒绝、格式错误、取消和进程恢复，比较提交前后状态 | 事件集合、状态修订、游戏时间、NPC 观察和回执保持相同 |
| 行动空转 | 分母为有完整参数且被规则层接纳的有效在世界行动；澄清、拒绝、规则不允许动作排除。分子为无任何有意义的状态字段/领域事件结果 | <5%；游戏时间增加本身不能掩盖空转，不能用虚构好感/随机奖励压指标 |
| 首屏可行动 | 冷启动到首个真实可提交行动可见；分别记录目标设备和网络条件 | ≤3 秒；模拟视口和真机分开 |
| 首个任务完成 | 新存档、游客、零模型、无教程、无配置，从进入到规则确认完成 Q | ≤3 分钟 |
| 双模式隔离 | 跨模式、跨存档、跨分支搜索和恢复测试；比较存储域、索引与上下文 | 零跨域记录；切换必须显式新建分支/迁移 |
| 同源授权集 | 同一权威授权 outbox 分别投影至两模式；比较 save/branch/NPC/grant/fact ID 集 | 初始授权集合逐项相等；差异只能来自检索策略，不得来自授权漏发或越权 |
| 投影恢复 | 在权威提交、消息读取、模式库写入和游标更新之间逐点崩溃并重启 | 不丢 committed grant、不重复应用；游标落后时读穿/重建或回执降级，不读陈旧数据 |
| 遗忘线召回 | 固定授权 fixture，按预设游戏时间、该 NPC 后续授权观察数和可区分线索分层统计 | 报告精确率、召回率、线索唤回率和不确定率；在盲评前不预设最佳公式或伪造“人类相似度”目标 |
| 策略迁移 | 对已知与来源不完整的 legacy saves 运行迁移预览、取消、失败和重试 | 未识别的旧策略不得自动映射；失败零丢档；模式变化产生新 branch lineage |
| 离线演化（若实现） | 对相同检查点、相同触发和重试进行重放；记录游戏时间与禁变类型 | 上限不越界；黑名单结果为 0；默认关闭档不受现实时间影响 |
| 摘要可靠性 | 按来源事件核对顺序、实体关系、因果、删除/修订和出处；失败摘要可重建 | 摘要与事件冲突时事件优先；所有摘要声明可追踪到输入范围 |

每种模式都需覆盖事件重放、澄清无写入、拒绝无越权、重试幂等、模型关闭、摘要缺失、索引重建、存档分支、策略版本升级和损坏文件恢复。由未来实现提交补充/修改的测试；本方案文档提交本身不新增或运行代码测试。

## 8. 38 项创新方向的落位

| 用户提出的方向 | 1.0 实施位置或后续边界 |
| --- | --- |
| 1 心理参数化人格 | 先用少量作者可审查、映射到可观察行为的角色字段；“26 项指标”不因某框架提出就直接采用。 |
| 2 人格动态演化 | 后续让经规则事件驱动的有限状态改变可追溯；1.0 禁止模型自改人格底座。 |
| 3 表里人格/认知可见性 | P0–P5 以角色、NPC、玩家、场景和 system-only 分层授权；system-only 只服务程序，不能注入 NPC。 |
| 4 情绪持久化/情绪记忆 | 作为后续状态投影；必须区分观察到的情绪、角色自述与推断，不作为客观事实。 |
| 5 程序事实/人格解释分离 | 核心架构决定，P2 实装回执和叙事边界。 |
| 6 事件感知记忆图 | 以 DomainEvent、因果/先后引用和 NPC 观察作为首版底座；关系图检索后续评测。 |
| 7 分层叙事记忆与冲突 | P6 让摘要指向事件范围；冲突保留多版本来源，不静默覆盖 Canon。 |
| 8 生命周期/遗忘强化 | P5 仅做有版本的检索衰减；不删除事实、不做误记。 |
| 9 长短记忆双机制 | 短期为近几轮叙事缓存；长期为事件与 NPC 授权观察，边界在 P2–P6 固定。 |
| 10 显式记忆控制 | P4/P5 存档策略和 NPC 授权规则可见、可导出；运行时模型不能自行放宽。 |
| 11 四通道消息/场景导演 | 采用 Intent、RuleOutcome、EnvironmentFacts、Narrative 四类类型化数据；不持久化或向用户暴露链式私密思维。场景导演后续只能调度。 |
| 12 内源多角色社会 | 1.0 外；先保证单 NPC 授权认知和持久 ID，再做角色锚定。 |
| 13 空间/叙事对齐 | 先靠权威 location、presence 和可达规则；生成性场面调度放到后续。 |
| 14 多智能体协作 | 后续以职责明确的提案者/导演/演员做隔离实验；最终仍服从唯一规则事务。 |
| 15 事件驱动对话 | P2 事件与状态可驱动台词上下文；不得用模型微调替代可复现事件。 |
| 16 视觉感知 | 后续经玩家许可接入摄像头/截图，按模态、用途、保留时间做数据门禁；不是首轮玩法依赖。 |
| 17 虚拟形象表达映射 | 后续采用白名单表情/动作事件映射，不允许任意模型生成脚本直接控制客户端。 |
| 18 实时语音/口型 | 后续独立测端到端延迟、语音来源同意、字幕和文字回退。 |
| 19 程序化场景图 | 作为异步衍生资产；每轮提交后按需生成，不阻塞或重掷结算。 |
| 20 语义感知提示钩子 | P6 建立类型化 PromptItem；授权检查必须先于 token 化，扩展不得重分类受保护事实。 |
| 21 结构化消息格式化 | 分离叙事正文格式化、DOM 安全和模型 prompt 组装；UI hook 不是 prompt hook。 |
| 22 文件系统世界模型 | 可以作为作者可读内容源候选，但 Canon 发布和运行态数据仍版本化、审核并生成可校验构建。 |
| 23 无后端/客户端优先 | P3 目标为游客本地行动和无模型闭环；云端能力依赖已有 S6，不用“纯前端”掩盖权威、备份和同步需求。 |
| 24 跨平台统一代码库 | 属于平台横切轨道；玩法状态只维护一个共享契约，不因此提前承诺 iOS 或原生商店验收。 |
| 25 安全插件沙箱 | 1.0 核心闭环完成后再做能力白名单、权限提示、资源限额、版本签名、更新和撤销；iframe 本身不是威胁模型。 |
| 26 去中心化市场 | 1.0 非目标；先建立角色卡来源、许可、撤回、审核和确权规则。 |
| 27 社区扩展生态 | 1.0 非目标；插件生态上线前须有审计、评分/举报、依赖和更新治理。 |
| 28 内容安全/年龄分级 | 作为平台和发布横切门禁；具体分级需用户边界及运营政策，不由本方案杜撰。 |
| 29 IP 保护 | 原创角色和 Canon 保留来源/授权链；对导入资产做可撤回来源登记，模型辅助写作不能被视为授权证明。 |
| 30 数据主权/隐私 | P3 本地优先、BYOK；云同步仍由 S6 认证、同意和删除/导出门禁负责。 |
| 31 行为透明度 | P2–P5 回执显示状态差异、规则版本、观察渠道和检索来源；不泄漏 system-only 内容或私密推理。 |
| 32 神经符号强化学习 | 研究沙箱，不进入 1.0 规则；先建离线模拟器、明确奖励和越权率，再考虑有限策略评测。 |
| 33 人格参数化 schema 记忆 | 后续比较不同角色对同事件的观察编码；保留共同事件证据和人格解释的分离。 |
| 34 具身多智能体 | 依赖确定的空间/行动 schema、感知权限和多模态测试，列为研究方向。 |
| 35 历史角色平台 | 后续内容平台项目；需史料校勘、出处与教育性评估，不能从角色数量推断内容质量。 |
| 36 协作式世界编织 | 先有分支、时间线修订和可审计回滚；多人协作不是共享可变状态的理由。 |
| 37 心跳/主体性行动 | P7 后另设限权调度器；wait/none 是合法决策，但任何主动行动必须有规则授权、成本、限频和玩家可见回执。 |
| 38 持久化人格闭环 | 作为长期总方向，不作为 1.0 实现承诺；身份、记忆、环境感知和动作权限必须分阶段签收。 |

PsyMem、DREAM、Project Sue、EvoSpark、AdaMARP、feltstate、Engram、NSARL 等名称及截图中的 Wazone 网络展示，在本轮可复核的公开来源中没有逐一建立可验证的论文/仓库/版本对应关系。它们保留为研究线索，不当作已验证的实现或结果。提交实现任务前须补精确论文 DOI、仓库 URL、版本/commit、许可和可复现实验。可核实的 PersonaForge 是 ACL 2026 Findings 论文，报告其设定下的 88 个角色和最长 50 轮结果；这不证明九霄的 80 轮事件事实检索或规则正确性。（Tong and Zou）

## 9. 主要失败模式与拒绝条件

| 风险 | 可能后果 | 必须采用的处理 |
| --- | --- | --- |
| 把“继续”解释为读全局事件 | NPC 取得未目击/未获知秘密，玩家会话出现知识泄漏 | 直接拒绝这种实现；只能检索该 NPC 的授权观察 |
| 把摘要或向量库当世界账本 | 摘要丢事件、人物归属错、系统无法重放 | 事件与原始来源为权威；摘要和索引随时可重建 |
| 把自由叙事正文当成可形式化验证的事实 | 普通文本检查不能证明没有隐含新剧情事实 | 高风险结果由规则模板/结构化槽位表达；回执是唯一可核对事实凭证，不宣称模型散文已被完整验证 |
| 两种模式共用同一 NPC 检索索引 | 遗忘策略缓存污染继续档，或继续档的命中率泄漏到遗忘档 | 存储域、索引、cache key 和事务 scope 全部带 mode/version |
| 记忆按现实时间衰减 | 玩家离线越久越受惩罚且结果不可复现 | 禁止真实时间进入遗忘分数 |
| 模型解析行动直接结算 | 零配置/启用模型形成不同玩法权限与事实 | 1.0 统一确定性 parser 和 signed rule boundary；模型只叙事 |
| 观察、交谈变成无意义空事件 | 用“时钟前进”掩盖玩法空转 | 作者给每类行动定义真实字段/后果；只更新时间不自动算有效效果 |
| 绝对承诺无限/完整记忆 | token 限制使模型仍无法逐字记住每个细节 | 承诺存储不衰减和可按索引查询；关键锚点由代码测试，普通回忆统计召回率 |
| 过早接入 Mem0/UwU/Agent 平台 | 游客部署依赖服务，规则权限复杂，版本升级破坏存档 | 先做原生适配契约和对照基线；任一外部依赖须 ADR 和可逆迁移 |
| 为“像人”引入随机误记 | 玩家把错误事实当模型 bug，存档不能复现 | 1.0 禁止 misremembering；所有随机只在规则事件中有种子、版本和回执 |
| 心理参数化造成伪精确 | 数字看似科学但无效度，角色变成刻板人格 | 先定行为量表和盲评；不以临床或现实心理诊断包装 NPC 参数 |
| 插件沙箱只隔离 DOM | 网络、存档、资源耗尽和更新供应链风险仍存在 | 独立威胁建模和最小权限 API；核心结算不开放任意插件写口 |
| 忘记维护当前状态入口 | 方案被误作已上线或重复建立缺口单 | 本文只写目标路径；实际销账只分别回写 P 轨或 S 轨缺口清单与对应证据 |

## 10. 1.0 非目标

1. 错误人物归属、错误记忆、叙事不可靠者视角和模型自由篡改 NPC 信念。
2. 模型写 DomainEvent、调整数值或绕过规则签字。
3. 全自动多 Agent 社会、后台持续心跳行动、神经符号在线学习和用户数据自动训练。
4. 默认启用的离线世界演化，以及玩家离线期间的死亡、偷窃、任务失败。
5. 必须依赖 Mem0 云平台、UwU/SillyTavern 服务、外部向量数据库或 BYOK 才能运行的首段。
6. iOS/桌面/商店就绪、去中心化市场、公共插件市场、实时摄像头和实时语音上线声明。
7. 未来源审核、未获授权的角色、IP 资产和原项目源码复制。
