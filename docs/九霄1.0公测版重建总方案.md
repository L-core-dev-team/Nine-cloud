# 《九霄》1.0 公测版重建总方案

> 版本：2026-09-23。性质：目标、接口与发布门槛；本文件不表示功能已经实现。
> 适用范围：中国大陆优先的成人 Web/PWA 公测。项目仓库继续保持私有。
> 配套文件：[11 项建议与产品体验验收](九霄1.0产品体验与11项建议落实方案.md)、[双作者分工与交付门禁](九霄1.0双作者分工与交付门禁.md)、[分阶段实施与 AI 执行清单](九霄1.0分阶段实施与AI执行清单.md)。
> 优先关系：本次明确的 1.0 决策覆盖 `PRODUCT.md`、`九霄UI设计1.0方案.md` 中“只改视觉壳”“不得迁移 React”等旧约束。旧文件仍记录当时的 0 号试玩状态；实施时须更新其现行措辞，不得把旧状态说成新产品现状。

## 1. 判断依据与真正的问题

本方案合并了此前两版 1.0 方案与用户提出的 11 项意见。判断依据包括旧版 `D:/九霄_WEB_1.0_空白版.html`、当前 `work/v1.js`、`work/jx-motion.js`、`work/ai-settings.js`、两条构建脚本、现有仓库文档、附图及 GitHub 当前主线。并未逐张人工核实 182 份 OCR 的原图；原图尚未在当前仓库定位到。

| 已核查事实 | 对玩家或交付的影响 | 处理 |
| --- | --- | --- |
| 旧版“新开一局”把建角放在当前视口；现版切回首页，建角留在首屏下方；“进入世界”可打开空游戏页 | 用户无法从按钮推断结果，首页和游戏区职责重叠 | 重建显式路由与任务入口，并用旧功能对照表逐项验收 |
| AI 设置保留五岗位等底层能力，但“青鱼推荐配置”被改名，界面分组被压平 | 玩家误以为旧能力被删，也更难理解配置层级 | 恢复名称、说明、分组与真实 Model ID 校验 |
| 约 11.9 MB 的生成 HTML 内嵌约 8.26 MB 字符的字体数据；两张山门 WebP 约 146 KB、252 KB | 首包大，且“换小图”不足以解决问题 | 资源外置、按需加载、字体子集与真实设备测量 |
| `work/build_v1.py` 与 `work/build_worldbook_ui.py` 两条路径可能生成不同功能的版本 | 源码预览、测试物和发布物不一致 | 单一工作区、单一构建与同一制品的验收 |
| 182 份 OCR 记录仍标记待审核，原始截图缺席 | 不能把 OCR 草稿宣布为 Canon | 私有原图索引、逐图核对、双人审定后发布 |

[GitHub PR #3](https://github.com/L-core-dev-team/Nine-cloud/pull/3) 已合并。实现从当前 `main` 建分支，不从本地旧 UI 分支继续堆叠。任何“成熟”“高性能”“已上线”的结论均须有对应的浏览器、真机、后端或运营证据。

## 2. 1.0 的目标、范围和不可缩减门槛

1.0 让玩家在手机和桌面浏览器中，不经指导就能建角、续玩、阅读已审 Canon，并长时间游玩一份可保存、可恢复的独立修仙世界。完成首个任务后，玩家可继续使用 BYOK 或平台模型额度进行自由叙事。每份存档有自己的世界事件；不把 1.0 说成共享 MMO。

两位作者已经选择“全功能成熟后公开公测”：九境五域长线玩法、双记忆、NPC 认知、按需图像/视频、插件与 MCP 边界、社区、账号云档和三类付费均须具备实际能力与验收记录。仅做菜单或适配器占位不算完成。两人开发、无固定发布日期，因此采用逐关验证，不用日历日期倒逼虚假完成。内部阶段可预览和回退；缺少任何公开门槛时，不发布删减的公开预览。

外部阻断条件是原图目录、运营主体、支付商户能力、最终价格表，以及适用的游戏、生成式服务、个人信息和社区运营要求的专业审查结论。法务判断须形成记录；本文件不预断某项许可证必然适用。向境内公众提供生成文本、图片、音视频的服务受《生成式人工智能服务管理暂行办法》约束。

## 3. 玩家信息架构

| 路由或入口 | 唯一职责 | 必须完成的动作 |
| --- | --- | --- |
| `/` 山门入口 | 踏入世界 | 以“九霄”为主视觉，点击“进入世界”后到 `/lobby`；不在主标题重复品牌短句 |
| `/lobby` 山门内 | 选择下一步 | 有档突出“继续游玩”，始终可新开一局、阅读世界设定或进入设置；导入存档可从菜单访问 |
| `/new` 建角 | 完成开局 | 旧版全部字段分步填写、返回、草稿恢复、摘要确认 |
| `/world` 世界 | 阅读已审设定 | 搜索、来源与版本可见；游戏内阅读层关闭后回到原回合和滚动位置 |
| `/game/:id` 游戏 | 阅读、行动、查状态 | 人物、物品、任务、地图、记忆、存档与 AI 设置有稳定入口 |
| `/settings/ai` AI 设置 | 选择模型与诊断 | 青鱼推荐配置、五岗位、参数、真实 Model ID、连接测试和调用记录 |
| `/settings` 与 `/settings/privacy` | 个性化与数据控制 | 动效、声音、省流量、同步范围、导出、删除、隐私政策 |
| `/extensions` | 管理扩展 | 权限、来源、启停、失败记录与官方/本地扩展区别 |
| `/community` | 分享与阅读游记 | 玩家预览脱敏稿、确认提交、审核状态、撤回与举报 |
| `/store` | 查看权益与费用 | 云订阅、额度、网关费率及逐笔计量依据 |
| `/credits` | 鸣谢与许可 | 作者、资产、字体与开源依赖的正确署名 |

首屏在 360×800 手机和常见桌面视口里，能无需滚动找到开局或续玩、世界设定、导入存档。一个标签不承担跳转和展开两种互相矛盾的行为。游戏阅读面稳定且高对比；玻璃、粒子和光效只用于导航与短反馈。键盘、触屏、屏幕阅读器、弱动效、省流量和媒体失败均能完成同一任务。

## 4. 游戏规则、叙事和世界资料

权威链路固定为：

`ActionIntent → 规则校验/结算 → DomainEvent → 状态投影 → NPC 可知信息与记忆过滤 → 叙事生成`

`ActionIntent` 至少携带存档 ID、玩家输入或结构化动作、期望状态版本和幂等键。规则层决定地点、境界、物品所有权、货币、任务、伤亡等事实；事件不可由叙事模型、Jev、记忆插件或媒体任务直接写入。解析不明时请求澄清。叙事失败保留已结算结果，只重试文字；同一幂等键不得重复回合。游客在本地运行同一规则；登录云档由服务端校验并提交。云端不把可篡改的游客历史当成可信多人战绩。

作者先签署“九境 × 五域 × 系统”规则矩阵。移动、修炼、获得和使用物品、NPC 交谈、战斗、任务，以及已记载的修仙系统，都需覆盖长期进入条件、消耗、收益、失败、恢复与事件。每个境界与地区均有可完成的代表路径和边界测试；短开场不等于长线玩法完成。关键剧情骨架和禁则由作者写定。模型只变化合规的语言与有限分支，不发明 Canon。无模型密钥时，确定性序章可走到首个任务完成。

世界资料分为私有原图、OCR 转录、作者裁定、已发布 Canon 四层。182 份待校 OCR 必须逐张关联原图、哈希、来源、审定记录和版本；找不到图的条目保持待核。冲突由作者裁定，旧档可继续按其原 Canon 版本解释。玩家端不装入未审资料或私有路径。SillyTavern 与 Risu 提供版本化、可测试的导入导出兼容；它们的提示注入方式不取得九霄世界事实写入权。

双记忆模式在建档时选择，并记录策略版本。事件历史永不因遗忘而删除；遗忘只改变 NPC 的观察、检索和表达。NPC 只知道其地点、关系与事件传播链允许获知的信息。Jev 仅作为意图识别候选；在固定数据集上比较准确率、拒识、校准、延迟和成本，通过后才能替换当前识别器，不能成为规则裁判。

## 5. 场景、声音与生成媒体

采用已选择的 B 山门构图。首批另建野外、宗门或城镇、战斗或异变，共四类场景。每类交付静态海报、移动裁切、可独立开关的远景/中景/前景、局部运动及环境声；山门至少有瀑布、水面、云雾与灯光的可见变化。场景由已提交的地点、时间、天气与事件 ID 查版本化清单，模型不能返回任意素材 URL。图片或视频只在玩家请求关键事件时生成；先显示预计价格、等待和取消/失败结果，生成物不自动成为 Canon。

声音从玩家明确点击后启用，提供静音、音量和字幕/文本反馈。`prefers-reduced-motion`、省流量、低性能或视频失败时使用静态海报；动作入口、状态和剧情照常可用。图像、字体和音频外置，首屏只预载必要资源，按场景加载；资源须有来源、许可、压缩参数和失效替代图。以真机表现而非截图判定“电影感”。

## 6. 架构、存档、账户和安全

`pnpm` 工作区划分 Web/PWA、Node API、异步 worker、共享 domain/contracts/content/UI。React + TypeScript + Vite 管界面，Hono 管 HTTP 接口，PostgreSQL + Drizzle 管账号、云档、事件、审核与账本；媒体放国内可达、可迁移的对象存储。数据库任务表与 worker 租约承载异步媒体及邮件，不让浏览器等待长任务。部署脚本、数据库迁移、备份、恢复演练和健康检查与代码同版。开发可用容器启动所需服务；生产采用国内可达的托管基础设施，不绑定单一厂商。

核心接口按资源划分：认证、存档与修订、回合、世界版本、媒体任务、社区稿件、扩展目录、权益及账单。请求与响应都有版本，所有云资源逐对象鉴权、限流并记录可审计的结果码。邮箱验证码以哈希保存并限制尝试次数；会话使用安全 Cookie 与 CSRF 防护。密钥不进仓库、云档、遥测或错误日志。浏览器可安全直连的 BYOK 服务商免费直连；其他服务商只通过登录后的受限付费网关，密钥只在请求期流经服务端。平台模型额度与玩家 BYOK 分账。

存档使用带 `schemaVersion`、`canonVersion`、`ruleVersion`、`memoryPolicyVersion`、`revision` 的信封。迁移先导出旧 `localStorage` 原样备份，再校验并导入 IndexedDB；失败不删旧数据。玩家登录后才主动开启云同步，分别选择核心档、叙事与媒体。云写入必须带 `expectedRevision`；冲突由玩家选云端、本地或复制新分支，绝不静默覆盖。支持完整导出、删除及备份恢复验证。

扩展实行显式能力清单。官方插件经审核和签名；玩家本地扩展运行于隔离环境，只获脱敏只读视图，不接触密钥、网络或世界事件提交。插件/MCP 生成的建议必须经过玩家确认与权威规则。社区只收玩家预览并确认的脱敏游记，经过审核后发布；提供撤回、举报与删除流程。隐私政策要写清第三方模型会接收哪些叙事数据。

## 7. 三类付费与运营门槛

1. 云订阅：权益、续费、过期、取消及存档数据保留规则由签署的价格/服务表驱动。
2. 平台模型额度：展示单次预计消耗，实际调用按计量扣减；失败或取消按规则退回。BYOK 不收此项费用。
3. 付费模型网关：以可核对的供应商实际成本为基数加收 1%，逐次留计量明细及供应商账单关联；税费、汇率、退款独立展示。无法核对实际成本的供应商不进入该通道。

三者须同时经过支付签名、重复回调、断网重试、对账、退款、额度并发扣减和异常告警测试。1% 若不足以覆盖支付、转发与运营成本，停止该产品上线，由双作者重新批准定价；工程人员不得暗改费率。运营主体、商户账号、价格表、隐私政策及专业合规审查缺失时，整个 1.0 不公开。具体价格作为经双作者签署的数据配置，不硬编码在客户端。

## 9. 测试、风险和公开声明

自动测试覆盖：旧档原文与状态、建角全字段、五岗位与连接测试、九境五域规则矩阵、同一幂等键只结算一次、100 回合长局、两个账号互读被拒、断网同步冲突、记忆模式隔离、插件越权、媒体失败、账单重放和退款。两作者盲评随机 100 回合叙事，Canon 越权为零，语言通过率至少 90%；未通过项按事实错误、人物失真、重复模板或节奏问题归档重做。

真机覆盖 4–6 GB 内存的中端 Android、普通集显笔记本、平板及桌面；弱动效和省流量模式能完成开局到首个任务。以真实用户第 75 百分位 LCP ≤2.5 秒、INP ≤200 毫秒、CLS ≤0.1 为目标，另测场景五分钟持续帧率与音画同步。目标未达须记录设备、网络、样本量和原因，不以开发机演示代替公测验收。

最大结构性风险是：两位作者、无固定运营主体、未收到全部原图，却要求所有长期系统在 1.0 达到成熟深度。解决方式是明确阻断门槛、错峰交付和不设虚假日期；不能通过文案修饰把缺口改称“已具备”。Web/PWA 是 1.0 正式分发；Android、iOS、HarmonyOS 与桌面安装包须另做签名、更新、真机和商店验证，不在此版声称已通过。
