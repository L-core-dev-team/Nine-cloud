# P4 融合架构变更摘要（main @ d98c221）

> 生成日期：2026-10-09
> 归档目的：与《P4分支与主支对照裁决简报.md》并列，记录 PR #65（codex/p4-authorized-recall）融合进 main 后的架构变更全貌。
> 融合原则：保留 main 的「身份与谱系硬化」（#64），叠加 P4 的「记忆语义与召回纪律」——两者正交，生产路径行为零改变，能力就绪、接线留待下一阶段。

## 2. 领域层（`packages/domain/src/memory`）

- **`policy.ts`**：新增 `MemoryClass` 四分类（`current-state` / `historical-event` / `subjective-belief` / `unclassified`）+ `ObservationGrant.memoryClass?` 可选字段——未标注即 `unclassified`，永不作证据。
- **`turn-journal.ts`**（融合核心）：授权观察记录同时携带 `grantIdVersion`（main V2 身份）+ `memoryClass`（P4 分类），14 键精确校验；新增 supersession 类型与校验（`assertSupersessionInput` / `isSupersessionKind`，五种取代理由：premise-revised / relation-changed / entity-dead / item-moved / clue-invalid）；`prepareNpcMemoryTurn` 增可选 `supersessionsForEvent` 入参、输出增 `authorizedSupersessions`，并强制「取代事件的 NPC 必须同事件被授权」。
- **`recall-authorized.ts`**（新增）：纯函数检索核心。`recognizeAuthorizedMemoryCue` 只认显式记忆问句（非问句返回 null）；确定性检索四纪律：槽位隔离（历史问题不取现状行）、supersession 门控（被取代的 current-state → `stale-only` 弃权）、时钟上界（拒绝未来证据）、结果有界（≤16 候选，超出计入 omitted）。
- **外置 JSON**：`p4-recall-cues-v1.json`（槽位词表 + 160 字符上限 + 20 停用词）、`p4-recall-policy-v1.json`（continue 模式、clockBasis、匹配规则、`incompleteArchive` 纪律、forgetting 显式声明不可用）——SHA-256 实算验证与代码常量、DB CHECK 三方互锁。

## 3. 服务层（`apps/api`）

- **`npc-memory-recall.ts`**（新增）：召回消费层 `resolveNpcMemoryRecall`——policy 指纹不符即 fail-closed（`policy-unavailable`）；`throughRevision = resultingRevision − 1`（只读已提交历史，绝不重授权事件载荷）；分页上限 10,000 行、游标不前进即 `incomplete`（绝不部分输出）；current-state 命中降级为 time-qualified 确定性话术（「只是当时的情形」）。
- **`npc-memory-turn-transaction.ts`**：`getAuthorizedObservationPage` 增 `throughRevision` 过滤 + LATERAL 聚合 supersessions；`commitAcceptedTurn` 事务内原子写取代行（校验：取代事件 ∈ 本批次 RULES 事件、NPC 已授权、grantId 不重复）；outbox SELECT/INSERT 完成 14 列融合（main 的 `grant_id_version` + P4 的 `memory_class`）。
- **生命周期 / 导出**：`npc_memory_observation_supersessions` 纳入账户擦除顺序（最前）与账号数据导出源。

## 4. 身份体系（融合结果）

## 5. 生产行为影响：零改变

- `resolveNpcMemoryRecall` 无生产调用方；grants 全落 `unclassified`；supersession 恒空。
- 遗忘曲线（`retrieve.ts`）、`narrative-memory-context.ts`、`belief.ts` 未被触碰（与分支逐字节比对确认）。
- 全部门禁不动：`RULES_NOT_READY` / `LICENSE_PENDING` / `HUMAN_GATE`。
- 验证：typecheck 6 包 ✓、domain 125/125 ✓、web 175/175 ✓、api 30 文件 ✓。

## 6. 双记忆模式（Continue / Forgetting）状态

融合保留双记忆模式的原有实现（逐字节零触碰），P4 作为「模式中立」的第三条检索路径叠加其上：

| 路径 | 触发 | 与双记忆的关系 |
| --- | --- | --- |
| 叙述上下文（原有） | 每回合叙事生成 | 双记忆主战场——continue 直接取 / forgetting 走 accessibility 衰减，未动 |
| 授权召回（P4 新增） | 玩家显式记忆问句 | 模式中立新路径——外置 policy 声明 `mode: "continue"`，且明确 `forgettingMode: "Unavailable until a separately reviewed decay policy is pinned"` |
| NPC 认知过滤（原有） | NPC 视角提取 | 未动 |

- 双记忆要素（`memoryMode` 存档钉死、continue-v1 / forgetting-v1 检索策略、ADR-0002 模式中立授权观察 outbox）逐字节保留。
- P4 底座（授权观察 outbox）本就是双记忆共用证据层；「显式问句才召回」与衰减正交：直接提问的答案来自被授权且未被取代的观察，不被遗忘曲线静默改写（被规则取代的旧现状显式弃权）。
- **缺口（下一裁决点）**：① Forgetting 下的授权召回语义空白，等衰减策略评审钉死；② 召回管道接线时须把 `memoryMode` 纳入 `resolveNpcMemoryRecall` 前置检查，避免 Forgetting 静默走 Continue 逻辑。

## 7. 后续接线点（能力已就绪，未接线）
