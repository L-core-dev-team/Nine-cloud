## 0. 一句话结论

**P4 与 main 是正交叠加，不是互斥。**

- **main（PR #64 合并后）**做的是「身份与谱系硬化」——给授权观察加**版本化 grant 身份**（`stableGrantIdV2` 绑定授权策略）、存档 schemaVersion 3 的 **branch lineage 与 canon artifact 钉死**。
- **P4 分支**做的是「记忆语义与召回纪律」——给同一批授权观察加**签名的语义分类**（MemoryClass）、**规则作者主导的取代记录**（supersession，只标记不删除）、以及「只有显式问句才触发，外置 JSON+SHA-256 钉死，不完整即弃权」的**授权召回管道**。

两者语义互补，仅在 4–5 个共享文件的**文本**上相撞（非逻辑冲突）。融合工作量：**中等偏小，且对 main 现有行为零改变**。

## 2. P4 核心概念落点（已逐项核实）

| 概念 | 实现位置 | 关键证据 |
|---|---|---|
| **MemoryClass 分层** | `policy.ts`（`memoryClasses` 四枚举 + `ObservationGrant.memoryClass?`）、`turn-journal.ts`（record 必填 `memoryClass`，兜底 `unclassified`）、**0020 SQL**（outbox 加 `memory_class` 列 + CHECK + 召回索引） | 未标注分类的授权默认落 `unclassified`，**不作证据** |

## 4. main 侧 P4 未触碰的部分（确认零影响）

- `retrieve.ts`（遗忘曲线、四种 journal 内检索）、`belief.ts`、`memory.test.ts`、`retrieve-modes.test.ts`：与 branch **逐字节相同**。

- `server-turn.ts`：两侧 `prepareNpcMemoryTurn` 调用均**不传** `supersessionsForEvent`，`commitAcceptedTurn` 均**不传** `authorizedSupersessions`。

### ⚠️ P4 当前是「能力就绪、生产未接线」

`resolveNpcMemoryRecall` **没有生产调用方**（仅被 `NPC_MEMORY_RECALL_POLICY` 自己的测试引用）；`p1-prologue-plugin.ts` 的 `grantsForEvent` 也未产出 `memoryClass`/`supersessionsForEvent`。因此**合并后生产路径一切照旧**：outbox 行全落 `unclassified` 默认值、supersession 恒空、recall 无调用方——**行为零改变，风险极低**。

## 6. 给作者的裁决建议

1. **建议合并，方向为「保留 main 身份体系 + 叠加 P4 记忆语义」**——即：
   - 保留 main 的 `stableGrantIdV2`/`grantIdVersion`/schemaVersion3 lineage/semanticSha256；
   - 叠加 branch 的 `memoryClass` 分类、supersession 表与触发器、授权召回管道（`recall-authorized` + `npc-memory-recall`）、外置 JSON+SHA-256。
2. 需要真正动脑的三方合并集中在 **`turn-journal.ts` 与 `npc-memory-turn-transaction.ts`** 两个文件（预计各 1–2 小时细致手工合并 + 类型对齐）。
3. 合并后**可将 `resolveNpcMemoryRecall` 接线与否留作下一阶段决策**（branch 已明确搁置）；甚至可以先合并后接线、分别 PR。
4. 附带改动（AI 定价 / e2e / docs）中，**e2e 分支版本应丢弃**（与 #64 已入 main 的修复重叠），AI 定价可保留并核对。
