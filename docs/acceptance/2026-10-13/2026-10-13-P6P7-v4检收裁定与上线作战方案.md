## 二、CI 失败根因：我已定位到确切行

### 现象

```
Error: Contrast audit found 1 failing samples including professional AI
{"page":"ai-professional","theme":"day","width":390,"kind":"dynamic-text",
 "selector":"span.eyebrow","text":"五岗位分别选型",
 "color":"rgb(76, 61, 32)","background":[167,169,170],"ratio":4.46}
```

`rgb(76,61,32)` = `#4C3D20`。我按 WCAG 公式复算，与报告一致。

### 根因（不在 `.eyebrow` 本身，在选择器守卫）

`apps/web/src/style.css` 两行冲突：

```css
/* 607 行 —— 无守卫 */
:root[data-theme='day'] .eyebrow { color: #755c47; }

/* 983 行 —— 有守卫 */
:root[data-theme='day'] body:not(:has(.ai-page)) .eyebrow { color: #403024; }
```

`ai-professional` 页面**含 `.ai-page`**，所以第 983 行的 `body:not(:has(.ai-page))` **不匹配**。于是落回第 607 行的 `#755c47`。

我实测对比度：

| 前景 | 背景 `rgb(167,169,170)` | 对比度 |
| --- | --- | --- |
| `#755c47`（第 607 行，当前生效） | 同上 | **2.63** ❌ |
| `#403024`（第 983 行现成值） | 同上 | **5.34** ✅ |
| `#4c3628` | 同上 | 4.77 ✅ |

**所以这是守卫写错，不是配色选错。** 第 983 行已经有一个合规的 `#403024`，只是被 `:not(:has(.ai-page))` 排除在 AI 页之外。

### 修复建议（二选一，推荐前者）

**方案 A（推荐）** —— 为 AI 页补一条覆盖，复用现成合规值：

```css
:root[data-theme='day'] .ai-page .eyebrow { color: #403024; }
```

理由：不改动既有选择器语义，不影响其它页面，且值已实测 5.34，有充足余量。

**方案 B** —— 把第 607 行的 `#755c47` 整体加深为 `#4c3628`（4.77）。影响面更大，会改变所有日间主题 eyebrow 的观感，需你视觉确认。

⚠️ **注意**：第 607 行那条无守卫规则是全局的，`#755c47` 在别的背景上未必违规。**不要一上来就全局改色** —— 先补 AI 页覆盖，跑完整对比度审计看是否还有其它样本。
