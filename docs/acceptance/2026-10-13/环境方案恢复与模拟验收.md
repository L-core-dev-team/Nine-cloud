## 已修复的工程问题

1. 在真实 Wrangler 4.147.0 运行时复现旧版 /api//auth/guest 返回 200 SPA HTML。加入根 functions/_middleware.js 抢先处理 API 命名空间，并把 /api 根路径纳入 _routes.json；修复后异常 API 路径返回 JSON 拒绝，首页、SPA 路径和静态资源继续正常响应。
2. 生产 API 上游限定为精确 https://api.jiuxiaogame.cn origin，拒绝同域名的未批准端口。
3. Caddy 的路线 A 名单补齐 account/phone 根路径和凭据路径尾斜杠/子路径；拒绝再次解码会改变含义的路径。普通被封锁请求返回 404，残余百分号/反斜杠歧义路径返回 400，均未到达上游。
4. Caddy 固定 CORS origin、显式 180 秒响应头超时。禁止缓存和安全头覆盖边缘拒绝、正常代理与上游故障；修复实测发现的缓存头叠加以及错误响应缺头。
5. 公网 smoke 不再只看 HTTP 状态：health/ready/session 必须是 JSON，ready 必须报告 database=ok。CLI 模拟会拒绝 HTML 回退、伪装为 200 的不可用数据库及非法公网地址。
6. 恢复验收由固定 12 表名单改成枚举所有非系统 schema 中的实际表，同时对比逻辑数据以及列、索引、约束、非内部触发器。PostgreSQL 自身的 pretty deparser用于约束输出，保留 Boolean 优先级，避免 BETWEEN 展开后等价括号重排被误判；没有用字符串删括号来放宽校验。
7. 执行文档统一引用 2026-10-11 的“Pages + 境内 Node API、先 A 后 B”裁决，校正认证运行时、SES/SMTP 预检、迁移范围与备份覆盖；已有批准记录保持原样，未代签 Bird。
