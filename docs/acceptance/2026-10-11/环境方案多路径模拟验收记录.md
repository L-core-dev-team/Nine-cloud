## 2. 本次本地实现

- 新增仓库根 `functions/api/[[path]].js`、`functions/health.js`、`functions/ready.js`；删除原先位于静态 `apps/web/public/functions/` 的伪函数副本。
- 新增 `functions/_lib/api-proxy.mjs`：仅接受配置的生产 API origin；生产 origin 只允许从正式站点域名请求。Pages 预览域名不能代理到生产 API。`APP_ENV=simulation` 只允许回环地址 HTTP 上游。
- 路线 A 按已记录的 v2 名单，在转发前封锁凭据签发、游客升级、手机号认证和全部账号路径；路径判定兼顾编码斜杠、嵌套编码、重复斜杠和尾斜杠。诊断读接口继续透传。
- 请求头采用白名单，不信任浏览器传来的 `X-Forwarded-For` / `CF-Connecting-IP`；请求体上限 8 MiB；仅透传必要响应头；独立保留多条 `Set-Cookie`；API 与错误响应设 `no-store` 和安全响应头。
- `apps/web/public/_routes.json` 只将 `/api/*`、`/health`、`/ready` 路由到 Functions；补充静态资源 `_headers`。Functions 自行设置安全响应头，避免依赖不会应用到 Functions 的 `_headers`。
- 移除 `_redirects` 中 Wrangler 报无限循环的 `/* /index.html 200` 通配重写，依赖 Pages 对无顶层 `404.html` 单页应用的内置回退；修正文内过期的 Functions 路径说明。
- 基线 `deployment/Caddyfile` 已有同名单的 v2 `@blocked` 404 规则，位于 `reverse_proxy` 前；生产 Compose 已透传 SES 三项环境变量。本候选验证其现状但不改动两份生产 Compose。
- 新增 8 项中继单测和仅绑定 `127.0.0.1` 的假 API；GitHub Actions 加入 `pnpm test:pages-relay`。

## 7. 2026-10-12 中继上游主机固定补记

- 本地环境分支提交 `4d607b647bc0fb4b1cb6a0b97392f370225001a0` 修复了上游 URL 构造并增加回归测试。修复前，以合成请求直接调用 health handler：输入路径 `//health` 会先规范化通过 `/health` 检查，但 `new URL(rawPath, API_ORIGIN)` 将它解释为 scheme-relative URL，目标变成 `https://health/`。复现使用 mock `fetch` 捕获 URL，没有向该主机发出网络请求；若有路由层把此原始路径交给 handler，白名单中的认证头可能被转发到错误主机。

- 修复将 pathname/query 设置到已固定的 API URL 对象上，并校验最终 origin；新增“scheme-relative health paths cannot retarget the approved upstream origin”回归测试。精确代码提交 `4d607b647bc0fb4b1cb6a0b97392f370225001a0` 上执行 `pnpm test:pages-relay`：9/9 通过。GitHub 上该新提交的完整 CI 尚待运行。
