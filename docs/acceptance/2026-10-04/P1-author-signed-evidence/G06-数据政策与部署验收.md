## 1. 数据政策模板

```json
{
  "version": "data-policy-2026-XX.v1",
  "expiresAt": "2026-12-31T23:59:59Z",
  "approvedBy": ["LYL", "Bird"],
  "maxSaves": 20,
  "perSaveBytes": 1048576,
  "totalBytes": 10485760,
  "trashRetentionDays": 30,
  "backupPolicy": "<必填：托管方冷备期限与清除依据的书面引用，不可留空>"
}
```

### 校验规则（`loadDataPolicy` 实际执行）

| 规则 | 违反时 |
| --- | --- |
| 文件 ≤16384 字节 | `INVALID_DATA_POLICY` |
| `version` 匹配 `^[\w.:-]{1,200}$` | 同上 |
| `expiresAt` 可被 `Date.parse` 解析 | 同上 |
| `approvedBy` **同时含 `LYL` 与 `Bird`** | 同上 |
| `maxSaves` / `perSaveBytes` / `totalBytes` 为安全整数且 ≥1 | 同上 |
| `perSaveBytes ≤ totalBytes` | 同上 |
| `trashRetentionDays` 为 0–3650 的安全整数 | 同上 |
| `backupPolicy` 非空字符串 | 同上 |
| `expiresAt` 未过期 | `DATA_POLICY_NOT_READY` |

**政策过期或缺失时**：拒绝生产写入、拒绝永久擦除，但**不影响已提交事件的读取**。

### 拟定值须书面确认

`20 份 / 1 MB / 10 MB / 30 天 / 冷备 90 天` 全部来自 `LYL-05` 的**拟定值**，须运营主体书面签认后方可写入。

## 2. 九步部署清单（顺序不可换）

| 步 | 动作 | 通过判定 |
| --- | --- | --- |
| 1 | 运营主体书面签认数据政策 + 清理责任 + 冷备依据 | 有签认件与责任人 |
| 2 | 采购：境内服务器、域名、发件域、生产 SMTP、`AUTH_SECRET` | 密钥只进私有环境 |
| 3 | 备份现有数据库 | 有备份与 SHA-256 |
| 4 | 跑迁移（幂等） | 迁移退出码 0 |
| 5 | SMTP 连接预检（不发信） | 通过；**注意预检成功 ≠ 投递成功** |
| 6 | HTTPS smoke | 公网可达，`/ready` 绿 |
| 7 | **真实生产验收** | 本人邮箱实际到达 / 双账号隔离 / CAS 冲突 / 导出 / 注销后 401 / 恢复演练 |
| 8 | 冷备工单或演练回执 | 由运营方出具，脚本生成不了 |
| 9 | 评估是否开 `ACCOUNT_DELETE_ENABLED` | 默认 `false` |

**第 7 步不可省。** 直接跳到第 9 步是不可逆事故。

## 4. 回滚

| 场景 | 动作 |
| --- | --- |
| 迁移失败 | **绝不**在未备份时重跑；先隔离库演练 |
| 新镜像不兼容旧 schema | 停止写入 → 核对兼容 → 切回旧镜像 → 跑 smoke |
| schema 不兼容且无法回退 | 隔离库恢复已验证备份 → 核对后切换 |
| 任何情况 | **不自动删除迁移、不倒退 live 数据、不 force push** |

**必须有人值守并记录**：恢复点、允许的数据损失范围、回滚执行人与时间。
