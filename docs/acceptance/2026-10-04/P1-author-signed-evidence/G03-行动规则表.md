# G-03 · 行动规则表（可执行成稿）

> 状态：**按已签执行规格 v3.0 与当前 PR #45 reducer 核对的摘要；不是运行验收或 G1 签收。**
> 绑定：八种世界行动分属七组；`free_text` 只进入澄清，不是第九种结算行动。当前 reducer 与运行时状态见下方 2026-10-04 更新。
> 红线：`POST /api/turns` 在规则未签署并部署前必须继续返回 HTTP 503 `RULES_NOT_READY`。

---

## 0. 全局不变量（每条规则都适用）

| # | 不变量 |
| --- | --- |
| I-1 | 被接受的行动必有 ≥1 条 `source=RULES` 事件，`revision` 恰好 +1 |
| I-2 | 至少一个经签署的 `WorldState` 字段发生 before/after 变化 |
| I-3 | 游戏时间前进一个规则定义的时间格（`1 刻 = 15 gameMinute`） |
| I-4 | 合法失败若产生耗时/消耗/伤势/关系/任务变化，走**同样的事件与投影** |
| I-5 | 提交前的拒绝、缺槽、澄清：**0 事件、0 耗时、0 消耗** |
| I-6 | 同一 `idempotencyKey` + 同一正文 → 返回原回执；同键异正文 → `ENV_IDEMPOTENCY_CONFLICT` |
| I-7 | 叙事重试只重写文字，**不重掷规则结果、不重扣消耗** |

## 1. 时间与余量基线

```
一日 = 96 刻 = 1440 gameMinute
一刻 = 15 gameMinute
时辰 = 120 gameMinute（每时辰 8 刻）
新档 gameMinute = 300（卯时初刻）
```

**余量自检（必须作为一条自动化断言存在）**

```
最短通关消耗 = observe.scan(3) + move(5) + observe.scan(3) + observe.study(6) + combat(25) = 42
比值 = STAMINA_MAX / 42 = 100 / 42 ≈ 2.38
断言：1.5 ≤ 100/42 ≤ 3     ← 低于 1.5 会让「一次失误等一天」成为常态；高于 3 倍体力沦为装饰
```

**任何消耗值改动后，这条断言必须重跑。**

## 2. 七类行动

### R01 · 移动 `move(destinationId)`

| 字段 | 内容 |
| --- | --- |
| 槽位 | `destinationId`：非空字符串，必须是规则目录中的地点 ID |
| 授权 | 已知目标必须有当前位置的规则边且边为 `open`；目录登记的相邻未知目标进入 `unexplored` 合法失败；其余无边目标拒绝 |
| 耗时 | 正常 1 刻；绕行 2 刻；受阻 1 刻 |
| 消耗 | 正常 5 / 受阻 10 / 绕行 15 / 未探索 5 |
| 事件 | `move.arrived` / `move.blocked` / `move.bypassed` |
| 投影 | 视结果更新 `locationId`、`gameMinute`、`stamina`、`travelLog[]` 或 `injuryFlags[]`；移动不会自行增加 `knownLocations[]` |

**四种结果**

| 结果 | 触发 | 事件 | 投影 |
| --- | --- | --- | --- |
| 正常抵达 | 边存在且 `open` | `move.arrived{from,to,minutes:15}` | `locationId` 改；`gameMinute+15`；`stamina-5` |
| 路断 | 边 `state='blocked'` | `move.blocked{toward,reason:'rockslide',minutes:15}` | 位置不变；`+15`；`-10`；`travelLog+1` |
| 绕行 | 规则目录存在可用绕行边 | `move.bypassed{toward,via,minutes:30,extraMinutes:15}` | 位置改；`+30`；`-15`；写入规则目录 `shoulderScrape` 对应的伤势 ID |
| 未探索 | 目标不在 `knownLocations`，且当前边列在规则目录 `unexploredEdges` | `move.blocked{toward,reason:'unexplored',minutes:15}` | 位置不变；`+15`；`-5`；不新增已知地点 |

**硬拒绝**（`INPUT_NO_SUCH_TARGET`）：`destinationId` 不存在于任何地点表 → 0 事件 0 耗时。

**边界样例（每条必须有一个自动化用例）**

| # | 输入 | 期望 |
| --- | --- | --- |
| 1 | 目标 = 当前地点 | 拒绝 `ENV_ROUTE_NOT_CONNECTED`（当前地点没有指向自身的规则边） |
| 2 | 目标已发现但无边 | 拒绝 `ENV_ROUTE_NOT_CONNECTED` |
| 3 | 边 `blocked` | 路断，事件 `move.blocked` |
| 4 | 落石清除后再次走同边 | 转为 `move.arrived`（受阻边必须可恢复） |
| 5 | `stamina` 不足 5 | 仍按移动结果结算；扣减钳制到 0。当前 facts/event 没有 `exhausted` 字段，也不标记软失败 |
| 6 | 成功抵达后用新 `idempotencyKey` 再请求同一地点 | 新请求不是 `duplicate`；当前地点没有自环时硬拒绝 `ENV_ROUTE_NOT_CONNECTED`。只有同键同请求才由事务层返回原回执 |

**恢复路径**：任何 `move.blocked` 都不推进任务进度，玩家可换解法或次日再来。

### R02 · 修炼 `cultivate(techniqueId, minutes)`

| 字段 | 内容 |
| --- | --- |
| 槽位 | `techniqueId` 非空；`minutes` 正整数（单位：刻） |
| 授权 | 功法在已签规则目录中可用；`stamina>0`；进度未达 10000 |
| 耗时 | 实际尝试刻数 × 15 gameMinute |
| 消耗 | 每个常规刻 20 stamina；体力不足时最多额外强练一刻并扣至 0 |
| 事件 | `cultivate.attempted` |
| 投影 | `cultivationProgress`、`stamina`、`fatigueCount` |

| 结果 | 触发 | 进度 | 事件字段 |
| --- | --- | --- | --- |
| 正常 | 可支付常规刻 | 每个实际常规刻 `+800`，上限 10000 | `result:'progress'` |
| 带伤强练 | 常规刻后余 1–19 stamina | 最多额外 `+200` 一刻 | `result:'fatigue'`；`fatigueCount+1`；余体力扣至 0 |
| 硬拒绝 | 功法不在规则目录 / `stamina=0` / 进度已满 | — | `ENV_TECHNIQUE_LOCKED` / `ENV_STAMINA_EMPTY` / `ENV_CULTIVATION_COMPLETE` |

**边界样例**

| # | 输入 | 期望 |
| --- | --- | --- |
| 1 | `minutes=0` 或负数 | 拒绝（正整数约束） |
| 2 | `minutes=1000` | 请求可解析；实际尝试仍受当前体力限制，超出可执行刻数的部分不执行、不计时；事件保留请求刻数与实际刻数 |
| 3 | 进度已满再修炼 | 拒绝 `ENV_CULTIVATION_COMPLETE`；0 事件、0 耗时、0 消耗 |
| 4 | 同键同请求重试 | 事务层返回原回执，进度不变；换新键是新行动，会再次按当前体力和进度结算 |
| 5 | `stamina` 恰为 19 | 走带伤分支（非拒绝） |

**红线**：**首段不设突破阈值。** 进度满 10000 不自动突破，突破是玩家主动宣告的事件，规则表不得内建。

### R03 · 物品 `acquire_item(itemId, quantity)` / `use_item(itemId, targetId?)`

| 字段 | 内容 |
| --- | --- |
| 槽位 | `itemId` 非空；`quantity` 正整数；`targetId` 可选 |
| 授权 | 物品 `itemId` 存在于物品表；`use_item` 须持有该物 |
| 耗时 | 每次接受的取得或使用均为 1 刻（15 gameMinute） |
| 消耗 | 0（物品自身被消耗） |
| 容量 | `SLOT_MAX = 8`（格，非重量） |
| 事件 | `item.acquired` / `item.consumed` / `item.depleted` |
| 投影 | `inventory[]`、`effectFlags[]` |

| 结果 | 触发 | 行为 |
| --- | --- | --- |
| 取得 | 当前地点存在匹配物品的规则来源、来源未领、数量匹配且未满格 | `inventory+`；`item.acquired{itemId,quantity,source,sourceId,minutes}` |
| 数量归零 | 使用最后一件 | 自动移除；`item.depleted`；效果由 `item.consumed` 投影 |
| 使用成功 | 目标合法 | `item.consumed` + `effectFlags` |
| **目标不匹配** | 物品对目标无效 | 硬拒绝 `ENV_TARGET_MISMATCH`；不消耗、0 事件、0 时间 |
| 硬拒绝 | 来源不存在 / 来源已领 / 数量不匹配 / 容量满 | `INPUT_NO_SUCH_TARGET` / `ENV_SOURCE_ALREADY_CLAIMED` / `ENV_SOURCE_QUANTITY_INVALID` / `ENV_INVENTORY_FULL` |

**边界样例**

| # | 输入 | 期望 |
| --- | --- | --- |
| 1 | 同一 `sourceId` 重复领取 | 拒绝 `ENV_SOURCE_ALREADY_CLAIMED`；不同有效来源给出同一 `itemId` 时才会合并数量，不新增格 |
| 2 | 8 格满时取得第 9 类物品 | 拒绝 `ENV_INVENTORY_FULL` |
| 3 | 对非目标使用 `item_bishuifu` | 硬拒绝 `ENV_TARGET_MISMATCH`，物品仍在身上 |
| 4 | 用完最后一件 | `item.depleted` + `effectFlags`，`inventory` 无残留 |
| 5 | P1 存档含规则目录外物品 | P1 reducer fail closed，回 `ENV_PAYLOAD_INVALID`；旧档展示与迁移保留策略不由本 reducer 承诺 |

### R04 · 交谈 `talk(npcId, utterance)`

| 字段 | 内容 |
| --- | --- |
| 槽位 | `npcId` 非空；`utterance` 非空 |
| 授权 | NPC 规则目录位置与当前地点一致 |
| 耗时 | 每次接受的交谈为 1 刻（15 gameMinute） |
| 消耗 | 0 |
| 事件 | `talk.occurred` / `talk.topic_learned` |
| 投影 | `npcInteractionLog[]`、`clues[]`、`idleCount` |

| 结果 | 触发 | 行为 |
| --- | --- | --- |
| 命中主题 | NPC 获准知道且话题在白名单 | `outcome='on_topic'`；可 `talk.topic_learned{clueId}` |
| 未命中 | 输入在规范化后不匹配该 NPC 的任何白名单 utterance | `outcome='idle'`；`idleCount+1`；reducer 不生成回复文本 |
| 硬拒绝 | NPC 不在场 / 目标不存在 | `AUTH_NPC_ABSENT` / `INPUT_NO_SUCH_TARGET` |

**三条硬约束**

1. **不设好感度数值。** 当前投影只记 `npcInteractionLog[]`、`clues[]` 与 `idleCount`，没有 `met` 字段。
2. reducer 只递增未命中话题的 `idleCount` 并记录 `talk.occurred`；三连闲聊钩子和回复文本属于 PR-7 文字层，当前 reducer 不生成台词。
3. 重复命中话题仍按 `on_topic` 记录；已存在的线索不会重复写入。当前契约没有 `repeat` 结果。

**边界样例**

| # | 输入 | 期望 |
| --- | --- | --- |
| 1 | 问「洪荒妖林核心在哪」且无白名单精确匹配 | 记录 `idle` 和耗时；当前 reducer 不生成回复，**不拒绝**，也不从事件日志推断 NPC 知识 |
| 2 | 问「昨天谁刷了船底」且无白名单精确匹配 | 记录 `idle` 和耗时；不得凭事件日志回答，后续文字层负责提供回复 |
| 3 | 连续闲聊 5 次 | reducer 只将 `idleCount` 递增至 5；第三次后的钩子与闲聊台词由 PR-7 文字层负责，当前 reducer 不触发 |
| 4 | 同一话题问 3 次 | 三次均按已匹配主题记录；线索只首次写入；每次接受交谈推进 1 刻 |
| 5 | 对不在场的 NPC 交谈 | `AUTH_NPC_ABSENT` |

### R05 · 基础战斗 `combat(targetId, techniqueId?)`

| 字段 | 内容 |
| --- | --- |
| 槽位 | `targetId` 非空；`techniqueId` 可选 |
| 授权 | 目标在规则目录中，且目录声明的位置与当前地点一致；已清障目标不可再次结算 |
| 耗时 | 2 刻（30 gameMinute） |
| 消耗 | 25 stamina；受挫时 `spiritStamina` 另算 |
| 事件 | `combat.resolved` |
| 投影 | `spiritStamina`、`obstacleState`、`injuryFlags[]` |

**三态裁决（无随机数）**

| 态 | 条件 | 结果 |
| --- | --- | --- |
| 驱退 `clear` | 白昼；日课恢复后的 `stamina ≥ 25` 且 `spiritStamina ≥ 25`；规则目录配置的作业位或护身物条件满足 | 清障目标的 `obstacleState='cleared'`；`spiritStamina-25` |
| 险胜 `clear_wounded` | 白昼；两项余量均 ≥25，但未满足作业位/护身物条件 | 清障目标的 `obstacleState='cleared'`；`spiritStamina-25`；写入规则目录配置的 `daytimeInjuryFlag` |
| 暗时受伤 `clear_wounded` | 非白昼；两项余量均 ≥25（准备条件不改变此结果） | 清障目标的 `obstacleState='cleared'`；`spiritStamina-25`；写入 `darkInjuryFlag` |
| 受挫撤退 `retreat` | 日课恢复后的 `stamina < 25` **或** `spiritStamina < 25` | `spiritStamina=5`；前往规则目录配置的 `retreatLocationId`；写入 `retreatInjuryFlag`；不清障、不完成任务 |

**时机分支（`§4.7`）**

| 时段 | 战斗 |
| --- | --- |
| 白天 `300 ≤ gameMinute % 1440 < 1020` | 按上表三态 |
| 黄昏/夜间 `gameMinute % 1440 ≥ 1020` 或 `< 300` | 非撤退时清障战斗仍会结算，但按规则目录的 `darkInjuryFlag` 记伤；资源不足撤退时改用 `retreatInjuryFlag` |

**为什么不用随机**：胜负交给准备与判断，不交给运气。且 1.0 记忆机制未实现，永久死亡会造成不可恢复状态——问卷与裁决均指向「有惩罚但不致命」。

**边界样例**

| # | 输入 | 期望 |
| --- | --- | --- |
| 1 | `spiritStamina=0` 时战斗 | 拒绝 `ENV_SPIRIT_STAMINA_EMPTY`，0 事件 |
| 2 | `stamina=24` 时战斗 | 受挫撤退（**不是**拒绝） |
| 3 | 战斗后叙事超时重试 | 事件、投影、时间、奖励完全不变（不重掷） |
| 4 | 同一清障目标再次战斗且已 `cleared` | 拒绝 `ENV_TARGET_ALREADY_RESOLVED`；0 事件、0 耗时 |
| 5 | 黄昏战斗后立即回看 | 写入规则目录 `darkInjuryFlag` 指定的伤势；当前自动化夹具用 `injury_crowded`，该夹具 ID 不是 Canon 声明 |

### R06 · 任务 `quest(questId, choiceId)`

| 字段 | 内容 |
| --- | --- |
| 槽位 | `questId`、`choiceId` 均非空 |
| 授权 | `questId` 与规则目录一致；`choiceId='claim_reward'`；`status='completed'` 且尚未领取 |
| 耗时 | 每次接受的领奖为 1 刻（15 gameMinute） |
| 消耗 | 0 |
| 事件 | 清障时由对应行动写 `quest.completed`；领奖写 `quest.reward_claimed`；没有独立 `quest.progressed` |
| 投影 | `questState{}`、`ferryState`、`inventory[]`、`locationGraph` 解锁边 |

| 结果 | 条件 | 行为 |
| --- | --- | --- |
| 完成 | 已签清障行动将 `obstacleState` 置为 `cleared` | 同一事务写 `quest.completed`；`status='completed'`、`ferryState='clear'` |
| 领奖 | 完成且 `rewardClaimed=false` | `quest.reward_claimed`；按规则目录发放 `rewardItemId` 并开放/新增 `unlockEdge`；当前示例 ID 来自合成夹具，不是 Canon 事实 |
| 重复领奖 | `rewardClaimed=true` | 拒绝 `ENV_QUEST_ALREADY_CLAIMED` |
| 硬拒绝 | `questId` 未知 | `INPUT_NO_SUCH_TARGET` |

**完成时机**：配置为清障路径的战斗、绕行或白名单交谈，在同一事务把阻碍从未清除改为已清除时追加 `quest.completed`。观察本身只产出线索，不能单独完成任务。进入行动前的观察、物品和交谈准备顺序可调整；已有存档若阻碍已经清除而任务仍未完成，不会由后续无关行动追补完成事件。

**边界样例**

| # | 输入 | 期望 |
| --- | --- | --- |
| 1 | 未通渡就领奖 | 拒绝 |
| 2 | 领奖后再次领 | 拒绝，库存不变 |
| 3 | 战斗、绕行、交谈分别清障 | 各自只在其前置满足时改变 `obstacleState`；已清障后再战斗被 `ENV_TARGET_ALREADY_RESOLVED` 拒绝，交谈或移动仍按各自当前地点与规则边校验，不能统称为“目标不在场” |
| 4 | 非 `root` 分支领奖 | 当前 ActionIntent、DomainEvent、TurnReceipt 契约只允许 `branchId='root'`；非 root 在契约层拒绝。PR-2 没有分支存档或跨分支玩法 |

### R07 · 观察 `observe(targetId, method)`

| 字段 | 内容 |
| --- | --- |
| 槽位 | `targetId` 非空（可引用 `npc` / `location` / `obstacle` / `prop`）；`method ∈ {scan, study}` |
| 授权 | 目标属于当前地点；其他地点的目标硬拒绝 `AUTH_UNAUTHORIZED_TARGET` |
| 耗时 | `scan` 1 刻 / `study` 2 刻 |
| 消耗 | `scan` 3 / `study` 6 |
| 事件 | `observe.result` |
| 投影 | `observationLog[]`、`clues[]` |

| 结果 | 触发 | 事件字段 |
| --- | --- | --- |
| 有发现（首层） | 首次 `scan` 目标 | `result='found'`、`clueLevel=1`、`clueId` |
| 有发现（深化） | 首次 `study` 该目标 | `result='found'`、`clueLevel=2`、`clueId` |
| 无新发现 | 该目标已被 `study` 过 | `result='none'`、`clueLevel=null` |
| 受阻 | 规则目录标记的持续阻挡或黄昏遮挡 | `result='blocked'`、`blockedReason` |
| 硬拒绝 | 目标不存在 | `INPUT_NO_SUCH_TARGET` |

**首段观察矩阵**

| 动作 | 层次 | 产出 |
| --- | --- | --- |
| 芦花渡 · 环视 | 1 | `clue_ferry_stuck` |
| 芦花渡 · 细察船底 | 2 | `clue_ferry_scrubbed` |
| 芦花渡 · 细察舟具 | 2 | `clue_wrong_way` |
| 望气台 · 环视 | 1 | `clue_rockslide` |
| 望气台 · 细察落石（白天） | 2 | `clue_crow_nest` |
| 望气台 · 细察落石（再次） | — | `none` |
| 望气台 · 细察落石（黄昏） | — | `blocked{too_dark}` |

**红线**：**任何成功的观察必须产出 `clueId` 或明确的 `none`。** 只返回感官描写视为未实现。

**边界样例**

| # | 输入 | 期望 |
| --- | --- | --- |
| 1 | 同一目标 `study` 三次 | 第一次 found，第二次 none，第三次 none |
| 2 | `scan` 两次且对应 clue 已知 | 第二次 `none`，因为没有新增线索 |
| 3 | 观察其他地点目标 | 硬拒绝 `AUTH_UNAUTHORIZED_TARGET`；规则阻挡/天暗才结算 `blocked` |
| 4 | 黄昏细察落石 | `blocked{too_dark}` |
| 5 | 观察无目标内容物 | `none` |

## 3. 事件目录（汇总）

| 行动 | 事件 | payload 必备 |
| --- | --- | --- |
| 移动 | `move.arrived` | `from, to, minutes` |
| 移动 | `move.blocked` | `toward, reason, minutes` |
