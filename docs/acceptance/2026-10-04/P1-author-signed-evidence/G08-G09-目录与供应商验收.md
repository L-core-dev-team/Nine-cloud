# G-08 · 模型目录来源核对

## 1. 核心立场（建议维持）

**不做实时价格自动同步，做「来源可审计」。**

理由：自动抓价会引入两个新问题——价格随时变导致估价不可复现；抓取失败时无法判断该信什么。这与本项目「相同签名必得相同结果」的可复现承诺直接冲突。

## 2. 来源登记模板

| 厂商 | 来源类别 | 采集日期 | 来源 URL | 币种 | 单位 | 地域 | 计费档 | 上下文 | 状态 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| | 原厂/聚合/托管/本地/自定义 | | | | 每百万 token | | | | active/deprecated/unavailable |

**来源类别必须区分**：聚合目录（如 OpenRouter）**不能**通过 author 字段反推原厂全集。

## 3. 五类必须正确处理的情况

| 情况 | 处理 | 禁止 |
| --- | --- | --- |
| 型号已退役 | 标 `deprecated` 并过滤出可选列表 | 继续展示并可选 |
| 账号/地域无权限 | 标 `unavailable` 并说明原因 | 当作「不存在」 |
| 价格缺失 | 标 `unknown`，**不精算** | 猜零或沿用旧值 |
| 来源冲突 | 标 `conflict`，**不精算** | 取其一 |
| 超过 90 天 | 停止精算，显示「快照已过期」 | 继续当作现价 |

## 4. 必须写进界面的声明

> **当前目录不是全球全集，也不是实时价格。** 型号须按你的账号与地域实际核对；缺价、冲突或已过期时不做估价。

## 5. 若要做定时采集（暂不建议）

必须先写 ADR 定：官方源失败如何回退、采集频率、变更如何审查、变更报告如何发布。在此之前不做。

# G-09 · 真实供应商验收

## 1. 铁律

| # | 规则 |
| --- | --- |
| 1 | 每人用**自己的** Key；不共享 |
| 2 | 页面 Key 只在页面输入；命令行探针 Key 只从当前进程环境读取，**不写文件、不写仓库、不写截图、不发聊天** |
| 3 | 刷新或关闭标签页后 Key 失效，需重输 |
| 4 | **LYL 的 Key 测出的结果不能替 Bird 签** |
| 5 | mock、模拟 200 响应**一律不算验收** |

## 2. 验收顺序（不可跳）

| 步 | 动作 | 记录 |
| --- | --- | --- |
| 1 | 验 `story`（**首个必验岗位**；探针脚本只覆盖此岗） | 协议、真实 Model ID、HTTP 码、耗时、用量 |
| 2 | 逐个开其余四岗位 | 每个**单独**记录，不合并 |
| 3 | 验协议差异 | 哪些字段必须省略（采样/上下文/格式/流式…） |
| 4 | 验重试与超时 | 重试是否重复计费；取消是否释放控件 |
| 5 | 验成本 | 单次实际消耗 vs 估价 |
| 6 | 账号/地域无权限的 | **记为该路径不可用** |
| 7 | 汇总脱敏 | 写 `AI_CONFIG_G1_PACKET.json` |

## 3. CORS 受限的处理

若供应商账号有浏览器 CORS 限制导致**无法在页面直连**：

1. 记为「该路径在当前账号/浏览器下不可用」；
2. 由运营方按**已批准范围**配置私有服务端适配；
3. **不得使用公共代理绕过。**

## 4. 验收包结构

```json
{
  "rcSha": "<RC_SHA>",
  "artifactHash": "<ARTIFACT_HASH>",
  "reviewer": "LYL | Bird",
  "roles": [
    {
      "role": "story",
      "required": true,
      "protocol": "openai-chat | anthropic | gemini | ...",
      "modelId": "<真实 Model ID>",
      "accountRegion": "<实际区域>",
      "httpStatus": "<脱敏>",
      "latencyMs": 0,
      "usage": { "input": 0, "output": 0 },
      "retryBehavior": "<是否重复计费>",
      "result": "pass | fail | unavailable",
      "signedAt": "<ISO8601>"
    }
  ]
}
```

**不得包含**：Key、完整提示词、完整响应正文、玩家隐私。

## 5. 判定

| 情形 | 结论 |
| --- | --- |
| 五个岗位全部 pass | G-09 技术侧闭合 |
| 某岗位因账号/地域 `unavailable` | 该岗位**不计入已验证**，须标注 |
| 只有连接探针成功 | **不算验收**——须跑通真实回合叙事 |
| 任一岗位用的是 mock | G-09 不成立 |


### CLI 探针边界

`tools/verify_provider.py` 只探测 OpenAI Chat Completions 兼容的 `story` 岗位，不覆盖另外四岗、完整游戏回合、Anthropic/Gemini 原生协议或成本限额验收。Key 通过 `JIUXIAO_API_KEY` 进程环境读取；`JIUXIAO_EVIDENCE_OUT` 必须指向仓库外绝对路径。报告仅包含脱敏状态、时延、有限 Token 计数和响应字符数，不含响应正文。完整 G-09 仍须按上表逐岗位验证并记录。
