## 0. 为什么必须有这份东西

P1 已冻结的事实里有两条会互相打架：

- 底稿 §23：**授权观察永不删除**
- 底稿 §9：**1.0 不允许错误人物归属、错误记忆**

问题是：T10 玩家当众羞辱 NPC，T50 双方和解。T10 那条观察按前者**必须留着**；但如果检索时把它当**当前状态**返回，就构成后者禁止的「错误记忆」。

**解法不是删除，是分类 + 前提校验。**

---

## 1. 三类认知（作者决策已确认）

| 类别 | 定义 | 例子 | 随时间变化 | 可被 supersede |
| --- | --- | --- | --- | --- |
| **① 当前状态命题** | 描述「现在是什么」 | 「我们现在是仇敌」「渡口现在堵着」 | ✅ 会变 | ✅ 可以 |
| **② 历史事件** | 描述「发生过什么」 | 「T10 他在渡口羞辱过我」 | ❌ 永不为假 | ❌ 不可以 |
| **③ 主观信念** | NPC 自己的看法 | 「他大概还在气头上」 | ⚠️ 会漂移 | ⚠️ 由规则处理，不删事件 |

**判定规则（自动分类器用）**

```
if 断言含「现在/此刻/目前」等时间指向 → ①
else if 断言含过去时制且指向已提交事件 → ②
else if 断言标记为 inference/opinion → ③
else → 拒收，不得入 MemoryEvidence
```

## 2. Supersession 规则

### 2.1 生效条件（全部满足才生效）

1. 被取代的观察属于**类别 ①**；
2. 存在**后续已提交的 `DomainEvent`**，其规则明确规定该前提已改变；
3. 该事件在**同一存档、同一分支**内；
4. supersession 记录由**规则事务原子写入**，不得由模型判定。

### 2.2 存储

```
observation_supersessions(
  saveId, branchId,
  observationGrantId,      -- 被取代的观察
  supersededByEventId,     -- 使其前提失效的后续事件
  kind,                    -- premise-revised | relation-changed
                             -- entity-dead | item-moved | clue-invalid
  reason,                  -- 规则产出的可读说明
  policyVersion
)
唯一键 (saveId, branchId, observationGrantId, supersededByEventId)
```

**不新增删除路径。** 旧观察完整可查，只是检索结果携带「已被什么取代」。

### 2.3 检索返回形态

```ts
type Recall = {
  observation: NpcObservation;      // 原始观察，不改
  accessibility: number;            // 0–1
  anchorKind?: 'fact-anchor';       // 事实锚点
  supersession?: {                  // 存在则必带
    supersededByEventId: string;
    kind: SupersessionKind;
    reason: string;
  };
  ambiguousWith?: string[];         // 相似但无法确证
};
```

### 2.4 叙事装配约束（最关键的一条）

| 观察状态 | 可进入 `NarrativeContext` 的位置 |
| --- | --- |
| 无 supersession 且未衰减 | 任意位置 |
| 有 supersession，**当前状态槽位** | ❌ **禁止** |
| 有 supersession，**历史槽位**（玩家明确追问往事时） | ✅ 必须携带 `supersededByEventId` |
| 类别 ③ 主观信念 | 仅「NPC 怎么看」槽位，且须标为 opinion |

**一句话**：变的是「我记得多清」，不是「发生过没有」。

## 3. 线索唤回契约

### 3.1 线索三型

| 型 | 例 | 作用 |
| --- | --- | --- |
| 稳定实体 | 芦花渡、避水符、岑九 | 精确定位 |
| 关系 | 摆渡人、仇敌 | 缩小范围 |
| 经历 | 落石、刷船 | 可能匹配多条 |

### 3.2 三种返回形态

| 形态 | 条件 | 返回 |
| --- | --- | --- |
| 完整 | 唯一强匹配 + 未被 supersession | 该观察完整 `authorizedFacts` |
| 部分 | 多条弱匹配 | 命中片段 + `ambiguousWith` + 显式 `partial` |
| 弃权 | 无匹配 / 匹配到的都未获授权 | **不返回任何片段**，附「想不起来」 |

### 3.3 三条硬约束

1. **线索只能提高可访问性，绝不扩大授权。** 线索命中不改变 `authorizedFacts` 的白名单。
2. **线索不得把类别 ② 的历史变成 ① 的当前。** 唤回历史只回答「当时」。
3. **无证据时必须弃权**，不得把空 `MemoryEvidence` 交给模型让它编。

### 3.4 弃权话术模板

```
「想不起相似的事。」        —— 无匹配
「像是见过类似的人，但拿不准。」  —— ambiguousWith 非空
「那件事后来怎么样了？」      —— 命中但已被取代，转向当前状态询问
```

## 4. 事实锚点（不受衰减）

| 项 | 规则 |
| --- | --- |
| 范围 | 姓名、关系等级、是否已结识、关键承诺、当前地点 |
| 存储 | 结构化字段，**不是检索片段** |
| 衰减 | **不受衰减影响** |
| 边界 | 只回答「现在是什么关系」，**不得携带情节细节** |

**为什么单列**：调查问卷显示「名字和关系」是玩家最在意的记忆锚点，而公式化的衰减会让它随时间失效——那样 T5–T80 的验收指标永远达不到。

## 5. 两模式隔离

| 维度 | 存档与继续（Continue） | 真实遗忘（Forgetting） |
| --- | --- | --- |
| 初始授权观察集 | **完全相同** | **完全相同** |
| 检索可访问性 | 不衰减 | 随游戏时间与亲历事件数衰减 |
| 线索唤回 | 可 | 可，返回完整或残缺 |
| 存储域 | 独立库 / 独立索引 / 独立 cache key | 同左 |
| 切换方式 | 新建分支重建，**不复制衰减分数** | 同左 |

**隔离红线**：两模式不得共用同一 NPC 检索索引、不得互相回退、不得在运行时静默切换。

## 6. 六条验收用例（必须先红后绿）

| # | 用例 | 期望 |
| --- | --- | --- |
| T-1 | **错误前提抵抗**：T10 羞辱、T50 和解后，NPC 被问「你还记得他羞辱过你吧？」 | 返回该观察**并携带 `supersededByEventId`**；不得以肯定语气当作当前事实 |
| T-2 | **当前状态解析**：问「他现在怎么看我」 | 返回关系状态字段；**不得**引用被取代的关系类观察作为当前值 |
| T-3 | **历史不可篡改**：问「渡口那天发生了什么」 | 完整返回 T10 观察，**不带** supersession 标记（因为这是问历史） |
| T-4 | **授权不越界**：查询另一存档的事件、未目击事件 | 恒空 |
| T-5 | **同源授权集**：同一 outbox 分别投影两模式 | 初始授权集合**逐项相等**；差异只允许来自检索策略 |
| T-6 | **同签名可复现**：固定全部签名输入重复检索 | 有序 grantId/片段/分值**完全一致** |

**T-1 是这六条里最关键的一条。** 它不过，G-04b 不能算闭合。

## 7. 与现有代码的差距（供 Bird 排期）

| 差距 | 现状 | 目标 | 阶段 |
| --- | --- | --- | --- |
| 授权 grant 字段 | `ObservationGrant` 仅 4 字段，授权边界外置给调用方 | 含 grantId、grantSequence、冻结 `authorizedFacts`、授权策略版本 | P2 |
| 授权 outbox | 未发现模式中立的持久化 outbox；journal 达 64 KB 会 splice 旧观察 | 权威 outbox 原子持久化，journal 只是派生投影 | **P2/P4 最高优先级** |
| 检索签名 | 4 项，policyVersion 不在签名内 | 覆盖全部策略与规范化输入 | P5 |
| supersession | 无 | 新表 + 规则事务写入 + 检索透传 | P4 |
| 锚点 | 无 | 结构化字段，免衰减 | P4 |

> **注意**：授权 outbox 是本项目**唯一一个「架构缺陷级」缺口**——journal 裁剪会静默删掉 NPC 当时的授权观察，导致「不遗忘」这一核心承诺在容量压力下失效。它属于 P2/P4，**但不阻止 P1 签署规则与 Canon**，只是必须在那之前补上。
