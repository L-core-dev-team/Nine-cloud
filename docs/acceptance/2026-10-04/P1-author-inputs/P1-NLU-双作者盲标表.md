## 四态定义（统一口径）

| 态 | 含义 | 世界事件数 |
| --- | --- | --- |
| **完整** | 唯一命中，槽位齐全，构造 ActionIntent 交规则层 | 由规则层裁定；被接受则 ≥1 |
| **缺槽** | 动作可识别但缺必要槽位 → 澄清 | **0** |
| **多义** | 命中多个合法动作或目标 → 给候选 | **0** |
| **未知** | 词表无法可靠映射，或否定/条件/指代未解析 → 原文回引确认 | **0** |
| **硬拒绝** | 解析通过但规则层前置不成立 | **0** |

> **关键区分**：缺槽 / 多义 / 未知是**解析层**结论（玩家补信息后可继续）；硬拒绝是**规则层**结论（补了也没用）。

## 陷阱条目（误接受判定重点）

| ID | 若出现下列行为即为**误接受** | 期望分类 |
| --- | --- | --- |
| NLU-06 | 剥离「不要」后执行 `move` | 未知（否定） |
| NLU-07 | 剥离「如果天没黑」后执行 `move` | 未知（条件） |
| NLU-08 | 把「那边」解析为 `loc_wangqitai` | 未知（指代）——**注意不是「缺槽」** |
| NLU-09 | 把「老李」当作可交谈 NPC | 未知 |
| NLU-10 | 为满足该输入而新增 `loc_honghuang_yaolin_core` | 硬拒绝 |
| NLU-11 | 把 `utterance` 内的否定当作玩家自身否定 | 完整（talk） |

> **分类准确性同样重要**：`missing`（玩家补信息后可继续）与 `unknown`（要求换说法）是两种不同体验。
> 0 事件结论相同，但**分类必须与 `action-parser.ts:322` 的回引文案一致**，否则 UI 会给出错误引导。

## 附：解析器已核验的三条设计（2026-10-04 逐行确认）

| 位置 | 行为 |
| --- | --- |
| `:89` | `NEGATION_OR_CONDITION` 拒绝「不要/别/不去/不想/不应/不能/没/未/如果/假如/要是/除非/等到/等…再」 |
| `:90` | `UNRESOLVED_REFERENCE` 拒绝「那边/这里/那里/这个/那个/它/他/她/刚才/之前/上次」 |
| `:129-132` | **speech 守卫**：若匹配到 `talk` 模板，则文本视为「对 NPC 说的话」而非对系统的指令，**跳过**上述两条拒绝。这保证 NLU-11 的 `utterance` 内否定不会压掉 talk 动作 |
| `:277` | **模板自身也不允许**以否定/指代词开头，防止有人写「不要去…」这类模板绕过 |
