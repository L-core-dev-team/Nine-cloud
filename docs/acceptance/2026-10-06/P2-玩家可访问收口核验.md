## A · 生产玩家路径

### A1 生产构建实际可用的页面路径

`apps/web/src/main.tsx:436,439-440` 将 `P2ReviewGame` 限制在 `import.meta.env.DEV` 分支；`:741-747` 的本机候选 store/reducer 也只在该分支加载。构建产物搜索结果见 A3。

新建云档回调位于 `main.tsx:771-794`：先请求邮箱会话，收到 401 才签发服务端游客会话，再向 `POST /api/games` 建档，校验 V3 `SaveEnvelope` 后进入 `/game/:saveId`。邮箱登录仍可使用。

`main.tsx:819-833` 对 `/game/:saveId` 保留两条既有兼容分支：能在浏览器本地存档列表找到的 ID 进入旧 `Game` 本地页面；新建云档 ID 进入 `CloudGame`。后者才是 P2 服务端权威玩法路径。不能把旧本地存档页描述为 P2 服务端结算。

`CloudGame.tsx:29-56` 读取服务端存档及建议；`:58-90` 提交自由文本、当前 revision、幂等键和叙事请求，显示服务端回执/叙述并刷新。普通生产构建应使用同源 `/api`；前端不持有结算规则。

### A2 权威规则和持久化调用链

`apps/api/src/app.ts:47` 挂载 games API。`apps/api/src/routes/games.ts:17-41` 提供 owner-scoped 存档读取与行动建议；`:43-81` 从服务端存档取得 player ID，构造 `free_text`、`root` branch `ActionIntent` 后调用 `turns.execute`；`:83-107` 由 `AuthoritativeGameService.create` 创建新档。未登录请求返回 401，缺规则时建档/建议返回 `503 RULES_NOT_READY`。

`apps/api/src/index.ts:30-46` 装配认证、规则 runtime、数据政策和存储，并创建一份 `ServerTurnService` 与一份 `AuthoritativeGameService`。`app.ts` 将同一 `ServerTurnService` 传给游戏路由；事件、状态投影和回执仍由服务端规则事务处理。`/api/turns` 兼容路由与游戏路由共用该服务，没有第二套客户端事实写入器。

生产加载边界：`turn-runtime.ts:53-57` 明确拒绝在 production 加载仓库内的 P1 review plugin；`:82-90` 只允许从可信宿主路径加载独立规则模块，并要求其行动/战斗规则版本与 `AUTHOR_RULES_GATE` 一致。当前 gate 的状态为 `APPROVED_BY_OWNER`，但这不等于规则模块文件已部署。本工作树的 `deployment/runtime` 不存在。没有外部 `TURN_RULES_MODULE` 时，新建与建议 fail-closed；这项不能由前端候选页补齐。
