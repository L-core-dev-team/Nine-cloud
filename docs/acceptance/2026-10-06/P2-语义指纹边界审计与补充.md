## 必须并入语义身份的补充项

1. 除 Rulebook 与 20 项 Mechanics 外，加入 `MAX_CULTIVATION_KES_PER_ACTION`、`PROLOGUE_V1_LOCATION_LIMIT`、规则模块与事件 reducer 的运行时代码、相关输入/决策/事件/世界状态/事实/增量契约，以及昼夜、每日体力和状态增量实现；API 回合执行器也纳入，以绑定规则结算、事务提交与叙事调用顺序。
2. 自然语言解析会决定实际交给规则层的 ActionIntent。原 bundle 包含解析器，但单独哈希 Rulebook/Mechanics 会漏掉这条路径。因此加入 parser 代码、候选模板、动作优先序和从当前内容/状态派生的可见目标标签。与判定无关的澄清文案不进入数据载荷。
3. 加入 NPC 可见性授权、`policyForNpc` 的模式映射、两种记忆策略制品以及 API/domain 记忆授权、更新和检索代码。Save envelope V1/V2/V3 的兼容 schema 仍属于工程兼容层，不放入语义载荷；SaveMemoryPolicy 的字段校验保留。
4. 事件 payload 目前没有按事件类型区分的 Zod schema。指纹必须覆盖事件构造代码和所有会消费这些字段的授权逻辑；不能把通用 JSON record误称为完整事件 payload 契约。
5. 全局搜索显示 `PROLOGUE_V1_FREE_ACTION_TICK_KEC_COUNT`、`TALK_COST`、`USE_ITEM_COST`、内容包 `PROLOGUE_V1_ACTION_ORDER` 当前没有被运行时结算读取；不得仅因其存在于文件就称为有效依赖。解析器实际读取的是 `CLARIFICATION_ACTION_ORDER`，它会影响候选顺序，必须纳入。

语义身份采用两部分：规范化 JSON 数据载荷与规范化 TypeScript 运行时代码指纹。JSON 对象键递归按 UTF-16 顺序排序；数组保序；不做 Unicode 归一化；对非 JSON 值拒绝计算。代码指纹先移除注释与类型语法，再对运行时代码树作确定性序列化；presentation-only 澄清问题、fallback 叙事、错误码标签、异常文案、验证文案和 Save envelope 版本兼容 schema 节点排除。规则分支条件、事件载荷、动作标签、记忆策略验证仍纳入。规范化算法与 TypeScript compiler 版本随代码指纹一并记录。该方法是保守的实现身份指纹，不是一般程序语义等价证明；代码重构若 AST 结构变化仍可能要求重新核准。

## §5 四问

1. **[查证]** V1–V4 的源码核验结论如上：messages 值不作判定输入；记忆策略读取 Save 的模式和完整 policy；事件 payload 还被 NPC 授权/叙事路径消费；reducer 除 Rulebook 外读取 mechanics、契约 schema、事实校验与时间/状态投影依赖。
2. **[查证＋实测]** 纯 JSON 数据采用 RFC 8785 JCS 兼容形式：嵌套对象键按 UTF-16 code units 递归排序，数组保序，UTF-8 规范字节计算 SHA-256，并用格式版本作 domain separation。单测核对嵌套键序不影响摘要、数组顺序会影响摘要；TypeScript AST 源码摘要单独计算。
3. **[查证]** `createPrologueV1RuleModule` 与 `createPrologueV1EventReducer` 在 API 插件中接收同一个 `dependencies` 对象，含 `rulebook`、`mechanics`、`messages`。它是共同数据输入，但不是全部语义依赖；额外依赖已按源码核验结果并入摘要载荷/AST 文件集合。
4. **[查证]** A、B 可不改 `prologue-v1-rules.ts` 完成；本轮没有改该文件。D1 的存档兼容和记忆策略适配、D2 的本地 store 上下文签名、D3 的事务审计元数据、D4 的 parser/runtime 接线、D5 的 E2E 均不要求改变玩法分支。未来若新增强类型事件 payload schema，须同步改契约和构造点；语义 AST 摘要会捕获代码变化，旧字节 pin 只作诊断。

### D · 本地接线与浏览器证据

原《P2-接线指令》§5 四问结论：

1. **[实测]** API 从 `canon-runtime.json` 原文件字节计算 SHA-256；浏览器开发路径以 Vite URL `fetch` 原字节并调用 `crypto.subtle.digest('SHA-256', bytes)`。API/浏览器缺少所需字节或密码学 API 时失败关闭，没有硬编码替代。建档回执、三类 build manifest 与文件实算值相同。
2. **[查证＋实测]** 本地 `RuleInvocationContext` 只含 ISO `occurredAt` 和稳定事件 ID 列表。审计时间由事务执行时产生，只写事件审计字段；事件 ID 由 save ID、幂等键和序号确定。游戏时钟基准来自存档 `state.facts.gameMinute`，消耗来自 Rulebook/Mechanics，记忆策略来自存档上锁的 policy 与 runtime；这些不是从现实时间推导。用不同审计时间跑同一输入的测试确认事件 ID、游戏分钟与状态变化相同。
3. **[查证]** reducer 来源为 `createPrologueV1EventReducer(dependencies)`，由 `packages/domain/src/prologue-v1-rules.ts` 导出；事件重放器 `replayEvents` 只负责排序事件批次并调用注入 reducer，没有另写规则或 reducer。
4. **[实测]** `runtimeEligible:false` 候选包只驱动 DEV-only `/game/:saveId` 审阅路径，不能作为生产授权。它足以验证 B1–B4 的本地接线、回执和事件账本；A1–A3 可独立实现。生产 `/api/turns` 仍封锁，候选规则未宣称已签署。

- D1–D3：规则 `decide` 和 `policyForNpc` 共用已验证的 V3 存档记忆策略适配。`commitLocalAuthoritativeTurn` 接收有类型的 `RuleInvocationContext`；`occurredAt` 为 ISO 审计时间，32 个候选事件 ID 由 `saveId + idempotencyKey + 序号` 确定性生成。时间只写事件审计字段，不参与游戏分钟、成本或记忆衰减。两种审计时间下相同输入的游戏状态、时间增量和事件 ID 测试通过。
- D4：开发环境 `/game/:saveId` 审阅路径使用生产 domain 的 `parseActionText`、`createPrologueV1RuleModule`、`createPrologueV1EventReducer` 与同一 dependencies 对象。合法行动写事件、回执和新 revision；澄清/拒绝只写回执，事件数与 revision 不变。此路径使用 `candidate-only`、`runtimeEligible:false` 内容，不等同于生产 `/api/turns`。
- D5：`pnpm test:e2e` 在一次性本机 PostgreSQL 17 测试库上退出码 0。P2 Chromium 旅程：建档、解析观察行动、提交 receipt-backed 作者候选叙述、刷新恢复、澄清、拒绝。结果为 revision 1、gameMinute 315、1 个事件、事件链及规则回放均通过；回执状态含 `accepted`/`clarify`/`rejected`，原始澄清文本未入账，页面错误 0。截图：[P2-gameplay-e2e.png](P2-gameplay-e2e.png)。叙述为确定性候选作者文本，不是模型输出或生产 Canon 验收。
- `canonArtifactHash` 实际值为 `sha256:a65fc6e9b3e5c233407d7602180d51d372c5bb3159b0d8f99cc142f70eb4f8f2`。浏览器建档回执与源文件精确字节 SHA-256 相同；`apps/web`、`apps/api` 与 `packages/db` 三个 build manifest 也与源文件逐字节哈希相同。缺少 `crypto.subtle` 时浏览器路径 fail-closed，没有硬编码回退。
- 生产 Vite bundle 中不含“九霄 · 本机玩法审阅”候选路由标记。推送分支不会更新已部署网站；部署仍是独立事项，本轮没有部署。
