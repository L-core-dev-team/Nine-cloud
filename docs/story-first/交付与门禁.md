# 本轮隔离候选交付说明

## 结论

批准的最小规则段已通过真实PostgreSQL十回合验证，包含交谈、拾取、地点移动、使用物品、战斗/任务完成、观察、返回、领奖及正文恢复。**这不满足完整沉浸玩法READY**：默认叙事未依据长期记忆产生后续剧情；人物建角资料仍未映射服务器能力；清障后的静态观察仍会提到灰羽鸦，正文缺少随状态改变的已批变体；五位真人测试尚未执行完毕，手机实机暂不可用。

## 已实施

- 游戏页以故事为主、行动区常显。前3项建议直接可见，其余在“更多行动”；点击只填入可编辑文字。修改后重新解析。提交立即显示处理中，禁用重复点击。
- 原规则已支持的拾取/领奖/返回主地点接入现有结构化接口，不改已签规则。明确保留当前自然语言支持范围，未知输入不产生假结果。
- 人物/行囊放在资料面板，显示已批物品名称；revision、回执、内部状态放入可展开详情。法律链接及会话丢失风险保留可访问。
- 完整收到的正文独立不可变保存，与回执/修订关联。恢复按存档/拥有者读取，支持超过100段的分页；旧档正文缺失明确标注。授权失效时不展示原账号剧情。
- 新增迁移0024只应用于本轮独立测试数据库；`STORY_ARCHIVE_ENABLED=true`只用于隔离宿主，在production启用直接拒绝启动。未执行生产迁移/写入/配置变更。
- 未启用伪流式、打字动画或未批准NPC对白。

## 可复现运行

在本工作树按顺序操作，原工作区不参与：

1. `pnpm install --frozen-lockfile --offline`
2. 独立Docker PostgreSQL17，端口仅绑定127.0.0.1:55434，库名jiuxiao_test；只给本轮测试使用。
3. 在当前进程设置本地 `DATABASE_URL`，运行 `pnpm --filter @jiuxiao/db db:migrate`；不复制生产连接串。
4. `pnpm typecheck`、`pnpm test`、`pnpm build`。
5. 设置相同隔离 `TEST_DATABASE_URL` 后，`pnpm test:integration`、`pnpm test:e2e`、`pnpm test:e2e:ui`、`node tests/e2e/story-first-golden.cjs`。
6. 不在E2E运行中重建dist；正式八脚本都必须完成，失败不能报告全绿。

平板通过USB端口转发访问localhost:4194，后端仅18891、独立库55434。这是测试会话的本机端口，其他电脑/外网不能直接用该localhost地址。五人可轮流在测试设备以独立站点档案运行；不要把这个地址作为公网发布地址。测试结束停止本轮进程即可；未修改设备系统信任/生产配置。

回滚候选：切换回父提交或另建其工作树，使用原独立库/预览；新库及正文保留以便取证，不执行破坏性down迁移，不修改权威事件。生产无需回滚，因为没有部署。
