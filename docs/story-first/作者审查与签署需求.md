# 作者审查申请：记忆叙事与自然语言扩展（未实施、未签署）

本候选没有改写已签署规则，也没有生成新的NPC对白。下列不是已批准游戏内容，不能随版本启用。生产维持Route A限制。

## 已证实断点

1. `p1-prologue-plugin.ts` 的 `narrativeFallback: receipt => renderDeterministicNarrative(receipt, contentPack)` 不读取传入的叙事上下文。它输出当前回执对应的已批准内容。相同话题重复对话不能因此声称NPC记住了玩家。
2. `server-turn.ts` 在规则事务提交后调用 `buildNarrativeMemoryContext`，后者按NPC授权、存档、分支、修订、时间及遗忘阈值过滤观察，再送入可选narrator。但默认确定性渲染器不消费这些历史观察。
3. P1观察授权数据可为 `unclassified`；不能把这列的数据存在说成短期转长期已完成。既有P2实验的历史事件分类/只读召回，也不能自动替代默认规则签署。
4. 当前已签署自由文本语法覆盖有限。拾取、领奖及返回主地点可通过本候选的结构化建议调用原规则。修改建议后重新走自由文本；当前不能承诺任意同义句都可执行。
5. 签署门禁包含规则源、叙事上下文构建及server-turn等文件。修改这些文件需要重新审查，不能只更新哈希。

6. 本轮平板实测清障后第8回合观察落石堵渡，原签正文仍有“灰羽鸦在石上落着。几十只，一动不动。”；战斗清除与静态观察正文缺少按状态变体，存在可见叙事一致性缺陷。证据为平板十段正文及最终夜间截图，不修改签署内容掩盖问题。

## 签署与实施顺序

1. 从现有获批内容导出可公开阅读的逐句来源及差异，标记所有新增正文。截图中的示例对白不是授权来源。
2. 作者逐项裁定规则、内容、记忆分类/忘却和引用边界；形成新版本标识与审查记录。
3. 在另一隔离分支实施裁定后的源变更，计算规则及内容语义摘要。审查者核对“阅读的文本/规则”和“被签署摘要”的对应，取得真实新签署；不伪造签名、时间或批准人。
4. 原版本仍失败关闭；先跑非法行动、隐私/授权、未来泄露、记忆对照、幂等、恢复与完整八项E2E，再做五人无提示试玩。
5. 生产开放、正文保存迁移、保留/删除/导出/容量政策、服务角色权限另走审批。通过隔离验收不产生生产批准。

回滚：隔离候选切回原已签版本与其独立测试库；不要把新规则档案交给旧渲染器强行读取。新语义不匹配应启动失败关闭，而非自动降级到无记忆叙事并声称成功。

## 目前能做与不能做

可做：现有批准段的行动菜单、阅读布局、完整已收到正文保存与恢复、诚实澄清、可追踪的十回合规则段。不可宣称：NPC已基于长期记忆生成默认续篇、无限自由文本理解、后续完整章节已获批准。整款沉浸玩法仍 `NOT_READY`。
