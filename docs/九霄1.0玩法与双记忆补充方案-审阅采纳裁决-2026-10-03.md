# 审阅结论

## 1. 裁决摘要

本裁决**有条件采纳** space-Bunny 补充稿中的工程风险识别和评测方向，但不照搬其全部缺口判断、算法公式或阶段安排。补充稿自述为非权威材料，代码核对基线为 `cda8d20`；当前 D 盘工作区为 `304c1c8423718a27d2a84a8c19ad175c8683d39b`。因此，本文件按当前工作区复核具体代码，并把研究证据、代码事实和设计建议分开。

本文件只记录 P 轨技术审阅，不改写原方案、不关闭或开启阶段、不纳入 Canon，也不触碰 S/UI 台账。P0 仍按既有验收结果保持关闭。补充稿提出的 SP-0 不能作为重新打开 P0 的依据。

最重要的新增发现是：当前 NPC 记忆 journal 为满足 64 KB 上限会移除较早的观察，而当前检索到的 PostgreSQL 事务保存的是完整世界事件和被裁剪后的最新 journal，未见持久化、模式中立的冻结授权观察 outbox。世界事件还在，不代表 NPC 当时获准知道的观察摘要、渠道和授权依据仍可恢复。这与“遗忘只改变检索，不删除认知材料”直接冲突，必须在 P4/P5 实现前解决。

## 2. 研究证据：可借鉴问题，不能替九霄定答案

### 2.1 Generative Agents 是检索排序基线，不是事实账本

Park 等人的 Generative Agents 使用相关性、近期性和重要性组合排序候选记忆；其近期性按沙盒游戏小时数衰减，参数为 0.995；重要性由语言模型在写入时评分。该工作可以作为“如何从长记忆中选出上下文”的对照，却没有证明这种分数适合九霄的 NPC 授权边界、事实核验或可复现硬门控。九霄可以选择不同的产品语义，但不能据此宣称算法“更优”。[Park et al.](https://arxiv.org/html/2304.03442v2)

**采纳：**在原方案的相关工作中解释两种目标的差异：Generative Agents 解决上下文候选排序；九霄先保证授权证据与规则事实，再决定 NPC 能否取回某段经历。把重要性分数是否由模型产生视为一个可检验的设计差异，不包装成研究证明的优势。

### 2.2 过时状态值得评测；历史事件不能被“取代”为假

STALE 以 400 个专家核验冲突情境和 1,200 个查询评估状态更新、错误前提抵抗和后续行为适配；该预印本报告其最佳受测模型总体准确率为 55.2%。Supersede 报告在 LongMemEval 的知识更新子集上，特定模型的有界记忆与全上下文准确率不同，并在更长对话条件下进一步下降。这些结果支持把“旧状态仍被当成当前状态”列入九霄的对抗评测，但它们来自特定基准、任务和系统，不能外推为九霄的预期准确率，也不能证明新增一张 supersession 表就能解决问题。[Chao et al.](https://arxiv.org/abs/2605.06527)；[Patel](https://arxiv.org/abs/2606.27472)

**修订采纳：**区分“当前状态有效性”和“历史事件真实性”。T10 的羞辱事件在 T50 和解后仍是真实的历史；变化的是关系或信任等当前状态。当前关系应来自规则维护的权威投影，历史追问仍可返回有授权依据的旧事件。只有对确实表达“当前值”的命题，才考虑按明确的规则前提标记失效或被新值取代；不得由语言模型自行判定，也不得删除、篡改旧观察。

### 2.3 Memora 的操作比例不能支持补充稿的因果表述

Memora 报告的 Add/Update/Delete 比例按周、月、季度条件分别变化：Update 为 13%、16%、18%。因此，“Update 仅 13% 却是失败主因”不是这些比例本身能推出的因果结论。FAMA 可提供“过时或已失效记忆被继续使用”的一种研究评测思路；它是该基准的度量，不是九霄的验收目标或记忆架构。[Uddin et al.](https://arxiv.org/html/2604.20006)

**采纳：**把过时状态使用列为独立错误类，与遗忘召回率、授权泄漏、实体错配分开报告。不要直接移植 FAMA 分数或把论文比例写入产品门槛。

### 2.4 不采纳未给一手来源的中文 NLU 准确率

补充稿列出的 96%、82%、71%、76.5% 和 43% 等中文解析准确率被标为二手或待核，未给出可复核的一手文献、数据集、标注规则和分母。本裁决不把这些数字用于技术选型或九霄验收。

**修订采纳：**建立九霄自己的冻结输入语料，按已知动作、缺槽、多义专名、否定、条件、跨轮指代、未知表达分层；对被接受的动作做双人盲标。门槛写成“冻结测试集上未发现误接受”，并报告样本量、分层和覆盖范围；不得宣称有限测试证明总体误解析率为零。

## 3. 当前代码核对：必须先守住“只遗忘、不删认知记录”

### 3.1 P4/P5 前的高优先级缺口

当前 `packages/domain/src/memory/turn-journal.ts` 定义 `MAX_JOURNAL_BYTES = 64_000`，`trimJournal()` 会对旧观察执行 `splice()` 并把被裁剪后的 journal 返回。当前 `apps/api/src/services/npc-memory-turn-transaction.ts` 在同一 PostgreSQL 事务中写入 `turn_events`、状态快照、回执及最新 `npc_memory_journals`；数据库 schema 有事件表和单份 NPC journal，但本次检索没有发现冻结授权观察 outbox/账本表。

这意味着当前实现保留了世界事件，却没有证明它能按**当时的授权规则和当时冻结的可见摘要**重建 NPC 观察。只从原始事件重新运行今天的可见性规则，可能改变 NPC 当时知道什么；从全局事件直接读取则可能越权。因此，这不是单纯的容量优化问题，而是记忆保留和授权可回放问题。

**实施前置建议：**

1. 在 P2/P4 定义并原子持久化模式中立的授权观察记录，至少包含稳定 grant ID、NPC、来源事件/修订、授权策略版本、游戏时刻、渠道和字段白名单化的冻结 `authorizedFacts`。不复制完整事件负载。
2. 把该账本作为可恢复的事实来源；Continue/Forgetting journal、摘要、向量或缓存均为派生投影。容量限制只能裁剪派生物，不能静默删除唯一授权记录。
3. 定义本地 IndexedDB 配额不足和云端事务失败时的行为：权威事件、回执和授权记录必须原子提交；提交失败不得产生已接受回合；投影失败可重建，但不得回退到另一模式或全局事件。
4. 在 P8 验证超过 journal 容量后的授权记录仍完整，且由同一 grant 前缀重建得到相同的 NPC 可见事实。

该缺口属于 P2/P4/P8 的后续实施验收，不阻止作者在 P1 签署规则与序章 Canon；它也不重新打开 P0。

| G-20：requestFingerprint 未覆盖时钟、规则和检索 | 当前 fingerprint 用于识别同一用户请求；它不应被误称为完整执行轨迹哈希。 | 保留 request fingerprint 语义。另行定义 authoritative event/replay provenance，不能把两种指纹混为一谈。 |

## 4. 逐项采纳裁决

| 主题 | 裁决 | 具体落点 |
| --- | --- | --- |
| 记忆检索研究对照 | **采纳并降格为对照** | 补 Generative Agents 的排序机制；不宣称九霄方案优于该研究，不把实验设定当验收证据。 |
| 授权观察与持久账本 | **采纳，最高工程优先级** | P2/P4 先持久化模式中立授权记录，再构建两种模式的隔离投影。 |
| 状态取代 / supersession | **修改后采纳** | 只处理可验证的当前状态命题；历史事件保持真实、可追溯和可按授权召回。先定义事实类型和规则前提，再决定是否需要独立表。 |
| `observe` 行动 | **采纳为 P1 规则候选** | 与 `talk` 区分；作者须定义目标、成本/耗时、成功/无新发现结果和可核对字段。不得先加一个只有叙述、没有规则语义的动作。 |
| `clarify` 候选、缺失槽位 | **采纳为 P1 契约需求** | 候选和缺槽由解析/规则层结构化返回；澄清前不得写世界事件、耗时或状态变更。 |
| 自然语言和 `free_text` | **拒绝“一律拒绝 free_text”** | 已知、唯一且槽位完整的词表/模板可转成签署过的 ActionIntent；未知或歧义输入应引用原文请求确认，不猜测、不结算。 |
| 幂等键 | **拒绝同 key 改正文重试** | 网络重试必须复用同 key 和同正文；澄清后修改正文是新请求，生成新 key，可共享交互关联 ID。 |
| RuleContext | **修改后采纳** | 需要只读、可序列化、版本固定的游戏时钟/规则输入/随机结果上下文。不要把任意闭包回调当作持久化重放契约；不得用 `Date.now()` 计算 NPC 遗忘。 |
| 重放与 TurnReceipt | **修改后采纳** | 区分“按已提交事件重放世界状态”和“重新计算规则决策”。随机规则要记录版本化 RNG/随机结果；事件日志是状态事实来源。叙事正文重试可不同，不得重结算。`appCommit` 属构建清单；密钥和完整私密 prompt 不进入每轮回执。 |
| 遗忘公式与线索加权 | **拒绝补充稿给出的精确公式作为既定方案** | `A_final=A_decay×(1+C)` 并不能普遍保证线索不会越过访问阈值；例如 `A_decay=0.4`、`C=1` 会得到 `0.8`。同时这与产品要求“线索可唤醒残缺回忆”存在目标冲突。先比较可复现基线，再用显式的普通衰减路径和线索唤回路径表示两种体验，报告完整/部分/未召回及错配。 |
| 锚点 | **修改后采纳** | 当前姓名、位置、关系等级等权威状态从状态投影读取，并仍受 NPC 可见性约束；历史情节受遗忘检索控制。主观信任/怨恨不等同于客观关系字段。 |
| 上下文预算 | **采纳优先级，不采纳固定百分比** | 身份、已提交回执、授权事实和当前状态设硬优先级；其余按真实模型 tokenizer、可用上下文和截断测试分配。不要预设所有模型通用的 15/10/30% 比例。 |
| 模式版本/分支 | **采纳不可静默改策略；分支字段条件采纳** | 新存档锁定模式和策略制品版本/哈希；模式索引、缓存和投影严格隔离。只有 1.0 支持分支/回滚/跨模式迁移时，才把 `branchId` 作为运行契约前提。旧版 `exact-recall-v1` 等名称不能自动解释成新模式。 |
| 合成可玩切片 | **暂缓** | 不用未经作者签署的内容补 P1 Canon。若需工程夹具，必须隔离在 test 中，不进入 UI、存档导出或 Canon；另需明确授权。 |
| 离线演化 SP-6/P7 | **不纳入当前 1.0 核心闭环** | 维持用户已裁决的“以后单独决定”；不能通过这份补充稿悄然恢复为默认功能。 |

## 5. 修订后的 P 轨落位

| 阶段 | 采纳后的工作边界 |
| --- | --- |
| P0 | 保持已关闭；不执行补充稿 SP-0 的“P0 再开”。需要后续改契约时，作为相应实现阶段的迁移任务，并保留兼容/回滚策略。 |
| P1 | 由作者签署玩法规则与序章 Canon；定义 `observe`、已知/缺参/歧义/未知输入语义、澄清候选和验收语料。工程审阅只验证规则可编码，不创作或代签 Canon。 |
| P2 | 在本地权威事务中定义事件、状态、游戏时钟、回执和冻结授权观察记录的持久化与恢复边界；不要把模型叙事放进结算事务。 |
| P4 | 实现按 NPC/事件授权的冻结事实记录与 Continue 投影；区分当前状态、历史观察和主观关系；为容量、授权重建和版本迁移定边界。 |
| P5 | 在相同冻结授权集上评测遗忘曲线；衰减仅取决于游戏时间与该 NPC 实际获准观察/接收的事件数。线索唤回允许返回有来源的部分证据；无证据时 abstain。公式和参数由盲评决定。 |
| P6 | Mem0、UwU Memory 等按其架构职责通过隔离 adapter 做对照，不设为游客首局运行依赖或事实源；关闭外部适配仍能运行。 |
| P7 | 当前排除；等待单独裁决。 |
| P8 | 验证跨模式授权集一致、旧观察不因容量裁剪而丢失、重试幂等、同输入检索可复现、未授权事件不泄漏、叙事重试不重掷规则结果。 |

## 6. 尚需人工签署或证据补齐

1. **Canon/规则作者：**为观察行动和序章动作提供已批准目标、结果字段、耗时、合法失败及可验证钩子。不能用工程夹具替代。
2. **Bird 技术复核：**重点审查授权观察 outbox 的持久性、事务边界、journal 容量策略、跨端一致性和恢复路径；本文件不是 Bird 的独立回执。
3. **产品决策：**确认 1.0 是否支持存档分支/回滚。未确认前不把 `branchId` 升为阻断级产品字段。
4. **评测证据：**形成冻结的九霄解析与记忆测试集；公布样本范围和标注一致性，不引用无来源的中文准确率数字。
5. **阶段门禁：**本裁决不替代既定 PR/CI、人工签收或 P1 启动条件，也不改变 P0 完成状态。
