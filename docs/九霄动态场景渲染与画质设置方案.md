# 《九霄》动态场景渲染与设备画质设置

**版本：** 1.0 技术决策草案，2026-09-24
**适用阶段：** S5 场景与声音。S0–S2 不接入尚未存在的渲染设置。
**状态：** 技术路线已记录；引擎选择与画质档仍须经原型测量和作者视觉确认。

## 1. 产品目标与边界

山门、野外、宗门/城镇、战斗/异变需要共享场景契约。每个场景由批准的艺术资产、地点与事件标识、运动层、声音层和降级海报组成。剧情只能引用清单中的资源 ID；模型不能返回素材 URL。

“电影感”由构图、资产、景深层次、光色、节奏、声音和帧稳定性共同形成。单个高分辨率背景图无法证明这些条件已达到。首页当前新增的山门图是概念资产，云雾、水流高光、湖面光纹和花瓣分别由浏览器层动画；它仍不是完整的 2.5D/3D 场景系统、真实水体模拟、环境声或游戏级光照。

## 2. 推荐实现路线

### 2.1 分层场景为共同基线

先交付高质量远/中/近景图层与明确遮罩，再由 `SceneHost` 按安全清单拼装。瀑布、云雾、水面高光、灯光和花瓣各自具有稳定区域、速度、强度和无障碍降级。镜头视差保持克制，避免移动设备上造成晕动。图层根据剧情中已结算的地点、时间、天气和事件选择。

所有档位都须保留静态海报。无 GPU、资源超时、WebGL/WebGPU 初始化失败、标签页隐藏、省电模式和弱动效设置下，游戏输入、剧情阅读、存档及导航仍可使用。

### 2.2 引擎采用可替换适配层

建立 `SceneRenderer` 接口，把资源清单、场景状态和用户偏好与绘制后端分开。先用真实九霄场景分别验证轻量 2.5D、Three.js `WebGPURenderer`、WebGI/Threepipe 插件路线的包体、启动、帧时间、移动端显存压力、无障碍退化和维护成本。只保留一个生产后端；不在同一页面叠装多套图形引擎。

Three.js `WebGPURenderer` 在可用环境使用 WebGPU，并提供 WebGL 2 后备；其官方文档仍标注渲染器处于持续开发状态，具体功能可能随场景与版本不同。WebGPU 需要安全上下文，且并非所有常见浏览器都支持。因此后端检测必须在运行时完成，不能靠 GPU/CPU/NPU 品牌或设备型号猜测。

WebGI 可提供渐进式渲染及屏幕空间反射、SSGI、景深、Bloom 等功能，适合作为对照原型。它建立在 Three.js 生态之上，具体版本、插件许可、维护和构建体积须在纳入前核验。WebGI/Threepipe 的效果不能直接当作所有机型均有的原生能力。

### 2.3 光追、神经渲染与超分的准入条件

- **光追：** 将软件 BVH 路径追踪视为高成本实验；WebGPU 并不等于浏览器已提供统一、可移植的硬件 RT 管线。只有静态展示、渐进出图或少数高端设备原型实测受益时，才作为可关闭的高画质附加层。不可阻断互动帧。
- **神经渲染：** 不是“设备有 NPU 就自动可用”。须指定模型、下载大小、推理接口、显存/内存峰值和结果验收基准。首版不强制下载神经模型，也不在未告知时发送画面到云端。先比较传统资产分层与 shader 效果；神经渲染仅在同等画质下显著降低帧时或带宽后进入候选。
- **超分：** 先测试渲染比例与空间抗锯齿，再评估 WebGPU 超分。Three.js FSR1 路线属于空间放大；第三方时间域超分依赖 WebGPU 及深度、运动向量等输入，不能承诺 WebGL 后备等价。超分若出现重影、闪烁、UI 模糊或移动端成本过高，应关闭并回到原生分辨率。
- **效果处理：** SSGI/SSR、景深、Bloom、体积雾近似、动态阴影分别作为预算项测量。首页文字与交互界面应独立于后处理，避免模糊和低对比。

## 3. 设置页契约

计划位置：`/settings/graphics`，按设备本地保存，不进入剧情存档，也不上传显卡标识或精确设备指纹。

| 设置项 | 用户选项 | 行为与限制 |
| --- | --- | --- |
| 画面质量 | 自动、极致、超高、高、平衡、流畅、标清 | 控制实际启用的效果、资源分辨率和渲染比例。名称对应公开定义的配置表，不以按钮文案伪装能力。 |
| 帧率上限 | 自动、120、90、60、30 FPS | 表示动画目标上限。实际帧率受屏幕刷新率、浏览器调度、功耗、后台标签页与设备负载影响，不是保证值。 |
| 渲染比例 | 自动、50%、67%、75%、100% | 只影响场景画布；DOM 文字和按钮保持设备原生清晰度。超分开关不能越过设备/API能力。 |
| 渲染后端 | 自动、WebGPU、WebGL 2、静态兼容 | 手动切换仅在运行时初始化成功时生效；失败后给出原因并可恢复自动。 |
| 环境效果 | 动态云雾、瀑布、水面光、粒子、Bloom、景深 | 分项开关；静态海报始终可用。弱动效会自动关闭相机漂移和装饰粒子。 |
| 省电策略 | 自动、性能优先、省电 | 隐藏标签页暂停场景循环；在帧时间持续超标时降低渲染比例或效果。没有标准化的浏览器电池/GPU 温度读取保证，因此不显示伪造的温度/瓦数。 |
| 音景 | 首次点击启用、音量、静音、场景音量 | 默认静音并由玩家手势解锁；网络或音频解码失败不影响游戏。 |
| 恢复建议 | 恢复推荐设置、检测兼容性 | 提供后端失败、上下文丢失、资源缺失等诊断，不收集无需的信息。 |

推荐起始值：自动质量、60 FPS 目标、自动渲染比例、自动后端、装饰音效关闭到用户点击启用。高端用户可自行选择 120 FPS 和极致档，但页面必须提示这是目标值并显示当前测得帧时间。

## 4. 自适应策略

1. 首次只加载当前视口需要的桌面或移动艺术版本，先显示同源静态海报，再异步加载运动层。
2. 检查 `navigator.gpu`、adapter/device 初始化、WebGL 2、尺寸限制、页面可见性和失败事件；不向服务端发送 adapter 信息。
3. 用短时间帧间隔样本决定是否降级，不根据单帧抖动切换。持续超过目标帧预算时，先降低后处理，再降低渲染比例，最后冻结装饰层；回升须有稳定窗口并设置滞回。
4. 用户手动选择高档后保留其选择，但发生过热/掉帧风险时给出本地提示并提供自动档。浏览器通常不提供可靠温度读取，不得伪报硬件状态。
5. 场景切换、画质变化、音频解锁和媒体失败均记录为不含个人正文的本地诊断事件；默认不上传。

所有配置必须能在 30 FPS 目标与减少动态效果条件下完成同样的开局、阅读和存档流程。长时间稳定性用真实目标设备测量，截图或开发机最高帧率不能替代设备验收。

## 5. 验收矩阵

### 功能与视觉

- 山门和三类后续场景具有桌面/移动构图与静态海报；剧情地点变化只能触发已批准的资源 ID。
- 每层运动可单独关闭；用户切换档位后实际效果、画布比例和目标帧限发生对应变化。
- 分别测试 WebGPU、WebGL 2、GPU 禁用、上下文丢失、图片 404、音频失败和 `prefers-reduced-motion`。
- 120/90/60/30 档逐一检查节奏、帧时与输入延迟；不把屏幕刷新率低于目标的设备标为“失败”。

### 性能

- 记录设备型号、系统、浏览器版本、分辨率和电源模式。每台设备测试冷启动、连续 5 分钟、场景切换与后台恢复。
- 指标包括帧时间 P50/P95、长帧比例、首屏 LCP、INP、CLS、图片解码/下载字节与 GPU 上下文恢复；只记录必要字段。
- 4–6 GB 内存中端手机和普通集显笔记本必须通过静态/轻动态路径。极致档只在确实支持的设备启用，不降低文字可读性和交互速度。

## 6. 分阶段交付

- **当前 S0–S2：** 只交付视觉方向样张、移动/桌面静态艺术版本及低成本叠层原型。真实存档导入和既有导航门禁优先；不展示假画质设置，不宣称电影级实时渲染。
- **S5 原型门：** 建 `SceneRenderer` 抽象和画质设置原型；同一山门资产用 CSS/2.5D、Three.js WebGPU+WebGL2 后备、WebGI/Threepipe 各做一份同尺寸测试。记录包体、启动、P95 帧时和许可。
- **S5 选择门：** 双作者比较图像方向并分别签视觉与工程结果。只把稳定、可降级、来源清楚的一条路线变成生产实现。4 场景声音与设备矩阵通过后，才关闭该阶段。
- **后续实验：** 光追、神经渲染、时间域超分须各自提交可重复的质量/帧时/内存对照数据；未证明增益则留在实验分支。
