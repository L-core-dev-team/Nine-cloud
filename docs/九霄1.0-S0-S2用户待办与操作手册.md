# 《九霄》1.0 S0–S2 用户待办与操作手册

这份文件只列工程代码不能替作者完成的事项。每项都给出输入、操作、产物和完成判定。

## 一、必须由作者完成的事项

### 1. S0 / G0：确认旧功能清单

**原因：** 工程只能读取按钮、字段和代码行为，不能替作者判断某个旧功能是否仍属于 1.0 产品。

**你需要做：**

1. 打开 [旧功能对照表](九霄1.0旧功能对照与存档样本.md)。
2. 逐行确认“保留”“改名后保留”“明确删除”三种结果。
3. 对删除项写出原因，例如“与新手任务重复”“暂不属于 1.0 公测范围”。
4. 对随机开局、TXT 补充资料、人物状态、综合情报、星记忆、pending 回合、临江仙演示档分别给出决定。
5. 在文件末尾填写作者 A 姓名、日期和签名摘要。

**完成证据：** 对照表每一行都有结果，不再出现“以后补”；提交一次只修改文档的 PR 或在 PR #8 留下逐项评论。

### 2. S0 / Canon：提供 182 条 OCR 的原图依据

**原因：** 当前仓库只有待校 OCR，工程不能替你判断文字是否正确，也不能把模型判断当作 Canon 审核。

**你需要做：**

1. 为每张原图建立稳定编号，例如 `canon-0001`。
2. 保留原图 SHA-256、来源、拍摄/导出时间和所属主题。
3. 逐张对照 OCR，标记“准确”“修订”“无法辨认”。
4. 记录地点、人物、禁则和版本冲突。
5. 两位作者分别确认后，才把条目标记为 `approved`。

**完成证据：** 私有审核表包含 `id / imageHash / ocr / reviewedText / status / reviewer / reviewedAt`；公开构建只读取 `approved` 条目。原图不要直接提交到 GitHub 或 PR。

### 3. 旧档迁移：从本地 HTML 导出文件

**重要边界：** 旧 HTML 以 `file://` 打开时，浏览器 localStorage 属于文件来源；新站以 `http://127.0.0.1` 或正式域名打开时，属于另一来源。新站不能直接读取旧页面的 localStorage。

**你需要做：**

1. 用 Edge 打开旧 HTML。
2. 在旧页面菜单中选择“导出存档”，保存生成的 JSON 文件。
3. 如果旧页面只有 localStorage 没有可见导出入口，先在旧页面打开开发者工具 Console，执行：

   ```js
   copy(localStorage.getItem('jiuxiao_v1_library'))
   ```

4. 将复制出的内容保存为 `jiuxiao-v1-library-backup.json`，不要把内容发到聊天或 GitHub。
5. 打开新版，在菜单选择“导入旧档 / JSON”，选择该文件。
6. 确认浏览器先下载 `九霄-导入前原文备份-*.txt`，再进入导入后的游戏页。
7. 核对姓名、地域、回合、消息、人物、物品和 pending 内容；发现一项不对就停止继续迁移，保留原文件和旧 localStorage。

**完成证据：** 原文件 SHA-256、导入前备份 SHA-256、导入后的字段核对表和失败截图。当前迁移不会删除旧键；不要在核对完成前清理旧浏览器数据。

### 4. AI 配置：确认“青鱼推荐配置”的真实内容

**原因：** 工程可以恢复字段和校验，但不能替你决定五岗位使用哪家服务商、哪个真实 Model ID，亦不能替你授权真实密钥。

**你需要做：**

1. 确认正式名称是否统一为“青鱼推荐配置”。如果旧任务书中的“君煜推荐配置”是历史称呼，写入兼容说明；不要让两个名称同时作为主入口。
2. 为主剧情、剧情导演、状态与记忆、世界档案、高级剧情分别填写实际 Model ID。
3. 单独决定每个岗位的 Base URL、Temperature、TopP、最大 tokens、超时和是否启用。
4. 只在本机或受控测试环境输入 API Key；不要提交 `.env`、截图或导出包。
5. 选择一个允许测试的非生产账号，记录连接测试时间、服务商、Model ID 和结果。
6. 确认调用记录是否允许留在当前会话，以及多久清理一次。

**完成证据：** 一份不含密钥的岗位配置表、一份真实连接测试记录和一份脱敏日志样本。缺少真实服务商账号时，只能标为“未实测”。

### 5. S1：本地数据库和邮件服务实测

**原因：** 当前 CI 只检查代码和 API 健康端点，没有证明 PostgreSQL、迁移和测试邮件服务真的可用。

**你需要做：**

1. 安装并启动 Docker Desktop。
2. 在仓库根目录复制 `.env.example` 为 `.env`，只填写本机随机数据库密码。
3. 执行 `docker compose config --quiet`。
4. 执行 `docker compose up --build -d`。
5. 检查 `docker compose ps`，确认 db、mail、api 均为运行状态。
6. 在当前 PowerShell 会话设置连接串（密码若含特殊字符需 URL 编码），例如 `$env:DATABASE_URL='postgresql://jiuxiao:本机密码@127.0.0.1:5433/jiuxiao'`，再执行 `pnpm --filter @jiuxiao/db db:migrate`，记录迁移输出。
7. 访问 `http://127.0.0.1:8787/health` 和 `http://127.0.0.1:8025`。
8. 执行 `docker compose down`，确认数据卷是否保留符合你的决定。

**完成证据：** Compose 日志、迁移日志、健康端点响应和数据库表清单。当前 API 尚未连接账号或存档服务，不能把这一步写成云同步验收。

### 6. 真机和浏览器验收

**你需要做：**

1. 在 Android 手机、iPhone、平板、桌面 Edge/Chrome 上分别完成“首页 → 建角 → 保存 → 继续 → 导出 → 导入”。
2. 检查软键盘、滚动位置、焦点、返回行为和文件选择器。
3. 开启系统弱动效和省流量模式，确认任务仍可完成。
4. 记录真实设备型号、系统版本、浏览器版本和问题截图。

**完成证据：** 每个设备一份任务记录；性能指标必须来自真实设备测量，不能用桌面演示代替。

## 二、目前工程已完成的部分

- S0 旧版哈希、控件/字段/存储键清单和双视口故障复现。
- S1 工作区、共享契约、Hono 健康端点、Drizzle schema、CI 和阶段 manifest。
- S2 首页路由、十字段建角、草稿、继续游玩、JSON/TXT/HTML 导入边界。
- 旧档 JSON 运行时校验、结构化消息保留、非法 revision 防护、存储失败提示。
- 当前局 IndexedDB 镜像和旧 `jiuxiao_v1_library` 的用户确认迁移。
- 导入前原文备份、Web 单测、浏览器 E2E 和远程 CI。

## 三、完成顺序

1. 先完成第 1、2、3 项，冻结旧功能和旧档语义。
2. 再完成第 4 项，确认真实 AI 配置和隐私边界。
3. 然后完成第 5 项，证明本地后端基础设施可启动。
4. 最后完成第 6 项，做真实设备任务验收。
5. 所有证据归档后，两位作者对同一 commit 签署 G0/G1 记录。

在第 1–3 项完成前，不应清理旧 HTML、旧 localStorage、原始 OCR 或旧存档备份。
