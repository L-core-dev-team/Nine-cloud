## 六、建议执行顺序

1. **Bird 先提交 Canon 私有审校交接摘要。** 说明原图批次清单、每个待裁条目、来源 ID/哈希核验方法与能复跑的命令；私有素材留在私有环境。
2. **LYL 完成逐条内容裁定。** 对冲突选择保留、区分或暂不发布；对仍含省略号的内容确认它们不产生额外设定。
3. **工程建立批准转换器。** 从双作者同摘要收据生成发布清单；对不满足来源哈希、审阅人或内容摘要的条目作硬失败。不要把 `confirmed` 字段直接解释成双作者发布许可。
4. **S3 规则表与旧功能映射并行定稿。** 作者只决定内容/规则语义；工程负责 reducer、事务和回归实现。
5. **按同一提交做 G1/G2。** 先通过旧功能矩阵、存档恢复、规则成功/失败与回放，再由 LYL、Bird 分别签收。
6. **最后接入 Canon 与记忆到游戏流程。** 版本化检索、来源展示、NPC 可见性与记忆持久化应依赖已批准内容和实际领域事件，不允许模型输出写入权威状态。

在上述步骤完成前，S0–S4 应报告为“部分基础已实现，阶段退出条件未满足”。不能用 PR 的 Draft/CLEAN、CI 通过或代码文件存在替代签收。
