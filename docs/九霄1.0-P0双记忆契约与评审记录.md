## 1. P0 结论

《九霄》需要先统一“什么是权威事实、NPC 凭什么知道、检索能返回什么、摘要可以做什么”。P0 选择一份模式中立的授权观察 outbox，并为每个存档分支固定唯一记忆策略。Continue 与 Forgetting 接收同一份授权观察；只有 Forgetting 改变线索检索的可访问性。

**作者 A 产品裁决（2026-09-29）：** 新存档默认走“存档与继续”，玩家主动选择“真实遗忘”；两者都在建档时固定并记录版本。该答复针对 PR #31 的提交 `a0885fa37628b1c673ef2444f0768a537496f8e8`，来自本 Codex 会话，尚未作为 GitHub review 留档。

Mem0、UwU Memory 分别代表结构化资料语义检索和长剧情摘要/相关检索的职责，不作为九霄核心存储或运行必需品。核心类型、授权过滤、存档、回放和确定性检索继续由现有 TypeScript domain、Zod contracts、IndexedDB/PostgreSQL adapter 实现。

**作者 A 产品裁决（2026-09-29）：** 1.0 核心闭环排除离线世界演化；P7 留待后续单独裁决。默认关闭。在单独裁决前，不定义现实时间触发方式、游戏时间上限、可推进字段或离线禁止事件，也不实现开启路径。“七个游戏日”仍只是讨论候选，不能写入常量或面向玩家宣传。该答复针对提交 `a0885fa37628b1c673ef2444f0768a537496f8e8`，尚未作为 GitHub review 留档。

**玩家文案候选，待 A 审核：**

- **存档与继续：** NPC 不会因游戏时间经过而忘记自己有权知道的事。这不代表 NPC 知道没有目击或获准转述的事件。
- **真实遗忘：** NPC 会随游戏经历逐渐难以回忆自己有权知道的事。人物、物品、地点或共同经历等线索可能唤起原始记忆，也可能只想起一部分。底层事件记录不会因此删除。

## 3. 权威边界与数据所有权

| 对象 | 写入者 | 允许读取者 | 不得承担的职责 |
| --- | --- | --- | --- |
| 世界事件及规则投影 | 通过批准规则的权威回合事务；有来源证明的导入器仅可建立迁移基线 | 回放器、状态查询、经授权的规则/场景服务 | 模型、摘要、记忆 adapter、插件不能改写或删除 |
| NPC 可见性裁决 | 版本化的九霄授权器，读取该事件与场景的规则输入 | 授权 outbox 构造器、审计界面 | 模型不能授予自己的知情权；全局日志不能直接成为 NPC 上下文 |
| NpcObservationGrant | 权威事务内的授权器；每份 grant 在提交时冻结 | 目标分支记忆投影器、可审计回放 | 不能包含整份未过滤事件负载；不能含目标检索模式 |
| NPC 记忆投影/索引 | 按存档选择的单一模式 adapter | 对应 NPC、场景和分支的受控 query | 不能反写 grant、事件、Canon、规则状态；不能跨模式回退 |
| MemoryEvidence | 只读检索器，必须依授权观察和固定策略版本产生 | NarrativeContext / 可解释性回执 | 不能补充来源以外的事实；不能从另一 NPC 的缓存取结果 |
| PlotDigest | 生成器产出的衍生制品，带来源修订区间及来源引用 | 玩家回顾、相关剧情检索 | 不是事件账本、授权证明、NPC 观察或世界真值 |
| NarrativeText | 模板或模型依据已提交回执和 MemoryEvidence 生成 | 玩家 | 不能成为状态投影、记忆 grant、规则决策或新的事件事实 |

“授权记忆完整”指已获准的事实片段和出处在该存档运行期内可校验、可按权限重建，不等于每轮都完整注入有限上下文，也不等于 IndexedDB/设备损坏后物理永久保存。

## 4. 建议版契约

以下字段是后续 contracts/domain/存储迁移的目标契约。此文档发布本身不代表字段已存在。

### 4.1 SaveMemoryPolicy 与分支谱系

记忆模式为判别联合，不接受任意字符串，也不从一个空字段或 legacy 标签推导。

| 字段 | 类型/约束 | 用途 |
| --- | --- | --- |
| mode | continue 或 forgetting | 存档分支唯一模式；创建时必选 |
| policyVersion | 稳定 ID，例如 continue-v1、forgetting-v1 | 解释这一支的检索语义；升级须迁移或开分支 |
| schemaVersion | 正整数 | 保存字段布局版本 |
| clockBasis | 固定枚举：game-minute+npc-grant-sequence-v1 | 防止接入现实时间或全局事件数 |
| policyArtifactHash | SHA-256 制品摘要 | 固定算法、阈值、定点计算和排序参数 |
| cueDictionaryHash | SHA-256 制品摘要 | 固定参与唤醒的实体词典和关系映射 |
| normalizerVersion | 稳定版本 ID | 固定 Unicode、大小写和词法规范化 |
| retrievalVersion | 稳定版本 ID | 固定候选生成、打分、阈值和排序 |
| visibilityPolicyVersion | 稳定 ID | 记录谁能知道什么；不可折叠为 mode |
| visibilityPolicyHash | SHA-256 制品摘要 | 固定授权规则内容；不能和记忆策略哈希混用 |
| createdAtRevision | 非负整数 | 当前策略开始生效的分支修订 |

存档至少还需分支元数据：branchId、可空 parentBranchId、forkRevision、创建策略版本及来源迁移 ID。父分支查询最多读到该分支的分叉修订，绝不读到父分支之后的事件。branchId、saveId、revision 均需运行时 Zod 校验与数据库约束。

策略制品哈希覆盖算法版本、定点单位、系数、阈值、舍入规则、同分排序、线索分类/权重、normalizer 与默认 abstain 行为。只更改权重也需新 policyVersion/hash；旧回合按原制品回放。createdAt 或日志里的 ISO 时间是审计时间，不参与衰减。

### 4.2 ActionIntent 和规则决策

ActionIntent 是用户意图候选，不是世界写入命令。解析器输出的结构至少可追溯存档、分支、玩家/NPC actor、预期修订、幂等键、已解析 action kind、受约束 payload 和 parser 版本。玩家原始输入不进入普通事件负载、日志或长期 NPC 记忆。需要调试时只保留经过同意的脱敏样例。

自然语言采用本地确定性规则词表与动作模板。解析状态分为：

| 状态 | 行为 | 状态/时间变化 |
| --- | --- | --- |
| 唯一命中且参数齐全 | 生成 typed ActionIntent，交给领域规则 | 解析器不写状态；规则决定后才可能提交 |
| 缺少必需参数 | 用简短问题补齐参数 | 不创建 DomainEvent，不消耗资源，不推进游戏时间 |
| 多个候选同样合理 | 列出有限候选供选择 | 不猜测，不推进游戏时间 |
| 没有已知映射 | 用安全转义后的原文询问玩家是否意指某个已支持行动；没有可信候选时请求重述 | 不报错、不假装理解、不结算 |

unknown/clarify 文案不得把用户输入拼接为系统或开发者指令。界面按纯文本渲染并限制长度。模型可在 BYOK 下帮助润色对话，但不能替代零配置解析器或自行生成授权事实。

当前序章必需行动为移动、观察、交谈、使用物品、战斗。当前 ActionIntent schema 未包含 observe，需在 P1 实现明确的观察 payload 和 P1/S3 作者签署规则；不能把观察塞进普通自由文本并宣称已支持。

规则决策保持 accepted / rejected / clarify 三态的事务语义：

- clarify 不提交事实；需要更多参数或消歧。
- rejected 不改变世界、资源和游戏时间；解释规则不允许的原因。
- 如果已尝试的玩法行动产生合法失败且消耗时间或资源，该失败应被规则接受并提交明确结果事件。不能用 rejected 假装一次已发生的游戏失败。
- 已接受且算作“完成回合”的规则结果须按签署规则产生至少一条可见变化、推进游戏时刻并生成可追溯回执。界面还须给出至少一个能回指已提交状态或获准线索的后续钩子。钩子是可重建的展示候选，不是世界事实；它不能来源不明或擅自新增 Canon。澄清和纯拒绝不是完成回合。
- 对已接受幂等键重复请求，回放原 TurnReceipt；不得再次消费资源、增加修为/关系、发放 grant 或推进时间。

### 4.3 DomainEvent 与 TurnReceipt

后续生产事件应有事件 schemaVersion、save/branch 身份、事件 ID、单调修订区间、规则版本与制品摘要、游戏时刻前后值、事件类型和经过约束的领域 payload。每轮事件按现有契约批量原子应用、回合只推进一档修订。所有玩家行动事件 source=RULES；MIGRATION 只用于隔离的迁移基线流程。

事件 occurredAt 保留审计用途。游戏衰减只读领域状态中的整数游戏分钟和 NPC 授权观察序列。自由形式 payload 的字段须由 event type/schema 白名单验证；类型名和规则 hash 不足以证明可见性。

TurnReceipt 必须绑定 saveId、branchId、idempotencyKey、算法版本化的 request fingerprint、输入/结果修订、RuleDecision、已提交事件 ID、游戏时刻范围及状态差异/状态证据引用。完成回合所需的后续钩子应引用可验证的状态字段或授权线索 ID，不能让叙述模型直接写入事实。它不得把完整 prompt、API Key、原始用户句子或 Chain-of-Thought 持久化。原始用户句子仅在当前输入解析所需的短暂内存中使用。澄清/拒绝回执保留原修订并注明未提交。

状态回执是玩家核对事实的界面模型，不替代权威事件。回执上的字段必须回指 DomainEvent 或当前版本化状态投影；叙述段落不能成为回执证据。

### 4.4 NpcObservationGrant 与冻结事实

Grant 由授权器在权威事务中创建，推荐字段如下：

| 字段 | 约束 |
| --- | --- |
| grantId | 稳定、幂等；建议由分支、NPC、触发披露事件及授权策略版本的规范化元组确定性生成，不由每次重试随机生成 |
| saveId, branchId, npcId | 必须与授权事务和目标 NPC 一致 |
| grantEventId | 导致 NPC 此刻获知信息的事件；目击时可为亲历事件，转述时为披露/对话事件 |
| sourceFactRefs | 仅作审计来源；检索不能借该引用读取原始全局事件 |
| npcGrantSequence | 每个 save/branch/NPC 单调递增；只在新 grant 持久化时增加 |
| gameTimeMinute | 授权时刻的整数游戏时间 |
| channel | 至少区分 witnessed、reported；新增渠道必须有明确审阅/传播规则 |
| authorizationPolicyVersion/hash | 冻结发放规则，延迟投影不能使用新规则重算历史 grant |
| authorizedFacts | 在提交时冻结的字段白名单值，不可替换为整个事件 payload |
| contentHash | 冻结授权事实、渠道和出处的规范化摘要，用于冲突及回放校验 |

每条 authorizedFacts 应保留稳定 fact ID、受控的 subject/object ID、字段/谓词和值，以及事实/陈述的认识状态和来源归属。若来自转述，记为“NPC-X 报告/主张了 Y”，不能提升为“Y 是权威世界事实”。事实表达不得包含 system-only 数据、玩家私密材料、密钥、未批准 Canon 或模型隐藏推理。

同一 grantId 的重放内容必须逐字节规范化相同；不同内容是完整性冲突，应停住游标并报警，不能覆盖。游标只有在目标模式库内事实与索引均持久化后才前进；收到消息不等于已投影。

### 4.5 MemoryEvidence、PlotDigest 和失败处理

MemoryEvidence 是某次 query 的不可变结果，至少含存档/分支/策略制品/NPC、匹配 grant/fact IDs、游戏时刻、检索线索 ID、渠道与来源、固定点评分、partial、稳定排序键和 cursor watermark。空结果使用显式 abstain。证据中的所有 fact IDs 都必须能回指该 NPC 的授权 grant。

partial=true 意味着只返回原 grant 中一个被确定性挑出的 fact 子集；它不表示事实被改写、互相混淆或模型猜测补全。叙述可以表达“想起一点”或“记不清”，但内容只能来自返回的 fact IDs；正文无法验证的开放文本不能升级为证据。

PlotDigest 属于叙事检索的衍生结果，必须记录 branch、来源 revision/event/fact IDs、摘要 schema/model/prompt 版本、生成状态及 hash。它不能发放 NPC grant。任何被用于 NPC 表达的摘要片段必须回到授权原子事实重新授权、复核，且保留主张/目击渠道；摘要自身不授予访问权。

| 故障 | 规则世界 | NPC 记忆/叙事 |
| --- | --- | --- |
| 规则校验/投影失败 | 权威事务整体回滚 | 不创建回执、授权或记忆观察 |
| 已提交世界事务、记忆 outbox 投影失败 | 保留已提交状态与回执 | 不回滚或重复结算；相同游标可重试。落后且不能读穿/重建时使用本回合回执和确定性叙事，不返回旧缓存 |
| 记忆策略版本或模式元数据不符 | 世界存档可安全加载并保留 | 该 NPC 检索 fail closed，显示无可用回忆，不切到另一模式 |
| LLM 超时/格式违规/拒绝 | 世界事实保持不变 | 重试正文时复用同一回执、grant prefix 与证据；超限后回退确定性文本 |
| 叙事事实无来源/与回执冲突 | 回执仍是权威结果 | 丢弃不支持断言，采用规则模板；不得重掷行动 |
| 旧档无法证明观察授权 | 原始导入备份保留 | 不把不明摘要注入 NPC 长期记忆 |

### 4.6 检索确定性与衰减输入

同一查询结果由下列完整签名决定：

saveId、branchId、mode、policyArtifactHash、visibilityPolicyHash、npcId、grantCursor、gameTimeMinute、normalizedCueIds、cueDictionaryHash、normalizerVersion、retrievalVersion。

签名一致时 MemoryEvidence 必须按字段完全相等。索引顺序、存储引擎返回顺序、LLM 随机种子或现实系统时间不能影响结果。各分数使用整数固定点（建议范围 0–10000）；使用确定的向下取整；最终排序键依次为分数降序、授权游戏时刻降序、npcGrantSequence 降序、grantId ASCII 升序。策略哈希固定阈值及并列处理。算法无需为同一版本读取可变全局配置。

Forgetting 的首版候选排序应区分两类衰减输入：

1. 授权时刻至当前时刻的非负游戏分钟跨度；
2. grant 建立后该 NPC 自己新增的授权观察数；非该 NPC 可见或未披露的世界事件不计数。

witnessed 和 reported 的区别必须保留。是否使用不同衰减曲线/系数由作者与固定评测数据决定，不由研发凭直觉指定。线索加权只影响源事实是否达到检索阈值，不改事实值、主体归属或来源。1.0 不引入检索触发后的长期强化、模型自主改写线索或错误记忆。

文档中的策略建议名称为 forgetting-v1，不是已确认的心理学模型。P3/P4 应冻结其完整系数与测试集；冻结前检索参数不得作为公测行为承诺。

### 4.7 两种存储适配器与投影恢复

| 层 | 1.0 本地先行路径 | S6 签收后的云端路径 |
| --- | --- | --- |
| 权威事务 | 在 jiuxiao-1 IndexedDB 内同一 readwrite transaction 写存档修订、权威事件、TurnReceipt 与模式中立 observation outbox | PostgreSQL 单一事务写同一权威对象，复用现有锁、CAS、幂等仓储 |
| 记忆适配器 | 每个模式独立 IndexedDB 数据库或严格隔离的数据库命名域；DB metadata 固定 mode/policy hash | Continue 与 Forgetting 独立 database/角色/连接；运行身份只能连接已选模式 |
| 投影恢复 | grantId 幂等；启动及回合后按 cursor 追平 outbox；不能在 IDB 事务里请求模型/网络 | 独立消费者写目标库后推进 cursor；按 grant prefix 可重放/重建 |
| 备份/导出 | 存档、事件和 outbox 一起导出；可重建索引另行标注；本地数据库分离不等于抗清理备份 | 权威档案备份与衍生索引备份分开；恢复时校验 branch、策略、权限哈希和 cursor |

不能把两个数据库的同步写称作一个 ACID 事务。核心规则事务只提交一次权威数据和 outbox。记忆库故障不取消已提交世界变化；回读使用 cursor 验证、幂等恢复或确定性退化。两模式物理分开只提供业务隔离，不能抵御管理员、同源恶意脚本或错误权限配置。

### 4.8 迁移策略

1. 不原地覆盖 v1 SaveEnvelope、旧事件或原始导入文件；保留不可变迁移备份及 hash。
2. 未含 memoryMode 的旧档先进入“待玩家选择”的迁移状态，不能被默认归类为 Continue。
3. 旧 exact-recall-v1 不自动映射 continue-v1；旧 accessibility-v1 不自动映射 forgetting-v1。旧公式只在原格式隔离解释，不能冒充新公式。
4. visibleSummary 只有在可证明 NPC、事件、目击/转述渠道、授权策略和披露字段均有效时，才可能转换为新 grant。现有结构缺少其中若干证明字段，因此默认不注入 NPC 长期认知。
5. 迁移向导建立新模式分支并记录 parent/fork revision、转换器版本和策略 hash。玩家可读的旧 transcript 与 NPC 可读记忆严格区分。
6. 未知 schema、坏 hash、游标越界、重复 grant 冲突或来源缺失时停在隔离副本；不得跳过错误后继续写权威存档。

## 5. 零配置解析样例与序章状态字段

以下均是**非 Canon 的语法夹具**，只检验解析状态和规则边界，不可直接发布为场景、人物或世界设定。ID 和事件内容都是占位符。

| 输入样例 | 预期解析 | 是否结算 |
| --- | --- | --- |
| “移动到 地点占位符 A”且 A 唯一存在于当前批准地图 | typed move intent | 交领域规则；规则通过后才结算 |
| “观察”但规则要求目标且当前场景不能默认目标 | clarify：询问观察对象 | 否 |
| “用 物品占位符 I”但背包存在两件候选 | clarify：显示两个可选物品 | 否 |
| “告诉 NPC-N：内容占位符” | typed talk intent；对话是否改变关系、任务或认知由规则决定 | 交领域规则；未定义效果时拒绝或澄清 |
| “攻击 目标占位符 N”但目标 ID 或战斗前置条件不明 | clarify 或规则拒绝；禁止文本推断成功 | 否，除非完整合法动作按规则作为失败事件被接受 |
| 无词表映射的表达 | 纯文本安全复述并问玩家要执行哪种已支持动作 | 否 |

按钮填入编辑框而非直接提交。按钮文字、自然输入与之后修改过的文字都要通过同一个解析器。首轮五类输入为移动、观察、交谈、使用物品和战斗；完整 1.0 仍要补齐现有 S3 六类签署规则，不用五类替代修炼、任务等阶段门槛。

首段游玩需要可结算并可回执的状态分类：

- 玩家：身份、当前位置、游戏时刻、资源/能力和受损状态；
- NPC/关系：当前场景存在性、关系量或关系阶段、NPC 可见性与披露状态；
- 物品：持有者、数量、可用性及使用结果；
- 场景：地点、时段/环境字段、已观察线索；
- 战斗：参与者、回合/行动次序、资源消耗与明确成败；
- 任务：目标、可观测进度、完成/失败及恢复条件。

这些是字段类别，不是 Canon 内容。每个可玩行动需要 A 批准字段含义、初值、变化规则和失败样例；B 再把获准字段映射到 DomainEvent 和 projection。天气、修为、好感、灵狐、血腥味等先前聊天例句不自动成为正式设定或规则。

## 7. 非 Canon 记忆与线索夹具

此夹具只测试“同一观察集合、两策略不同检索结果”及出处边界。角色 ID、地点、物品和事件均为虚构占位标记。

**夹具输入：** 某次授权事件 E-01 生成 grant G-01，NPC-N 在游戏分钟 120 目击事实 F-01（主体 P-01、对象 I-01、谓词/取值由夹具定义）。另一个 NPC-N2 没有对应 grant。之后 NPC-N 收到 K 条自己的授权观察，游戏时钟前进到 M。

**Continue 预期：** 对 F-01 的合法线索查询可检索到完整 F-01，不因 M 或 K 衰减。NPC-N2 查询同一线索必须 abstain。

**Forgetting 预期：** 在 M、K 和冻结策略下，合法线索返回固定的来源事实子集或 abstain；可能 partial，但 fact ID/value/source 不得被改写。将 M 或 K 改回相同值、恢复同一 grant prefix 与制品哈希，结果必须逐字段相同。

**转述预期：** 报告事件 R-01 授权 NPC-N 获知“报告者 P-02 声称 F-01”，证据标为 reported 且归属 P-02。查询结果不能将该报告改成 NPC-N 亲眼看到，也不能改成 F-01 已获世界规则确认。

**分支预期：** 从父分支修订 r 分叉的新分支只继承 r 及以前的授权 grants；父分支 r 之后和另一分支的 grant 均不可见。

## 8. 风险审查与缓解

| 风险 | 具体失败方式 | P0/P1 对策 |
| --- | --- | --- |
| 把摘要当真相 | NPC 从全局摘要获知未披露的谋杀/物品/任务 | 摘要只能作为玩家衍生物；NPC 输入只接授权 grant 中冻结 fact |
| 误认转述 | 将“某人说 X”升级成“X 已发生” | 证据保留 reported channel、报告者与主张类型 |
| 策略漂移 | 浏览器、服务端或升级后同输入返回不同记忆 | artifact hash、schema 与 normalizer 版本固定，策略变更开新分支 |
| 分支串线 | 读到父分支未来/另一模式的记忆 | 每次 query 验 branch/mode/hash/cursor；以错误拒绝而非回退 |
| outbox 中断 | 世界已提交而 NPC 索引落后 | 游标、幂等 grant、启动恢复；未追平时无旧缓存叙事 |
| 看似可信的“人类遗忘” | 公式稳定但并不拟合人类心理或玩家预期 | 对外称游戏记忆策略；盲测评估；系数不由主观直觉宣传 |
| 旧存档被静默重解释 | 失去原有对话或给 NPC 凭空补记忆 | 原档备份、显式选择、新分支、证据不足不注入 |
| 过早引入新依赖 | 客户端脱网/关闭 Mem0/UwU 后不能玩 | 核心 adapter 可替换；全关时规则与检索继续运行 |
| 观察行动空转 | 按钮只有文案，没有状态或线索变化 | P1 规则必须产出受签字段或明确拒绝；不合成 Canon |
