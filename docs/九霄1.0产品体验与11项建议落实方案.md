# 《九霄》1.0 产品体验与 11 项建议落实方案

> 版本：2026-09-23。性质：产品、界面、内容与视觉的可验收规格；不表示现有产品已实现。
> 上位交付约束：[1.0 公测版重建总方案](九霄1.0公测版重建总方案.md)。双作者权责见[分工与交付门禁](九霄1.0双作者分工与交付门禁.md)，代码阶段见[AI 执行清单](九霄1.0分阶段实施与AI执行清单.md)。
> 视觉输入：用户附图中的 A/B/C 山门比较图、B 竖版背景与横版全景；已经选择 B。原图是设计参考，不自动等于可分层动画素材。

## 1. 把 11 项意见转成产品决策

| 序号 | 用户指出的问题或要求 | 1.0 决策 | 证据与否决条件 |
| --- | --- | --- | --- |
| 1 | 旧版功能和内容被藏到首屏下方；新开一局、世界设定、进入游戏交叉；首页与游戏区重复；青鱼设置被简化 | 首屏只负责进入世界；进入后给出续档、新局、世界设定和 AI 设置，角色创建由新局进入；旧版字段与能力重组保留 | 陌生玩家无需提示即可理解先入山门、再选去处；每个入口各有明确结果。逐项旧版功能对照通过，不能以“代码里存在”代替可用 |
| 2 | 单 HTML 难以承担响应式和多端过渡；背景静止、瀑布与流水声缺失、剧情无法换景 | Web/PWA 分层构建，四类场景按结算事件切换；局部水、雾、光、声实时编排 | 中端手机能连续使用，弱动效仍完成任务；动画不能改变操作结果或遮挡文字 |
| 3 | 豆包、DeepSeek、Grok 只供参考，方案需独立研究 | 对每项外部建议写来源、前提、替代方案和采纳理由；使用官方文档验证可变事实 | “某模型建议如此”不是立项证据；无法核实的能力标为待核 |
| 4 | 设计应回应玩家、产品高度与两位作者的出发点 | 以能否自由行动且世界自洽、能否读懂并信任结果为核心；作者的 Canon 与工程权威分开 | 两位作者分别签产品体验和工程证据；玩家任务失败可定位到责任层 |
| 5 | 借鉴 Mneme、苹果/华为、Codex/Claude Code、Anime.js 并有自己的创造 | 借任务导航、材质和动效规律；以九霄的山门、月华、朱印和长文阅读形成自有系统 | 原样复制参考界面、许可不清、性能不可用或破坏阅读的方案不通过 |
| 6 | 兼顾美观、舒适、安全、可玩、丰富、合适、全面、功能、感觉、流畅、社区、无 AI 感和灵活 | 建立 13 维评审表，并为每维配置任务、缺陷例子和实测证据 | 不以单张效果图给整版打“成熟”标签 |
| 7 | 文件与内容结构要清晰、严谨、完整 | 产品页面、权威规则、Canon、媒体、账号和账单使用独立且版本化的契约；构建唯一 | 同一个版本的源码、测试、预览和公开包功能一致 |
| 8 | 界面要容纳世界书、ST/Risu、双记忆、Jev、实时媒体、插件、MCP、付费及完整站务 | 玩家能发现并管理已交付能力；长期数据结构与权限边界清楚 | 不存在点开后只写“敬请期待”的 1.0 核心功能 |
| 9 | 打破平庸布局，达到成熟商业产品水准 | 采用场景化、渐进呈现的游戏壳；创新围绕行动、反馈与世界变化，而非特效数量 | 真人独立完成任务、长局稳定、持续性能和内容一致性均通过 |
| 10 | 补齐服务端、数据库等完整工程 | 账号、选择性云档、权威回合、媒体任务、社区、权益、计费、日志、备份都有运行与恢复证据 | 只有接口文件或 mock 服务不算完成 |
| 11 | UI、文档和代码去 AI 味，接近资深人类作者与工程师的表达 | 作者主导叙事语气与命名，技术文档写事实/决策/限制；设计文案逐屏人工审查 | 机械套话、虚构功能、无法复现的“极致”结论和泛滥装饰均退回 |

这 11 条不是额外愿望清单。第 1、2、6、10 条决定产品是否可用；第 4、8、11 条决定九霄是否仍是一个可信的世界。其余条目限定方法。任何两项发生冲突时，先保全权威事实、玩家任务和隐私，再作具体设计裁决并留记录。

## 2. 旧版能力的迁移方式

G0 关口先制作可签署的“旧版功能 → 新位置 → 验收动作”表。首批逐项如下，实际字段以旧版运行界面和源代码核对后补齐；不得凭记忆删去少见配置。

| 旧版能力 | 新位置 | 玩家验收动作 |
| --- | --- | --- |
| 作品简介、开局说明 | 山门内的简介与帮助页；首屏只保留进入世界 | 点击“进入世界”后能找到简介，并分清离线序章与 AI 扩展 |
| 角色创建全字段与地域选择 | `/new` 分步建角 | 填写、退回修改、刷新草稿、确认摘要并开局 |
| 世界观与世界书 | `/lobby` 的世界设定入口、`/world`；游戏内阅读层 | 进入世界后打开，或从一回合中阅读后关闭；位置不丢失 |
| 新建、继续、多存档与旧快照 | `/lobby` 和游戏存档面板 | 有档时可续玩；新局从角色创建开始；覆盖风险明确；旧档先备份再迁移 |
| 导入、导出与恢复 | 菜单中的导入；游戏存档面板 | 原始档下载、错误文件拒绝、成功导入且状态一致 |
| 青鱼推荐配置及说明 | `/settings/ai` 顶层分组 | 看见原名称、适用说明、候选参数和覆盖前预览 |
| 五岗位模型与参数 | 同一 AI 设置中的岗位页 | 每岗位 Model ID、供应商、参数与启用状态能单独核验 |
| 连接测试和调用记录 | AI 诊断页 | 对真实接口发测试请求；成功/失败、费用、耗时和错误可查且不泄密 |
| 失败重试、结构化结果与记忆 | 游戏内回合状态和记忆页 | 叙事失败不重复结算，重试后回合数量不变；记忆来源可追溯 |

旧版还存在的任何功能都须进入完整对照表，给出“保留、重组、明确淘汰”之一。淘汰需要两位作者的具体理由和旧档影响评估。不能因为新界面暂时没位置就悄然删除。

## 3. 三条玩家旅程与界面规则

### 3.1 首次玩家：无密钥也能完成一个任务

玩家先看到以“九霄”为主的山门画面和唯一的“进入世界”按钮。点击后，`/lobby` 给出续旧档、新开一局、阅读世界设定与 AI 设置等去处。“新开一局”直接进入角色创建，避免重复按钮。完成确认后，玩家在确定性序章中移动、获得并使用物品、交谈、经历基础战斗和完成首个任务。此路径不要求先注册、付费或配置 AI。

### 3.2 回访玩家：入山后续玩是首要动作

山门入口先以“九霄”主视觉呈现，点击“进入世界”再进入山门内的任务选择页。任务页读取本地档元数据，显示角色、位置、最后时间和同步状态；“继续游玩”进入准确回合。玩家可在游戏内打开世界书，再回到同一段剧情和滚动位置。断网时明示本地写入与待同步数；云端修订冲突时呈现云端、本地和复制新分支三个可理解的结果，不静默覆盖。

### 3.3 使用 AI 的玩家：看得懂费用与权限

AI 设置以“青鱼推荐配置”为入口，之后才展示供应商、五岗位、参数、连接测试和调用记录。BYOK 直连标明免费；需付费网关的供应商在保存前说明密钥流向和 1% 费率。平台额度单列余额与预计消耗。调用失败指出故障类别和可恢复动作，不把技术堆栈抛给玩家。媒体生成先询问费用和等待时间；玩家取消后不产生世界事件。

## 4. 视觉系统与动态场景规格

B 构图保留中轴山门、月华与深蓝夜山。界面强调改用冷月银蓝和少量暖金；桃枝保留自然花色，朱红只作为印章图案细节。移动端不得仅把桌面图居中裁断；标题、门、动作按钮与瀑布关系需单独排版。山门可用有层次的静态岩体、树与建筑，瀑布和水光局部循环，前景桃枝轻动，雾与灯光由事件触发。战斗不使用连续闪屏来冒充戏剧性；变化应先让玩家读懂行动后果。

四类场景均制作以下资产包：静态海报；适合横屏/竖屏的安全裁切；可循环局部运动层；环境声及静音时的文字反馈；色彩和文字对比检查；来源、许可、版本及文件大小记录。场景清单只接受已结算的地点、时间、天气和事件 ID。资源加载失败直接使用海报，禁止白屏。生成图像/视频作为玩家请求的补充表现，与已有的世界状态和 Canon 分离。

设计素材的借鉴边界：Apple Liquid Glass 是材质参考；华为沉浸光感是光与空间的灵感，不假定 ArkUI 能力可直接移植到 Web；Anime.js 用于时间编排；Codex/Claude Code 借状态层次与命令可发现性；[Mneme Web](https://github.com/LYL-Z/mneme-web) 借任务连续性。任何可复制代码或资产须核对实际许可，并与用户私有内容隔离。`liquid-glass-react` 自述 Safari/Firefox 只能部分呈现折射，关键导航使用普通浏览器也能读懂的回退材质。

## 5. 13 维评审表：每项如何被证伪

| 维度 | 可观察的通过证据 | 典型失败 |
| --- | --- | --- |
| 美观 | 四场景与界面属于同一视觉体系，两作者在真机图上认可 | 首屏美、游戏页粗糙 |
| 舒适 | 30 分钟中文长文阅读仍清晰，亮度和动画可调 | 玻璃叠在正文上、字形闪烁 |
| 安全 | 越权访问、密钥泄漏、重复扣费测试为零 | 日志存密钥、账户互读 |
| 可玩 | 无密钥首任务可完成；自由行动有确定反馈 | 精美场景里无法推进任务 |
| 丰富 | 九境五域规则矩阵与代表性长局可用 | 只有序章，后面依赖模型胡写 |
| 合适 | 视觉、文案和功能符合修仙世界与成年玩家 | 科技仪表盘喧宾夺主 |
| 全面 | 旧版能力对照表全部签字，新增能力有入口 | “青鱼”或调用记录失踪 |
| 功能 | 每个按钮有单一、可预测的结果 | “新开一局”返回无提示的首页 |
| 感觉体验 | 场景、音、光、反馈支持剧情转折 | 运动与剧情事件脱节 |
| 流畅 | 真机 Web Vitals 和五分钟场景帧率达标 | 开发机流畅、普通手机卡顿 |
| 社区 | 游记预览、脱敏、审核、撤回、举报全流程 | 分享后无法控制个人信息 |
| 无 AI 感 | 盲评叙事通过、没有 Canon 越权和模板套话 | 堆叠空泛宏大词语 |
| 灵活 | 不同视口、弱动效、省流量、断网可完成任务 | 某个特效或服务失败即无法玩 |

对每一维记录设备、版本、操作、观察、失败等级和复测结论。采用真实用户的独立任务测试，不给玩家口头导航。前四位首次玩家中若有人不能在首屏找到建角/续玩、世界设定或导入入口，先修入口，不加新特效。

## 6. 可验收的文案与“无 AI 味”标准

UI 文案用玩家熟悉的行动词，不以抽象概念命名核心按钮。剧情写作先由作者定义人物的欲望、冲突、不可说之事和事件后果，再让模型在这个框架内变换表达。100 回合随机盲评中，任何物品、境界、死生、位置或任务事实越权都为阻断；语言通过率至少 90%。未通过的样本标记事实错误、人物失真、重复、空泛抒情或节奏问题，回写到内容和模型评测集。此门槛衡量可修复的文字质量，不替代长期玩家感受。

代码和文档也须去模板化：变量和组件名称说明真实职责；架构图对应可运行模块；性能报告给设备与原始记录；每项“完成”附成功操作。不要写“极致沉浸”“全面赋能”等无法验证的结论。

## 7. 设计与产品验收脚本

1. 在 360×800 手机无档进入：山门首屏不滚动即可点“进入世界”；随后能找到“新开一局”“阅读世界设定”和 AI 设置，菜单内可导入旧档；建角返回和刷新后字段仍在。
2. 在有档桌面进入：续玩是主动作；从游戏打开世界书，返回仍位于同一回合和段落。
3. 对照旧版逐项查看青鱼配置、五岗位、参数、连接测试、调用记录和存档恢复；每项至少有成功与失败操作。
4. 在四场景切换时核对事件与素材版本；静音、弱动效、省流量和资源 404 均可完成同一行动。
5. 从自由输入得到歧义澄清、规则失败、叙事失败三类结果；任何重试不得多生成事件或费用。
6. 发布游记前看到脱敏预览并主动确认；未经审核不公开。
7. 两作者在中端 Android、平板、集显电脑和桌面浏览器分别完成 30 分钟阅读、首任务、长局片段与媒体失败恢复。

产品评审的结果为通过、带问题通过、阻断三类；“带问题通过”不得用于隐私、账务、Canon 越权、存档损坏或核心任务失败。
